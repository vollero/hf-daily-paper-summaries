# MobilePA-Bench: Benchmarking Mobile Planner Agents on Complex Real-World Tasks

> [← Daily summary](../2026-08-25.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2608.23035) · [arXiv](https://arxiv.org/abs/2608.23035)


## One-sentence takeaway

MobilePA-Bench shows that leading LLM planners remain unreliable on stateful mobile workflows requiring ordered tool use, delegation, memory retrieval, and reusable skills, with the best model scoring 75.52% overall.

## Problem and motivation

Existing mobile-agent evaluations emphasize either GUI manipulation or offline function-call matching. The authors argue that neither captures central planners operating under live state changes, tool dependencies, permissions, runtime errors, personalization requirements, and heterogeneous execution routes. MobilePA-Bench addresses this gap with executable, tool-centric evaluation of complex mobile workflows (Abstract; Sections 1 and 2).

## Approach and contributions

- **Comprehensive benchmark:** 1,705 tasks spanning 13 mobile domains and 212 tools, divided into Basic Tool Use, Sub-agent Collaboration, Memory Usage, and Skill Usage (Sections 1 and 4.1).
- **Stateful execution sandbox:** Structured tools execute against persistent application databases, mutate state, log operations, and return runtime feedback for replanning (Sections 3.2.1–3.2.3; Figures 2–4).
- **Unified action interface:** Direct tools, sub-agent entry points, memory search, and dynamically loaded skill tools share a function-calling protocol (Section 3.2.2).
- **Evidence-aligned verification:** Tasks use fixed tool-call, terminal-state, or agent-behavior checkers, augmented by memory- and skill-specific gates (Section 3.3.1; Figure 5).
- **Open evaluation infrastructure:** The authors claim to release all tasks, evaluation data, and the sandbox for diagnosis, training, and agentic reinforcement learning (Section 1).

These results establish performance under MobilePA-Bench’s sandbox, tool recall, step limit, gates, and weighted aggregation. They support the authors’ claim that compound mobile planning remains unreliable in this setting. They do not establish real-device reliability, user satisfaction, safety in deployment, or that skill reuse itself causes better performance; the skill-versus-memory comparison involves different task dimensions rather than a controlled intervention.

## Limitations and validity risks

The supplied text contains no dedicated author-stated limitations section.

- **Analyst inference—simulator validity:** Execution uses structured backend databases without full visual rendering. This improves throughput but leaves unclear how closely results transfer to real devices, latency, UI variation, and hardware-dependent failures (Sections 2.1 and 3.2.3).
- **Analyst inference—delegation scope:** Sub-agent scoring evaluates route selection and handoff quality, not successful downstream policy execution, so it does not measure complete delegated task reliability (Section 3.4.2).
- **Analyst inference—metric dependence:** Overall rankings depend on the authors’ fixed 50/10/20/20 weights and required gold-memory and gold-skill gates; alternative valid retrieval or skill strategies may be penalized (Sections 3.4.3–3.5).
- **Analyst inference—limited stability evidence:** Repeated-run analysis covers only Qwen3.6-27B, so comparable variance is not established for the 13 main models (Section 4.3).
- **Analyst inference—missing causal ablation:** No reported ablation isolates the benefit of stateful feedback, skill loading, memory access, candidate recall size, or each verification gate.
- **Analyst inference—task provenance:** Tasks are described as synthesized from realistic scenarios and human-curated seeds, but the supplied text does not provide detailed annotator procedures, agreement statistics, contamination checks, or evidence of real-user representativeness (Sections 3.3–3.4).

## Open research questions

1. **How well do benchmark scores transfer to real phones?** Simulator-to-device validity is not evaluated. A next experiment could replay a stratified task sample on physical devices and compare success, failure categories, and trajectory divergence.

2. **Which benchmark components improve diagnosis or training?** The paper reports no component ablation. A factorial study could remove state feedback, memory gates, skill expansion, or specialized delegation and measure capability-specific changes.

3. **Can planners improve compound reliability across capabilities?** Different models lead different dimensions, while multi-stage errors reportedly cascade. A next experiment could construct matched tasks requiring one, two, three, or four capabilities and quantify how success decays with composition depth.

4. **How sensitive are results to evaluation design?** Only one weighting scheme, top-15 tool recall, and a 15-step budget are reported. Sweeps over weights, recall size, step budget, and equivalence-aware gates could test ranking robustness.

## Confidence and missing information

**Confidence: high** for the benchmark design and reported results because the supplied text includes detailed methods and tables.
