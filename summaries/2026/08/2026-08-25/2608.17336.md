# TileMix: Tile-Centric Mixed-Precision Attention for LLM Inference Acceleration

> [← Daily summary](../2026-08-25.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2608.17336) · [arXiv](https://arxiv.org/abs/2608.17336)


## One-sentence takeaway

TileMix accelerates dense long-context LLM prefill by routing hardware-aligned attention tile groups between FP16 and INT8 inside one fused kernel, recovering much of uniform-INT8’s quality loss while retaining all legal token interactions.

## Problem and motivation

Dense self-attention requires \(O(L^2)\) query–key score computation, making long-context prefill expensive in compute and memory traffic. The authors argue that existing approaches either apply a largely uniform numerical format, prune token interactions, or use tiling only for data movement; none provides spatial FP16/INT8 routing over score-tile groups inside a fused dense-attention streaming loop (Sections 1–2).

The resulting systems challenge is to dispatch heterogeneous Tensor Core paths within the latency-critical inner loop, rescale their outputs into a common domain, and safely update one online-softmax state without sacrificing dense connectivity (Sections 1 and 3.2).

## Approach and contributions

- **Tile-group precision routing:** Each legal hardware-aligned score-tile group is assigned to either FP16 or blockwise INT8 query–key computation; no interactions are removed (Section 4.1; Figure 2).
- **Shared-state fused execution:** INT8 scores use Tensor Core multiplication with INT32 accumulation and scale restoration. Both score paths then enter a common floating-point domain and update the same FP16 online-softmax state; values and \(PV\) remain FP16 in the primary evaluated prefill path (Section 4.3; Appendix C).
- **Compact routing:** Up to 64 routing decisions per query-tile row are packed into a 64-bit word and decoded with shift-and-mask operations. A grouping factor lets one bit govern adjacent key tiles, producing \(O(H_kT_m)\) routing metadata (Section 4.2; Figures 3–4).
- **Practical interfaces:** The implementation supports training-free static policies, grouped-query attention, variable-length batches, quantize-once and on-the-fly operand preparation, plus a separately described INT8 key/value-cache interface (Sections 4.1–4.3; Appendices C–D).
- **Evaluation:** The authors test retrieval, long-context QA, prefill throughput, and numerical deviation across LLaMA, Qwen, and Vicuna models (Section 5; Appendices E–G).

These results establish an empirical accuracy–throughput frontier on the evaluated models and A100 implementation. They do not establish universal superiority: mixed configurations sometimes trail uniform INT8 in throughput, quality depends materially on layout and task, and no statistical uncertainty is reported. The exceptional 16k factual-recall gains are reported consistently across models, but the supplied text does not explain their mechanism or rule out benchmark-specific effects.

## Limitations and validity risks

- **Author-stated:** Evaluation targets forward inference during long-context prefill; the current kernel uses FP16 and INT8 Tensor Core paths on NVIDIA A100 GPUs. Other formats require new scaling and scheduling logic (Limitations, page 9).
- **Author-stated:** Evaluated policies are static, data-free templates shared across layers, batches, and KV heads; adaptive policies are supported by the interface but not evaluated (Limitations; Appendix B).
- **Author-stated:** The primary prefill evaluation quantizes Q/K but keeps \(V\) and \(PV\) in FP16. The INT8 KV-cache path is a separate interface rather than the main measured configuration (Appendices C–D).
- **Analyst inference:** Hardware portability is uncertain because measurements use only A100 40GB GPUs and an A100-specific fixed autotuned configuration.
- **Analyst inference:** The text provides no repeated-run variance, confidence intervals, or significance tests for accuracy or throughput.
- **Analyst inference:** The dramatic SpTrans gains on 16k factual recall merit targeted validation because they greatly exceed FP16 yet disappear at longer contexts; no causal ablation explains this anomaly.
- **Analyst inference:** Layout comparisons confound spatial placement with realized coverage because requested 25/50/75% coverage may differ slightly at boundaries, and coverage counts tile groups rather than actual INT8 FLOPs (Appendix B).
- **Analyst inference:** Energy use is discussed only as a possible broader impact; no power or energy measurements are supplied.

## Open research questions

1. **Can routing be made input-adaptive without erasing the throughput gain?** Only static templates are evaluated. A next experiment could compare static routing with an online importance predictor while measuring accuracy, routing overhead, and end-to-end throughput.

2. **Do the gains transfer beyond A100 and FP16/INT8?** Hardware and formats are narrow. Implementing matched kernels on another GPU generation or with FP8/INT4 would test portability under the same quality and timing protocol.

3. **What causes the exceptional 16k factual-recall gains?** The paper reports large, cross-model SpTrans improvements but no mechanistic ablation. Experiments varying stride geometry, prompt construction, random seeds, and decoding settings could test whether the effect reflects useful routing structure or benchmark sensitivity.

4. **How does TileMix affect full serving workloads?** The main measurements cover prefill, while decode and INT8 KV caching are only described as interfaces. End-to-end tests combining prefill, decode, concurrent requests, latency percentiles, memory use, and energy would establish deployment-level value.
