# Apodex 1.1: Scaling Agentic Intelligence for Complex Work

> [← Daily summary](../2026-08-25.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2608.23283) · [arXiv](https://arxiv.org/abs/2608.23283)


## One-sentence takeaway

Apodex 1.1 combines executable file/search/code environments, persistent state, multi-agent coordination, and trajectory-level SFT/RL to improve verifiable long-horizon work, although component-level attribution and several evaluation comparisons remain limited.

## Problem and motivation

The authors target the gap between producing a plausible answer and completing useful, inspectable work over long horizons. Such work requires agents to operate on files and code, gather evidence, preserve state and provenance, recover from failures, revise plans, and satisfy explicit delivery requirements—not merely reason in text (Sections 1–2.1).

They argue that conventional parameter, data, and inference scaling do not directly address two missing scaling surfaces: the diversity of executable environments in which agents learn, and the amount of useful work coordinated across agents, branches, and time (Sections 2.2–2.3).

## Approach and contributions

- **Environment Scaling:** Constructs composable file, search, and code worlds with explicit state transitions, budgets, failure modes, verifiers, isolation, and replay records. File-world coverage spans 33 domains, 318 occupations, and 1,208 deliverable clusters (Sections 3.1.1–3.1.3).
- **Agentic Coordination Scaling:** Trains decomposition, delegation, asynchronous result integration, targeted verification, dynamic replanning, and termination of obsolete work. Agent Team externalizes coordination through a persistent task board (Section 3.2).
- **AgentOS and shared harness:** Maintains files, retrieved evidence, executable state, artifact provenance, dependency graphs, interventions, and controlled publication across single- and multi-agent runs (Section 3.3).
- **Unified training:** Uses a broad SFT mixture followed by agentic RL. PIVOT-RL identifies consequential failure points, preserves useful prefixes, and optimizes localized continuations alongside full unhinted tasks (Section 3.4).
- **Evaluation assets:** Introduces FrontierResearchBench for end-to-end scientific delivery and HDS6 for process verification; it also reports the existing internal FrontierSearchBench (Sections 4.4–4.5).

The evidence consistently shows higher scores for Agent Team than ReAct across the reported matched Apodex settings. This supports a system-level benefit from coordination plus additional organized computation, but it does not isolate whether gains arise from delegation, verification, parallelism, larger compute budgets, the task board, or another component. Results also do not establish universal superiority: Apodex trails listed references on BioMysteryBench, coding benchmarks, and FrontierResearchBench.

## Limitations and validity risks

- **Author-stated runtime limits:** AgentOS does not guarantee source, computation, or scientific correctness; high-stakes outputs still require appropriate verification and human review (Section 3.3.4).
- **Author-stated persistence limits:** Coordination state is run-scoped, is not atomically checkpointed with the filesystem, and cannot rewind historical workspace state after restart (Section 3.3.4).
- **Author-stated security boundary:** Publication controls operate mainly through built-in writing surfaces rather than a universal syscall-level monitor (Section 3.3.4).
- **Author-stated causal limit:** HDS6 does not isolate individual component effects. Its Deep Discover comparison is also not a matched single-run ablation because version 1.0 aggregates eight runs while version 1.1 uses one (Sections 4.5; Figures 5–6).
- **Analyst inference:** Agent Team versus ReAct confounds coordination policy with additional computation; no compute-matched comparison is reported.
- **Analyst inference:** Component ablations for PIVOT-RL, environment families, task-board persistence, asymmetric verification, and adaptive team effort are absent from the supplied text.
- **Analyst inference:** Several comparisons mix reported leaderboard values, internally reproduced results, and different harnesses. Table 9 explicitly compares FrontierAgent, Codex, and Claude Code systems, limiting model-only conclusions.
- **Analyst inference:** The report gives limited training reproducibility detail: dataset sizes, RL algorithmic specifics, compute budgets, contamination controls, and model architecture beyond 35B/397B references are not supplied.

## Open research questions

1. **Which coordination component produces the gains?** The paper evaluates the combined Agent Team system but provides no component ablation. A next experiment could independently remove the task board, asymmetric verification, adaptive fan-out, and replanning under a fixed inference budget.

2. **Do improvements survive compute matching?** Agent Team receives additional organized computation relative to ReAct. A controlled study could equalize tokens, tool calls, wall-clock time, and total model FLOPs across single-agent sampling and coordinated teams.

3. **How much does PIVOT-RL contribute beyond conventional trajectory RL?** Figure 4 shows improvement as RL compute grows but does not compare localization against an otherwise matched full-trajectory method. An experiment could hold trajectories and compute fixed while varying pivot localization and corrective hints.

4. **How robust are internally judged benchmarks to grader choice?** FrontierSearchBench uses a model-judge panel for alignment, while FrontierResearchBench uses GPT-5.6-Sol for some semantic judgments. Regrading with blinded human experts and alternative judge panels would test sensitivity and agreement.

## Confidence and missing information

**Confidence: high** for the described system and reported results, because the supplied text includes the complete report, detailed methods, tables, and explicit caveats.

Material missing information includes exact model architecture, full training-data composition and scale, SFT/RL compute, inference budgets for each system, compute-matched ablations, statistical uncertainty across repeated runs, contamination analysis, complete benchmark release status, and sufficient implementation detail to reproduce PIVOT-RL independently.
