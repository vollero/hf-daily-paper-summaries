# The Optimizer Is the Agent: Reasoning-Driven Search across Prompts, Programs, and ML Workflows

> [← Daily summary](../2026-08-10.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2608.06714) · [arXiv](https://arxiv.org/abs/2608.06714)


## One-sentence takeaway

ReASearch lets a tool-using language-model agent control budgeted search through reasoning and persistent memory, matching or outperforming specialized optimizers across most of 14 prompt, program, and ML-workflow tasks.

## Problem and motivation

Optimization of prompts, programs, and training workflows occurs over large, discrete spaces where semantic and execution feedback is useful, yet existing systems generally leave candidate selection, budget allocation, exploration, and recovery to fixed outer-loop algorithms. The authors ask whether a single reasoning agent can internalize this search policy rather than merely generate edits inside an evolutionary, bandit, Bayesian, or textual-gradient controller (§1).

This matters because a shared optimizer could reduce domain-specific search engineering and adapt its strategy from observed failures. The identified gap is the lack of systematic evidence that one controller-light agent scaffold can optimize across distinct artifact types (§1; Appendix A).

## Approach and contributions

- **Unified agentic optimizer:** ReASearch represents optimization as sequential reasoning over textual artifacts. A task-agnostic agent chooses evaluations, diagnoses outcomes, edits artifacts, verifies candidates, backtracks, and allocates its remaining budget (§2.1–§2.2).

- **Domain-specific tools, shared loop:** The same scaffold handles prompt optimization, program evolution, and ML-workflow optimization by changing only the system prompt and available tools. General tools include file access, Python/Bash execution, context compaction, and persistent `lessons.md` memory; specialized tools expose evaluation and editing operations (§2.2–§2.3; Appendix G).

- **Long-horizon state management:** Per-turn state, context compression, persistent lessons, and structured search history preserve why earlier attempts succeeded or failed (§2.2; Appendix F–G).

- **Cross-domain evaluation and behavioral analysis:** The authors evaluate 14 tasks and analyze emergent behaviors such as verification, causal diagnosis, hypothesis-driven revisions, reverting, and adaptive exploration (§3).

The results support the authors’ claim that one scaffold can perform competitively across heterogeneous optimization settings and that memory and executable analysis are functional components rather than decorative additions. They do not establish that reasoning eliminates all controller logic: the scaffold still assembles per-turn state, supplies stagnation warnings, defines tools, enforces budgets, and uses domain prompts (Appendices F–G). Nor do the results prove global optimality of discovered mathematical solutions; the tables compare against supplied best-known values, while stronger optimality language is largely based on trajectory analysis.

## Limitations and validity risks

- **Author-stated scope condition:** Performance depends on an optimizer model with sufficient long-horizon agentic ability and scales with backbone capability (Appendix D).

- **Author-stated variance concern:** Prompt evaluations can be noisy; Terminal-Bench validation runs show substantial variation, and the method deliberately rechecks candidates (§2.3.1; Appendix B).

- **Analyst inference — limited replication:** The main evaluation averages three independent optimization runs (§3), which may be insufficient for highly variable agent and RL outcomes.

- **Analyst inference — harness confound:** The Claude Code comparison matches instructions, budgets, code, data, evaluator, and hardware, but ReASearch additionally re-emits structured state and stagnation advice every turn. This identifies the scaffold as part of the intervention but does not isolate reasoning from state presentation (Appendix F).

- **Analyst inference — incomplete component isolation:** Memory and Python are ablated, but the supplied text does not report ablations of per-turn state re-emission, stagnation warnings, search-tree review, editing subagents, or verification subagents.

- **Analyst inference — uneven comparisons:** Baselines and backbones vary by category, and not every method is run with every backbone. “Human best-known” results may also have different computational provenance from the fixed evaluator-call comparison (§3.2).

- **Analyst inference — possible task-specific leakage in crypto setup:** Manual iteration and leaderboard lessons are distilled into the agent instructions before optimization, limiting interpretation as fully autonomous search from the published baseline (Appendix H.3).

- **Analyst inference — reproducibility unclear:** Tool specifications and artifacts are described, but the supplied text does not establish public code, exact hardware for each task, raw run logs, or all random seeds.

## Open research questions

1. **Which harness element produces the gains?** The paper groups state re-emission, lessons, stagnation warnings, and search-tree review together. A factorial ablation across these components, using identical backbones and tasks, could measure their independent and interacting effects.

2. **How robust are conclusions under more runs and budgets?** Several settings are noisy, while averages use three optimization runs. A next experiment could run many seeds across short, medium, and long budgets and report confidence intervals, failure rates, and anytime performance.

3. **Does agent-controlled search generalize to sparse or delayed feedback?** Most tasks provide executable metrics or detailed training feedback. An experiment could progressively reduce feedback frequency and granularity while measuring degradation relative to explicit search controllers.

4. **When should explicit controllers remain preferable?** ReASearch is not uniformly best, as seen in TXN and the near-tie on NanoGPT. A controlled benchmark varying search-space structure, evaluation noise, and cost could identify regimes where agent reasoning, classical search, or hybrid control is most efficient.

## Confidence and missing information

**Confidence: high** for the reported architecture, task coverage, tables, and component ablations because the supplied text is extensive and includes methods and appendices.

Material missing or unclear: public code and artifact availability; complete raw trajectories and logs; exact hardware assignments; all random seeds; statistical significance tests; detailed results for every one of the claimed 14 tasks under every baseline/backbone; full ablations of harness features and subagents; and independent verification of “human best-known” or optimality claims.
