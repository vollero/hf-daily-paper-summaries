# FreeToken: Efficient Edge-Native MoE Serving with Bandwidth-Adaptive Execution

> [← Daily summary](../2026-08-19.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2608.16157) · [arXiv](https://arxiv.org/abs/2608.16157)


## One-sentence takeaway

FreeToken combines bandwidth-aware CPU–GPU execution, semantic state and expert caching, and elastic memory management to serve 35B–753B MoE models interactively on single consumer or workstation machines.

## Problem and motivation

Frontier open-weight MoE models can require hundreds of gigabytes of weights even though each token activates only a small fraction, making local inference bottlenecked by expert storage and movement rather than computation alone. Existing edge engines use largely static offloading policies that poorly handle dense expert access during prefill, sparse but changing access during decode, repeated context edits in agent workflows, and fluctuating consumer hardware resources (§§1–2).

The authors identify three gaps: prefill repeatedly transfers nearly all experts and recomputes edited contexts; decode cache misses are not efficiently divided between PCIe transfer and CPU execution; and fixed memory configurations cannot adapt to heterogeneous or changing edge resources (§§2.1–2.3).

## Approach and contributions

- **Bandwidth-adaptive execution:** Prefill overlaps full-layer expert transfers with GPU computation using double buffering. During decode, a closed-form \(q^\star \approx mB_P/B_H\) policy divides \(m\) missing experts between GPU cache fills and direct CPU execution according to measured PCIe and host-processing bandwidth (§§3.1–3.2).
- **Semantic-aware reuse:** Recurrent-state checkpoints are placed at tool-call, thinking-block, and conversation boundaries so edited agent contexts can resume from surviving prefixes. A shared LRU expert cache exploits routing locality between adjacent decode steps (§§3.1–3.2; Figure 2).
- **Elastic edge runtime:** GPU expert-cache capacity can be rebuilt at scheduler safe points without restarting or reloading the host expert pool. A prearranged FreeToken Weight format and post-load memory pinning reduce startup overhead (§§3.3, 4.2).
- **Integrated heterogeneous implementation:** Routing-dependent cache control and concurrent CPU/GPU execution remain inside CUDA Graph execution, while CPU-resident weights act as the source of truth (§§4.1–4.2).
- **Broad serving support:** The authors report support for more than 20 MoE models and demonstrate models from 35B to 753B parameters on hardware ranging from an 8GB laptop GPU to one 96GB workstation GPU (§1; §7).

These results support the authors’ claim that the integrated runtime improves throughput and tail latency across the tested MoE models, agent workloads, and machines. They do not establish model-quality improvements, deployment behavior beyond the tested NVIDIA systems, multi-user serving scalability, or superiority under every precision, batch size, and workload distribution.

## Limitations and validity risks

- **Author-stated platform fallback:** If the expert pool cannot be pinned or registered for DMA, FreeToken falls back to pure CPU expert execution, sacrificing peak transfer performance (§4.2).
- **Author-stated capacity condition:** Full-layer prefill double buffering requires space for two complete layers; otherwise the system uses on-demand loading (§3.1).
- **Analyst inference — narrow model sample:** Although support for more than 20 models is claimed, detailed evaluation centers on two models, with GLM-5.2 used only for a separate workstation demonstration (§§1, 5.1–5.3).
- **Analyst inference — hardware scope:** All six systems use discrete NVIDIA GPUs, so results do not establish behavior on integrated GPUs, other accelerator vendors, or operating systems where pinned DMA is constrained (Table 1; §4.2).
- **Analyst inference — incomplete statistical reporting:** Figures report means and, for cache traces, min–max bands, but the supplied text does not state repetition counts, confidence intervals, or variance for end-to-end throughput and TTFT (§5).
- **Analyst inference — comparison coverage varies:** Some baselines cannot serve particular models or multi-turn workloads, and MoE-Infinity serves only W1; therefore not every headline comparison uses the same baseline set (§5.2; Figure 3).
- **Analyst inference — task validity is constrained:** Coding runs must produce a gold patch and W4 must finish all turns, but broader output-quality or accuracy measurements are not reported (§5.1).

## Open research questions

1. **Does the bandwidth policy remain optimal under rapidly changing contention?** The paper profiles \(B_H\) and \(B_P\) at deployment, while motivating resources that vary during use. A next experiment could introduce controlled CPU, PCIe, and DRAM contention and compare static profiling with online re-estimation.
2. **How much does semantic checkpoint placement contribute independently?** The supplied evaluation isolates prefill overlap and expert-cache locality, but not semantic state caching. An ablation could compare semantic anchors with uniform, recency-based, and no recurrent-state checkpoints on edited multi-turn traces.
3. **How does FreeToken scale to concurrent users or larger decode batches?** Evaluation emphasizes real agent trajectories and per-request metrics, but concurrency scaling is not reported. A follow-up could sweep simultaneous sessions and batch sizes while measuring throughput, TTFT tails, cache interference, and memory repartitioning.
4. **How portable is the design beyond the tested NVIDIA systems?** The implementation relies on CUDA Graphs and pinned host transfers. A next experiment could reproduce the scheduling policy on integrated-memory or non-CUDA accelerators and quantify which mechanisms remain beneficial.

## Confidence and missing information

**Confidence: high** for the reported design and experiments because the supplied text includes the complete paper, equations, setup, and main numerical results.

Material missing information includes repetition counts and uncertainty for end-to-end measurements; detailed results for the claimed 20-plus supported models; an isolated semantic-state-cache ablation; accuracy or quality measurements beyond task-completion requirements; concurrent-serving results; energy consumption; and evaluation on non-NVIDIA platforms.
