# Harness the Memory: A Holistic Evaluation of Memory Substrates in Memory Agents

> [← Daily summary](../2026-08-19.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2608.15008) · [arXiv](https://arxiv.org/abs/2608.15008)


## One-sentence takeaway

Under a controlled LLM-agent harness, memory-substrate quality and cost vary sharply by task regime, retrieval breadth, backbone, and history length, supporting regime-aware routing rather than a single universal substrate.

## Problem and motivation

Long-horizon LLM agents must store growing experience, retrieve useful information, and manage memory within compute and storage budgets. The authors argue that existing evaluations offer poor guidance for choosing the underlying memory substrate because they concentrate on dialogue benchmarks, emphasize accuracy over efficiency, and frequently use only one backbone. Their survey reports that LoCoMo and LongMemEval constitute 62% of 76 benchmark–system pairs, only 21% of 52 systems measure any efficiency dimension, and 81% primarily use GPT-family models (Figure 1; Appendix A.2).

The paper addresses this gap by holding the surrounding agent harness fixed and varying the memory substrate across both fact-retrieval and sequential-decision settings.

## Approach and contributions

- **Controlled substrate harness:** Evaluates 11 implementations from seven external and internal memory families on identical histories, prompts, auxiliary-LLM settings, three backbones, and four benchmark suites (§§2–3; Figure 2).

- **Broad performance-and-cost accounting:** Instruments 26 metrics covering task quality, storage, latency, token and call consumption, management overhead, and total cost (§3; Appendix D, Table 6).

- **Cross-regime comparison:** Tests conversational QA and memory capabilities alongside embodied planning and code generation, mapping substrate-specific performance–latency trade-offs (Tables 1–2; Figure 3).

- **Diagnostic ablations:** Sweeps retrieval depth on LoCoMo and ALFWorld, probes attention allocation, and tests conflict resolution at 6K, 32K, and 262K tokens (§3; Figures 4–6).

- **Design conclusion:** The authors propose routing among substrates by regime and history depth, with the heuristic “trade read breadth for write depth”—retrieve selectively while investing in write-time distillation or structure (§§5.1–5.3).

These results establish heterogeneous performance–cost trade-offs within the tested harness and show that retrieval breadth can correlate with opposite outcomes across the two probed tasks. They do not establish that the proposed routing rule generalizes to untested models, domains, memory implementations, or production workloads. The attention probe supplies a mechanism-consistent observation, but the supplied text does not describe a causal intervention proving that the attention shift causes the performance change.

## Limitations and validity risks

- **Author-stated:** MemGPT, Mem0, and Zep are excluded from the main comparison because their auxiliary-LLM demands reached 2,739–8,984 calls and 11.8–23.1 hours per LoCoMo run (Appendix B.3; Appendix G). This narrows claims about production-grade systems.

- **Author-stated:** M8 replaces its reference PPO controller with a zero-shot LLM that receives all skill bundles, while M11 replaces in-place KV-cache editing with utterance-level re-prefill (Appendix B.1–B.2; Appendix G). Their results therefore apply to modified implementations.

- **Author-stated:** M7 is unavailable for user-centric dialogue tasks, M9 is incompatible with the tested Gemma MoE model, and M10 is omitted from agent-centric benchmarks because accumulated histories exceed tested context windows (§3).

- **Analyst inference:** The fixed gpt-4o-mini auxiliary model and judge may couple outcomes to one proprietary model and judging configuration; no alternative-judge robustness result is supplied (§3; Appendix D.2).

- **Analyst inference:** Several highlighted gaps are point estimates. The authors argue that differences of at least 0.05 are unlikely to reverse under resampling, but the supplied text provides no confidence intervals or significance tests (Appendix D.4).

- **Analyst inference:** The attention analysis covers M1 and specific model/task settings, so it does not by itself demonstrate the same mechanism for all substrate families (Figure 5).

- **Analyst inference:** Hardware is fixed at 4×H200 GPUs, while external API and write costs differ by method; latency rankings may change under other deployment architectures (§3; Appendix D.3).

## Open research questions

1. **Can a learned router outperform fixed substrate selection?** The paper motivates routing but does not report an implemented router. A next experiment could train a selector using task type, history length, latency budget, and retrieval diagnostics, then compare it with the best fixed substrate on held-out regimes.

2. **Is attention reallocation causally responsible for agentic degradation?** Figure 5 shows correlated attention shifts only for M1. A controlled experiment could mask retrieved regions, preserve observation attention, or reorder equivalent evidence while measuring task success.

3. **Do the conclusions survive reference-faithful and production-grade implementations?** M8 and M11 are modified, while three production systems are excluded. A budget-matched study could compare faithful implementations under equal token, call, latency, and storage constraints.

4. **How well do substrate choices transfer beyond these benchmarks and backbones?** Coverage is limited to three models and four suites. A next experiment could evaluate the same harness on additional long-running interactive tasks while holding histories and budgets constant.
