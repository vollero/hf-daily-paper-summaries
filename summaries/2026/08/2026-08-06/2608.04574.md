# When Memory Lies: An Empirical Study of Spatial Memory Staleness in VLM Agents

> [← Daily summary](../2026-08-06.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2608.04574) · [arXiv](https://arxiv.org/abs/2608.04574)


## One-sentence takeaway

In a controlled dynamic gridworld, stale spatial memory can make VLM agents markedly less safe than using no memory, while read-time filtering mitigates much of the harm only when the agent can reliably ground current observations.

## Problem and motivation

The paper studies how memory-augmented VLM agents behave when a previously correct spatial claim conflicts with a changed environment. This matters because an agent may confidently follow outdated “safe” information into a hazard even while receiving a truthful current observation.

The identified gap is the intersection of memory staleness, multimodal grounding, and safety-sensitive action: prior memory-agent work emphasizes storing and reusing knowledge, factual-staleness work focuses on textual facts, and spatial benchmarks largely use static observations rather than changed spatial memories that affect actions (Sections 1–2).

## Approach and contributions

- **SpatialSTALE testbed:** A fully observable dynamic \(8\times8\) FrozenLake environment with one textual memory entry per cell. Safe frozen cells and lethal holes can change before or during navigation (Sections 3.1–3.4; Appendix A).
- **Paired evaluation:** The same instances test entry-level stale/valid classification from either text grids or rendered images, followed by navigation measuring success, death, path length, and reward (Sections 3.2–3.5).
- **Controlled memory comparison:** NoMemory, raw NoFilter memory, one-shot SelfVerify, batched/event-aware OMCD filtering, and an Oracle-label ablation isolate the effects of memory consumption, auditing, and label quality (Section 4).
- **Empirical characterization:** Six VLMs are evaluated for detection; four serve as text-mode navigators. The analysis links modality-dependent auditing to downstream safety and distinguishes early stale-memory deaths from exploration failures (Sections 5.1–5.4).
- **Released assets:** The authors report releasing code, all 50-seed map sets, full model traces, and reproducibility pipelines (Section 1).

The evidence establishes a causal safety cost within this controlled setting because strategies share the same navigator, live observation, action space, and seed set while differing in memory presentation. It also supports a strong model-dependent modality gap and shows that filtering can remove much of the raw-memory penalty in text mode.

It does not establish that OMCD is superior to memoryless navigation generally, that Oracle and OMCD are equivalent, or that the numerical effects transfer to realistic embodied environments. The vision-navigation evidence is explicitly exploratory and small-scale.

## Limitations and validity risks

- **Author-stated:** The environment is a fully observable, symbolic \(8\times8\) FrozenLake. Results are controlled-mechanism estimates, not field estimates (Section 6).
- **Author-stated:** Memory always contains one textual entry per cell, including synthetically completed unvisited cells; partial coverage, noisy memories, and distractors are not tested (Sections 3.2 and 6; Appendices B and K).
- **Author-stated:** Vision navigation uses only 10 seeds with three episodes per cell, so its downstream conclusions are exploratory (Sections 5.1–5.2 and 6).
- **Author-stated:** Oracle, trajectory, and F1–success analyses are narrower than the full text-navigation evaluation, and model-specific asymmetries may not generalize (Section 6).
- **Author-stated:** Failure to detect an Oracle–OMCD difference is not an equivalence result; a formal equivalence test and possibly greater power would be needed (Section 5.3).
- **Analyst inference:** Because the current observation is complete and truthful at every step, the study measures conflict resolution under full observability rather than memory’s value when observations are incomplete or noisy (Appendices B–C).
- **Analyst inference:** The main navigation comparison lacks an external symbolic planner, so it does not separate errors specific to LLM action selection from errors avoidable by conventional planning (Appendix C).
- **Analyst inference:** Recommended model temperatures are mentioned but not enumerated in the supplied text, limiting exact reconstruction from this text alone (Section 5.1).

## Open research questions

1. **Does the stale-memory safety tax persist in larger or partially observable environments?**  
   The paper tests only fully observable \(8\times8\) grids. A next experiment could scale to \(16\times16\) and \(32\times32\) grids while independently varying observation occlusion and memory coverage.

2. **Can audits remain reliable with realistic visual noise and ambiguous changes?**  
   Current changes are binary F/H flips in a fixed rendering. A next experiment could introduce lighting, viewpoint, localization, or object-state uncertainty and evaluate calibrated abstention as well as F1.

3. **How should action policies use filtered memory safely?**  
   Oracle labels do not measurably improve over OMCD in the present setting, while residual deaths remain. A next experiment could hold filtered memory fixed and compare the LLM navigator with symbolic planning or conflict-aware action policies.

4. **Which errors matter more than aggregate detection F1?**  
   Per-seed F1 is uncorrelated with navigation success and does not capture whether a missed entry lies on the chosen path. A next experiment could evaluate path-weighted, hazard-weighted, or decision-conditioned detection metrics against downstream death.
