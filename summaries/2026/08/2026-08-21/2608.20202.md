# MemTrapBench: Benchmarking Cognitive Traps in LLM Memory Use

> [← Daily summary](../2026-08-21.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2608.20202) · [arXiv](https://arxiv.org/abs/2608.20202)


## One-sentence takeaway

MemTrapBench shows that relevant long-term memories can systematically impair an LLM’s current reasoning or beliefs, while the prompt-based AdaptiveMem mitigation recovers some performance without reducing results on the tested standard memory benchmark.

## Problem and motivation

Existing memory benchmarks mainly test whether information is correctly extracted, stored, updated, and retrieved. The authors argue that this misses a downstream failure mode: even accurate and relevant memories can anchor an LLM to an obsolete strategy or distort what it treats as true, making its answer worse than one produced without memory.

They call these failures **memory-induced cognitive traps** and target two broad categories: **Reasoning Fixation** and **Belief Distortion** (Sections 1 and 2.1–2.2).

## Approach and contributions

1. **Failure formulation and taxonomy.** A memory trap occurs when response quality with memory is lower than without memory. The taxonomy covers Task Boundary, Cognitive Bias, Trauma, and Safety scenarios (Sections 2.1–2.2).

2. **MemTrapBench.** The benchmark contains 1,050 multi-turn instances: 350 Cognitive Bias, 350 Task Boundary, 200 Safety, and 150 Trauma. Dialogues contain 18–40 turns and undergo automated filtering plus expert review (Section 2.2; Figure 2).

3. **Cross-system evaluation.** The study compares no memory, full-history prompting, and four memory frameworks on Gemini-3-Flash-Preview and Qwen3-30B-A3B-Instruct-2507 (Section 3.1; Table 1).

4. **AdaptiveMem.** This inference-time system prompt asks the model to detect task transitions, strategy fixation, feedback-induced avoidance, and unsafe contextual premises before applying memory. It requires no architecture, retrieval, storage, or parameter changes (Section 3.6; Appendix A).

The evidence supports the authors’ claim that their constructed histories can induce substantial performance losses across the tested models and memory strategies. Trap-free controls and partial-history experiments provide evidence that semantics matter beyond merely supplying extra context.

It does not establish that memory is generally harmful, that these effects occur at the same rate in natural conversations, or that AdaptiveMem generalizes beyond the tested models, frameworks, benchmarks, and sampled evaluation sets.

## Limitations and validity risks

- **Author-stated scope:** MemTrapBench is a diagnostic stress test of harmful memory influence, not a general evaluation of memory utility (Section 2.2).
- **Analyst inference — syntheticity:** GPT-5.4 generated the expanded dialogues from manually designed seeds. Although automated and expert validation was applied, the paper provides no comparison here between benchmark traps and their prevalence in organic user conversations.
- **Analyst inference — model coverage:** Evaluation uses only two model families, limiting claims about broader LLM behavior (Section 3.1).
- **Analyst inference — judge dependence:** Primary scoring relies on GPT-5.2. Claude-Sonnet-4.6 confirms the direction of one dedicated-subset comparison, but absolute scores differ substantially (Section 3.5; Table 5).
- **Analyst inference — mitigation evaluation scale:** AdaptiveMem is tested on random samples of 200 instances from each benchmark rather than the complete benchmarks (Section 3.6).
- **Analyst inference — incomplete mitigation ablations:** The supplied text does not isolate which AdaptiveMem instruction contributes most, compare against equally long generic caution prompts, or report prompt-overhead costs.
- **Reproducibility status:** The paper says code and data “will be available”; the supplied text does not establish that they were available at evaluation time (page 1 footnote).

## Open research questions

1. **How often do cognitive traps arise in natural interactions?** The benchmark deliberately plants adversarial traps. A next experiment could annotate long, organically collected conversations for comparable task-boundary, fixation, feedback, and safety failures.

2. **Which AdaptiveMem component produces the gains?** The prompt combines four risk checks and a decision procedure without component ablations. A factorial prompt ablation could remove or independently test each instruction.

3. **Can a model detect when memory should be ignored before generating an answer?** AdaptiveMem provides general instructions but no explicit calibrated detector. A next experiment could train or evaluate a trap-risk classifier and measure detection precision, recall, and downstream answer quality.

4. **Do the findings extend beyond textual external memory?** The experiments cover interaction-history and retrieval-based frameworks, not parametric memory. The benchmark could be adapted to fine-tuned or model-edited systems and compared under the same no-memory-style controls.

## Confidence and missing information

**Confidence: high** for the reported benchmark design and tabulated results because the supplied text includes the main paper, tables, figures, and supplementary prompts.

Material missing or unclear includes per-instance data, expert-annotation agreement, automated-filter thresholds, complete task-specific judging rubrics, compute and inference costs, statistical significance tests for most comparisons, AdaptiveMem’s full-benchmark results, and evidence of public code/data availability.
