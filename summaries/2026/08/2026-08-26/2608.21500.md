# SecOPD: Mitigating Adaptive Prompt Injections by On-Policy Distillation

> [← Daily summary](../2026-08-26.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2608.21500) · [arXiv](https://arxiv.org/abs/2608.21500)


## One-sentence takeaway

SecOPD trains an LLM to ignore indirect prompt injections using clean-context, token-level on-policy distillation, reducing Qwen3.6-27B’s PISmith pass@10 attack success rate from 94.0% with Meta-SecAlign to 9.0% while preserving average benchmark utility.

## Problem and motivation

LLM agents consume untrusted websites, files, emails, and tool context that may contain instructions intended to override trusted prompts. Existing model-level defenses distinguish trusted prompts from untrusted data through special message types and defensive fine-tuning, but adaptive attacks optimized against the defended model can still achieve very high attack success rates (ASRs).

The authors attribute part of this weakness to sequence-level feedback in DPO and GRPO: one score is assigned to a whole response, obscuring which tokens correctly answer the trusted task and which follow an injection. This is particularly problematic for mixed responses containing both behaviors (Sections 1, 3.2; Figure 1).

## Approach and contributions

- **Secure On-Policy Distillation (SecOPD):** The student generates a response from an attacked input. A frozen copy of the initialization model scores each generated token under the corresponding clean input, where the injection has been removed. The difference between clean-context teacher and attacked-context student log probabilities supplies token-level advantages (Sections 4.2–4.3; Algorithm 1).

- **Paired clean/attacked training construction:** Each example preserves the trusted instruction and benign context while adding an injected goal to the untrusted-data field. Training includes mostly beginning/end insertions and a smaller number of completion-style delimiter attacks (Section 4.1).

- **Fine-grained defensive credit assignment:** Trusted-task and injection-following spans within the same rollout can receive different feedback, including reasoning tokens, without an external security judge or task-specific reward model (Sections 3, 4.3; Figure 2).

- **Adaptive and cross-domain evaluation:** The authors compare SecOPD with an undefended model, Meta-SecAlign, and GRPO on static and adaptive SEP attacks, AgentDojo tool use, and seven utility benchmarks (Sections 5.1–5.4).

- **Released artifacts:** The abstract states that code and a Qwen3.6-27B SecOPD model are available, although licensing and complete reproducibility details are not included in the supplied text (page 1).

These experiments establish strong comparative robustness for this model and the tested attacks, especially against the paper’s PISmith configuration, while retaining performance on the selected utility benchmarks. They do not establish immunity to prompt injection, robustness against future adaptive attacks, applicability to direct injections or jailbreaks, or generalization across model families. The AgentDojo result is also mixed: SecOPD improves on Meta-SecAlign but not GRPO in ASR, and its Slack-domain ASR remains 24.8% (Table 6).

## Limitations and validity risks

**Author-stated limitations**

- SecOPD addresses indirect prompt injections with a benign user; it is not presented as a defense against jailbreaks, direct prompt injection, or other malicious-user attacks (Limitations).
- It assumes the system already knows which input segments are trusted and untrusted, so it does not solve contextual trust-boundary identification (Limitations).
- Its reasoning traces act as though the injection were absent. This may interfere with downstream detectors that expect injection awareness (Limitations).
- The authors explicitly do not claim to solve prompt injection: PISmith still reaches 9.0% ASR, and stronger future attacks may break the model (Limitations).

**Analyst inferences**

- **Model-family scope:** All main defense comparisons use Qwen3.6-27B, so cross-architecture generalization is untested (Section 5.1).
- **Training-distribution attribution:** The GRPO and SecOPD runs use the same injection pool but different injection sampling distributions, with more completion-style attacks for GRPO. This weakens a strict claim that their differences arise only from sequence-level versus token-level feedback (Appendix G).
- **AgentDojo comparability:** SecOPD and GRPO use a 32,768-token maximum context, while the undefended and Meta-SecAlign evaluations use 16,384. The supplied text does not quantify how this affects the comparison (Appendix H).
- **Judge dependence:** SEP ASR uses witness filtering followed by six unanimous LLM-judge calls. The unanimity rule may suppress positives, and the audit covers one static run rather than the reported adaptive PISmith evaluation (Appendix D).
- **Limited ablation evidence:** The supplied text does not report ablations isolating teacher identity, injection-mixture composition, LoRA rank, training-set size, or whether scoring reasoning tokens is necessary.
- **Incomplete reproducibility detail:** Table 8 gives core hyperparameters, but the supplied text does not establish compute cost, training duration, random-seed variance, or confidence intervals.

## Open research questions

1. **Does SecOPD transfer across model families and scales?** Only Qwen3.6-27B is evaluated. A next experiment could apply the same paired-input recipe to several architectures and sizes, using identical training and PISmith evaluation protocols.

2. **How much of the gain comes specifically from token-level feedback?** GRPO differs in both feedback granularity and injection sampling distribution. A controlled experiment could match data, attack proportions, optimizer budget, and LoRA configuration while varying only token-level versus sequence-level supervision.

3. **Can the defense retain injection-aware reasoning without increasing ASR?** The current method encourages traces that behave as if no injection appeared. A next experiment could add an auxiliary objective for calibrated injection recognition and evaluate both security and compatibility with downstream detectors.

4. **How robust is SecOPD to stronger or differently optimized attacks?** The authors acknowledge that future attacks may exceed PISmith. Evaluation could use multiple independently designed adaptive attackers, larger attack budgets, cross-attack transfer, and tool-use-specific adaptive optimization.

## Confidence and missing information

**Confidence: high** for the method description, reported benchmark values, and stated scope because the supplied text includes the main paper and appendices.
