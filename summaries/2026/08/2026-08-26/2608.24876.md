# Recursive Experiential-Working Memory Evolution for Long-Horizon Agent Harnesses

> [← Daily summary](../2026-08-26.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2608.24876) · [arXiv](https://arxiv.org/abs/2608.24876)


## One-sentence takeaway

Recuris improves frozen LLM agents on long-horizon tasks by coupling verified working state with experiential-skill invocation, then using structured traces to localize failures and validation-gated patches to evolve only the implicated memory components.

## Problem and motivation

Long-horizon agents must track changing goals, invoke relevant skills, execute tools, and verify progress despite increasingly noisy histories. The authors argue that existing experiential-memory systems often retrieve against the initial request or full dialogue, which can obscure unresolved goals and misalign skills with current needs (Introduction, pp. 3–4).

They identify a second gap in self-improvement: final success or failure provides little evidence about whether a repair belongs in stored skills, state tracking, invocation policy, or verification. Coarse memory rewrites may therefore target the wrong mechanism (Introduction, p. 4; §2.3, p. 8).

## Approach and contributions

- **Verified experiential–working-memory coupling:** Working Memory records each goal’s status, evidence, and blockers. It selects skills from Experiential Memory at defined execution events, while environment-grounded checkers admit only supported state transitions (§§2.2.1–2.2.3, pp. 7–8).

- **Structured diagnostic traces:** Each step records working state, invoked skills, action, observation, proposed update, and checker decision. This makes otherwise hidden invocation and state errors observable (§2.1.2, p. 6).

- **Bounded recursive evolution:** A fixed Meta-Agent attributes diagnosed failures to experiential memory, working-memory specification, invocation policy, or checkers; it patches only implicated components. A fixed gate requires source-task repair without unacceptable regression on held-out development tasks (§§2.3.1–2.3.4, pp. 8–9).

- **Frozen-model portability:** The base LLM, tools, Meta-Agent, gate, and outer harness remain fixed. Memory evolved using one deployment model is reused unchanged with other models (§3.1, pp. 10–11).

- **Two adaptation regimes:** Cross-task evolution is used where tasks share tools, policies, or procedures; isolated Terminal-Bench tasks instead receive within-task memory updates between budget-matched retries (§2.3.5, p. 10; §3.5, pp. 23–24).

The evidence supports substantial cross-task gains where tasks share policies or procedures, along with better observability of injected memory faults. It also supports the authors’ narrower claim that state-grounded invocation can outperform presenting the same skills continuously.

It does not establish that every gain is statistically resolved: several Table 1 differences have intervals including zero, all τ2-Airline coupling-ablation intervals include zero, and Terminal-Bench adaptation is directional rather than significant. The horizon analysis is correlational, while SkillFlow evaluates templates selected within their task families rather than transfer to unseen tasks.

## Limitations and validity risks

- **Author-stated statistical uncertainty:** Differences of a few points may reflect run-to-run variation; rerunning an identical τ2-Retail package produced a \([-6.98,+7.27]\)-point interval (Appendix A, p. 31).

- **Small gate split:** The 12-task τ2-Retail development split yields wide intervals and rejected candidates that later improve held-out results. The authors characterize the gate as conservative rather than a reliable good-versus-bad patch classifier (Appendix E, p. 34).

- **Incomplete localization classes:** Checker faults are excluded from the injected-fault ground truth because removing checkers did not affect τ2-Retail pass rate; localization performance therefore covers only \(E,W,\rho\), not all four patchable components (Table 4 discussion, p. 18).

- **SkillFlow is in-sample across tasks:** Templates are selected within each family and evaluated on that family, with no held-out task split. Only transfer across target models is out of sample (Appendix C, pp. 32–33).

- **Terminal adaptation is inconclusive at aggregate scale:** Matched-budget learning gains and all reported per-attempt intervals include zero; most of the solved-within-budget headline is explained by retries (§3.5, pp. 23–24).

- **Domain-specific mechanisms:** Different components matter in Retail and Airline, and Airline’s smaller sample leaves its coupling effects unresolved (Figure 6, p. 15; §3.3.2, pp. 14–15).

- **Resource reporting gaps:** Per-turn rendered-memory tokens and dollar costs are unavailable; token records are not aggregated for SkillFlow or Terminal-Bench (Appendix D, p. 33).

- **Analyst inference:** Because the Meta-Agent is itself an LLM and evolution is performed only with one deployment model per benchmark, robustness to substantially different Meta-Agents, evolution models, verifier errors, or adversarial traces remains only partially tested. The two Meta-Agent implementations reduce—but do not eliminate—this concern (§3.4.3, p. 20).

## Open research questions

1. **Can the validation gate distinguish beneficial patches with fewer tasks?** Its small development split rejects candidates that later show held-out gains. A next experiment could compare sequential or uncertainty-aware admission rules on identical candidate streams and a preregistered test set.

2. **How well can all four memory components be localized?** Checker faults were not meaningfully testable on τ2-Retail. A next experiment could construct domains where each checker decision affects success and inject balanced faults into \(E,W,\rho,C\).

3. **Does evolved memory generalize to unseen SkillFlow tasks or families?** Current selection is in-family and in-sample. A next experiment could evolve on some family members and evaluate frozen templates on held-out members or newly created families sharing the same procedure.

4. **When does within-task adaptation outperform pure retrying?** Aggregate Terminal-Bench differences are unresolved despite several adaptation-only successes. A larger paired study could stratify tasks by failure stability and compare learned patches with frozen-memory retries at equal rollout and token budgets.
