# AgentRoom: Concurrent Multi-Agent Coding in a CRDT-Backed Shared Workspace

> [← Daily summary](../2026-08-26.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2608.23740) · [arXiv](https://arxiv.org/abs/2608.23740)


## One-sentence takeaway
AgentRoom combines a CRDT-shared filesystem with explicit file claims, status, and broadcasts, reducing two-agent coding abandonment and outperforming uncoordinated parallel merging in the authors’ matched-compute TypeScript evaluation.

## Problem and motivation
Existing multi-agent coding systems commonly serialize agents through phase handoffs or merge independent outputs after generation, limiting useful concurrency and leaving agents vulnerable to early “stub-and-exit” abandonment. CRDTs prevent byte-level data loss but do not ensure that concurrent edits are semantically compatible. The authors ask whether explicit coordination over a CRDT workspace can outperform sequential and implicit or uncoordinated alternatives at matched compute (Introduction; §§2.1–2.2).

## Approach and contributions

- **Shared runtime:** Multiple agents concurrently edit one character-level CRDT filesystem, with updates merged within a stated two-second window (§2.1; Figure 2).
- **Structured coordination:** MCP tools provide atomic advisory file claims, release, status inspection, recent-message reading, and an append-only broadcast log (§§2.1–2.3).
- **Matched-compute evaluation:** AgentRoom is compared with solo coding, independent parallel generation plus post-hoc merging, a shared CRDT without coordination, prompt-only collaboration, and a reconstructed ChatDev-style sequential pipeline (§§2.4, 3, 4.2–4.3).
- **Failure-mode analysis:** A deterministic classifier and stratified tests measure one-file abandonment separately from infrastructure failures (§4.1; Appendix B.12).
- **Portability probes:** Small descriptive checks cover Python DevBench projects and a Rust+axum version of the main ledger task (Appendices B.16–B.17).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| AgentRoom strongly reduced one-file abandonment. | Across 12 model×task strata, Solo had 13.7× AgentRoom’s abandonment odds: 95% CI [3.9, 48], \(p<10^{-5}\); totals were 40/131 Solo versus 5/94 AgentRoom. | §4.1; Figure 6 |
| Run-to-run variation contracted with two agents. | On T4, quality-score SD changed from 0.23→0.14 for Sonnet, 0.25→0.17 for Haiku, and 0.27→0.15 for GPT-5.4. | Figure 4; §4.1 |
| Explicitly coordinated concurrency beat independent parallel merging. | T4, Sonnet 4.6, 600-second matched-compute setting: AgentRoom mean 0.669 (\(n=14\)) versus parallel-merge 0.456 (\(n=12\)); difference +0.213, Welch \(t=3.35\), \(p=0.003\). | Table 1; §4.2 |
| AgentRoom exceeded the reconstructed sequential pipeline. | Same model, task, CLI, and stated compute: AgentRoom 0.669 (\(n=14\)) versus ChatDev-style 0.333 (\(n=6\)); Welch \(t=3.78\), \(p=0.006\). | §4.3; Table 1 |
| Quality peaked at two agents in the tested scaling sweep. | T4 Sonnet means for \(N=1,2,3,4\): 0.544, 0.669, 0.553, 0.489; test counts instead peaked at \(N=3\). | §4.5; Figure 5 |
| Execution probing supported the endpoint comparison. | Mean capabilities passed out of 10: AgentRoom 5.06 (\(n=17\)), Solo 3.67 (\(n=33\)), and parallel-merge 1.00 (\(n=15\)); some intermediate ordering differed from the judge. | Appendix B.18 |
| Cross-language checks were directionally weak or descriptive. | Python DevBench: 8/10 AgentRoom versus 7/10 Solo; Rust+axum: 0.740 (\(n=4\)) versus 0.714 (\(n=5\)), \(p=0.68\). | Appendices B.16–B.17 |

The evidence supports a robust reduction in the paper’s specifically defined abandonment outcome and a positive matched-compute contrast against parallel-merge in one principal Sonnet/T4 setting. It does not establish execution-verified correctness broadly, isolate every bundle component causally, or demonstrate gains across languages, larger agent counts, or arbitrary software projects.

## Limitations and validity risks

- **Author-stated:** Headline experiments use one Express.js/TypeScript runtime; Python and Rust studies are underpowered portability checks (§7).
- **Author-stated:** Main tasks lack held-out correctness suites. Agent-authored tests and an LLM-judge composite are not execution oracles, and “quality” excludes security, maintainability, and long-term evolution (§§2.5, 7).
- **Author-stated:** The component probe is too small for a precise decomposition: the interval for the MCP step spans zero, so only the observed ordering is claimed (§5; Appendix B.13).
- **Author-stated:** Hosted proprietary models and default sampling prevent bit-for-bit reproduction; one model was excluded because of concurrent-MCP CLI crashes (§§3, 4.4, 7).
- **Author-stated:** Quality declines beyond two agents in this setup, but the absence of a multi-channel ablation prevents attributing that decline to broadcast congestion (§4.5).
- **Analyst inference:** The ChatDev comparison has limited external validity because it is a reconstructed pattern baseline with only six non-infrastructure-failure runs, rather than the published framework (§4.3).
- **Analyst inference:** The Rust result is sensitive to exclusion of one coordination-artifact run, while the reported retained comparison is statistically inconclusive (Appendix B.17).
- **Analyst inference:** Judge cross-validation reduces but does not eliminate measurement risk: LLM-versus-regex correlation is 0.67, and the execution probe reverses some adjacent-condition rankings (§2.5; Appendix B.18).

## Open research questions

1. **Does AgentRoom improve execution-verified correctness on broader repositories?** The headline tasks lack held-out tests and share one runtime. A next experiment could use multiple languages and independently authored hidden integration suites.

2. **Which coordination primitive produces the gain?** Claims, broadcasts, state visibility, prompts, and CRDT merging are not separately ablated. A powered factorial experiment could toggle each component while holding agents and compute fixed.

3. **Can the protocol scale beyond two agents?** Mean judged quality declines at three and four agents, but the cause is unresolved. A controlled comparison of single-channel, topic-specific, and hierarchical communication could test whether message congestion explains the decline.

4. **How robust is abandonment suppression across model families and task types?** Several per-model cells are small or CLI-unstable, and non-coding generalization is explicitly open. Larger preregistered studies could stratify by model, repository scale, and task category using the same deterministic failure codebook.

## Confidence and missing information
**Confidence: high** for summarizing the supplied paper’s claims and reported results; **medium** for their broader interpretation because the strongest quality comparison is concentrated in one model–task setting.

Material unavailable or unresolved in the supplied text includes the actual release contents and accessibility, full per-run data, confidence intervals for every quality contrast, a fully independent execution oracle for the main suite, powered cross-language replication, and a complete factorial ablation of the coordination components.
