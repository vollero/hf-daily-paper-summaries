# MoTE: Mixture of Task Experts for Multi-Task Video Understanding

> [← Daily summary](../2026-08-26.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2608.24763) · [arXiv](https://arxiv.org/abs/2608.24763)


## One-sentence takeaway

MoTE routes each video–prompt sample through one task-specific decoder FFN expert plus a shared expert, improving five-task COIN accuracy over dense and learned-routing controls while keeping active computation independent of the number of stored task experts.

## Problem and motivation

Procedural video-language models must derive heterogeneous outputs—such as current-step recognition, future-step forecasting, task identification, and procedure prediction—from the same visual evidence. The authors argue that dense decoders force these tasks through shared FFNs, risking task interference, while conventional learned token-level MoE routing does not align naturally with task-level objectives. The identified gap is a decoder that preserves shared visual-language grounding but provides explicit, modular, task-specific computation (Sections 1–2).

## Approach and contributions

- **Task-routed decoder:** MoTE replaces every decoder FFN with an always-active shared expert and multiple task-specific FFN experts. One expert is selected for the entire sample and used at every decoder layer; attention and the multimodal backbone remain shared (Section 3.2; Figure 2).
- **Explicit or prompt-derived routing:** Training uses known task identities. At inference, a frozen text encoder can select the nearest registered expert description by cosine similarity when no task index is supplied (Section 3.2).
- **Modular capability changes:** New experts can be added while freezing existing routes and shared components; experts can also be removed from the decoder and selector registry (Section 3.4).
- **Video and document instantiations:** VideoLLM-MoTE is evaluated on five COIN tasks and Ego4D narration extension; GLM-OCR-MoTE tests transfer to OCR and receipt key-information extraction (Sections 4.1, 4.4–4.5).
- **Controlled routing analysis:** The paper compares explicit task routing with dense all-expert activation and learned token- and sample-level routing under the same expert topology (Section 4.6.1; Table 8).

The evidence supports the authors’ claim that explicit task-aligned routing is beneficial within the tested topology and tasks, and that frozen expert addition preserves unchanged routed behavior. It does not isolate MoTE as the sole cause of gains over all published VideoLLM baselines because model scale, visual encoders, and training recipes differ. Nor does it establish robust prompt routing beyond clearly separated synthetic paraphrases or general expansion to unrelated domains.

## Limitations and validity risks

- **Author-stated:** MoTE assumes meaningful, stable task boundaries; ambiguous, overlapping, and compositional requests may require softer, hierarchical, or composed routing (Appendix A.9).
- **Author-stated:** Freezing existing components during incremental expansion protects old routes but reduces plasticity, reflected by the 61.0% sequential versus 62.9% joint-training average (Section 4.3; Appendix A.9).
- **Author-stated:** The cross-dataset experiment concerns semantically related video-language tasks and is not evidence of unrestricted transfer; Ego4D-only baselines retain better PPL and timing (Section 4.4).
- **Analyst inference:** The 100% selector result has limited ecological validity because all prompts were generated for five predefined, clearly separated intents, with only 50 held-out examples (Appendix A.6).
- **Analyst inference:** Stored parameters grow linearly with the number of task experts even though active parameters remain fixed, creating a deployment memory trade-off (Section 4.7; Appendix A.1).
- **Analyst inference:** The 8B split-expert versus 1B copied-FFN comparison changes both construction and backbone scale, so its **60.3% versus 62.9%** result does not cleanly isolate expert initialization (Section 4.6.2; Table 9).
- Code, checkpoint availability, run-to-run variance, confidence intervals, and statistical significance are not established in the supplied text.

## Open research questions

1. **Can routing handle ambiguous or multi-intent prompts?** The selector only covers synthetic prompts with one of five clear intents. A next experiment could evaluate human-written ambiguous and compositional prompts with top-k, soft, or multi-expert routing.
2. **How far can modular expansion move across unrelated domains?** The main expansion test adds related procedural-video tasks, while document KIE is a separate auxiliary conversion. A next experiment could add a distant task family sequentially to one checkpoint and measure both acquisition and retention.
3. **Can shared components be updated without forgetting?** Fully freezing them preserves prior routes but reduces peak accuracy. A next experiment could compare constrained shared-backbone updates, replay, and regularization against frozen and joint-training endpoints.
4. **How does the architecture scale to many experts?** Active FFN computation stays constant, but storage grows linearly. A next experiment could vary expert count and task granularity while measuring memory, accuracy, routing errors, and serving latency.
