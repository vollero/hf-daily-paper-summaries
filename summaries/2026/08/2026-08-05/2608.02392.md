# GROVE: Growing and Reasoning over Temporally Stratified Memory from Streaming Video Experience

> [← Daily summary](../2026-08-05.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2608.02392) · [arXiv](https://arxiv.org/abs/2608.02392)


## One-sentence takeaway

GROVE is a training-free streaming-video framework that causally builds one temporally stratified memory for both reactive question answering and proactive assistance, outperforming the compared systems across five benchmarks while ablations show that different memory strata matter at different temporal scales.

## Problem and motivation

Wearable assistants must both retrieve past visual evidence when asked and recognize when past experience is relevant without being prompted. The authors argue that existing video-memory systems largely assume query-first retrieval, while proactive systems use separate triggering-oriented memory and control mechanisms. The identified gap is a single, causally updated memory that remains searchable during streaming and supports both query-driven recall and situation-driven intervention (Introduction; Methodology, “Problem setting”).

## Approach and contributions

- **Shared memory substrate:** Reactive QA and proactive assistance use the same observed-prefix memory and access library, differing only in whether retrieval begins from a user query or the current perceptual state (Methodology, Eq. 1–2).

- **Temporally stratified construction:** Each incoming window produces narrative captions and a structured perceptual trace, then is consolidated into timestamped **moments**, activity-level **episodes**, and recurring cross-episode **patterns**. Updates use no future observations (Methodology, “Incremental Memory Construction”; Algorithm 1).

- **Scale-native retrieval:** Perception Lookup handles exact current details; Moment Recall retrieves timestamped facts; Episode Replay reconstructs activities; and Pattern Traversal follows pattern-to-episode-to-moment links for broad or cross-period reasoning (Table 1).

- **Two access policies:** A bounded multi-round agent selects retrieval skills for reactive QA, whereas proactive assistance constructs a fixed evidence schema from the current scene, preceding moments, its episode, and associated patterns (Methodology, “Retrieval over the Memory”).

- **Controlled empirical study:** Five benchmarks test lifelong QA, streaming understanding, forward answering, and query-free services; structural, retrieval, segmentation, width, cost, and skill-selection ablations examine the proposed design (Tables 2–9 and 14–20).

The results establish strong performance against the listed systems and show complementary effects from memory organization, retrieval entry points, and temporal boundaries under fixed-backbone ablations. They do not establish architecture-independent gains: GROVE uses different reasoning backbones across benchmarks, and some comparisons involve systems with different models, inputs, or protocols. The ablation scores also should not be directly equated with the main MM-Lifelong scores because the ablations use GPT-5-mini rather than GPT-5.2.

## Limitations and validity risks

- **Author-stated:** Errors missed by the frozen perception model during ingestion cannot be recovered later; higher strata update only after an episode closes; construction and multi-round retrieval grow costlier with history; and cross-benchmark component conclusions are weakened by differing reasoning backbones (Limitations).

- **Author-stated scope conditions:** Frame sampling is sparse—every five seconds on MM-Lifelong and EgoServe and every two seconds elsewhere—creating a temporal-resolution/throughput trade-off (Experimental Setup; Fig. 3).

- **Analyst inference:** Some evaluations provide unusually strong task information. HoloAssist and CaptainCook4D receive canonical procedures and known task information, while forward OVO-Bench and ESTP-Bench expose candidate questions during memory construction. The authors say these follow benchmark protocols, but performance may not transfer to settings where tasks or questions are unknown in advance (Appendix A.1).

- **Analyst inference:** Prompts are scenario-specific rather than uniform, so results measure the complete configured system rather than a domain-agnostic memory mechanism alone (Appendix A.1; Table 21).

- **Analyst inference:** Pattern formation relies on LLM matching and summarization, but the supplied experiments do not report direct accuracy, calibration, or error analysis for pattern assignments. Downstream ablations demonstrate utility, not correctness of individual links.

- **Analyst inference:** The paper announces future code availability; the supplied text does not establish that code, generated memories, or inference traces are currently accessible.

## Open research questions

1. **How robust is GROVE when questions and task schemas are unavailable during construction?** This remains open because some forward and instructional settings expose benchmark-defined questions or procedures. A next experiment could rebuild those memories without this information and measure the same track-level metrics.

2. **How do ingestion errors propagate through moments, episodes, and patterns?** The authors acknowledge irrecoverable perception misses but do not quantify propagation. Manually annotating a sample of each stratum and tracing errors upward would separate perception, segmentation, consolidation, and retrieval failures.

3. **Can memory growth remain affordable over months or years?** The paper reports sublinear pattern consolidation and short-horizon throughput, but also acknowledges increasing cost with history. A continuous multi-month stress test could measure storage, construction throughput, retrieval latency, and recall as memory size grows.

4. **Would learned or adaptive routing outperform the fixed scale cues and schemas?** Skill-selection ablations show that routing matters, but no trained router is evaluated. A controlled comparison among the current LLM router, a lightweight learned router, and an oracle skill selector could quantify remaining routing headroom.

## Confidence and missing information

**Confidence: high.** The supplied text includes the full method, principal tables, appendices, prompts, and limitations. Material missing or unresolved information includes actual code availability, statistical uncertainty or repeated-run variance, direct accuracy of episode and pattern construction, complete hardware/time cost totals for all benchmarks, and an evaluation that removes benchmark-specific question visibility and task priors.
