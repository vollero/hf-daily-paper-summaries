# PartAgent: Agentic 3D Part Segmentation via Expert Integration and Closed-Loop Refinement

> [← Daily summary](../2026-11-25.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.32554) · [arXiv](https://arxiv.org/abs/2611.32554)


## One-sentence takeaway

PartAgent combines frozen 3D region proposals with multiview 2D masks and VLM-guided refinement, achieving 68.41 Mask Match mIoU on PartObjaverse-Tiny-WT, 8.53 points above the strongest reported competitor (§4.2, Table 1).

## Problem and motivation

3D part segmentation divides an object into coherent components for part-level 3D understanding. The authors identify two problems: 3D proposals can fragment a component or merge distinct components, and 2D predictions can disagree across views about boundaries and part identities. Even after combining these cues, the initial partition can still need targeted corrections (§1).

## Approach and contributions

1. **Training-free expert integration.** PartAgent combines a frozen 3D segmenter, a frozen 2D mask generator, and a vision–language model (VLM) to produce a complete, non-overlapping part partition (§3.1, §4.1).
2. **Multigranularity candidate construction.** The method maps 2D masks onto the surface, weights evidence by projected area and viewing angle, and uses it to subdivide 3D proposals. A tree and directed acyclic graph represent alternative groupings. The VLM selects an initial partition and retains alternatives (§3.2, Fig. 3).
3. **Observation-driven refinement.** The VLM can inspect a region, regroup existing regions, request a local 2D mask repair, select another partition, or stop. A separate VLM call verifies proposed changes, and the outcome informs later decisions (§3.3, Figs. 3–4).

The results support improved part-mask matching on the evaluated objects, with a smaller incremental gain from refinement after expert integration. Mask Match can select the best mask for each ground-truth part across candidates, and Partition Match selects the best complete candidate. The accuracy of the single partition the agent returns remains unquantified by these metrics (§§3.3, 4.1).

## Limitations and validity risks

- **Author-reported constraints.** API cost motivated subsampling the larger benchmarks and running most ablations on one watertight-mesh subset. The core-module ablation was repeated on the remaining meshes from that same benchmark. The authors also show cases where hallucinated 2D parts can become false 3D parts (§4.1, Appendices A and C.2).
- **Analyst inference.** The candidate-based metrics give credit for having a good alternative available, so part of the measured gain could come from expanding the candidate bank. The reported action ablations leave the separate effects of verification and adaptive action selection unresolved (§§3.3, 4.1, Appendix C.2).
- **Reporting ambiguity.** Some prose cross-references conflict with the supplied table captions. For example, §4.2 points to Table 3 for the four-benchmark comparison, while the matching caption is labeled Table 2. The numerical summary above follows the prose and uses the caption to identify the comparison.

## Open research questions

1. **How much does refinement improve the partition the agent actually returns?** The reported metrics select among candidates using ground truth. Score the returned partition directly before and after refinement, then compare it with the best candidate.
2. **How much do adaptive action selection and verification each contribute?** The action ablations remove individual tools while keeping the broader loop. Compare adaptive and fixed action schedules under matched inference budgets, with and without verification.
3. **Does viewpoint selection help with poorly visible parts?** The evaluation uses four fixed views and reports no visibility-stratified comparison. Compare fixed and adaptive views under the same rendering and API budgets, grouping results by part visibility.

## Confidence and missing information

**Medium.** The supplied prose describes the method and headline comparisons clearly. Material gaps include full baseline rows and the identity of the strongest comparator for each headline result, uncertainty across repeated runs, direct scores for the returned partition, per-object API cost and latency, and implementation details such as exact prompts, fusion thresholds, and candidate enumeration. The supplied text establishes a planned release of evaluation data and splits.
