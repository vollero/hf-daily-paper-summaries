# Nemotron-Labs-VisualCreation: Pixel as Code for Agentic Visual Creation

> [← Daily summary](../2026-11-25.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.31358) · [arXiv](https://arxiv.org/abs/2611.31358)


## One-sentence takeaway

Nemotron-Labs-VisualCreation uses a shared generate–render–inspect interface for raster images and editable visual artifacts, and its Nemotron-native workflow improves compositional adherence and world-knowledge scores over the same standalone raster generator (Tables 6 and 9).

## Problem and motivation

A visual brief can require expressive imagery, exact wording, factual grounding, precise layout, and editable source in the same deliverable. The authors identify a coordination gap between raster generators, which synthesize appearance, and explicit programs, which expose text, geometry, and layout for revision. They propose using rendered previews as common evidence for selecting and improving outputs across these formats (§§1–2).

## Approach and contributions

- **Pixel as Code and the creation harness.** A shared interface renders learned visual tokens into pixels or executes explicit programs such as SVG, HTML/CSS, and plotting code. Direct raster requests use planning and visual candidate selection. Browser-based structured and hybrid requests use a fixed layout contract, renderer checks, and multimodal review to assign defects to the responsible component, make targeted repairs, and retain the best checkpoint (§2, Figs. 5–7).
- **Raster tokenizer and generator.** Nemotron-Labs-Image-Tokenizer uses a fixed Leech-lattice codebook. Nemotron-Labs-Image-30B-A3B adapts a language-pretrained backbone to predict visual tokens through progressive-resolution mid-training and group-relative reinforcement learning. The RL procedure refreshes the prompt mix when too few candidates for a prompt differ enough in reward to guide learning (§§3.3.1, 5.1–5.2).
- **Specialized visual coding models.** Two VisionCode variants learn to generate editable programs and markup through supervised fine-tuning and task-specific rewards based on execution and rendered quality. The browser harness uses a separate Dual Coder composed of Nemotron 3 Ultra and Nemotron-3.5-Super-VL, while the VisionCode variants are evaluated standalone (§§3.2.2, 5.3, 6.3).

The reported results support better reference-based reconstruction and gains from adding the complete agent workflow to a fixed raster generator. The authors describe their best configuration as competitive with GPT Image 2 and Nano Banana Pro across most benchmarks with available comparisons. That claim depends on the benchmark and configuration, with smaller gains on broad visual-generation tests and some baselines still ahead (§6.2, Tables 6–10). The browser examples illustrate feasible repairs. Their frequency and effect on end-to-end artifact quality remain unquantified, and the standalone VisionCode scores measure a different configuration.

## Limitations and validity risks

- **Author-stated.** Text-and-image-conditioned editing and multi-reference generation were included in training but left unevaluated. System comparisons measure the bundled workflow, leaving the effects of planning, retrieval, and visual selection unresolved under matched inference budgets (§§6.2, 8).
- **Author-stated.** Tokenizers still alter small characters and fine structures, and distribution and no-reference metrics vary across domains. The coding aggregate depends on the included models and metrics, excludes incomplete results, and is descriptive (§§6.1, 6.3, Appendix C).
- **Analyst inference.** Raster comparisons against external models use reported leaderboard and report values with uneven coverage. Cross-model rankings therefore warrant more caution than the same-generator comparisons (§6.2).
- **Analyst inference.** Selected browser repairs and standalone coding scores leave open how often the full harness improves editable artifacts, preserves unaffected content, or introduces regressions across browser and native formats (§2.2, Fig. 7, §6.3).

## Open research questions

1. **Which agent operations account for the GenEval2 and WISE gains?** The configurations bundle planning, conditional retrieval, and candidate selection. Compare component ablations with the same generator, candidate count, and inference budget on both benchmarks (§6.2, §8).
2. **How reliably does targeted browser repair improve an artifact without disturbing correct regions?** Figure 7 gives selected examples. Compare repair enabled and disabled on the same initial checkpoints, measuring requirement satisfaction, regressions, and runtime (§2.2, Fig. 7).
3. **How well does the raster model follow edits and combine multiple references?** These capabilities appear in training, while the reported raster suite tests text-to-image generation. Evaluate held-out edit and multi-reference requests for instruction fidelity and preservation of source details (§§4.2, 6.2).

## Confidence and missing information

**High** confidence in the method summary and the benchmark values as reported. Material missing information includes component-level effects at matched inference budgets, end-to-end latency and cost, representative browser repair success and regression rates, text-and-image-conditioned evaluation, and the standalone BizGenEval score. Appendix A.1 contains a heading for the reward judge’s system instruction, but the instruction text is absent from the supplied retrieval. The abstract links a raster model entry, while release availability for the tokenizer, VisionCode weights, and full harness is unconfirmed in the supplied text.
