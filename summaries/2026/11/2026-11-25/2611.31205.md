# ACAP: Asynchronous Coding Agents for Efficient Robot Control

> [← Daily summary](../2026-11-25.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.31205) · [arXiv](https://arxiv.org/abs/2611.31205)


## One-sentence takeaway

ACAP uses persistent coding agents and an adaptive coordinator within a single robot, reducing task-balanced time cost by 28.2% versus a single-agent Direct Policy in a real-world study spanning 25 task/platform settings (Abstract, §§4.3–4.5, §5.1).

## Problem and motivation

A single coding agent can issue concurrent robot commands, but decisions about every component still pass through one reasoning process. A failed grasp can therefore delay unrelated work by the other arm. Assigning each arm its own agent removes that bottleneck, but permanent delegation can add communication and replanning when the arms share an object or workspace. The authors identify a need for robot policies that overlap independent work and adapt control as physical dependencies change (§1).

## Approach and contributions

1. **Persistent agents within one robot.** Each member runs its own observe–reason–code–execute loop for a configurable control group and retains observations, history, and programs across assignments and control transfers within an episode (§§3.1, 3.3).
2. **Adaptive coordination and control transfer.** A hyper-agent uses observations and member reports to assign work, set dependencies, grant shared-workspace access, and return coupled groups to direct lead control. Buffered messages, event-based waits, and exclusive command ownership support these handoffs (§§3.2–3.3, Fig. 2).
3. **Real-world evaluation and rollout dataset.** Two bimanual studies compare policy variants, and a mobile demonstration extends the member interface to chassis and torso control. The dataset links observations and generated code to agent interactions, robot actions, and physical feedback (§§4.3, 5.5, 6, App. E).

The evidence supports lower end-to-end time cost for the tested ACAP configuration. The Fixed comparison holds model and reasoning settings constant and supports the value of adaptive control on Collaborative tasks. The Direct comparison combines asynchrony with lighter member reasoning, leaving their individual effects unresolved. The time-cost metrics combine elapsed time and noncompletion, and the mobile demonstration establishes feasibility for the illustrated task only.

## Limitations and validity risks

- **Author-stated.** ACAP has no dedicated motion-level collision-checking layer. The authors leave geometry-based motion checks and execution monitoring to future work (App. F).
- **Analyst inference.** The Fixed comparison changes both control permissions and role instructions, so it cannot isolate takeover permission alone. The Direct comparison also changes agent organization and reasoning settings (§4.4).
- **Analyst inference.** Generalization across model families and mobile tasks remains uncertain. The studies use Astra throughout, and the mobile evidence is a single described demonstration (§§4.4, 5.5).
- **Analyst inference.** Progress annotation hides policy labels and uses task-specific milestones, but permits intermediate judgments. The supplied text gives no inter-annotator agreement, leaving scoring consistency unclear (§4.5, App. B.3).

## Open research questions

1. **How much latency reduction comes from asynchronous scheduling itself?** Direct also differs in reasoning configuration. Compare asynchronous and serialized member loops with identical model settings, tools, and control permissions (§§4.4, 5.4).
2. **When should the lead take over coupled groups?** The examples show successful takeover and successful continued delegation, while the aggregate comparison leaves the best choice for individual task phases open. Compare takeover and continued delegation from matched physical states, measuring completion, waiting, and recovery (§5.2, Fig. 4).
3. **What does motion-level collision checking cost in practice?** ACAP lacks this layer. Compare instrumented controllers with and without geometry-based checks in matched, monitored trials, measuring interventions, hardware faults, completion, and elapsed time (App. F).
