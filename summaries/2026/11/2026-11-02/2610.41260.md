# SketchDirector: Complex Scene Sketching via Agentic Layout Reasoning and Detail Refinement

> [← Daily summary](../2026-11-02.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.41260) · [arXiv](https://arxiv.org/abs/2610.41260)


## One-sentence takeaway
SketchDirector combines executable object-level layout reasoning with diffusion-guided vector refinement, reporting better multi-object sketch quality than five baselines, although the supplied text omits numerical comparison results (§§3–4).

## Problem and motivation
Text-guided scene sketching must depict individual objects while coordinating their placement, scale, occlusion, and details. The authors argue that holistic sketch generation limits object reuse and editing, while existing object-aware approaches provide insufficient iterative layout control (§§1–2). Editable scene sketches could support animation, concept art, and interactive design; these applications motivate the work but are not evaluated (§1, Fig. 2).

## Approach and contributions
- **Executable scene composition:** An LLM decomposes the prompt into drawable objects, and the existing SketchAgent generates separate Bézier draft assets. SketchDirector composes these through move, scale, rotate, layer, delete, and regenerate operations (§§3.1–3.2).
- **Closed-loop layout reasoning:** Plan–Execute–Verify–Correct combines boundary and scale checks with VLM assessment. Scene-specific failure memory and successful cross-scene experience guide corrections; experience retrieval uses object-set Jaccard similarity (§3.3).
- **Structure-preserving refinement:** Contour subdivision preserves the initial curve geometry, followed by progressive object-level and accumulated-scene RFDS optimization. This refinement procedure, rather than SketchAgent or RFDS themselves, is a claimed contribution (§3.4).
- **MCSketch8K:** The authors introduce editable vector assets, composition layouts, and manipulation annotations, describing 1,000 scenes with over 4,000 object assets across 800 categories. Release availability and construction details are not established in the supplied text (§1).

## Limitations and validity risks
- **Author-stated:** Complex physical and semantic interactions remain difficult; refinement can duplicate objects; verification and optimization incur substantial computational cost (§4.4, Fig. 13).
- **Analyst inference—limited generalization evidence:** Evaluation uses small prompt samples from the authors’ own dataset and a university-community participant pool. Performance on independently sourced prompts or professional workflows remains unestablished (§4.2).
- **Analyst inference—judge dependence:** GPT-5.5 is both the default agent and one of the evaluation judges. Multiple judges and human preferences provide complementary evidence, but per-judge results are unavailable (§§4.1–4.2).
- **Reproducibility gaps:** Dataset construction and splits, memory initialization and evaluation ordering, verification weights/thresholds, and refinement hyperparameters are insufficiently specified. The stated grid dimensions and cell size also do not reconcile with the reported canvas resolution (§§1, 3–4).

## Open research questions
- **Can interaction modeling improve relational accuracy?** Interaction failures remain explicit limitations. Compare the current planner with relation-aware constraints on a held-out interaction-focused prompt set, using human judgments and relation correctness (§4.4).
- **Can refinement preserve instance counts reliably?** Duplicate-instance hallucinations remain unresolved. Add instance-aware constraints and measure count errors alongside detail quality and structural drift (§4.4).
- **How well does experience memory transfer beyond familiar objects?** Retrieval uses object-set overlap, while evaluation ordering and memory contents are unspecified. Compare frozen, empty, and incrementally updated memory on disjoint object combinations (§3.3).
- **What quality–cost trade-off is achievable?** Iterative verification and per-object refinement are expensive. Sweep verification frequency and refinement iterations, measuring latency, failure rates, and human preference (§§4.1, 4.4).

## Confidence and missing information
**Confidence: medium.** The method is described clearly, but comparative strength cannot be quantified from the supplied text.

Material missing information includes numerical contents of Tables 1–3, preference rates from Fig. 8, uncertainty estimates, exact evaluation prompts, dataset provenance and splits, release status, memory evaluation controls, diffusion backbone identity, and complete optimization and verification settings.
