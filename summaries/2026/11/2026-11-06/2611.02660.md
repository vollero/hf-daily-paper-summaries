# HeLM: Hierarchical Explicit Language Memory for Non-Markovian Manipulation

> [← Daily summary](../2026-11-06.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.02660) · [arXiv](https://arxiv.org/abs/2611.02660)


## One-sentence takeaway
HeLM’s event-triggered language memory improves history-dependent robot manipulation over the evaluated baselines, achieving 81.3% strict intra-episode task success versus 29.3% for visual keyframe memory, while relying on predefined events and task-specific training (Table 8; §6).

## Problem and motivation
Some manipulation tasks require history that current images cannot reveal: completed button presses, previously wiped regions, or an object’s original location. The authors identify two shortcomings of existing memory approaches: latent memory is difficult to inspect, while accumulating visual history increases computation (§1).

They also target **inter-episode persistence**: retaining information from one instruction to complete a later instruction when the current observation cannot recover that information (§4.1).

## Approach and contributions
- **Explicit hierarchical memory:** A fine-tuned vision-language high-level policy maintains textual task state and issues commands to a low-level VLA controller. Working memory tracks current progress; episodic context retains summaries across instructions (§§3.2–3.3).
- **Factorized, event-triggered inference:** The same VLM uses separate detection and update prompts. Detection runs at action-chunk boundaries; memory and commands update only after a detected event or instruction change (§3.4).
- **TaskSpec-based supervision:** Annotated short subtask trajectories are paired with synthetic memory states to train detection and updates. Inference receives task-specific event/action vocabularies, but not ground-truth memory transitions (§3.5; Appendix A).
- **Evaluation suite:** The authors introduce ten real-world tasks with 56 variants, including five inter-episode tasks, and evaluate memory modality, inference design, compositional generalization, and resource scaling (§4; §5).

The contribution is this combination and evaluation; the paper itself acknowledges earlier language-memory and hierarchical robot systems (§2).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Higher intra-episode partial success | Across five real-world tasks, mean subtask success: HeLM **85.7%**, Keyframe-HLP **72.9%**, PCMB-π0 **39.5%**, memoryless π0 **16.7%**; 15–30 trials per task. | Figure 5; §5.2 |
| Advantage survives strict scoring | Mean success requiring every subtask, correct order, and termination: **81.3%** versus **29.3%** for Keyframe-HLP and **0%** for both π0 baselines. | Table 8 |
| Stronger cross-episode performance | Five real-world inter-episode tasks: **89.2%** mean subtask success versus **16.6%** for Keyframe-HLP. Other baselines were excluded. | Table 1; §5.2 |
| Memory and fine-tuning matter in simulation | LIBERO-Mem, ten tasks, 20 held-out rollouts per task: HeLM **58.5%** task success; π0.5 **36.5%**; memoryless hierarchy **12.0%**; memory-equipped HLP without task-specific fine-tuning **8.5%**. | Table 2; §5.4 |
| Two-stage inference improves average performance | Real-world intra-episode mean subtask success: **85.7%** versus **67.7%** for joint event/memory/command prediction; the two-stage version performs worse on A4. | Table 3 |
| Generalization to held-out configurations | Without additional HLP fine-tuning, mean subtask success across five task families: **78.0%** versus **65.7%** for Keyframe-HLP, which also exhibits termination failures. | Table 4; §5.5 |
| Limited-horizon robustness | Extended A1 reports **100%** success through seven subtasks; A2 reports **77–100%**, including **88%** at seven. Appendix labels this “success rate” without restating its exact scoring definition. | Table 9 |
| Lower memory growth than keyframes | With the same HLP backbone, authors report **2.5×** faster long-horizon inference; at eight stored events, Keyframe-HLP reaches **28 GB** peak VRAM while HeLM remains below **6 GB**. | Figure 6; §5.6 |

The controlled keyframe comparison and ablations support the usefulness of textual memory and separated inference in these settings. They do not establish open-ended memory discovery or broad superiority over all memory architectures. Subtask success explicitly excludes order and termination penalties; inter-episode scores also aggregate subtasks from both instructions, rather than isolating later-instruction recall (Appendix E).

## Limitations and validity risks
- **Author-stated scope:** Events require task-specific definitions; continuous state histories are untested; chunk-level detection may miss transient events; and the working/episodic split lacks a comparison against one persistent memory (§6).
- **Error propagation:** False-positive detections can corrupt memory and subsequent commands without self-correction (§5.3).
- **Baseline coverage:** Inter-episode evaluation has only Keyframe-HLP as a comparator. PCMB is adapted to π0 rather than evaluated in its original architecture; the authors acknowledge possible scale effects (Appendix D).
- **Simulation validity:** Wrist-camera visibility undermines intended occlusion tasks, and some initial states contain spawn errors (Appendix F.3).
- **Analyst inference—limited generality:** One real-world arm platform, discrete task families, and short tested histories leave broader embodiment and persistent-memory validity unresolved (§5.1; Table 9).
- **Reporting ambiguities:** A3’s generalization description assumes canonical-order training, while the base suite lists order permutations; the precise training overlap is unclear (Appendices B.1–B.2). Appendix F.2 reports 13.18 GB base-system VRAM, whereas §5.6 reports under 6 GB in its scaling comparison; measurement scopes are not reconciled.

## Open research questions
- **Does separating working and episodic memory help?** This ablation is explicitly missing (§6). Compare both fields against a single persistent text memory under matched training and context budgets.
- **Can corrupted memory recover?** False-positive events currently cause unrecoverable updates (§5.3). Inject detection errors and test visual rechecking or memory rollback.
- **Can events be learned beyond predefined vocabularies?** TaskSpec supplies event definitions (§6). Evaluate unfamiliar tasks with learned event discovery against manually specified events.
- **How far does persistence scale?** Real-world inter-episode tasks contain two instructions, and extended sequences remain short (Table 6; Table 9). Test longer instruction chains with distractors and delayed recall, scoring later instructions separately.
