# SWE-Trail: History-Guided Trajectory Collection for Coding Agent Training

> [← Daily summary](../2026-11-03.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.02074) · [arXiv](https://arxiv.org/abs/2611.02074)


## One-sentence takeaway
SWE-Trail keeps prior repair attempts private to a trajectory collector, improving student resolution over independent sampling on two coding benchmarks, although uncertainty intervals for its history-specific gains include zero (§4.2).

## Problem and motivation
Independent sampling increasingly revisits previously explored repair targets, reducing the marginal value of additional coding trajectories (§2.1). Prior attempts could guide further exploration, but showing their lessons directly to the coding agent may produce training examples that depend on advice unavailable at evaluation. The authors therefore ask how history can guide collection without entering the agent’s context (§1).

## Approach and contributions
- **History-guided allocation:** An offline compiler combines prior attempts with bounded read-only repository checks to create state detectors, local comparison objectives, and sampling-temperature schedules. These remain private and fixed during collection (§3.1).
- **Bounded execution comparisons:** At a detected state, the agent proposes actions from its ordinary context. The collector executes the default and one alternative from the same checkpoint, then selects using shuffled, source-identity-blind execution evidence. Each trajectory permits at most one comparison (§§3.2–3.3).
- **Continuous training records and controlled evaluation:** Only the selected route is exported, preserving original reasoning and actions while removing collector information. Experiments compare downstream supervised fine-tuning utility against independent sampling, history-free collection, randomized controls, and post-hoc selection (§§3.3–4.3).

## Evidence and main results

Reported downstream changes below are percentage points in mean test-based resolution across three independent training runs. Multilingual contains 300 tasks; SWE-Pro contains 731 (§4.1).

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Main student improves over independent sampling | For the 124B Ling student, H5 exceeds SeedBank by **2.33 points on Multilingual / 1.60 on SWE-Pro**. Every H5 run exceeds every SeedBank run; exact one-sided run-level permutation **p=0.05** on each benchmark. | §4.2; Appendix E.1 |
| History-specific improvement remains uncertain | H5 exceeds H0 by **2.22 / 0.87 points**, with task-paired 95% bootstrap intervals **[-0.2, 4.6] / [-0.8, 2.5]**. These intervals condition on the trained models. | §4.2; Appendices D.2, E.2 |
| Gains appear with another student | Qwen3-14B-Base trained on the same trajectory sets gains **3.11 / 2.42 points** over SeedBank and **1.67 / 1.60** over H0. | §4.2; Appendix E.4 |
| Both allocation and retention choices contribute | Relative to H5 for the 124B student, random detection lowers resolution by **1.44 / 1.28 points**; random retention lowers it by **0.89 / 1.19**. Run ranges overlap H5. | §4.2 |
| Collection yield alone does not track training utility | Across **1,500 trajectories per condition**, H0 adds **37 resolved trajectories** over SeedBank but only **0.11 Multilingual points**; H5 adds **16 resolved trajectories** over H0 alongside **2.22 additional Multilingual points**. | §4.4; Table 21 |
| Additional history has diminishing returns | For the 124B student, H10 adds **0.22 / 0.14 points** over H5 while recorded total collection tokens rise **12.9%**. Costs exclude obtaining prior attempts. | §4.3; Appendix G.2 |
| Selection can complement collection | Top-5-of-10 remains **1.56 / 0.96 points** below H5. Top-5-hybrid reaches **66.22% / 43.14%**, exceeding H5 by **0.56 / 0.32 points**. Each retains **1,500 training trajectories**; collection costs are not exactly matched. | §4.3; Appendix G.3 |

The evidence supports improved training utility under the tested setup and replication across two students. It does not firmly establish the history-specific effect across evaluation tasks, identify which trajectory changes cause the gains, or demonstrate superiority under equal total collection compute.

## Limitations and validity risks
- **Authors’ stated scope:** Collection uses one model and one scaffold. History stays fixed within a round, and every issue receives the same collection budget (§6).
- **Statistical uncertainty:** H5–H0 task-bootstrap intervals include zero. The run-level test uses only three models per condition; its reported p-value is the smallest attainable with that design (Appendices E.1–E.2).
- **Comparison limits:** SWE-Gym, SWE-Lego, and SWE-TRACE are controlled adaptations rather than full reproductions. Top-5-of-10 is not exactly compute-matched to H5 (Appendices C.3, G.3).
- **Cost accounting:** Prior-attempt collection is excluded; H0 offline compiler tokens and SeedBank provider usage are unavailable. Full end-to-end efficiency is therefore not established (Appendix B.2).
- **Mechanism evidence:** Behavior changes are descriptive. A small selector replay identifies candidate coverage as a frequent limitation, but its findings cannot represent all comparisons (Appendices F.2, G.1).
- **Analyst inference:** Advice-induced train–test mismatch remains a plausible explanation rather than an isolated causal finding: retaining versus removing advice produces mixed benchmark effects (Appendix H.2).

## Open research questions
- **Does the benefit transfer across collectors and scaffolds?** Only one collection model/scaffold pair is tested (§6). Repeat H5–H0 comparisons with alternative pairs under matched budgets.
- **Can adaptive history and issue budgets improve efficiency?** Both remain fixed here (§6). Compare multi-round history updates and issue-adaptive allocation against fixed collection using equal total compute.
- **Is candidate generation the main bottleneck?** The limited replay flags missing useful proposals more often than selector failures (Appendix G.1). Vary proposal diversity and count while holding comparison locations and compute fixed.
- **Which trajectory properties improve learning?** Yield and process statistics do not identify causal contributors (§4.4; Appendix F.2). Train matched corpora that separately control resolution mix, repeated reads, and validation behavior.

## Confidence and missing information
**Confidence: medium.** The supplied narrative supports the central results and their uncertainty, but many referenced tables contain captions without numerical bodies, and several promised prompts or schemas are absent. Exact training hyperparameters, full evaluation budgets, compiler/selector model assignments, complete per-run results, and public code/data/model release status are unavailable or insufficiently specified.
