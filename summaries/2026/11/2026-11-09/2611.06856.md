# LongBanana: An Expert-Verified Benchmark for Long-Context Multi-Reference Image Synthesis

> [← Daily summary](../2026-11-09.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.06856) · [arXiv](https://arxiv.org/abs/2611.06856)


## One-sentence takeaway
LongBanana evaluates whether image generators faithfully combine many visual references, finding that agent workflows improve constraint satisfaction but remain harness-dependent, while its automated evaluator still makes substantial item-level errors.

## Problem and motivation
A convincing image can still copy the wrong reference, attach an attribute to the wrong entity, include a distractor, or violate layout and count requirements. The authors argue that existing evaluations insufficiently measure these provenance and binding errors when evidence is distributed across many images (§1).

The target is therefore reference-grounded correctness across selection, rejection, binding, and composition, assessed through individual obligations rather than a holistic image-quality score (§§1–2).

## Approach and contributions
- **Benchmark:** LongBanana-Bench contains 90 expert-designed cases across nine subclasses covering scene composition, visual appearance, and reference reasoning. A typical case has approximately 32 references and more than 20 cross-reference constraints; the benchmark contains 4,670 atomic checklist items (§§2.1–2.3).
- **Graph-grounded evaluation:** Experts design scenarios, an LLM structures their constraints into entity–relation graphs, and curators review the resulting instructions, references, and checklists. Node, edge, and whole-graph obligations map to Content Fidelity, Relational Binding, and Global Constraint Satisfaction (§§2.3–3).
- **Audited evaluator:** LongBananaEval routes individual items to rubric critics, optionally uses OCR, counting, layout, and identity tools, and records evidence traces. Its judgments are validated against reviewed human labels (§§3–4.2).
- **Generation framework and study:** LongBanana-Gen compares direct generation, minimal agent harnesses, and ReAct–Plan–Exec–Reflect (RPR) workflows. A graph-informed, optimally scheduled direct baseline tests how much explicit structure alone contributes (§4.1; Appendix D.1).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Human labeling shows substantial consistency | Across 900 outputs and 46,700 reviewed labels, an independently double-labeled subset of 7,005 labels achieved 89.4% exact agreement and quadratic weighted κ = 0.83. | §4.1 |
| Agentic judging improves item agreement but remains imperfect | On the full audit pool, with Gemini 3 Flash shared by both judges, exact ternary agreement increased from 50.99% to 66.81%; opposite-end errors decreased from 44.09% to 24.81%. | Appendix C.2; Table 10 discussion |
| Explicit graph staging strengthens direct generation | With Nano Banana 2 fixed, PD-Direct scored 74.6 versus FP-Direct’s 68.4 on unweighted checklist average; difficulty-weighted P@70% was 35.6% versus 24.4%. Both direct baselines used an eight-reference backend budget. | §4.1; Table 2 |
| Best overall harness configuration exceeds the structured direct baseline | OpenClaw + RPR achieved 78.4 checklist average and 47.8% P@70%, versus PD-Direct’s 74.6 and 35.6%, on the same 90 cases with Nano Banana 2. | Table 2 |
| RPR gains depend on harness and metric | OpenCode’s average increased from 77.3 to 77.8 while P@70% fell from 47.8% to 43.3%; Hermes-Agent’s average increased from 73.9 to 75.6 while P@70% fell from 43.3% to 35.6%. | Table 2 |
| Backend choice remains consequential | Authors report that Nano Banana 2 leads all nine subclasses under fixed OpenClaw + RPR; numerical Table 3 entries are absent from the supplied text. | §4.3, “Image-backend comparison” |

These results support better checklist fulfillment from selected agent workflows in this benchmark, rather than uniform improvement from adding RPR. Checklist average measures individual requirement fulfillment; P@70% measures how often a case crosses a difficulty-weighted threshold, so their rankings can differ.

The evaluator evidence establishes improvement over the matched single-pass judge, not equivalence to expert annotation. Output-level correlations are described as higher, but their numerical values are unavailable in the supplied Table 1.

## Limitations and validity risks
- **Author-stated scope:** The taxonomy excludes video generation, 3D scene composition, and unrestricted multimodal planning. Dense annotation is expensive, and evaluator results depend on multimodal backbones and verification tools (Appendix E.1).
- **Analyst inference—measurement risk:** The remaining 24.81% opposite-end item error rate warrants caution when interpreting automated diagnostic labels and small score differences (Appendix C.2).
- **Analyst inference—comparison attribution:** PD-Direct receives privileged graph information, whereas agents receive neither that graph nor the checklist. Runtime, API cost, and per-run compute are unreported, so the results do not establish efficiency or gains under matched computational budgets (§4.1; NeurIPS checklist, item 8).
- **Scoring comparability:** The component ablation uses difficulty-weighted averages calibrated within its own configurations; the main tables use unweighted averages and frozen weights only for P@70%. These scores should not be directly conflated (Appendix D.2).
- **Evidence and reproducibility gaps:** Several tables appear only as captions, including uncertainty diagnostics. The abstract claims code and data availability, while the checklist says public access with executable reproduction instructions is not provided. Actual release completeness is unresolved from the supplied text.

## Open research questions
1. **Can revision preserve already satisfied constraints?** RPR sometimes reduces pass rate and temporal/state performance, with authors suggesting over-revision drift. Compare ordinary reflection against revision that explicitly tracks and protects satisfied constraints (§4.3; Appendix D.2).
2. **How much of the agent advantage survives matched budgets?** Resource use is unreported. Compare PD-Direct and agent workflows under equal generation calls, reference exposure, and cost, reporting both accuracy and latency.
3. **Does evaluator validity transfer to new systems and task distributions?** Validation covers the reported audit pool, with substantial residual item errors. Test frozen judging configurations on independently labeled outputs from unseen backends and newly authored cases (§4.2; Appendix C.2).
4. **How does performance scale with reference density and distractors?** The benchmark emphasizes dense references but supplies no controlled scaling results. Vary reference count, constraint density, and hard-negative count while preserving the underlying target scene (§§2.1–2.3).

## Confidence and missing information
**Confidence: medium.** Benchmark design and Table 2 comparisons are explicit, but important supporting results are unavailable.

Missing information includes numerical output-level judge correlations, backend and component-ablation table entries, confidence intervals and paired-test results, exact verification-tool implementations, per-run resource use, and executable reproduction instructions. Public asset availability is internally inconsistent in the supplied text.
