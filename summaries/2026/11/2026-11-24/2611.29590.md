# KernelShift: Benchmarking Kernel Optimization Across Evolving Hardware

> [← Daily summary](../2026-11-24.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.29590) · [arXiv](https://arxiv.org/abs/2611.29590)


## One-sentence takeaway

On KernelShift, coding agents beat compiler auto-vectorization across all four Arm SVE kernel families, but their adaptation to SME2 matrix tiles was uneven and they generally lagged expert SME2 kernels (§§4.1–4.2).

## Problem and motivation

New CPU instructions can change how a fast kernel needs to be structured, even when the computation stays the same. For example, Arm SME2 exposes matrix tiles that support a different implementation strategy from earlier vector extensions. The authors identify a gap in benchmarks that evaluate fixed targets or collections of devices. KernelShift asks whether agents can adapt to successive programming interfaces while optimizing matched computations where reference coverage permits (§§1–2, 5).

## Approach and contributions

- **Task construction pipeline.** Coding agents use deterministic scripts to turn repository kernels into portable C++ starting points, task specifications, hidden workloads, and optimized references. Humans select kernels, approve workloads where execution traces are unavailable, and review references (§2.1, Appendix B).
- **Benchmark and evaluation environment.** KernelShift contains 99 evaluated kernel specifications and 1,582 workloads from ncnn, llama.cpp, Arm SIMD Loops, and KleidiAI. A common interface exposes compile, evaluate, and disassemble tools backed by the target hardware (§§2.2–2.3, Appendices A.1 and B.2).
- **Adaptation study.** The authors compare matched tasks across Arm generations, vary available instructions on fixed machines, inspect actual instruction use, and test whether shape-specialized kernels improve end-to-end llama.cpp inference (§§4.2–4.5, Appendices C.2 and F).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Agents beat compiler auto-vectorization across all source families. | On the 79-kernel Graviton3 SVE set, every evaluated system achieved a family-level geometric mean of 2.4–19.8× over the `-O3` SVE-enabled starting point across the four families. | §4.1, Appendix D, Table 16 |
| Expert-reference gains varied by source. | On the same SVE set, the best family-level Speedup@40 was 2.74× for ncnn, 1.95× for llama.cpp, and 1.56× for SIMD Loops against their respective references. | Relative performance held up from SVE to SVE2 but often fell on SME2. | On eight matched SIMD Loops kernels, the SVE2-to-SVE ratio of expert-relative Speedup@40 was 0.94–1.05 across evaluated models. On six matched KleidiAI kernels, the SME2-to-SVE ratios were 0.42, 0.46, and 0.41 for DeepSeek-V4-Pro, GLM-5.3, and GPT-5.6-luna, respectively. The two Claude models stayed at similar levels. Each generation used its own expert reference. | §4.2, Table 4, Appendix A.2 |
| Exposing SME2 instructions did not improve this agent’s performance over Neon alone. | On 20 KleidiAI kernels on Apple M4, nanobot with GPT-5.6-luna averaged Speedup@40 of 0.141× with Neon only, 0.059× with streaming SVE, and 0.085× with full SME2 over three seeds, against the same expert reference. No final full-SME2 candidate used ZA outer products. | §4.2, Table 3 as captioned, Appendix G |
| Agent gains were larger against weaker references. | Across 79 Graviton3 SVE kernels, the Spearman correlation between median agent Speedup@40 and expert speedup over unvectorized scalar code was −0.69. | §4.3, Figure 3 as captioned |

Appendix A.2 gives a conflicting task-set description for the SME2 ablations. | §4.4, Table 5 caption, Appendix A.2 |
| Shape-specialized kernels improved end-to-end inference. | On Graviton4, for Q4_K_M Qwen3.5-4B and Llama-3.1-8B-Instruct, replacing selected GEMMs yielded 1.30–1.57× prefill and 1.04–1.10× decode speedups across the reported 1–16-thread settings versus original llama.cpp’s repacked i8mm fast path. The authors report essentially unchanged perplexity. | §4.5, Table 6, Appendix E.1 |

Speedup@40 retains the best correct candidate within 40 tool calls and uses geometric means over hidden workloads and then kernels (§§2–3). The fixed-machine M4 ladder shows that expanding the available instruction set can hurt the tested agent under a shared reference. The cross-generation ratios also reflect changes in processor and reference implementation, so they cannot isolate the effect of the instruction set. The headroom correlation is descriptive, and the deployment result establishes gains for the tested fixed shapes and serving settings.

## Limitations and validity risks

- **Author-stated.** Expert-reference availability restricts matched comparisons. The SME2 evidence centers on 20 KleidiAI kernels, and the kernel benchmark uses single-core Arm CPUs. Transfer to other architectures and broader multicore settings remains open (§6).
- **Author-stated.** Public expert code may appear in model training data. Appendix H reports a cutoff-based check for one agent on one SME2 set, leaving possible training exposure elsewhere unresolved.
- **Analyst inference.** Expert strength varies by source, and inclusion requires a usable reference. Aggregate scores therefore depend on task selection and baseline strength. The end-to-end comparison also gives generated kernels fixed shapes while the library serves a broader shape distribution (§4.3, Appendices A.3 and E.1).
- **Analyst inference.** The fixed-machine ladders use one model–harness pair, so their results give limited evidence about how other systems respond to the same instruction choices (§4.2, Appendix A.2).

## Open research questions

1. **Can agents learn to use ZA reliably from working examples?** The paper reports gains from pitfall examples and limited ZA adoption, but does not establish which guidance improves passing ZA implementations. Compare matched prompts with and without a verified minimal ZA example, and measure passing ZA use and Speedup@40 (§§4.2, 4.4).
2. **How much of the inference gain comes from fixed-shape specialization?** The comparison uses general-purpose llama.cpp kernels. Benchmark agent and expert implementations specialized to identical shapes on the same host and under the same serving settings (§4.5, Appendix E.1).
3. **Does the adaptation gap recur beyond Arm?** The evaluated sequence covers Arm CPUs. Build a matched-kernel instruction ladder on another architecture and hold the machine, reference, and tool budget fixed within that ladder (§6, Appendix C.2).

## Confidence and missing information

**Medium.** The supplied prose supports the main direction of the results, and the fixed-machine ladder includes numerical rows. Several tables are supplied only as captions, including the full system-level SVE results, cross-generation results, ablations, per-setting inference results, and bootstrap intervals. Consequently, the full rankings, per-setting breakdowns, and individual intervals cannot be checked from the supplied text. The SME2 ablation prose and caption describe 20 KleidiAI kernels, while Appendix A.2 lists a 32-kernel subset. The ladder and headroom results above are identified by their captions because nearby cross-references point to different numbers.
