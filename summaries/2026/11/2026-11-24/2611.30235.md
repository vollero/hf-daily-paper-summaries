# PixelOne: From Options to Pixels in a Single Forward for GUI Grounding

> [← Daily summary](../2026-11-24.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.30235) · [arXiv](https://arxiv.org/abs/2611.30235)


## One-sentence takeaway

PixelOne distills a zooming search teacher into a model that selects a visual token and then a pixel from a native-resolution screenshot in one forward pass, with Pro-35B-A3B reaching 83.77% mean point-in-box accuracy at 0.43 s per target across four benchmarks (§4.1, §S4.4, §5).

## Problem and motivation

GUI grounding maps a screenshot and a natural-language instruction to a click. Small controls in crowded interfaces demand both fine visual detail and low latency. The authors identify two problems with fixed-bin single-pass grounders such as GUI-Decisions and GUI-Swift: downsampling can erase target detail, and each global coordinate bin spans more pixels as screenshot resolution increases (§§1–2).

## Approach and contributions

- **Shared decision head.** A teacher adapts VideoJEV’s text-option scorer to select rows and columns over progressively zoomed crops. The student reuses the same query/key head to rank visual tokens from a full-resolution screenshot. A lightweight pixel head then picks the highest-scoring valid pixel within the winning token using features from the same forward pass (§§3.1–3.2, Figs. 2–3).
- **Search-to-pixel distillation.** The student inherits the teacher’s weights and learns from distributions projected from scored search regions onto tokens and pixels. Distillation covers only regions the teacher explored and applies only when its final click hits the box. Every example supplies box supervision (§3.3).
- **Click-aligned pixel loss.** The loss trains a high-scoring subset of in-box pixels to outrank out-of-box pixels within each supervised token, directly addressing how the decoder chooses a click. The paper evaluates both language-LoRA and fully fine-tuned Pro variants (§3.4, §S2.3).

The matched controls support separate contributions from teacher initialization, spatial distillation, and pixel ranking under the tested training recipe. The local comparisons measure screenshot-to-click performance under each model’s own image-processing policy. End-to-end agent success, performance under a common image budget, and latency on other hardware remain untested in the supplied text.

## Limitations and validity risks

- **Author-reported scope.** OSWorld-G evaluation covers the 510 rectangular targets. Timing uses one H200 at batch size 1 and excludes file reading, model loading, and warmup. Published reference scores can use different annotation and refusal protocols, and full training totals for GUI-Owl and UI-Venus-2 are unverified (§§S4.1, S4.3–S4.4, Table S5).
- **Analyst inference.** The Pro comparison cannot isolate full fine-tuning because continuation data volume and the attention configuration also change. Table 2 reports single training runs, leaving run-to-run variability unresolved (§4.3, §S2.3).
- **Analyst inference.** A wrong token choice is unrecoverable if that token contains no valid click. The pixel-loss guarantee is conditional on selecting a token that contains an in-box pixel (§3.2, §S3.2).

## Open research questions

1. **How much of Pro’s gain comes from data volume, full fine-tuning, or bidirectional attention?** The reported variants change all three. Run a factorial comparison from the same student checkpoint with matched data order and multiple seeds (§S2.3).
2. **When is native resolution worth the extra visual tokens?** External models use different image policies, and the high-resolution examples are selected successes. Compare native and downsampled inputs under matched token budgets, stratifying accuracy and latency by screenshot resolution and target size (§S4.3, §S8.1).
3. **Do grounding gains carry over to multi-step computer use?** The benchmarks score isolated clicks against boxes. Swap grounders inside a fixed agent and measure task completion, misclick recovery, and end-to-end latency on the same workflows (§S4.1).

## Confidence and missing information

**High** for the method and explicitly reported results. The supplied text omits the numerical bodies of several tables, including the full local baseline matrix and detailed latency profiles. It also leaves training-run variability, teacher-gate acceptance rates, and public availability of checkpoints, code, and traces unestablished.
