# WeightCode: Installing New Capabilities into Neural Networks via Weight-Space Programming

> [← Daily summary](../2026-11-24.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.25476) · [arXiv](https://arxiv.org/abs/2611.25476)


## One-sentence takeaway

WeightCode uses a frozen LLM to write gradient-free weight edits that improve command composition, simulated pickup, and image corruption robustness while largely preserving measured prior behavior, and shows that vision programs can be rerun across independently trained models of the same architecture.

## Problem and motivation

Adding a capability after training requires turning task knowledge into a computation the network can execute while preserving behavior it already learned. The authors identify a gap between retaining a numerical weight edit and retaining the procedure that constructed it. A procedure can inspect a different checkpoint and recompute an edit in that checkpoint’s weight coordinates, or inform a later update to the same network (§§1–2).

## Approach and contributions

- **Capability installation.** A frozen LLM writes Python programs that inspect weights and activations and construct updates from task knowledge such as a grammar, demonstrations, or labeled examples. Under the main protocol, labeled checks select candidates under a retention rule, while forward passes, statistics, and closed-form computations construct the updates. The edited network retains its architecture and runs independently of the LLM (§§3.1–3.3, A.1).
- **Mechanistic verification.** Interventions isolate the role of selective noise-correction gates in a ViT-Lite, and component tests show how coordinated input and output edits let an existing SCAN Transformer compose a newly enabled primitive (§4.2, §A.6).
- **Program reuse and successive editing.** The authors rerun unchanged programs on independently trained checkpoints using target-specific examples. They also write new programs for already edited networks, using the earlier code and retention checks for previously installed behavior (§§3.2, 4.3–4.4).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| SCAN command composition improved on both splits | Held-out exact match rose from 0.0% to 99.8% for `jump` compositions with 257 weight changes and no measured change on old commands. For `around right`, it rose from 17.6% to 89.6%, with a 0.3-point drop on old commands. | §4.1, Figure 2a, Table 2 |
| BabyAI acquired pickup | With eight demonstrations, held-out pickup success rose from 0.0% to 98.4%, and old-mission success rose 0.4 points. The best behavior-cloning reference kept by the retention rule reached 1.1% pickup success. | §4.1, Figure 2a, Table 2 |
| ImageNet programs beat the evaluated fine-tuning methods | On held-out ImageNet ResNet-18 tests, net gains were +10.47 and +17.62 points for severity-3 Gaussian noise versus +8.67 for best kept fine-tuning, and +8.84 and +14.26 for severity-4 contrast reduction versus +3.38. The comparison matched examples, external checks, and the retention rule. | §4.1, Figure 2b, Tables 3 and 8 |
| Selective gates drove the ViT-Lite noise result | On the CIFAR-10 selection split, removing the block-2 gate reduced net gain from +31.75 to +10.05 points. Removing all gates returned accuracy to baseline, and forcing them open reduced clean accuracy by 5.03 points. | §4.2, Figure 3, Table 10 |
| Rerunning carried over gains across training seeds | Ten programs rerun on five other ViT-Lites each averaged 83–110% of their source-network corruption gain on held-out tests. Copying fixed edits yielded mean gains of −1.42 to +0.01 points across programs on the selection split. | §4.3, Figure 4, Table 7 |
| A second edit added contrast robustness while retaining noise robustness | On held-out ViT-Lite tests, six contrast programs written after the noise edit added +5.23 to +14.50 points on contrast, while the earlier noise gain changed by −0.17 to +0.23 points. Four met the prespecified 10-point threshold for the added capability. | §4.4, Figure 5, Table 13 |

The held-out results establish capability gains on the tested tasks, while the interventions support a causal explanation for particular edits. For images, *net gain* sums the change in corrupted-image accuracy and the change in clean accuracy. Retention was measured on designated reference inputs. The evidence leaves cross-architecture portability and preservation under untested conditions unresolved.

## Limitations and validity risks

- **Author-reported boundaries.** The main demonstrations build on existing computations. In exploratory tests, a new synthetic operation worked in isolation but composed poorly, and a CIFAR-100 class addition fell below the strongest prototype reference (§§5, A.10).
- **Author-reported variability and trade-offs.** Only five of ten ViT-Lite sessions met the prespecified comparative criterion. Fine-tuning overtook some programs under looser clean-loss bounds, and the contrast edits’ first-layer rescaling harmed performance on other noise conditions (§§A.2–A.3, A.7).
- **Author-reported protocol exceptions.** Manual inspection found finite-difference steps that the automatic audit missed. The authors exclude the affected sessions, including rounds of the exploratory four-round stream, from their main protocol evidence (§§A.1, A.11).
- **Analyst inference.** Matching examples and external checks leaves compute and prior knowledge unmatched because the program writer brings a pretrained LLM and can do within-run selection. The SCAN grammar-generated reference also includes some test commands, so its score measures what can be achieved given the rule rather than conventional held-out supervised generalization (§3.3, §A.1, Table 2).

## Open research questions

1. **Can programs install representations that support new compositions?** The synthetic lookup worked alone but composed poorly. Train a model with a controlled missing operation, then compare a lookup edit and an edit integrated into the existing computation on held-out compositions (§A.10.1).
2. **How portable are programs across architectures?** The reported reruns use compatible checkpoints of the original architecture. Test a program with a shared interface for inspecting layers across a ViT and a ResNet on the same corruption, with matched target examples and retention checks (§§3.2, 4.3).
3. **How many successive edits can preserve prior gains under the main protocol?** The main ViT-Lite experiments cover two rounds, while the longer ResNet-20 stream includes excluded operations. Run a longer audited sequence with a fixed cumulative retention budget and test every prior condition after each edit (§4.4, §A.11).

## Confidence and missing information

**High** for the reported benchmark outcomes and their stated settings. The supplied text gives aggregate or prose summaries for several appendix tables but omits some row-level values. It also does not establish public availability of the executable programs, prompts, session traces, or edited checkpoints, or provide a compute-matched comparison with fine-tuning.
