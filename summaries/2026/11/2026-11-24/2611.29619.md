# Wactorz: Self-Writing LLM Agents That Discover, Repair, and Migrate at the Edge

> [← Daily summary](../2026-11-24.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.29619) · [arXiv](https://arxiv.org/abs/2611.29619)


## One-sentence takeaway

Wactorz runs LLM-generated Python as persistent, supervised actors connected by MQTT, and a single smart-home demonstration shows a generated counter discovering an existing data stream, recovering from a deliberate fault with its count intact, and moving to a Raspberry Pi.

## Problem and motivation

Sensor-driven automations need to keep running, recover from faults, and operate across the hardware already deployed near sensors. The authors identify a gap between task-oriented LLM orchestrators that terminate after a job and persistent edge automation systems whose rules are written by hand. (Introduction, p. 1)

## Approach and contributions

- **Runtime code generation and supervision.** A planner turns pipeline requests into Python actors that can be added to the running system. A supervisor restarts failed actors individually and reloads persisted state. Repeated runtime errors can trigger an LLM repair that is saved for subsequent launches. (Fig. 1, p. 1; “Supervision and self-healing,” p. 2)
- **Discovery from observed messages.** The planner receives MQTT topic contracts and sample payloads when generating consumers for existing streams. A dashboard visualizes the resulting wiring and flags missing producers, unused outputs, and field mismatches. (Topic discovery, p. 2; Fig. 2, p. 3)
- **Edge placement for generated and hand-written agents.** Migration stops the source actor, transfers supported state, and retains the source copy until the destination confirms startup. The runtime also supports versioned model delivery and shadow evaluation. The authors claim novelty for the combination of LLM-generated code, supervision, and migration in first-class actors. (Introduction, p. 1; “Edge nodes and live migration,” p. 2; “Wactorz as a Library” and “Models at the Edge,” pp. 3–4)

The run establishes feasibility for the illustrated workflow. The observed repair restored liveness while dropping an explicitly requested behavior. General repair reliability, migration downtime, and unattended safety remain unmeasured in the reported evaluation.

## Limitations and validity risks

- **Author-stated.** The syntax validator is a blocklist, actors in one process share privileges, and isolation depends on deployment placement. Repair can change requested behavior. Migration is constrained by state serialization, transfer caps, and release compatibility. The authors report one run of one scenario and no systematic repair success rates across models or fault types. (Limitations, pp. 4–5)
- **Analyst inference.** The run cannot isolate how much observed-payload discovery contributed because the paper reports no comparison with schema-only wiring. Aggregate elapsed time also leaves migration interruption and recovery time unresolved. (Topic discovery, p. 2; Demonstration, p. 4)

## Open research questions

1. **How often does repair preserve user intent?** The only reported repair removes the requested fault behavior. Inject several fault types across models and score both recovery and compliance with behavioral tests.
2. **When do observed payloads improve wiring?** The demo includes one successful extension and no discovery ablation. Compare sample-backed and declaration-only planners under schema drift and optional fields.
3. **How disruptive is migration under load or network failure?** The demo shows a successful move and gives no interruption or message-loss measurements. Vary message rate, state size, and destination connectivity, then measure downtime, lost or duplicate events, and rollback success.

## Confidence and missing information

**High** confidence in the description of the architecture and the scope of the reported demonstration. The supplied text gives no repeated trials, comparative baselines, per-stage time or cost breakdowns, systematic repair or wiring results, migration interruption measurements, or empirical results for model shadowing and promotion.
