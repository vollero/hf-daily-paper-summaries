# MORSE: Optimizing Streaming Memory Design via Open-World Auto-Research

> [← Daily summary](../2026-11-24.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.30011) · [arXiv](https://arxiv.org/abs/2611.30011)


## One-sentence takeaway

MORSE uses recurring streaming-video failures to research and revise memory policies around frozen video-language models, reaching 75.1% accuracy on OVO-Bench real-time and backward-tracing questions with Qwen3-VL-8B, 3.1 percentage points above the next-best evaluated harness using that backbone, at a measured mean answer latency of 0.30 seconds (Table 1, Figure 4).

## Problem and motivation

A single-pass video system must decide what to retain before it knows what users will ask. With limited frame storage and a query-time latency budget, its write policy must preserve useful evidence and its read policy must find it quickly. The authors identify a gap in prior streaming harness evolution methods, whose editors typically devise fixes from prior knowledge and a predefined tool inventory even when published methods or pretrained models could address recurring failures (§§1–2).

## Approach and contributions

- **Failure-driven research.** An LLM editor groups recurring failures from training traces, searches papers, model cards, and code for remedies, and turns its findings into executable changes to memory and retrieval (§3.2, Appendix B.1).
- **Joint evolution of policies and perception tools.** The editor can request pretrained, non-generative perception services. After host provenance review and integration, candidate harnesses can use their outputs to change what gets stored and retrieved while keeping the answering VLM frozen (§3.2, Appendix A.1).
- **Two-stage validation.** Selection first rewards gains in mean correct-option probability, then seeks lower estimated answer latency within per-update and cumulative quality-loss limits. Both stages enforce frame-storage, answer-latency, and write-load constraints. The evolved Qwen3-VL-8B harness moves clip indexing and object detection to the write path (§3.3, §4.3, Table 8).

## Evidence and main results

The numerical results below use Qwen3-VL-8B unless a transfer target is named.

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Highest aggregate scores within each of the three evaluated frozen-backbone groups | OVO-Bench RT+BT question-weighted accuracy was **75.1%** (+3.1 percentage points), StreamingBench question-weighted accuracy was **78.9%** (+2.7 points), and StreamBench LLM-judged free-form score was **71.6%** (+6.3 points). Each margin is over the next-best evaluated harness using Qwen3-VL-8B. | §1, §§4.1–4.2, Tables 1–2 |
| Larger gains on backward tracing than real-time perception | From seed to final harness on OVO-Bench, backward-tracing accuracy rose from **52.8% to 65.3%**, and real-time accuracy rose from **78.4% to 82.4%**. | §4.3, Table 3 |
| Faster answers with more work during ingestion | On OVO-Bench with one H100, mean answer latency was **0.30 s**, 6.0× faster than MemEvo and 3.5× faster than OASIS. From the accuracy-stage checkpoint to the final harness, measured write cost rose from **0.87 to 1.19 s per 8 s of video**. Separately, estimated mean validation latency fell from **0.73 to 0.17 s**, with test accuracy changing by at most **0.8 points per benchmark**. | §§4.3–4.4, Figure 4, Table 8, Appendix C.1 |
| Both open-world components contributed in the reported ablation | On OVO-Bench RT+BT, full MORSE scored **75.1%**, evolution with tool acquisition but without online research **72.9%**, and evolution with online research but a fixed tool inventory **70.6%**. The unevolved seed scored **67.4%**. The evolved variants used matched splits, budgets, and gates. | §4.5, Table 4 |
| The harness transferred to different answering models | On OVO-Bench RT+BT, the unchanged program and tools raised LLaVA-OneVision-2-8B from **54.8% to 71.1%** and Gemma-4-26B-A4B from **65.4% to 75.1%**. MemEvo scored **65.3%** and **70.8%**, respectively. | §4.5, Table 5 |
| Gains extended to held-out driving video | On timestamp-causal ODV-Bench multiple-choice QA, MORSE scored **67.1%** versus **62.6%** for MemEvo and **58.6%** for the direct VLM. Driving videos were outside the evolution data sources. | §4.2, Appendix C.3, Table 12 |

The reported comparisons support gains across the tested benchmarks and backbones, and the transfer experiment shows that one evolved harness helped two additional answering models. The latency evidence quantifies a shift of computation from query time to ingestion on the tested hardware. The size of these gains across independent evolution runs and under a fixed total memory budget remains unknown.

## Limitations and validity risks

- **Author-reported scope.** The frame cap leaves captions and embeddings free to grow. OVO-Bench excludes forward active responding, and StreamingBench excludes omni-source and proactive-output tasks (§3.1, Appendices A.1 and A.3).
- **Author-reported regressions.** Other harnesses scored higher on Qwen3-VL-8B conversational interaction and knowledge-based questions in StreamBench. Every accepted accuracy update in the main run also broke some non-target training questions, showing that added evidence can distract the answering model (§4.2, Appendix B.4).
- **Analyst inference.** Table 4 supports the value of each component when the other is present. A matched evolution run with both components disabled and repeated runs would be needed to estimate their interaction and the variability of the reported gains (§4.5).
- **Analyst inference.** The MemEvo comparison evaluates its published final program with documented implementation choices, so it compares resulting harnesses. It leaves the relative effectiveness of the two search procedures under a matched compute budget unresolved (Appendix C.4).

## Open research questions

1. **How much does online research help independently of tool acquisition?** The reported ablation omits the evolved condition with both disabled. Run a repeated factorial comparison from the same seed with matched candidate and compute budgets (§4.5, Table 4).
2. **How well does MORSE retain distant evidence under a fixed total storage budget?** The frame store is capped, while captions and vectors can grow. Evolve and test harnesses under matched byte budgets on progressively longer streams, measuring backward-tracing accuracy and retrieval latency (§3.1, Appendix A.1).
3. **When does moving computation to ingestion improve total cost?** The efficiency stage lowers query latency while increasing write cost relative to its starting checkpoint. Replay the same streams at different query rates and report total GPU time, write backlog, and tail answer latency (§4.4, Appendix C.1).

## Confidence and missing information

**High** for the method description and the headline results explicitly stated in the supplied text. Several tables appear only as captions with selected values recoverable from nearby prose. The text leaves unavailable the complete per-backbone and per-task results, variability across repeated evolution runs, end-to-end evolution cost including tool integration, and release status of the MORSE implementation and evolution splits.
