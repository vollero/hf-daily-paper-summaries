# The Noise Floor of a Quantization Comparison: Engine, restart, batch and kernel drift, measured against 8-bit and 4-bit effects in two decision models

> [← Daily summary](../2026-11-18.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.15671) · [arXiv](https://arxiv.org/abs/2611.15671)


## One-sentence takeaway

On two Clef models served on one NVIDIA GB10, both 4-bit builds changed more top-1 decisions than any measured serving variation, while Q8_0 was sometimes statistically indistinguishable from that variation and aggregate accuracy obscured many individual decision changes (§§4.1–4.4).

## Problem and motivation

A quantized model is often compared with a BF16 reference served under different conditions. Engine, server instance, batching, and kernel selection can each change the selected answer, making it hard to attribute disagreement to quantization. Accuracy also nets out correct-to-incorrect and incorrect-to-correct changes, so a stable score can conceal substantial turnover. The authors identify a gap in measuring production-engine restart drift and quantization on the same decisions (§§1–2).

## Approach and contributions

- **Paired comparison protocol.** Compare each quantized build with BF16 in the same engine, then compare its top-1 flip rate with rates from measured engine, restart, batch, and kernel changes. Use paired bootstrap intervals on the same records and exact intervals for zero-flip pairs (§§3.4, 4.1).
- **Serving measurements with verified kernel selection.** Evaluate Clef-flash and Clef across three engines and five formats, explicitly verify which Gated DeltaNet path ran, and report five preregistered tests on Clef-flash with an exploratory rerun on Clef (§§3.1–3.5, 4.2).
- **Decision-level analysis and release.** Explore how restart drift varies across instances and split full-set flips into correct-to-incorrect, incorrect-to-correct, and wrong-to-wrong changes. The authors report releasing code, recipes, per-record outputs, and preregistrations (§§4.3–4.4, Code and data availability).

The authors' preregistered Clef-flash predictions that FP8 would fall within BF16 restart drift and that BF16 engine changes would be at least as large as within-engine 8-bit effects both failed. The exploratory Clef rerun yielded the same outcomes, with one engine-versus-Q8_0 interval reaching zero (§4.2). The results establish separation from the observed serving variation for the tested 4-bit builds. A general restart bound remains unknown. The full-set comparison uses transformers BF16, so those flip counts include any engine contribution (§§4.3–4.5).

## Limitations and validity risks

- **Author-stated.** Both models share an architecture and release, and all results come from one GB10. Most restart estimates come from one pair per build. Concurrent vLLM requests allow batch composition to vary across launches, and the third-instance probe changes graph-cache state and request stream together (§§4.3, 6).
- **Author-stated.** The transformers batch comparison also changes the process. The batch-1 repeatability check covered one Clef-flash task and was not repeated on Clef. The authors added an interpretation of the H2 scoring rule after seeing the 27B results (§§3.5, 4.1, 6).
- **Analyst inference.** The paired intervals quantify variation from resampling records within the observed runs. They do not quantify variation across fresh launches, and the first-200-per-task selection limits extrapolation to differently sampled workloads (§§3.4, 4.3).

## Open research questions

- **What drives NVFP4 restart drift?** The third-instance probe changed graph-cache state and request stream together. Cross cold and warm graph caches with full and subset streams, then repeat launches in each condition with fixed request ordering (§§4.3, 6).
- **How stable is the separation between 8-bit effects and serving drift?** Q8_0 overlaps some measured serving contrasts, and each build has few restart replicates. Repeat each build across multiple launches and hardware platforms using the same paired records (§§4.1, 6).
- **How much drift comes from batch size alone?** The transformers batch comparison also changes the process, and Clef lacks a matched batch-1 repeat. Compare batch sizes within a pinned-kernel process and repeat each size across fresh processes for both models (§§4.1, 6).

## Confidence and missing information

**High** for the reported comparisons within the tested configurations. The supplied text omits the referenced per-pair TVD tables, released per-record outputs, and full analysis and preregistration files. Private operational records are withheld. The distribution of drift across many restarts, the separate effects of cache state and request stream, and behavior on other hardware or model families remain unmeasured (§§4.1, 4.3, 6, Code and data availability).
