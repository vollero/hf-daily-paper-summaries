# CADMAGEDDON: High-Fidelity CAD Reconstruction with Local Inference

> [← Daily summary](../2026-11-18.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.22563) · [arXiv](https://arxiv.org/abs/2611.22563)


## One-sentence takeaway

CADMAGEDDON uses an open-weight vision–language model to assemble editable CAD features from geometry fitted to a target mesh, and the authors report better volumetric IoU, surface-type agreement, and Chamfer distance than the evaluated baselines on all five main benchmark subsets (Table 1, §4.2).

## Problem and motivation

Meshes from suppliers and legacy systems preserve a tessellated shape but lack the feature history engineers need for redesign. The authors identify a gap in reconstructing editable CAD for complex mechanical parts on a single machine, where proprietary geometry can stay on premises. They argue that learned methods can lose accuracy and numerical precision on mechanical parts, while direct fitting can recover precise dimensions yet choose an unsuitable feature decomposition (§1).

## Approach and contributions

- **Feature decisions grounded in the target mesh.** Geometric tools fit and name entities such as section levels, profile arcs, analytic surfaces, and hole patterns. Qwen3.8-27B uses renders and tool reports to select and compose features, and the builder resolves those references to fitted dimensions. The contribution is the interface between feature selection and target-derived fitting (§§2–3.4, Fig. 1).
- **Incremental construction and correction.** The agent executes each operation, inspects missing and excess material, and can revise earlier features. The driver returns an eligible saved program with the smallest volumetric residual against the input mesh (§§3.4–3.5).
- **Open-source implementation and two CAD backends.** The agent uses a single open-weight model without task-specific reconstruction training and emits executable CadQuery or native FreeCAD PartDesign programs (Abstract, §§3.6, 4.4).

The shared-subset comparisons support a geometric reconstruction advantage, including better agreement in surface types on the mechanical-part subsets. IoU and GMS condition on returned geometry, so the invalid rate matters when interpreting those means. The leaderboard uses different input modalities and subsets, and the BenchCAD-2 harness comparison uses unequal retry budgets. The evidence leaves the independent effect of the named-geometry tools, recovery of original design intent, and runtime on a single GPU or laptop unresolved.

## Limitations and validity risks

- **Author-stated:** The system assumes a clean mesh of a single part. Benchmarks are CAD-derived, and real scans and assemblies are left for future work (§5).
- **Author-stated:** Detector coverage and available operations bound feature recovery. The authors report persistent failures on thin walls and a dense through-hole pattern. CadQuery output uses literal dimensions and represents fillets and chamfers as explicit solids, limiting recovery of design intent (§5).
- **Author-stated:** Iterative calls with long contexts make reconstruction slower than single-pass learned methods, and frontier leaderboard comparisons vary in input modality and evaluated subset (§5).
- **Analyst inference:** CADFit’s imported metrics reduce scoring comparability. The selected examples in Figure 2 illustrate the largest margins and cannot establish how often those qualitative improvements occur (§4.1, Fig. 2).

## Open research questions

1. **How much accuracy comes from named geometry and residual feedback individually?** The same-model harness comparison changes several factors at once, including the retry budget. Run component ablations on identical mesh inputs with the model, call budget, and attempt count held fixed.
2. **How robust is feature recovery to scan noise and missing surfaces?** All evaluated meshes are CAD-derived. Test paired CAD exports and physical scans of the same parts, measuring geometric fidelity and feature recovery as scan quality varies.
3. **What latency and memory does local reconstruction require?** The benchmark runs used four GPUs. Run the same parts and settings on one 48 GB GPU and a specified laptop, recording peak memory, completion rate, per-part latency, and reconstruction quality.

## Confidence and missing information

**High** for the method description and the reported comparisons within their stated protocols. The supplied text includes the captions and selected results for Tables 1 and 4, but their numerical bodies are absent. It also lacks measured single-GPU and laptop performance, a matched frontier comparison, and an evaluation of recovered design intent.
