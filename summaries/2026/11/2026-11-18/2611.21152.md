# From Repositories to Training Environments: Scaling Long-Horizon Coding Agents with Environment Evolution Loop

> [← Daily summary](../2026-11-18.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.21152) · [arXiv](https://arxiv.org/abs/2611.21152)


## One-sentence takeaway

RepoFactory turns real repositories into verifiable coding tasks, and supervised fine-tuning on its evolved environments raises Qwen3.5-35B-A3B’s NL2Repo accuracy by 22.6 percentage points over the base model and 5.1 points over training without environment evolution (Table 1, §5.2).

## Problem and motivation

Building a complete repository requires sustained implementation and coordination across files, which short bug-fix tasks only partly exercise. The authors identify two gaps in existing environment pipelines: validation checks whether a task works but gives little guidance on its training value, while feedback from solver rollouts or downstream training is slow and costly for long-horizon tasks (§1, §2.2).

## Approach and contributions

- **Repository-to-environment pipeline.** RepoFactory turns public projects into isolated reconstruction tasks with a natural-language specification, an API manifest, a containerized workspace, and a test-based verifier. The learner builds the project from scratch while the reference implementation and evaluation code remain hidden (§3.1–3.2).
- **Proxy-guided environment evolution.** A construction agent jointly revises the reference implementation, specification, and tests. The objective multiplies a validity gate by static call-graph reachability and an implementation-scope score based on code size and direct runtime dependencies. Validity requires full reward for the reference and zero reward for the unchanged workspace. The loop uses test execution and code analysis for feedback, without solver rollouts during evolution (§3.1–3.2).
- **Training corpus and model.** The pipeline produces 10,159 environments across 17 software domains. Filtered Qwen3.8-Max trajectories from 5,577 environments supply 10,947 samples for supervised fine-tuning, yielding RepoHorizen-35B-A3B (§4, §5.2, Appendix A).

| Finding | Evidence / setting | Location in paper |

| Training gains continued at the largest tested dataset size | NL2Repo accuracy rose from 36.5% with 3,000 training environments to 46.4% with 5,577. | §5.3, Fig. 3 |
| Both proxy targets showed downstream gains | With 2,000 trajectories per level, NL2Repo accuracy rose from 30.2% after round 3 to 32.9% after round 12 when targeting scope, and from 30.2% to 32.5% when targeting coupling. Coupling results fluctuated at intermediate levels. | §5.6, Fig. 5 |

The results support improved candidate recovery and better benchmark performance under the reported recipe, with the largest gain on repository reconstruction. The authors interpret the ablations as evidence that scope and coupling help guide evolution. The scope runs also used more supervised tokens at later levels, leaving the contribution of task scope at a fixed token budget unresolved. The reported average gains differ slightly from subtraction of the displayed rounded scores. Published comparisons in Table 2 used varying harnesses.

## Limitations and validity risks

- **Author-stated.** The environment collection focuses on Python, and the structural proxies do not identify the specific capabilities each task requires (§7).
- **Analyst inference.** Giving full reward to the reference and zero reward to the unchanged workspace checks two endpoints. These checks leave open whether the verifier accepts alternative correct implementations or rejects plausible partial ones (§3.1–3.2).
- **Analyst inference.** The reported fine-tuning comparisons leave uncertainty about run-to-run variation and whether the gains persist under another agent scaffold. The supplied text reports one scaffold for the authors’ evaluations and gives no uncertainty estimates (§5.1–5.6).

## Open research questions

1. **Does optimizing scope help at a fixed supervised token budget?** Later scope levels had more supervised tokens (§5.6). Fine-tune on earlier and later levels with matched token budgets and evaluate on NL2Repo.
2. **Do the same proxies work for non-Python repositories?** The pipeline has limited coverage of other languages (§7). Build matched cohorts in another language and compare validation yield and downstream accuracy with and without evolution.
3. **How well do evolved verifiers score independently written solutions?** The validity gate checks the reference and unchanged workspace (§3.1). Evaluate original and evolved verifiers on independently reviewed correct, incomplete, and incorrect implementations.

## Confidence and missing information

**High** confidence in the method summary and reported point estimates. The supplied text leaves unavailable run-to-run variance, supervised token totals for the main evolved and no-evolution comparison, a direct cost comparison against rollout-guided evolution, and the exact contents of the linked releases.
