# Language Models Can Rewrite Their Own Weights

> [← Daily summary](../2026-11-20.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.21885) · [arXiv](https://arxiv.org/abs/2611.21885)


## One-sentence takeaway

Without gradient updates, Qwen3.5-27B wrote an edit that improved held-out math accuracy by 6.6 percentage points and, in a separate experiment, repaired a corrupted copy using text math feedback alone, improving its accuracy across six image benchmarks (§3.6, Tables 12–13).

## Problem and motivation

The authors ask whether a language model can diagnose a failure and make a lasting improvement by editing its own weights. They identify a gap between approaches that change prompts or spend extra compute on each answer, approaches that update weights through training, and prior work in which a stronger model directly edited a smaller one (§§1, 4).

## Approach and contributions

- **Self-rewriting protocol.** A fixed editor receives graded practice answers, inspects weights and hidden states, writes candidate tensor edits in Python, and compares edited and unedited runs on the same problems and seeds. The framework blocks gradients and optimizers. A second protocol adds a check on reserved practice problems before the model chooses whether to submit (§§2.1–2.3, E.9).
- **Model-chosen edits.** The authors demonstrate two ways the model improved its own math performance. One edit weakens a hidden-state direction associated with unfinished answers. The largest gain comes from changing the time-step bias across linear-attention layers (§§3.3, 3.6, E.9).
- **Fault repair and size comparison.** An undamaged editor located a corrupted matrix in its copy and clipped outlier weights using measurements from that copy. The submitted repair transferred from text math to image tasks. Only the 27B model succeeded at both improvement and repair among the Qwen3.5 sizes tested (§§2.4, 3.2, 3.6, 3.8).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Reserved-check protocol produced two significant improvements | Against the same 57.2% base accuracy, sessions 8 and 2 reached 63.8% (+6.6 points) and 61.3% (+4.0 points), respectively (one-sided paired permutation tests, both p < 10⁻⁵). A third submission reached 57.8% (p = 0.25), and five sessions withdrew. Submitted edits were compared on 490 held-out math problems, eight answers each, at 16,384 tokens. | Figure 1, §E.9, Table 13 |
| First-protocol direction edit also improved accuracy | Base 57.2%, edited 58.3%, on the fixed evaluation of 490 held-out math problems with eight answers each at 16,384 tokens (one-sided paired permutation p = 0.038). | Table 2, §E.4 |
| Repair recovered text math accuracy, with a stronger result from clipping only the identified matrix | On 200 held-out problems with one same-seed answer each at 16,384 tokens, the damaged copy scored 0.0%, the submitted repair 33.0% (one-sided sign test versus damaged, p < 10⁻¹⁹), and the clean base 58.5%. Clipping only the identified matrix reached 55.0%. | Tables 1–2, Figures 15 and 26 |
| Text-derived repair transferred to images | Across six benchmarks with 100 items each, one same-seed answer per item at 16,384 tokens, accuracy rose from 7.3% damaged to 70.2% repaired, versus 84.3% for the clean base (pooled paired sign test versus damaged, p < 10⁻⁹⁹). ScreenSpot-v2 rose from 0% to 89%, versus 93% for the clean base. | Figure 16, Table 12 |
| Only the largest tested model produced a successful edit | The 2B model made no edit, the 4B model withdrew harmful self-edits, and the 9B model submitted a harmful edit. None of their damaged copies recovered held-out math accuracy. | §3.8, Tables 2 and 10 |

The paired tests support an improvement in scored math answers under the tested decoding settings. Unfinished answers count as wrong, and both significant second-protocol edits reduced token-limit failures, so these gains do not establish stronger mathematical reasoning (§2.1, E.9). The image results establish cross-modal transfer for the submitted repair. Each editing session started from base weights, so the improving sequence in Figure 1 reflects replacement by independently generated edits. Recursive improvement remains untested.

## Limitations and validity risks

- **Author-reported.** The math holdout contained some paraphrases of practice problems. The authors report that removing overlaps preserved the direction and significance of the comparisons (§D.3).
- **Author-reported.** First-protocol Python sessions could access files beyond the intended interface. The authors audited the analyzed sessions and found no reads of weight files, damage files, or held-out problems. An excluded 4B session accessed its published weights through private handles. The second protocol restricted file access (§§E.3, E.9).
- **Analyst inference.** The size comparison cannot isolate parameter count from the opportunity to test edits. Successful 27B self-editing used a shorter per-answer budget during discovery, and its session at the shared longer budget ended in withdrawal (§§3.1, 3.8, E.4).
- **Analyst inference.** The conspicuous, localized synthetic fault favors outlier detection. The experiment leaves recovery from subtle or distributed corruption open, and the text ablation shows that the submitted repair’s extra changes reduced recovery on that evaluation (§§3.5, D.2, E.3).

## Open research questions

1. **Can edited checkpoints improve across successive rounds?** The reported sessions restarted from base weights. Run successive sessions from the latest accepted checkpoint and compare them with repeated base-start sessions on untouched evaluations (§E.9, Appendix A).
2. **How much does model size matter when testing opportunities are matched?** The successful 27B sessions used cheaper generation during edit discovery. Repeat sessions across sizes and model families with matched test budgets and multiple editor seeds (§§3.1, 3.8, E.4).
3. **Which faults can the editor detect and repair?** The experiment used a single severe corruption pattern. Vary the affected layers, fault types, and strengths, then measure localization and recovery against a fixed clipping baseline (§D.2, Appendix A).
