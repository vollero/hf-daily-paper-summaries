# System 1 agents: a method for local, reliable and fast agentic AI

> [← Daily summary](../2026-11-20.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.21053) · [arXiv](https://arxiv.org/abs/2611.21053)


## One-sentence takeaway

A local agent that compiles tool calls into finite choices achieved 93.9% fully correct outcomes on 1,952 imaging and biomedical requests versus 91.3% for the best tested local LLM setting, with zero invented values detected across 10,888 System 1 calls (Table 1, Extended Data Table 7).

## Problem and motivation

The authors identify two barriers to agentic analysis of sensitive clinical data. Cloud inference sends requests off site, while local generative agents can silently introduce argument values that alter downstream analyses. The authors argue that tool calling often requires selecting a tool and assigning values already available from the request, schema, or deterministic rules, making it a candidate for local decision models that score options without generating text (Introduction).

## Approach and contributions

- **Tool calling through finite choices.** The agent selects a catalogue tool or declines, checks whether the tool can fulfill the request, and uses a deterministic compiler to turn its JSON schema and the request into argument questions. An interchangeable decision model scores the options in one forward pass per question. Missing required values trigger a templated prompt in deployment (Fig. 1, Methods).
- **Oracle-guided compiler development.** An oracle chooses the labelled value when offered, exposing candidate coverage failures separately from model selection errors. Compiler changes were developed on development requests, subject to cross-model improvement and regression checks (Methods, “Development method”).
- **Replayable evaluation.** The authors benchmark six System 1 configurations against 18 local LLM settings and report releasing the framework, labelled requests, catalogues, scorer, and recorded outputs for replay and rescoring (Table 1, Data and Code availability).

The results support a benchmark advantage in tool selection and missing-argument handling, with more mixed results for argument filling. The grounding check measures whether a value has an accepted source. A grounded value can still be assigned to the wrong argument or violate the schema. The study evaluates call construction and abstention. End-to-end workflow outcomes and clinical performance remain unmeasured.

## Limitations and validity risks

- **Author-reported.** Agents sometimes chose the wrong tool or argument, and schema-invalid values appeared in 22 of 10,888 System 1 calls. Requests involving unsupported input types challenged both approaches. The authors also acknowledge that allowing a value from anywhere in the request to count as grounded undercounts hallucination (Results “Reliability,” Discussion).
- **Analyst inference.** The evaluation is concentrated on two biomedical catalogues. All published prompts came from imaging notebooks and were complete, while all underspecified and out-of-scope prompts were custom. Interactive clarification and the additional deployment confidence cutoff were omitted from evaluation, and the LLM comparison scored the first call without tool execution (Methods).
- **Analyst inference.** Shared-backbone comparisons show mixed results and change both the model configuration and the calling method. They leave the separate contributions of candidate extraction, thresholding, and decision-model training unresolved (Extended Data Table 4, Methods “Development method”).

## Open research questions

- **How well does the compiler transfer to unfamiliar schemas?** Both evaluation catalogues are biomedical. Freeze the compiler and test it on unseen catalogues, using the oracle to measure candidate coverage and distinguish it from model selection accuracy.
- **How much do schema checks improve reliability?** The authors propose validating candidates after observing schema-invalid calls. Compare candidate validation on and off with the same model, measuring schema violations, correct-call rate, and unnecessary clarification.
- **What happens when calls are executed in sequence and users answer clarification prompts?** The reported evaluation leaves interactive and downstream outcomes open. Run matched multi-step workflows with scripted user replies and score final task success, error propagation, and clarification burden.

## Confidence and missing information

**High** confidence in the reported benchmark comparisons, which have explicit denominators, scoring rules, and per-agent results. The supplied text lacks end-to-end execution and interactive clarification results, performance on unseen catalogues or other hardware, and a quantitative breakdown of compiler coverage failures versus decision-model errors on the held-out set.
