# HiVe-Mem: Interleaving Horizontal Memory Expansion and Vertical Evidence Composition for Multimodal Agents

> [← Daily summary](../2026-11-13.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.12872) · [arXiv](https://arxiv.org/abs/2611.12872)


## One-sentence takeaway
HiVe-Mem combines graph-expanded episode retrieval with learned per-episode evidence selection, achieving the best average F1 and judge scores among evaluated multimodal baselines while reporting roughly 90% lower token consumption across three benchmarks (Table 1).

## Problem and motivation
Long-running multimodal agents must recover information distributed across text–image interaction histories. The authors identify two gaps: semantic retrieval can miss episodes connected through contextual cues, and fixed memory representations can omit necessary detail or expose excessive context. HiVe-Mem addresses both which episodes are retrieved and which evidence each episode contributes (§1).

## Approach and contributions
- **Horizontal Memory Expansion:** Build a sparse episode graph from shared textual and cross-modal anchors, weighted by inverse document frequency. Expand summary-retrieved seeds with one-hop neighbors ranked by anchor specificity and query relevance (§3.2).
- **Vertical Evidence Composition:** A lightweight MLP uses query and episode-summary embeddings to select any subset of summaries, captions, grounded image crops, raw images, and raw interaction text. PPO optimizes answer F1 with an optional token-cost penalty (§3.3; Appendices A.2–A.4).
- **Combined framework and transfer evaluation:** The contribution is the integration of episode expansion with per-memory evidence composition. Experiments transfer the selector from Qwen3-VL-4B-Instruct to GPT-5-mini without additional training (§4.1; Appendix A.3).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Best average performance with Qwen | Across three benchmarks, HiVe-Mem averages **32.32 F1 / 57.96 LJ**; strongest competing multimodal averages are **28.42 F1** for M2A and **48.35 LJ** for MMA. | Table 1 |
| Performance transfers to GPT-5-mini | Without selector retraining, HiVe-Mem averages **35.94 F1 / 64.69 LJ**, versus best competing multimodal averages of **34.04 F1** for M2A and **60.71 LJ** for MemVerse. | Table 1; Appendix A.3 |
| Substantially lower reported token consumption | Average total input/output consumption is **0.658M versus 7.812M** for MemVerse with Qwen, and **0.748M versus 7.350M** for MIRIX with GPT-5-mini—the most token-efficient multimodal competitors in each setting. Authors report reductions of **91.6% / 89.8%**. | Table 1; §4.2 |
| Expansion provides a modest additional gain | Qwen, equal benchmark-average LJ: full model **57.96**, semantic-only retrieval with the same memory count **56.51**; removing visual anchors gives **57.30**, removing IDF weighting **56.55**. | Table 2; §4.4 |
| Rich evidence matters substantially | Under the same Qwen evaluation, summary-only evidence gives **44.47 LJ**, versus **57.96** for full HiVe-Mem; removing raw text gives **49.68**, removing raw images **51.02**. | Table 2 |
| Selection varies with query type | For visual-dominant queries, raw images are selected for **35.2%** of retrieved memories, averaged equally across benchmarks with Qwen at λ=0. | §4.5; Figure 4 |
| Limited online latency evidence | HiVe-Mem reports **1.03 seconds TTFT** on Mem-Gallery with Qwen. | §4.5; Figure 3(a) |

These results support improved average benchmark performance and reduced reported token use, including one cross-model transfer setting. They do not establish universal superiority: on WorldMemArena with Qwen, MMA scores **28.24 F1**, exceeding HiVe-Mem’s **23.66** (Table 1). Main results use λ=0, so their efficiency gains occur without an explicit token-cost penalty (§4.1). Token counts do not establish full lifecycle cost, including construction, training, and storage.

## Limitations and validity risks
- **Author-stated:** Only five default evidence forms, one lightweight selector architecture, and two base models are evaluated; richer representations, alternative selectors, and broader transfer remain open (Appendix C).
- **Analyst inference—ablation scope:** The “without vertical composition” comparison uses summaries alone. It establishes the value of richer evidence, but does not isolate learned selection against fixed all-evidence or token-matched heuristic selection (Table 2).
- **Analyst inference—evaluation scope:** Adversarial settings are excluded, and WorldMemArena coverage is restricted to Lifelong. Robustness beyond those settings is unestablished (Appendix A.3).
- **Analyst inference—statistical uncertainty:** Main performance tables provide no repeated-run uncertainty or significance tests. Figure 4’s error bars describe variation across benchmarks, not training-run uncertainty.
- **Reproducibility gaps:** Appendix E contains prompt headings and partial rubric descriptions rather than complete prompts. The supplied text also leaves anchor normalization, construction-model identity, and selector input dimensionality insufficiently clear: §3.3 concatenates embeddings, while Table 3 lists a 2048-dimensional embedding and a 2048-input MLP.
- **Release ambiguity:** The abstract says code is available; the Reproducibility Statement says release is planned upon publication.

## Open research questions
- **Does learned selection outperform simpler policies at matched token budgets?** Summary-only ablation does not isolate this benefit. Compare PPO selection with fixed mixtures and query-conditioned heuristics along matched quality–token curves.
- **How robust are graph links and crops to construction errors?** Both depend on VLM-generated information, but error sensitivity is not reported. Perturb anchors and crop coordinates, then measure retrieval recall and answer quality.
- **How broadly does the selector transfer?** Transfer is demonstrated for one destination model, and broader coverage is explicitly left open. Freeze the selector and evaluate additional model families and scales.
- **Do efficiency gains persist as memory grows?** Reported token use and limited TTFT analysis do not establish lifecycle scaling. Measure construction cost, graph-update time, storage, and answering latency over progressively longer histories.

## Confidence and missing information
**Confidence: medium.** The supplied text clearly supports the method and tabulated results, but confidence in generalization and reproducibility is limited.

Material missing information includes benchmark sample counts and split isolation details, complete prompts, main-result run variability, numerical budget curves, construction/training/storage costs, latency hardware and measurement protocol, and an unambiguous implementation release status.
