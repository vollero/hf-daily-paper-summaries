# JustRUA: A Controlled Study of GPT-6 Robot-Use Agents

> [← Daily summary](../2026-11-13.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.16009) · [arXiv](https://arxiv.org/abs/2611.16009)


## One-sentence takeaway
On a fixed RoboDojo simulation subset, the authors raise GPT-6 Astra’s score from 29.7 to 50.3 through harness and geometry changes, although the final improvement combines code execution with a larger decision budget (Table 1; §5.4).

## Problem and motivation
Robot-use agents let a multimodal model command robot motions through a fixed planner without an intervening learned control policy. Reported systems vary their harnesses, evaluation subsets, budgets, and components simultaneously, making gains difficult to attribute. The authors investigate whether apparent model weaknesses instead reflect the surrounding interface and control loop (§§1–2).

## Approach and contributions
- **Controlled component study:** Compare harness, action interface, experience reuse, and scene geometry along a cumulative configuration path, retaining the official motion planner. This tests incremental usefulness rather than every component combination (§§2.2–2.3).
- **Evaluation protocol:** Construct a fixed 111-episode subset covering all 42 RoboDojo tasks, allocating additional layouts to tasks with high observed uncertainty. Supplement scores with video-based behavior counts and estimated episode costs (§§2.4–2.5).
- **JustRUA configuration:** Retain full episode history, a 20-control-step motion cap, compact gripper readings, RGB-predicted depth, and code-based coordinate solving; remove the model-decision cap in the final configuration (§§3–5).
- **Reusable evidence:** The authors report releasing the evaluation set, code, and episode replays. The central contribution is comparative evidence about existing design choices rather than a new learned robot policy (§§1, 7).

## Evidence and main results
| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Harness changes substantially improve score | On the 111-episode evaluation set, official L3 scores 29.7; Codex with full history scores 34.7; adding the 20-step cap reaches 38.0. | Table 1; §§3.1–3.2 |
| Tested alternative interfaces do not consistently improve performance | Against the default score of 38.0, relative targets score 33.9, semantic operations 34.6, and model-chosen motion lengths 37.9 on the same evaluation set. | Table 1; §3.3 |
| Move sequences mainly alleviate decision limits | Sequences score 42.0 versus 38.0 for the default under a 100-decision budget; retaining the old scores for the six budget-exhausting episodes reduces the sequence score to 39.4. | Appendix C, Table 13 |
| Experience reuse changes behavior without a clear overall gain | Evaluation-set scores: default 38.0, visual demonstrations 39.9, text trajectories 35.2, self-built library 37.0. Each uses experience from evaluated tasks; the library practices each task once. | Tables 1, 4; §4 |
| Predicted-depth configuration reduces manipulation errors | Across the same 42 first-round episodes, compact readings versus predicted depth: empty grasps 41→16 and fine-placement failures 18→7. Evaluation-set score rises from 39.8 to 42.4. | Tables 1, 5; §5.2 |
| Depth helps despite poor absolute accuracy in sampled frames | Raw predicted-depth MAE is 73.7 cm, with Pearson correlation 0.993 against simulator depth, averaged over six head-camera frames from two tasks. | Table 7 |
| Final configuration improves score at higher estimated cost | Predicted depth versus final JustRUA: evaluation-set score 42.4→50.3 and success rate 35.4%→43.3%; first-round mean episode cost lower bound $7.74→$12.53. Code execution and removal of the decision cap occur together. | Table 1; §5.4 |
| One example supports a benefit beyond extra decisions | On one `insert_tubes` layout, predicted depth versus coordinate solving scores 40→100, using 65→57 decisions and 500→496 control steps. | Table 9 |

These results support the usefulness of the tested harness and geometry package under fixed conditions. They do not isolate every mechanism or establish leaderboard performance: the official full-evaluation baseline is 29.0, whereas 29.7 is its subset score. Each configuration has only one evaluation-set run, and the final code/budget change is bundled (§8; Table 1).

## Limitations and validity risks
- **Author-stated scope:** One benchmark, one acting model, simulation only, and one run per configuration limit generalization and estimates of variability (§8).
- **Author-stated evaluation limits:** The subset was selected using the default testbed’s history. Its Generalization group weights random layouts differently from the official protocol, and it may rank configurations differently from the full benchmark (Appendix D).
- **Author-stated incomplete comparisons:** The cumulative path is not factorial; component interactions remain untested. Experience reuse covers only a small practice budget and draws on evaluated tasks (§§2.3, 4.3, 8).
- **Analyst inference—attribution:** The final gain cannot be assigned separately to coordinate solving or additional decisions. Likewise, adding depth also adds camera metadata and further gripper readings, so that comparison does not isolate depth images alone (§§5.2, 5.4; Appendix H).
- **Measurement limits:** Behavioral counts are model-reviewed lower bounds from first-round episodes; small differences are not conclusive. Cost assumes all cacheable inputs receive cached pricing and excludes experience-production costs (§§2.5, 4.3).
- **Interpretive limit:** The authors’ claim that remaining failures are mostly task-specific comes from reviewing low-scoring first-round episodes, rather than testing whether general fixes resolve them (§6).

## Open research questions
- **How much does coordinate solving contribute independently of budget?** The final step changes both. Run code-enabled and code-disabled agents with and without the decision cap on identical layouts (§5.4).
- **Which part of the geometry package drives improvement?** Depth, calibration metadata, and additional readings arrive together. Ablate these inputs separately while holding context and decision budgets fixed (§5.2; Appendix H).
- **Do the component rankings generalize?** Evidence is limited to one model and a selected simulation subset. Repeat comparisons across independent layouts, additional models, and physical manipulation tasks (§8).
- **Can experience improve unseen tasks?** Current demonstrations and practice use evaluated tasks. Build a library on disjoint tasks, vary practice budgets, and measure transfer to held-out tasks (§4).

## Confidence and missing information
**Confidence: medium.** The supplied text supports the reported comparisons and their main caveats, but causal attribution and generalization remain limited.

Material missing evidence includes repeated-run uncertainty for configuration differences, a full official evaluation of JustRUA, separate code/budget and geometry-input ablations, human validation of behavior counts, realized operating costs and latency, and physical-robot results.
