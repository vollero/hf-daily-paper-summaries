# Module-Aware Optimization for Graph Neural Networks

> [← Daily summary](../2026-11-12.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.08379) · [arXiv](https://arxiv.org/abs/2611.08379)


## One-sentence takeaway
GraphMuon adapts Muon updates to graph-propagated feature covariance, reaching AdamW’s validation-loss target faster in 13 of 15 evaluated configurations, while its theoretical guarantee controls local representation perturbations rather than convergence.

## Problem and motivation
A GNN weight matrix acts on propagated features \(X_g=SH\), so equal-sized parameter updates can produce different output perturbations depending on graph structure and feature covariance. The authors identify a mismatch: AdamW normalizes coordinates and Muon normalizes matrix directions, but neither explicitly calibrates updates to the geometry of the propagated inputs (§§1–3).

## Approach and contributions
- **Graph-aware direction:** Transform momentum using a regularized, trace-normalized propagated-input covariance, apply Muon’s approximate polar orthogonalization, then transform back. An exponent \(\tau\) controls the metric’s influence (§4.1).
- **Graph-aware scale:** Normalize the direction using raw covariance to control its induced pre-activation perturbation. Trace normalization is deliberately excluded here to retain feature scale (§4.2; Appendix D).
- **Theory:** Establish a representation-perturbation bound, construct feasible Muon directions exhibiting covariance-dependent amplification, and characterize the exact-polar update as a graph-metric Procrustes solution (§4.3).
- **Implementation and evaluation:** Reuse forward activations, subsample covariance estimates, cache eigendecompositions, and evaluate multiple graph tasks and architectures (Appendices G.3–G.8). The abstract provides a code link; availability was not independently checked.

| Finding | Evidence / setting | Location in paper |
|---|---|---|

| Predictive performance is competitive, not uniformly superior | Five-seed test results: BACE/GINE ROC-AUC **0.7927 ± 0.0429** versus AdamW **0.7127 ± 0.0570**; ARXIV/GAT accuracy **0.6926 ± 0.0027** versus **0.6928 ± 0.0027** | Table 2 |
| Both components help under the ablation protocol | MAG wall-clock speedup versus Muon: direction alone **1.07 ± 0.04×**, scale alone **2.28 ± 0.22×**, combined **3.60 ± 0.12×**; target is rounded-down Muon validation loss | Table 3; §5.3 |
| Local perturbation control | For the normalized direction step, \(\|X_g\Delta W\|_F/\sqrt n\leq\alpha\|D\|_F\); exact-polar optimality additionally requires positive-definite metric, full column rank, and input dimension at least output dimension | Theorems 1–2 |
| Modest overhead in one profiling setting | PRODUCTS-scale input, approximately **1.2M** nodes and width **512**: GraphMuon **1.411 s/step** versus Muon **1.372 s/step**; both peak at **28.211 GB** CUDA memory | Table 12 |

The evidence supports faster attainment of a specific AdamW-derived loss target across most tested configurations. It does not establish universal training acceleration or statistically significant predictive superiority. The perturbation theorem concerns the direction step with current inputs fixed; it does not bound the full network’s training trajectory or include the separate weight-decay perturbation.

## Limitations and validity risks
- **Author-stated:** Small graphs can yield noisy, low-rank covariance estimates; controlling representation perturbations need not improve convergence or generalization (§6).
- **Analyst inference:** Exact-polar optimality does not directly establish equivalent guarantees for finite Newton–Schulz iterations, cached metrics, or sampled covariance. Sampling fidelity is tested on ARXIV, but broader approximation effects remain incompletely isolated (Theorem 2; Table 11).
- **Protocol inconsistency:** Table 7 specifies a QUESTIONS budget of 300 epochs, while Tables 1 and 14 report target attainment at 481 epochs for AdamW and 320 for Muon.
- **Tuning ambiguity:** The text claims equal tuning budgets, but documents an additional \(\tau\) grid for GraphMuon without explaining how total search effort is equalized (Appendices G.3, G.5).
- **Reproducibility limits:** Hardware is specified, but exact software versions are absent. Table 2 uses five seeds while shared defaults specify ten; protocol-specific seed counts are not consistently explicit.
- **Comparison scope:** Table 15 includes Shampoo and natural gradient under an accuracy target, so those results should not be merged with the main validation-loss comparisons.

## Open research questions
- **Can covariance reliability guide graph-awareness strength?** The authors identify unreliable covariance as a failure regime. Compare fixed \(\tau\) with effective-rank or stability-driven schedules on small graph batches (§6).
- **How much benefit specifically requires propagation?** The paper distinguishes \(C_g\) from pre-propagation covariance \(C_H\), but supplies no direct optimizer comparison. Test otherwise identical updates using each covariance (Appendix E.1).
- **Where does overhead outweigh optimization gains?** Two configurations lose in wall-clock time. Sweep model width, graph size, sampling budget, and cache refresh frequency while measuring target attainment and per-step cost (Table 14; Appendix G.4).

## Confidence and missing information
**Confidence: medium.** The method and reported results are detailed, but the budget inconsistency and tuning ambiguity limit confidence in comparison fairness. Missing information includes exact software versions, complete per-configuration tuning and seed records, uncertainty estimates for most expanded timing results, and direct propagated-versus-unpropagated covariance ablations.
