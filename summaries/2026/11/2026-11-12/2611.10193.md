# Ensemble Routing for Prompt-Adaptive Cost-Aware LLM Inference

> [← Daily summary](../2026-11-12.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.10193) · [arXiv](https://arxiv.org/abs/2611.10193)


## One-sentence takeaway
PISA-E reuses prompt-specific model capability estimates to adapt ensemble membership and size without retraining, achieving better reported macro-average quality–cost trade-offs than evaluated competitors across four routing benchmarks (§§3–4).

## Problem and motivation
LLM services must balance response quality against inference cost across heterogeneous prompts. Single-model routing cannot combine complementary model capabilities, while fixed ensembles spend the same number of model calls on every request. The authors identify a gap in jointly adapting ensemble composition and cardinality before generation, with an explicit cost–quality preference adjustable at inference time (§1).

## Approach and contributions
- **PISA capability estimation:** Represent prompts using soft memberships over X-means clusters of embeddings, then train one regularized logistic correctness predictor per candidate model. Select a model using predicted capability and normalized training-average invocation cost (§3.1).
- **PISA-E ensemble selection:** Reuse those predictors to estimate strict-majority success under conditional independence using a Poisson-binomial calculation. Rank models by cost-aware utility, evaluate odd-sized ranking prefixes, and select the highest-utility subset. The preference parameter changes at inference time without ensemble-specific training (§3.2).
- **Capability-aware response selection:** Query selected models in parallel, then choose an existing response using BERTScore similarity weighted by the predicted capabilities of both candidate and reference models (§3.2).
- **Empirical contribution:** Evaluate single-model and ensemble routing under ID and held-out-task-group OOD conditions, with analyses of cardinality, ranking, dependence modeling, and response resolution (§4; Appendices C–E).

## Evidence and main results

All results below are author-reported. Task performance uses benchmark-specific scores, macro-averaged across task groups and then across the four benchmarks.

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| PISA leads aggregate single-model routing | Normalized HV ×100: **37.41 ID / 22.85 OOD**, versus **35.78 / 21.33** for EmbedLLM-MF; first in six of eight benchmark–setting combinations. Uses p40 cost reference. | §4.2, Table 1 |
| Better ID performance at lower invocation cost | PISA-E, α=0.75: **73.78%**, **84 × 10⁻⁴ USD/query**; SelectLLM: **73.18%**, **132 × 10⁻⁴ USD/query**—a **0.60 percentage-point** gain with approximately **36%** lower cost. | §4.3, Table 2 |
| Better OOD performance at lower invocation cost | PISA-E, α=0.85: **60.85%**, **292 × 10⁻⁴ USD/query**; DFPE: **60.37%**, **387 × 10⁻⁴ USD/query**—a **0.48 percentage-point** gain with approximately **25%** lower cost. | §4.3, Table 3 |
| Highest aggregate quality when cost is unpenalized | At α=1, PISA-E scores **75.27% ID / 63.24% OOD**, exceeding the strongest competing ensembles by **2.09 / 2.87 percentage points**. | §4.3, Tables 2–3 |
| Adaptive cardinality improves aggregate trade-offs | PISA-E HV ×100: **39.35 ID / 26.30 OOD**, ahead of the strongest fixed-cardinality alternatives by **0.28 / 1.80 points**, using p70 cost reference. | §4.4, Table 5 |
| Capability weighting improves response selection | With the Poisson-binomial estimator at α=1, self-weighted BERTScore beats standard BERTScore by **0.92 ID / 1.21 OOD percentage points**. | §4.5, Table 6 |

The evidence supports aggregate improvements in the evaluated offline settings, rather than universal dominance: some competitors win individual benchmarks, and singleton routing achieves higher HV on RouterBench than adaptive ensembling (§§4.3–4.4). Five-seed evaluations use fixed partitions; their variability does not measure uncertainty across alternative splits (Appendix A). The supplied text contains table captions and narrative results, but omits table bodies, preventing inspection of complete per-benchmark results and standard deviations.

## Limitations and validity risks
- **Author-explicit surrogate limitation:** Strict-majority correctness is a proxy for the final semantic resolver’s success. Conditional independence is assumed; a Gaussian-copula alternative does not consistently improve results (§§3.2, 4.5).
- **Author-explicit optimization limitation:** Greedy ranking prefixes do not guarantee the globally optimal subset. Exhaustive comparisons cover only Track-2 and RouterBench with a restricted maximum ensemble size (Appendix E).
- **Analyst inference—deployment economics:** Reported costs exclude local routing and response-resolution overhead. Consequently, the stated savings do not establish total system cost or latency improvements (Appendix A).
- **Analyst inference—generalization scope:** OOD means held-out task groups within existing benchmarks, with separately fitted ID/OOD routers. This does not establish robustness to changing model pools or live service drift (§4.1; Appendix A).
- **Analyst inference—objective mismatch:** Predictors learn thresholded binary success, while reported task performance can use graded scores. Calibration and sensitivity to that threshold are not reported in the supplied text (§3.1; Appendix A).
- **Missing component evidence:** No isolated soft-versus-hard assignment ablation or prompt-dependent cost-estimation comparison is supplied.

## Open research questions
1. **How well does surrogate utility predict actual resolver quality?** The authors explicitly distinguish the two. A next experiment could measure their agreement across candidate subsets and task groups, including calibration under OOD shifts.
2. **Do savings persist after full system overhead?** Routing and resolution overhead are excluded. A live benchmark could measure end-to-end monetary cost and latency, including embeddings and BERTScore.
3. **Which capability-estimation components drive the gains?** Soft memberships are central, but an isolated ablation is unavailable. Compare hard assignments, soft assignments, and direct embedding predictors under matched tuning.
4. **How robust is routing to changing pools and prices?** Evaluation assumes a fixed pool and training-average costs. Test model additions, removals, and price or response-length shifts with and without refitting.

## Confidence and missing information
**Confidence: medium.** The supplied methodology and narrative results support the main findings, but complete table bodies, numerical uncertainty estimates, benchmark sizes and model pools, exact OOD group assignments, selected hyperparameters, runtime measurements, and code or checkpoint availability are unavailable.
