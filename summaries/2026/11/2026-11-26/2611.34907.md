# Agentic LongLive: Asynchronous Agentic Memory for Long Video Generation

> [← Daily summary](../2026-11-26.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.34907) · [arXiv](https://arxiv.org/abs/2611.34907)


## One-sentence takeaway

An agent that prepares text and image memory from past prompts improved state, protagonist identity, and location consistency on LongStory-Online, while optimized LongLive-2.0 and LongLive-H3 configurations generated video faster than playback (Tables 1–2).

## Problem and motivation

Live video generators must maintain characters, objects, and places as users introduce new prompts. Their rolling attention caches retain only a small part of the story, and reusing generated frames can propagate mistakes. Offline storytelling agents can plan from a complete script and regenerate failed shots. In the live setting studied here, prompts arrive at shot boundaries, playback cannot wait for memory construction, and each shot is generated once (§1, §2.1).

## Approach and contributions

- **Asynchronous memory preparation.** While one shot plays, a separate agent plans and draws memory for the next. An auxiliary worker computes attention key/value blocks in advance where the backbone permits it. At the boundary, the generator uses the newest ready version and falls back to older memory if needed (§§2.1–2.3, Fig. 2).
- **Prompt-derived text and image memory.** The agent tracks persistent entity states from revealed prompts without observing the generated video. It composes a global reference for identity and persistent state and a shot-level reference for active entities and place. A router uses the incoming prompt to keep, recall, or drop the place reference. Prepared text cards are appended for entities named in the prompt (§2.3, Fig. 3).
- **Learned memory selection.** A LoRA-tuned 8B planner learns via GRPO which entities to store and draw before the next prompt arrives. Training uses hidden future annotations for scoring and an image reward calibrated against downstream video judgments (§2.4, App. D).
- **Online evaluation benchmark.** LongStory-Online introduces 25 stories and 857 shots with terse prompts revealed one shot at a time and hidden annotations for persistent state, identity, and location (§3.1, Table E2).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Strong same-backbone consistency gains | On LongStory-Online with three seeds, LongLive-2.0 with built-in memory versus the full system scored 38.2% → 64.5% on persistent state, 44.1% → 89.0% on protagonist identity, and 15.0% → 55.4% on place revisit. Revisit counts returns where both shots are judged to be at their planned place. | Table 1, §3.1, App. E |
| Identity gains transfer to both H3 generators | On LongStory-Online with two video seeds, full memory versus independent shots raised identity from 61.0% to 98.0% on RAVEN and from 58.2% to 96.8% on LongLive-H3. Severe artifacts also rose from 0.5% to 3.0% and from 0.9% to 5.0%, respectively. | Table 1, §3.2, App. C |
| Real-time throughput depends on hardware and optimization | Optimized full systems reached 34.3 FPS on six B200 GPUs for BF16 LongLive-2.0 and 34.7 FPS on eight B200 GPUs for LongLive-H3, against 24 FPS playback. In separate BF16 H100 release-inference timing runs without cards, asynchronous LongLive-2.0 memory added 0.9% wall time with zero reported stall, versus 60.4% overhead for the synchronous agent. | Table 2, App. B |
| Text cards and planner training contribute differently | With the RL planner on LongLive-2.0, adding named-entity cards to image memory gained 13.9 state and 19.3 identity points on LongStory-Online. With image memory alone, the trained 8B planner beat the 35B planner by 3.6 state and 7.0 identity points. With cards present, neither planner difference was statistically significant. | Tables 3–4, App. C |
| Human preferences support continuity gains | In a seed-0 study with 32 volunteers viewing four shots per story, the full system received 98.8% of story-averaged best-version votes for persistent state against LongLive-2.0 built-in memory. In the three-way LongLive-H3 comparison, visual-quality vote shares were 43.6% for the full system and 55.1% for independent shots, with no significant difference. | §3.2, App. I |
| Identity and imaging quality held up over the extended runs | The authors report roughly flat identity and imaging quality for the full system over nine hand-written stories extended to 14 minutes, using two seeds. | Fig. 6, App. C |

The same-backbone comparisons support a consistency gain under the paper’s sequential-prompt protocol. The ablations show that scene routing matters for place consistency and that text cards contribute substantially to state and identity. The evidence for overall visual quality is mixed across backbones. The long-horizon and timing runs establish performance for the tested durations, hardware, and prompt pacing. Quality and speed were measured in separate runs, with recorded live-agent memory streams replayed for the main quality comparisons (§3.1, App. B).

## Limitations and validity risks

- **Author-reported.** Prepared memory can preserve a stale appearance when the current prompt first introduces a change or when a recalled scene contains an older view of a character. On LongStory-Online, planned close-up framing fell from 75.5% with LongLive-2.0’s built-in memory to 63.7% with the full system across three seeds (App. H).
- **Author-reported.** The system uses extra GPUs. H3 still computes some memory conditioning after the prompt arrives, and an H100 agent missed most update deadlines at LongLive-H3’s playback pace (§3.3, Table B3). The main automated judge also helped write the benchmark prompts and Hard stories. A second judge largely corroborated the consistency comparisons on a seed-0 configuration with an earlier global-memory design, but agreement on severe artifacts was weak (App. E).
- **Analyst inference.** Generalization to unscripted interactive sessions remains uncertain. The benchmark uses prepared stories with fixed annotations, and human raters were a convenience sample who saw selected shots from one seed (§3.1, Apps. E and I).
- **Analyst inference.** A fixed generator attention window bounds active context, while the prefill worker caches at most eight locations in the reported implementation. The text leaves end-to-end storage growth and recall past that capacity unclear (§2.1, App. C).

## Open research questions

1. **Can memory reflect a new state within the shot where it is introduced?** App. H documents stale references and leaves within-shot updates untested. Compare boundary-only memory with an update at a chunk boundary, measuring first-change state accuracy, visible discontinuities, and latency.
2. **Can the agent reliably recall places beyond its prefilled cache capacity?** The reported router caches at most eight locations (App. C). Run longer stories with more locations and delayed revisits, comparing eviction and retrieval policies on recall accuracy, memory footprint, and deadline misses.
3. **Do the gains hold with unscripted prompts and variable timing?** The benchmark uses prepared stories and key speed tests use paced prompts (§3.1, App. B). Run interactive sessions with user-authored prompts and variable shot lengths, measuring consistency, memory lag, and playback stalls.

## Confidence and missing information

**High** confidence in the reported comparisons under the stated protocol. The supplied text does not establish consistency beyond 14 minutes, performance in unscripted live sessions, end-to-end storage growth as entities and locations accumulate, or audio consistency on H3. The paper links code and reports a released LongLive-H3 checkpoint, but the supplied text does not establish public availability of the benchmark files or planner weights.
