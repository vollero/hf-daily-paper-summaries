# SEEK: Self-Evolution through Execution Knowledge for Agentic Robot Manipulation

> [← Daily summary](../2026-11-26.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.33915) · [arXiv](https://arxiv.org/abs/2611.33915)


## One-sentence takeaway

With its underlying model fixed, SEEK carries forward measured action effects and revisable robot programs, raising the average task score from 27.0 to 54.4 versus the same system with no carryover on unseen layouts across all 42 RoboDojo tasks after ten evolution attempts per task (Table 2, §4.3).

## Problem and motivation

A robot guided by a multimodal model can adapt during an attempt, but it may repeat the same mistakes when the working context resets. Replaying actions is unreliable when scene layouts change, and reusable programs can encounter conditions their authors did not anticipate. The authors identify a gap in combining programs that act autonomously where applicable with persistent evidence, including failed actions, that supports revision during execution (§§1–2, Table 1).

## Approach and contributions

- **Self-Evolving Programmatic Policy (SEPP).** A main program and reusable operations derive targets, choose actions, and verify progress from current observations. Applicable procedures execute without a model request. A request for help or a stall can trigger guidance or a validated code revision (§3.3, Fig. 2).
- **Persistent Action-Effect Bank (PAEB).** The bank stores dispatched actions, measured before-and-after observations, execution context, and provenance for effective and ineffective actions. Procedure versions cite supporting records, which can be retrieved by ID (§3.4).
- **Evidence-linked revision across attempts.** After each evolution attempt, the fixed model reviews the trace and outcome and can keep, replace, or revert procedures. The next attempt inherits the evidence and code and initializes scene-dependent state from fresh observations (§3.5).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Carryover improves held-out RoboDojo performance | GPT-6 Astra at xhigh effort, across 42 tasks and 50 unseen episodes per task. After ten evolution attempts per task, SEEK scored **54.4 vs 27.0**, with **48.0% vs 19.7%** strict success, against the same system with no carryover. Score improved on 37 of 42 tasks. | §§4.1, 4.3, Table 2 |
| SEEK scores higher with fewer evaluation requests than the direct agent | GPT-6.2 Astra at xhigh effort on 34 non-Open tasks, with ten matched unseen episodes per task. After five evolution attempts per task, SEEK scored **80.1 vs 49.6**, achieved **75.0% vs 40.7%** strict success, and averaged **14.1 vs 63.2** requests per episode (**77.6% fewer**). | §4.2, Table 2, Fig. 3 |
| Evidence and procedure carryover are complementary on the analysis subset | On nine RoboDojo tasks, mean score was **30.3** with neither, **47.5** with procedures only, **57.3** with evidence only, and **70.4** with both after ten evolution attempts for the carryover configurations. Both together scored higher than either alone on each task. Operation reuse was **82.3%** with both and **68.4%** with procedures only. | §4.4, Table 4 |
| A second model benefits from carryover | On three analysis tasks with Claude Opus 5.5, ten evolution attempts raised mean held-out score from **24.0 to 62.4** and reduced requests per episode from **35.7 to 26.0**, relative to no carryover. | §4.6 |
| Physical tabletop trials favor SEEK | On four Franka Panda tasks with ten unseen episodes per task, SEEK after five evolution attempts scored **83.3 vs 66.9** and averaged **34.4 vs 52.2** requests per episode against GPT-6 Astra acting directly at xhigh effort. An operator scored the episodes. | §4.6, Fig. 5 |

The matched no-carryover comparison isolates the value of persistent knowledge within SEEK because both conditions can adapt during evaluation. The direct-agent comparisons measure the combined effect of SEEK’s execution framework and prior attempts. Request counts cover evaluation episodes, leaving end-to-end cost, including evolution, unestablished. The results support reuse on new layouts of practiced tasks.

## Limitations and validity risks

- **Author-stated.** Perception tools, the executor, and the action interface stay fixed, so errors in components such as SAM3 can limit performance. Knowledge is accumulated separately by task. Cross-task transfer, longer-term accumulation, stale evidence, and additional embodiments remain open (§5).
- **Analyst inference.** The ablation covers nine tasks, the GPT-6.2 Astra comparison excludes Open, and the physical evaluation uses one arm with operator scoring. These settings limit how broadly the corresponding results can be generalized (§§4.1–4.6).
- **Analyst inference.** Leaderboard methods use different experience and demonstration protocols, and the listed GPT-6 Astra agent uses medium effort. Those comparisons support rankings under the reported settings, while the matched no-carryover experiment provides the cleaner estimate of carryover’s contribution (§4.2, Tables 2–3).

## Open research questions

1. **Can accumulated knowledge transfer to a new task?** The experiments retain knowledge separately by task. Initialize held-out tasks with evidence and procedures from related tasks and compare with an empty start under the same attempt budget (§5).
2. **How does SEEK handle stale evidence over longer deployments?** The main protocol evaluates a ten-attempt snapshot. Run longer sequences with controlled scene or hardware changes and compare append-only retention with pruning or compression (§§3.4–3.5, 4.1, 5).
3. **When do fewer evaluation requests offset the cost of evolution?** The reported metric counts requests per evaluation episode. Measure cumulative requests, tokens, and wall-clock time from initialization through repeated deployments against the matched direct agent (§§4.1–4.2).
