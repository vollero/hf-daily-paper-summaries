# Evaluating Memanto on DolphinBench for AI Agents

> [← Daily summary](../2026-11-26.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.28231) · [arXiv](https://arxiv.org/abs/2611.28231)


## One-sentence takeaway

On DolphinBench, Hermes with Memanto and GPT-6-Luna passed 503 of 600 tasks (83.83%) for $10.86 with a 15.32 s median task latency, leading the reported configurations on all three metrics in a comparison that varied the agent model and settings (§§5–6, Table 1, Figures 1 and 3).

## Problem and motivation

Workplace agents must recognize when an action depends on prior interactions, retrieve the relevant detail, and apply it correctly through a tool. The authors argue that question-answering benchmarks typically signal what to retrieve and that answerability alone leaves memory dependence untested. DolphinBench addresses this gap with simulated workplace actions screened for dependence on relevant history under a GPT-5.6-Luna validation protocol (§§1, 3).

## Approach and contributions

The study evaluates the previously described Memanto system. During ingestion, Hermes processes each dated message in a fresh conversation and chooses what to save as typed semantic records. During testing, it starts fresh for each task and retrieves from frozen memory. Memanto ranks binarized representations exhaustively using information-theoretic scoring, with a relevance threshold of 0.1 and a cap of 50 records (§§2, 4–5, Figure 2).

- **Benchmark run and release.** The authors report task completion, cost broken down by agent and memory operations, and median task latency. They report releasing the ingestion and test scripts and run results (§§1, 5–6, 8).
- **Per-persona comparison.** The study compares all three personas with reported Hermes runs, including the largest task-count gain on Alex, the infrastructure engineer (§6, Figure 4).
- **Retrieval hypothesis.** The authors propose that admitting both earlier facts and later revisions may help the agent act on current information. The mechanism remains untested (§7).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Higher end-to-end task completion | On 600 DolphinBench tasks, Hermes with Memanto and GPT-6-Luna passed 503 (83.83%). The strongest reported baseline, Hermes with Mem0 and GPT-5.6-Luna, passed 424 (70.67%), a gap of 79 tasks or 13.16 percentage points. Memanto used medium reasoning and up to 6 iterations per conversation. The reported Hermes baselines used high reasoning and up to 60 iterations. | §§5–6, Table 1, Limitations |
| Lower total evaluation cost | With ingestion and all 600 tasks included, the Memanto configuration cost $10.86 ($8.69 for memory operations and $2.17 for agent tokens). The cheapest reported configuration, Hermes with built-in memory, cost $61.48. | §6, Table 1, Figure 1 |
| Lower median task latency | Including tool use, Memanto took 15.32 s per task at the median, versus 37.69 s for Mem0, the fastest reported Hermes baseline, and 32.19 s for Claude Code with built-in memory, the fastest reported baseline across setups. | §6, Figure 3 |
| Similar completion rates across personas | Out of 200 tasks per persona, Memanto passed 170 for Morgan (85.0%), 166 for Alex (83.0%), and 167 for Riley (83.5%). The best reported Hermes baseline on Alex passed 132 of 200. | §6, Figure 4 |

The shared grading protocol makes end-to-end completion comparable on this benchmark. Each pass required every deterministic and LLM-judged check to pass. The results establish the reported configuration’s lead on these runs. How much of that lead came from memory, how often the system retrieved the right facts, and whether the proposed revision mechanism helped remain unresolved (§§5–7).

## Limitations and validity risks

- **Author-stated.** The baselines were drawn from official reports and were never rerun under matched models or inference settings. Harness versions, prices, and infrastructure may differ. Agent costs came from Hermes estimates with retries unaudited separately, and memory costs came from Moorcheh Cloud credits, so accounting coverage may differ (§7, Limitations).
- **Author-stated.** The study did not isolate the retrieval threshold or record cap. The authors propose analyzing failed tasks and repeating trials (§§7–8).
- **Analyst inference.** Testing on three synthetic personas with frozen memory leaves transfer to live workflows uncertain, particularly when agents must write to memory during task execution (§§3, 5).
- **Analyst inference.** The benchmark’s task screening demonstrates dependence on supplied history for the GPT-5.6-Luna validation runs. The same dependence remains unverified for GPT-6-Luna (§§3, 5).

## Open research questions

1. **How much of the completion advantage comes from the memory system?** The reported runs vary model and inference settings together with memory. Rerun Memanto and the baselines with the same model, harness version, reasoning effort, and iteration budget (§7, Limitations).
2. **Do the retrieval threshold and cap help the agent act on revised facts?** The paper offers a mechanism without an ablation. Vary both settings and measure whether the latest fact reaches context, whether stale facts are used, and whether the task passes on cases with known revisions (§7).
3. **How stable are the scores and latency across runs?** Trial-to-trial variation is unreported. Repeat full ingestion and testing for each matched configuration and report variation in task completion, cost, and median latency (§8).

## Confidence and missing information

**High** confidence in the summary of the reported run and its settings. The supplied text includes Table 1’s caption and selected results in prose, but omits the full table body. It also lacks repeated-trial estimates, matched baseline runs, retrieval ablations, and a breakdown of task failures by cause.
