# Efficient Video Retrieval Augmented Generation via Token Allocation

> [← Daily summary](../2026-11-26.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.32938) · [arXiv](https://arxiv.org/abs/2611.32938)


## One-sentence takeaway

Lembas allocates a shared token budget across retrieved video frames and subtitles by estimating their marginal value, improving single-turn accuracy in the tested embedding-based pipeline and reducing prefill compute while improving accuracy on the tested multi-turn benchmark (Table 1, Fig. 8b).

## Problem and motivation

Processing every frame of a long video can exceed a vision-language model’s context window or make inference expensive. Some questions need fine detail from a few frames, while others need evidence spread across time. The authors argue that existing frame selection and compression methods often allocate tokens using independent relevance scores or fixed rules, overlooking both diminishing returns within an item and overlap among retrieved items (§§1–2).

## Approach and contributions

1. **Joint allocation across frames and subtitles.** Lembas runs downstream of an existing retriever. It combines query relevance with fitted, saturating token-value curves and discounts redundancy using within-modality embedding similarity (§§3.1–3.2).
2. **Iterative water-filling.** A Frank–Wolfe solver repeatedly updates redundancy-adjusted relevance and solves a water-filling subproblem. The authors prove an \(O(1/\ell)\) objective gap after \(\ell\) iterations for the continuous relaxation with exact subproblem solves. The implementation rounds down to whole tokens and retains the highest-ranked tokens (§3.3, Algorithm 1, Appendix A.3).
3. **Incremental reuse across turns.** Query-independent rankings let the model prefill only newly requested token ranks. Attention from the current query re-ranks cached evidence without an additional VLM call (§3.4).

The evidence supports an accuracy–prefill compute improvement for the tested embedding-based and multi-turn settings. The graph-based LongVideoBench result shows that gains depend on the retrieval setting. Prefill TFLOPs include auxiliary model calls and exclude offline indexing (§4), so the comparisons leave end-to-end serving cost unresolved.

## Limitations and validity risks

- **Author-stated.** The offline token-value fit may be sensitive to shifts in query distribution. The authors suggest refitting when feedback is available (§3.2). The discrete allocation problem is NP-hard, and the convergence bound applies to the continuous relaxation before rounding (Appendix A.1, A.3).
- **Analyst inference.** The multi-turn evaluation uses one benchmark and one LLM judge. Judge agreement with humans and the uncertainty around small accuracy differences are unreported in the supplied text (§4, Fig. 8b).
- **Analyst inference.** The per-turn budget allows the retained cache to grow as new evidence accumulates. The reported prefill savings leave memory use and end-to-end performance under tighter cache limits open (§3.4, Eq. 10, §4 Metrics).
- **Analyst inference.** QuoTA uses the same token-budget comparison but substantially more prefill compute because of its scoring calls. Its Table 1 entries therefore provide a different compute comparison from the closer-budget Top-K entries (§4, Table 1, Appendix B.3).

## Open research questions

1. **How well do the token-value curves transfer across query distributions?** The authors flag distribution shift and report offline fits. Fit on one benchmark, transfer to another, and compare fixed and refitted curves at the same token budgets (§3.2).
2. **Can cross-modal redundancy modeling improve allocation?** The objective penalizes overlap within each modality, leaving overlap between frames and subtitles untested. Compare the current objective with a cross-modal penalty on Video-MME at equal budgets (§3.2).
3. **How do the cache savings hold up under a fixed memory cap?** The reuse rule retains earlier evidence and the evaluation reports prefill TFLOPs. Test longer same-video dialogues under several cache limits and measure accuracy, latency, peak memory, and recomputation (§3.4, §4).

## Confidence and missing information

**Medium.** The supplied text includes the core equations, pseudocode, proof, and full Table 1. It gives prose summaries for several other results, but omits the numeric bodies of Tables 2–5, the plotted values in Fig. 8, and the exact prompt in Fig. 9. This leaves per-baseline multi-turn results, complete ablation and solver breakdowns, and the full hyperparameter configuration unavailable. The exact subtitle-token ranking procedure, run-to-run uncertainty, and Lembas code release status are also unspecified.
