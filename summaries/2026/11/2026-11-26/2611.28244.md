# Demystifying the Autoresearch Harness: How Context and Skills Shape Self-Evolving Agents

> [← Daily summary](../2026-11-26.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.28244) · [arXiv](https://arxiv.org/abs/2611.28244)


## One-sentence takeaway

In a controlled study across three model backbones and two benchmarks, expandable per-attempt digests were the strongest memory variant in every setting, pruning unused skills was the best skill policy on average, and their combination outperformed AIDE and OpenEvolve under a shared iteration cap.

## Problem and motivation

Long-horizon autoresearch agents repeatedly write, run, and revise solutions using grader feedback. As attempts accumulate, their history can overflow the context window, while redundant lessons can crowd the skill library. The authors argue that existing harnesses combine memory with different search policies, prompts, and tools, making it hard to determine which memory choices improve performance (§1).

## Approach and contributions

- **Controlled comparison.** A shared agent loop proposes, refines, or debugs a solution, runs it through a grader, and distills lessons into a task-local library. Each variant changes one memory component relative to a recency-truncation baseline that already has an unmanaged skill library (§§3–4, Fig. 2).
- **Analysis of two memory tiers.** Folding keeps an expandable digest for each attempt, while compaction summarizes older attempts together. The skill variants delete persistently unused lessons, merge semantically similar lessons, or promote selected lessons to standing rules. A No-Skill ablation estimates the contribution of the library itself, and retrieval logs show how usage differs by backbone (§§3.3–3.4, 5.1–5.3).
- **Combined harness.** MLEvolver pairs folding with deletion and is evaluated against AIDE and OpenEvolve on MLE-Bench Lite and KernelBench Level 3 (§6, Fig. 5).

The controlled variants support attributing the observed gains to memory-policy changes within the shared loop. The authors link folding’s advantage to access to individual attempts, but the experiment evaluates digests and full-record retrieval together. The AIDE and OpenEvolve results establish a system-level ranking under the stated model, context, and iteration limits. Those systems also differ in search strategy, and the shared caps leave total inference cost unresolved (§§3.3, 5.1, 6.1–6.3).

## Limitations and validity risks

- **Author-stated.** The mechanism study uses sequential refinement, leaving parallel search unexplored. The system comparison omits interactive coding agents because their open-ended tool use complicates budget matching. Libraries reset for each task, so cross-task transfer and multi-task distillation remain untested (Limitations).
- **Analyst inference.** The reported experiments provide no matched factorial comparison of folding and deletion on the §6 settings, so their interaction is unresolved. The cross-system comparison uses gpt-6-sol alone, which limits conclusions about whether the ranking holds for other backbones (§§4.1, 6.1).
- **Analyst inference.** Kernel speedups depend on the reported GH200, PyTorch Eager reference, and median-latency protocol. The stratified mechanism-test subset excludes some degenerate or algebraically reducible tasks, so its aggregate describes a selected workload (App. A.1–A.2).

## Open research questions

1. **How much of folding’s gain comes from reopening full records?** Folding bundles digest coverage and full-record retrieval (§3.3). Compare digest-only history with selective expansion under equal context and inference budgets.
2. **Do folding and deletion reinforce each other?** The paper tests them individually in the shared loop and combines them for the system comparison (§§4, 6). Run all four combinations on identical tasks and backbones, with repeated runs.
3. **Can curated lessons transfer to related tasks?** Each library starts empty (Limitations). Seed libraries with lessons from separate training tasks, then compare transferred and empty libraries on held-out related tasks, tracking both gains and regressions.

## Confidence and missing information

**High** for the reported rankings and metrics in the specified settings. The supplied text does not establish repeat-run counts or uncertainty intervals for the main comparisons, total inference tokens or wall-clock cost per system, or public availability of the MLEvolver implementation and raw run logs.
