# "Shall We Approve?" Consequence-Aware Approval for Autonomous Coding Agents

> [← Daily summary](../2026-11-04.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.40753) · [arXiv](https://arxiv.org/abs/2610.40753)


## One-sentence takeaway
Caper uses sandbox-observed command effects to reduce harmful coding-agent outcomes and distinguish dangerous tools from harmless twins, with evidence limited to isolated, nonadaptive benchmark settings (§§4–5; Limitations).

## Problem and motivation
Shell-command text can conceal harmful behavior in scripts, build targets, or binaries. The same command can therefore be safe or destructive depending on workspace contents. The authors identify a gap between approvers that judge textual requests and systems that expose changes only after execution for an agent or human to assess (§§1–2; Figure 1).

The goal is to prevent consequences beyond the user’s authorized task while preserving safe task completion, without requiring approval from a human at every step (§3).

## Approach and contributions
- **Transactional approval:** Caper snapshots a network-disabled container, executes the command once under system-call tracing, and withholds output. An independent LLM approver either retains the resulting state or triggers rollback and returns a reason for replanning (§§4.1, 4.3).
- **Bounded effects evidence:** Reports summarize persistent file changes, bounded content diffs, network attempts, protected reads, output, process attribution, and observation coverage. Attribution connects earlier reads and later consequences within the same process; it does not establish precise data flow (§4.2).
- **Controlled evaluation asset:** The authors introduce YoloFS-Ext, with hidden destructive behavior packaged in scripts, Makefiles, script chains, and binaries, paired with harmless twins. They report publicly releasing this extension (§5.1; Appendix A).

## Evidence and main results

All approval-based experiments use GLM-5.3-Flash as the agent; Caper’s approver uses gpt-5.6-luna. Each system runs each task once (§5.1).

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Lower SABER harm | Caper: **6.7%** harmful outcomes; five text-based approval systems: **14.8–18.8%**; no approval: **19.7%**. Uses a common revised oracle on the jointly judged task subset. | §5.2; Appendix A |
| Lower hidden-tool harm with better completion | On **102 dangerous YoloFS-Ext tasks**, Caper has **7.8%** harmful outcomes and **60.8%** safe completion; YoloFS has **35.3%** harm and **22.5%** safe completion. | §§5.1–5.2 |
| Selective blocking | Caper blocks the harmful command in **84.3%** of dangerous YoloFS-Ext tasks, while falsely blocking **1.0%** of **102 safe twins**. The full-dialogue approver without effects evidence falsely blocks **61.8%** of twins. | §5.2; Figure 4; Table 9 |
| Benefit within the Claude Code harness | Replacing Auto Mode’s classifier with Caper’s hook reduces harmful outcomes from **14.8% to 10.0%** on SABER and **62.7% to 6.9%** on YoloFS-Ext, with the same agent and approver model. | §5.2 |
| Content diffs contribute to safety | Removing content diffs raises YoloFS-Ext harm from **7.8% to 13.7%**; Appendix D attributes the increase to overwrite tasks. | §5.3; Figure 6; Appendix D |
| Compact reports with added execution overhead | On SABER, median report size is **0.9 KB**, versus **62.5 KB** for raw traces; aggregate reduction is **99.4%**. Median approval latency is **3.2 s**, versus **3.3 s** without evidence; sandbox work adds approximately **0.5 s per allowed command** and **1.5 s per blocked command**. | §5.5 |

The results support the authors’ claim that observed effects improve approval selectivity in these settings. They do not establish general safety: harmful outcomes remain, networking is disabled, and adaptive adversaries are absent. SABER safe-outcome preservation is asserted in §1, but the supplied text lacks the numerical Table 3 body needed to quantify it.

## Limitations and validity risks
- **Author-stated:** Rollback restores local container state; effects that escape isolation cannot be undone. Networked deployment requires additional confinement (Limitations).
- **Author-stated:** Direct harms from non-shell tools are outside Caper’s gate. One execution also cannot establish safety against deferred behavior, sandbox detection, report injection, or harmful changes split across commands (Limitations).
- **Author-stated:** Both approval and SABER judging depend on fallible LLM judgments. A matched comparison with Codex’s automatic reviewer was not conducted (Limitations).
- **Analyst inference:** One run per task leaves run-to-run stability unmeasured. Most approval experiments share one agent model, limiting evidence of transfer across agents (§5.1).
- **Analyst inference:** YoloFS-Ext’s controlled delete/overwrite tasks provide a strong selectivity test but narrow coverage of real development harms. Its programmatic labels are clearer than SABER’s revised mixed oracle (§5.1; Appendix A).
- **Evidence gap:** Several referenced tables and figures lack their numerical bodies in the supplied retrieval, preventing full inspection of baseline comparisons and confidence intervals.

## Open research questions
- **Can adaptive attackers evade observation?** Neither benchmark tests them. A next experiment could introduce sandbox detection, deferred payloads, report injection, and harm distributed across commands (Limitations).
- **Can approval remain effective with external services?** Disabled networking avoids irreversible transfers but limits realism. Test a recording proxy with controlled service responses and measure both safety and completion (§4.1; Limitations).
- **How stable are the gains across models and repeated runs?** The main evaluation uses one agent and one run per task. Repeat matched experiments across agent–approver combinations and random seeds (§5.1).
- **What evidence is lost under report compression?** Reports aggregate and omit events under a size budget. Sweep that budget on commands with many consequential events and measure missed harms and false blocks (§4.2).

## Confidence and missing information
**Confidence: medium.** The supplied prose clearly describes the mechanism and principal results, but full quantitative verification is limited.

Material missing information includes numerical bodies for the main results and confidence-interval tables, the exact jointly judged SABER denominator, complete baseline reproduction details, and full approver prompts. Repeated-run results and adaptive-attack evaluations are not provided.
