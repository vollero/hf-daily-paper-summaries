# Mage-VL-Cowork: A Full Training Recipe to Learn Hybrid Computer Use From Evolved Harnesses

> [← Daily summary](../2026-11-04.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.40747) · [arXiv](https://arxiv.org/abs/2610.40747)


## One-sentence takeaway

The authors report that a five-stage curriculum combining evolved teacher harnesses, reusable task-generation workflows, and online RL produces a 4B GUI–terminal agent scoring 66.0% on OSWorld-Verified under a 50-step budget (§§4, 6.1–6.2).

## Problem and motivation

Computer-use agents must choose between visual interaction and code or terminal execution: GUI actions reach rendered and live application state, while code can efficiently manipulate structured files. The authors argue that merely exposing both channels does not teach effective routing, and distilling default teacher behavior can transfer inefficient channel choices (§1).

They identify two additional gaps: existing post-training pipelines often assume an already capable starting model, and constructing each training task through a fresh agent run repeats expensive environment-authoring work (§§1–2).

## Approach and contributions

- **Evolved teacher harness:** Optimize tool interfaces, prompts, context handling, and installed terminal libraries before collecting demonstrations. Tool pruning is part of the process; a controlled comparison examines GUI–coding supervision against an accessibility-augmented alternative (§§3.1, 6.7).
- **Workflow-first synthesis:** Mage-CUA-Forge reuses skill-conditioned workflows and application preparers to generate coordinated instructions, initial environments, and rubrics. Student feedback expands the skill taxonomy across generation rounds (§§3.2–3.4).
- **Progressive hybrid training:** Starting from an intermediate multimodally aligned checkpoint, train GUI midtraining → GUI SFT → coding/terminal SFT → hybrid SFT → online GRPO. One policy selects both action channels; asynchronous rollout infrastructure supports desktop RL (§§4–5).
- **Evaluation assets:** Construct WebVoyager-Static with resettable website replicas and trace/backend verification, plus Single Step Cowork Bench for diagnosing grounding, action selection, and output format. Public release is not established (§6.1; Appendix B.2).

The evidence supports the reported benchmark performance, recurring-cost savings, and a useful teacher-harness comparison. Sequential checkpoint gains do not isolate each curriculum component’s causal contribution. The browser result concerns the **SFT checkpoint**, whereas the headline desktop result concerns the **RL checkpoint**. Parameter count and token reductions alone do not establish practical on-device latency or energy efficiency.

## Limitations and validity risks

- **Author-described cost boundaries:** Generation savings exclude workflow authoring/debugging. Nominal training compute excludes base pretraining, vision-encoder computation, and separate attention/recomputation overhead (§6.3; Appendix B.4).
- **Analyst inference—comparison uncertainty:** Desktop baselines use reported settings with differing step budgets. The supplied text omits the actual table cells and provides no confidence intervals or per-run score dispersion, so close rankings are difficult to assess (§§6.1–6.2).
- **Analyst inference—limited causal isolation:** No full stage-removal or ordering ablation is reported. The harness experiment supports the compared variants, but does not independently isolate prompt changes, tool pruning, data composition, and other harness components (§§6.4, 6.7).
- **Analyst inference—replica validity:** WebVoyager-Static changes both environment and grading relative to live evaluation. Reported live-to-static score drops therefore do not by themselves isolate judge inflation from environment differences (§§6.1, 6.6; Appendix A).
- **Analyst inference—selection and deployment gaps:** The paper reports 33 OSWorld-Verified evaluations during RL without clearly separating checkpoint selection from final evaluation. It also supplies no measured on-device deployment results despite its on-device framing (§6.4; Figure 7; §7).

## Open research questions

1. **Which curriculum stages are necessary?** Sequential gains leave stage contributions unresolved. A matched-data, matched-compute study could remove or reorder coding/terminal and hybrid SFT stages.
2. **When does an additional action channel help compact students?** The AX comparison shows harm for one configuration, not a general rule. Vary channel interfaces and demonstration quality while holding teacher, task set, and training volume fixed.
3. **How well does replica-trained browser competence transfer to live sites?** Deterministic replicas avoid instability but do not establish live robustness. Evaluate matched replica/live tasks with audited outcomes and separately record access failures.
4. **When does workflow authoring pay for itself?** Recurring savings exclude initial construction. Measure total authoring, debugging, maintenance, and generation expenditure across increasing task volumes.

## Confidence and missing information

**Confidence: medium.** The supplied prose supports the main reported findings, but several tables and figures appear only as captions.

Material missing information includes complete baseline settings and table values, uncertainty estimates, detailed training hyperparameters and dataset mixtures, development-set construction and overlap controls, checkpoint-selection procedures, total workflow-authoring cost, public asset availability, and measured on-device performance.
