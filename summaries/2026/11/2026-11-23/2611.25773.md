# Duopra: From Full-Duplex Conversation to Full-Duplex Agency

> [← Daily summary](../2026-11-23.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.25773) · [arXiv](https://arxiv.org/abs/2611.25773)


## One-sentence takeaway

Duopra unifies direct tool calls and backend delegation in a streaming speech policy, raising FDB v3 Pass@1 from 4.7% to 44.7% with the same Qwen3-8B backend while improving three turn-control metrics over RV-Audio and losing spontaneous backchanneling on the tested items (Tables 1 and 14).

## Problem and motivation

A full-duplex voice agent must decide when to speak and when it has enough information to act. User corrections can supersede arguments, and later calls may depend on earlier results. The authors identify a gap in frontend–backend systems: the backend can execute a request only after the frontend sends it, and execution depends on whether the request preserves the user’s latest values and all required steps. In the authors’ streaming setup, RV-Audio + Harness rarely reached execution, making initiation a measurable bottleneck (§§1, 3, 5.3).

## Approach and contributions

- **Joint policy and failure analysis.** The authors formalize turn control, speech and private tool actions as outputs of one causal streaming policy. They distinguish backend hand-offs, executed domain calls and success conditional on execution (§3).
- **Unified action interface.** Duopra extends RV-Audio with private JSON actions for schema retrieval and tool invocation. The same `call` operation handles direct domain calls and delegation through `query`, which carries a natural-language request with the latest values, steps and dependencies. The model chooses the route when both are available (§4.1, Appendix C).
- **Three-stage post-training.** Protocol supervised fine-tuning teaches calls, clarification and result reporting. Streaming Dr. GRPO trains thinker LoRA adapters with rewards for timely, complete and grounded execution. A final projector-only stage aligns the speech generator’s conditioning with the base model while holding the trained thinker fixed (§§4.2–4.4, Figure 2).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Higher task completion with the same backend | In the authors’ FDB v3 streaming pipeline, with 300 sessions per configuration, Pass@1 was 4.7% for RV-Audio + Harness, 17.0% for DuplexOmni and 44.7% for Duopra Backend, all with Qwen3-8B. Duopra’s gain over RV-Audio + Harness was 40.0 percentage points, with a paired 95% CI of [31.3, 48.7]. | Table 1, Table 13b |
| Initiation accounted for the gain over RV-Audio + Harness | The baseline handed off in 33 of 300 sessions, setting an 11.0% ceiling with those hand-offs fixed. Domain tools ran in 31 sessions. The baseline passed 14 of those 31 and Duopra Backend with the same Qwen3-8B backend passed 12. Duopra passed 122 of the remaining 269 sessions. | §5.3, Appendix F.1 |
| Later training improved multi-call completion | FDB v3 Direct Pass@1 rose from 26.0% after SFT to 26.7% after Stage 2a and 47.7% for final Duopra. On the 102 sessions requiring two or three calls, the corresponding scores were 2.0%, 0.0% and 27.5%. | Figure 3, Table 13a |
| Backend choice changed coverage and conditional success | For Duopra Backend on FDB v3, switching from Qwen3-8B to DeepSeek raised success among sessions with an executed domain call from 51.5% to 64.1%, while coverage fell from 86.7% to 77.0%. Pass@1 rose from 44.7% to 49.3%, with a paired 95% CI for the change of [−2.3, 11.7] percentage points. | Table 1, Table 13b |
| Turn control improved selectively | On FDB v1.0, RV-Audio to Duopra takeover rates went from 59.1% to 75.6% after user turns, 18.1% to 5.4% during real pauses, and 79.5% to 91.3% after interruptions. None of the post-trained checkpoints produced a backchannel on the 55 tested backchannel items. | Table 14 |
| Projector repair reduced speech recognition errors | With the Stage-2b thinker, text and synthesis schedule fixed on the 221-utterance projector-selection set, Chinese character error rate fell from 6.01% to 2.58% and English word error rate from 9.74% to 7.66%. | Appendix F.4, Table 15 |

The matched-session evidence supports the authors’ diagnosis that initiation constrained RV-Audio + Harness in this pipeline. FDB v3 Pass@1 measures executed-call correctness, including the absence of extra calls. Spoken response quality and factual-answer latency are measured separately. Live adaptive interaction and a common-protocol ranking against published systems remain untested (§5.1, Appendix E, Table 10).

## Limitations and validity risks

- **Author-stated.** Tool-use evaluation uses prerecorded requests and simulated APIs, so users cannot react to the agent’s speech or tool results. Training starts from one base model and uses synthetic speech from a limited set of voices. Published comparisons use different setups, judges and scoring rules (Limitations, p. 9).
- **Author-stated.** Stage 2b changes both the task mix and reward rules. The checkpoint comparison supports the combined stage, while individual reward effects remain unresolved. The utterances used to select the repaired projector also supply its reported error rates (Appendices F.2 and F.4).
- **Analyst inference.** The same-backend comparison estimates the effect of replacing the frontend and its request interface together. It cannot isolate the contribution of training from the interface change. The confidence intervals quantify variation across benchmark recordings for the evaluated checkpoints. Variability across independent training runs remains unknown (Table 1, Appendix E.3).
- **Author-reported residual errors.** Wrong arguments remain a major failure mode after call coverage improves, and interruption takeover declines from Duopra-RL1 to final Duopra despite improving over RV-Audio (§§5.4–5.5, Tables 14 and 16).

## Open research questions

- **Can the policy handle corrections prompted by its own actions?** Prerecorded users cannot react to intermediate results. Run live multi-turn sessions in which users revise goals after tool feedback, and score final task state and superseded calls.
- **What drives the improvement on multi-call requests?** Stage 2b changes the curriculum and reward together. Cross the old and new task mixtures with the old and new rewards under matched training budgets, then repeat training across seeds.
- **Can spontaneous backchanneling be recovered while preserving tool accuracy?** All post-trained checkpoints lost the behavior on the tested items. Vary backchannel-focused retention data or rewards and measure both backchannel timing and FDB v3 Pass@1.
- **Does projector repair generalize to unseen speech conditions?** The reported fixed-thinker comparison uses the selection set. Freeze the chosen projector and test it on independent speakers, utterances and synthesis conditions.

## Confidence and missing information

**High** confidence in the description of the method and the reported within-pipeline comparisons. The supplied text lacks live multi-turn tool-use results, independent training-run variance, isolated Stage-2b reward effects, independent intelligibility estimates for the selected projector, and verification that code, checkpoints or training data are publicly available.
