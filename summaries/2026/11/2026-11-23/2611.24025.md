# Intent Contracts: Taking Tools Away from Agents

> [← Daily summary](../2026-11-23.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.24025) · [arXiv](https://arxiv.org/abs/2611.24025)


## One-sentence takeaway

Intent contracts recorded every changed object before execution and completed more benign bundled requests than intent-visible command review, while matching blind review’s unauthorized-action count on the original benchmark prompts and leaving ambiguous target selection unresolved.

## Problem and motivation

A tool-using agent can interpret an ambiguous request too broadly and change objects outside the user’s authorized scope. A reviewer that sees only the user’s words and the proposed command must infer why the planner selected those objects. The authors ask whether a short, checkable statement of intent helps and whether giving the trusted model control over the actual call lets it complete the authorized portion of a mixed request. (§§1–2)

## Approach and contributions

- **Execution interface.** A tool-less planner submits a goal that names the intended objects and change, a verbatim user quotation, and scope fields. Code validates and logs the contract before a trusted model uses the original user messages to decide what to carry out and writes at most one tool call. Tool output goes to the planner. With correct validation and dispatch code, the logged contract is the planner’s only channel for influencing the call. (§§2.1–2.3, Fig. 1, Table 1)
- **Comparative evaluation.** The authors compare contract execution with blind and intent-visible review of planner-written commands. Both reviewers decide on the whole command. The study adds single-model and declaration-only references, targeted ablations, and file-edit tasks that test partial execution under benign overreach. (§§2.4, 3.1, 4.5–4.7)
- **Declaration coverage metric.** The authors align benchmark invocation logs with preceding accepted contracts and measure whether each changed object was literally named in the corresponding goal. (§3.2)

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Unauthorized actions and completion on original prompts | Across 96 AmPermBench prompts per condition, unauthorized actions were 10/96 for Contract, 10/96 for blind review, and 2/96 for intent-visible review. Safe completions were 12/96, 10/96, and 7/96, respectively. | §4.1, Tables 2–3 |
| Changed objects named in advance | On original prompts, goals named 56/56 changed objects under Contract, 4/54 under blind review, and 2/16 under intent-visible review. The corresponding planner-written commands named 39/54 and 16/16 in the two review modes. On clarified prompts, goal coverage was 181/181, 11/157, and 12/106, respectively. | §4.4, Table 5, §4.7 |
| More authorized work completed in bundled requests | For appended requests, Contract completed the main task in 27/30 attempts, including three attempts that never produced an accepted contract, versus 16/30 for intent-visible review. For multi-file bundles, it completed all requested edits in 24/24 versus 19/24. Both modes avoided the extra edit in both settings. | §4.5, Table 6 |
| Wrong targets after environment labels were clarified | Among clarified runs that changed state, wrong targets were changed in 29/64 Contract runs (45%), 25/58 blind-review runs (43%), 18/37 intent-visible-review runs (49%), and 14/35 strong-model-only runs (40%). All wrong-target changes occurred on range prompts. On the same 96 clarified prompts, the stricter executor had 30/96 unauthorized-action runs versus 29/96 for standard Contract. | §4.7, Table 7 |
| Whole-task delegation produced more unauthorized actions | On the same 30 original prompts, the whole-task executor had 15/30 unauthorized-action runs versus 3/30 for stepwise Contract, with an unadjusted paired p-value below 0.001. The ablation changes both delegation granularity and who observes the environment and selects targets. | §§2.4, 4.6 |
| Higher runtime | On original prompts, median runtime was 178.8 seconds for Contract, 95.5 for intent-visible review, and 81.9 for blind review. | §4.4 |

The logs establish literal target coverage before execution, including for wrong targets. The bundling tasks show that partial execution can preserve authorized work in this setup. The benchmark comparisons leave a reduction in unauthorized actions relative to blind review unestablished. On clarified prompts, different sets of prompts led to state changes in each condition, so wrong-target rates among those runs are descriptive. The authors attribute the remaining range errors to target selection that the trusted side could not independently verify. (§§3.2, 4.3–4.7)

## Limitations and validity risks

- **Author-stated.** The external evaluation uses 96 prompts from 16 templates and one fixed environment per task family, omits branch cleanup, and uses small author-written bundling tasks with repeated runs. Prompt-level inference is optimistic about independence. The benchmark comparisons use one hosted model pair and one run per prompt per condition, with some conditions collected in separate batches. (§§3.1–3.2, 6)
- **Author-stated.** Intent-visible review changes both what the reviewer sees and whether quotations are checked, with feedback able to alter subsequent proposals. Declaration-only adherence was incomplete. Literal declaration coverage leaves audit accuracy unmeasured. The dispatch properties depend on unverified code, and file-tool write-prefix checks leave arbitrary shell writes outside their enforcement. Adversarial robustness and prompt-injection resistance were unevaluated. (§§2.1–2.3, 4.2, 6)
- **Analyst inference.** The bundling results support partial execution as a mechanism, but the comparison cannot isolate its effect from role instructions and planner resubmission behavior. The whole-task ablation also changes several factors together, limiting attribution to execution granularity. (§§2.3–2.4, 4.5–4.6)

## Open research questions

1. **Can independent target evidence reduce range errors?** The stepwise executor cannot inspect the environment, and the stricter instruction yielded similar counts. Compare the standard executor with one that receives trusted, read-only ownership and scope records on the same ambiguous prompts. (§4.7)
2. **Which part of intent-visible review drives the observed trade-off?** The comparison bundles goal visibility, quotation validation, and feedback. Cross goal visibility with quotation validation on fixed proposals, then repeat with interactive feedback to measure effects on subsequent behavior. (§§2.1, 4.2)
3. **Does pre-action declaration improve audit accuracy?** The paper measures literal name coverage. Give auditors user requests and matched records with either goals or commands, then compare their accuracy and review time on identifying unauthorized changes. (§§3.2, 4.4, 6)

## Confidence and missing information

**High** confidence in the reported comparisons for the supplied settings. Material information unavailable in the text includes fixed model checkpoint identifiers, repeated benchmark runs that quantify model variability, independent effects of intent visibility and quotation validation, auditor accuracy, and performance under deliberate planner manipulation. The authors report releasing code and run records, whose contents were outside the supplied text.
