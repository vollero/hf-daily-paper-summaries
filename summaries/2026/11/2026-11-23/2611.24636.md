# Clover-35B-A3B-Preview Technical Report

> [← Daily summary](../2026-11-23.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.24636) · [arXiv](https://arxiv.org/abs/2611.24636)


## One-sentence takeaway

Clover adapts Gated Delta Networks for block diffusion by combining recurrent prefix memory with bidirectional attention inside each block, and leads all seven agent benchmarks in the authors’ comparison while showing workload-dependent decoding speed (§§3.2, 3.6–3.7).

## Problem and motivation

The authors identify a gap between the promise of parallel token generation and the demands of agent workloads, where models must solve tasks across repeated interactions with tools and executable environments. In their reproduced comparison, LLaDA2.2 flash and DiffusionGemma trail the evaluated Qwen models on both Terminal-Bench 2.1 and SWE-bench Verified (§1, Table 1).

## Approach and contributions

- **Block-diffusion Gated DeltaNet.** Clover adapts the Qwen3.6-35B-A3B text backbone into a diffusion mixture-of-experts model with approximately 35B total and 3B active parameters per token. Completed context is stored in recurrent memory. During denoising, a read from that memory competes with active-block tokens in a shared softmax with learned block-size calibration. A separate, zero-initialized convolution adds right context within the active block (§§3.1–3.2, Figures 1–2).
- **Training, decoding, and deployment.** Two-stream training pairs masked reconstruction with an auxiliary causal objective. Clover applies prior dMoE routing to pool experts across block tokens, drafts in parallel, and uses its own causal path to verify a prefix. For hybrid CPU–GPU inference, the report tests placing frequently used experts on the GPU using workload routing statistics (§§3.3–3.5, 4.2).
- **Joint decision variant.** A fixed answer template places related questions’ candidate-label predictions in one block, allowing a single denoising pass after shared context prefill. The authors describe this variant as planned for a subsequent release (§5.1).

The agent results establish a lead under the reported harnesses and model-specific decoding settings. The replay results measure continuation speed without tool execution or task-success measurement, and the system comparisons leave the drafting algorithm’s independent contribution unresolved. The decision results show higher complete-set accuracy on the tested inputs, while logical consistency and the source of the gain remain unmeasured (§§3.6–3.7, 5.2).

## Limitations and validity risks

- **Authors’ limitations.** Replay speed depends on penalties and verification budgets, and the compared systems differ in target models, verification trees, and decoding policies. Some external scores in the on-device comparison use different harnesses. The internal decision sets were reused during development, and the authors acknowledge room for improvement in difficult knowledge, competition math, and standalone coding (§§3.6–4.1, 5.2).
- **Analyst inference.** The report supplies no controlled ablation separating shared-softmax history fusion, block-size calibration, and right-context convolution. The consumer-GPU test uses only MATH-500, with placement informed by mathematical workloads and different quantization and CPU settings across models. It therefore leaves transfer to local agent workloads and the causes of cross-model speed differences unresolved (§§3.2, 3.6–3.7, 4.2).

## Open research questions

- **Which BD-GDN components matter most?** The reported benchmarks evaluate the design as a whole. Train matched variants that remove history calibration and right-context convolution separately, then compare agent accuracy and throughput across block sizes (§§3.2, 3.6–3.7).
- **Does replay speed translate into faster successful agent runs?** Replay omits tool execution, while the live benchmark reports task scores separately. Run the same live tasks under matched harnesses and report success, time to completion, and generation time under each decoding configuration (§§3.6–3.7).
- **Do joint decisions generalize to unseen groups with coupled constraints?** The internal sets were reused during development, and complete-set accuracy does not directly measure consistency. Compare joint and independent modes on a held-out suite that varies question dependence and scores explicit constraint violations (§5.2).

## Confidence and missing information

**High** confidence in the architecture description and tabulated comparisons within their reported settings. The supplied text omits training corpus composition, token budget, actual loss weights, uncertainty estimates for the main comparisons, and the GPU model used for the decision-latency test. Section 3.6 also states a benchmark count that does not match the visible rows in Table 1.
