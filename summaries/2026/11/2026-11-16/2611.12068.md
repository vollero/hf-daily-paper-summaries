# MIRIX-2.0: Multi-Agent Memory System

> [← Daily summary](../2026-11-16.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.12068) · [arXiv](https://arxiv.org/abs/2611.12068)


## One-sentence takeaway

MIRIX-2.0 combines preserved memory records, a bounded provenance hypergraph, and offline consolidation to improve conversational recall and procedural task success, while leaving full-system cost and individual component effects unresolved (§§3–5).

## Problem and motivation

Long-lived agents need to recall precise user details and reuse successful procedures across sessions. The authors identify a tradeoff: summarization can discard details, direct retrieval faces growing histories, and parametric memory requires training. Their goal is to combine source fidelity, bounded evidence access, and distinct identities for repeated events in one system serving both user and agent memory (§§1–2.1).

## Approach and contributions

- **Separate evidence from its index.** Six specialized memory writers, inherited from MIRIX, store typed records; episodic and semantic records receive a provenance hypergraph index. Records commit before indexing, and graph failures cannot roll back committed memories (§§2.2, A.1).
- **Represent connected facts and occurrences.** N-ary frames bind participants, roles, literal values, times, and source-row citations. Undated episodic records receive distinct occurrence identities (§2.3).
- **Retrieve within explicit budgets.** A deterministic planner selects query operators and evidence budgets. Retrieval combines anchor-associated records with relation-cited records, returning graph facts alongside their supporting rows. The answering harness adds conditional verification (§§2.4, A.3–A.4).
- **Consolidate differently for facts and procedures.** Semantic AutoDream merges eligible entity anchors without rewriting evidence; procedural AutoDream distills task transcripts into curated skills with checked quotation-based citations (§2.5).

The authors claim novelty in integrating user-centric and agent-centric memory within one store. The supplied evidence supports the integration, but does not independently establish their priority claim (§1).

## Evidence and main results

M0 is flat memory, M1 adds the graph, and M2 adds semantic AutoDream. User-memory experiments use a gpt-4.1-mini answerer/extractor; conversational accuracy uses a gpt-4o-mini judge with majority-of-three voting (§3.1).

These results support the evaluated configurations’ utility across several tasks. They do not isolate the effects of n-ary representation, source citations, verification, or procedural subcomponents. Bounded evidence access is a design property; it does not establish constant latency as histories grow. The strongest accuracy configuration, M2, has no corresponding timing evaluation (§§3.4–3.5).

## Limitations and validity risks

- **Authors’ stated limitations:** grouped ablations; single-run user-memory results; partial reliance on an LLM judge; only three agent runs with substantial variation; some author-reported baseline values (§5).
- **Comparison sensitivity:** the HyperMem LoCoMo rerun scores below its originally reported result. GPT-5.2 MetaClaw comparisons are not controlled reruns (§§3.2–3.3).
- **Missing mechanism measurements:** no merge-precision, source-detail-retention, skill-provenance-coverage, or routing-contribution evaluation is reported. Memory length and user-memory ingestion tokens are also absent (§3.5).
- **Scope limits:** document QA evaluates M1 only; MemoryCD configuration is unidentified; personalized text metrics do not directly measure factual consistency, preference satisfaction, or user approval (§§3.1–3.2).
- **Analyst inference:** retaining rows protects against consolidation deleting those rows, but cannot guarantee faithful initial writing or correct retrieval, because both depend partly on model decisions. The paper does not measure source-detail retention (§§A.1, A.6, 3.5).
- **Authors’ deployment risks:** sensitive information, persistent mistakes, and stored prompt injection remain concerns; provenance and quotation checks do not replace access control or review (Ethics statement).

## Open research questions

1. **Which components cause the gains?** Grouped ablations leave this unresolved (§5). Next experiment: independently disable n-ary frames, cited rows, occurrence identities, and answer verification under matched budgets.
2. **How does full-system performance scale with history?** M2 is untimed, and fixed evidence caps do not establish latency scaling (§3.4). Next experiment: grow histories while measuring M1/M2 accuracy, latency, ingestion cost, and consolidation cost.
3. **How reliable are semantic merges?** Merge precision and retention are unmeasured (§3.5). Next experiment: audit identity decisions and downstream retrieval on ambiguous aliases and repeated events.
4. **When do procedures help or interfere?** Some ALFWorld categories decline relative to no memory, and procedural components lack separate ablations (§3.3). Next experiment: compare always-on skill retrieval with selective retrieval across task categories and more independent runs.

## Confidence and missing information

**Confidence: medium.** The supplied prose clearly describes the architecture, settings, major results, and caveats. However, table bodies are absent despite captions and surrounding summaries, and some table references are inconsistent. Missing material includes complete numerical tables, M2 costs, scaling measurements, user-memory variance, detailed error audits, and the MemoryCD configuration. Public code availability is an author claim here; no external verification was performed.
