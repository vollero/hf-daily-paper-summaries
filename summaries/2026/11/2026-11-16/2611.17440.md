# Interpreting Coding Agents Through Their Behavioral Trajectories

> [← Daily summary](../2026-11-16.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.17440) · [arXiv](https://arxiv.org/abs/2611.17440)


## One-sentence takeaway
Across 143,209 coding-agent trajectories, the authors find that similar solve rates conceal reproducible workflow differences and that aggregate execution profiles distinguish deployed agent stacks across repository and language splits, subject to task-composition and measurement limitations (§§3–5).

## Problem and motivation
Binary task success reveals whether coding agents solve issues but provides little information about how they search, edit, test, or stop. Comparing these behaviors across systems is difficult because harnesses expose different tools and trace formats. The authors address the need for a shared operational representation and large-scale comparisons that account for success rates and rollout variability (§§1–2).

## Approach and contributions
- **Shared measurement pipeline:** A deterministic parser maps tool calls and execution outputs to operation, file-role, mutation, and read attributes. The authors apply it to 143,209 trajectories from 125 configurations spanning 117 base models and report releasing the parser, analysis pipeline, and an annotated subset (§§3–3.1).
- **Outcome-matched workflow comparison:** Same-scaffold configurations with nearly equal solve rates are compared using six workflow metrics, calibrated against repeated-rollout split-half controls (§§3.2–3.4).
- **Behavioral retrieval:** Cosine nearest-neighbor matching tests whether aggregate profiles identify the deployed stack across disjoint repositories and languages. Repository and multilingual experiments use different feature representations (§4.3; Appendix C).
- **Stack-component analysis:** Controlled panels characterize behavioral shifts associated with model generation, scaffold, and configured reasoning effort (§4.2; Appendix E).

The contribution is a cross-stack empirical measurement framework; it does not introduce a new coding agent or establish access to internal reasoning.

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Parser reliability varies by attribute | On 500 held-out, stratified actions, against reference labels requiring agreement from at least five of six LLMs: primary-operation agreement 82.4%, target-role 77.0%, mutation-type 68.8%, and read-mode 96.6%. | Table 1; Appendices A.2–A.3 |
| Similar success does not imply similar workflows | Among 60 same-scaffold pairs with solve-rate differences ≤1 percentage point over ≥50 shared tasks, all separated on ≥2 of six metrics; 58/60 separated on ≥3 under task-paired 95% bootstrap intervals. | §4.1; Table 2 |
| Separation exceeds the empirical rollout-variation baseline | Separation on ≥3 metrics occurred in 0.781% of eligible same-stack split-half replicates, versus 96.7% of matched distinct-stack pairs. | Table 2; Appendix B |
| Repository-disjoint profiles identify stacks | Across 111 stacks and 222 directional queries between disjoint Python repository halves, the eight-feature profile achieved 85.1% Top-1 and 96.8% Top-3 retrieval; stated random baseline: 0.9%. Action coordinates alone reached 62.6% Top-1. | §4.3; Table 7 |
| Cross-language retrieval is strong but uneven | Across 16 stacks, five languages, and 320 directional queries, the separate 12-feature profile achieved 90.3% Top-1 and 98.8% Top-3; stated random baseline: 6.25%. Worst-split Top-1 was 56.3%; action composition alone achieved 87.5% pooled Top-1. | Appendix C.3; Table 8 |
| Higher configured effort mainly adds exploration in one controlled panel | For Opus 4.8 in Claude Code on 110 common tasks, two rollouts per task, Low→xHigh increased actions by 23.0 (95% CI [16.5, 27.8]) and exploration/read actions by 12.7 [11.0, 14.5]. Test-invocation change was +0.7 [−1.8, 2.3]. | Appendix E; Table 12 |
| Scaffold changes editing and reading interfaces | For Opus 4.7, native edits accounted for 37.0% of recognized edits under SWE-agent-like scaffolding versus 92.4% under Claude Code; native reads were 5.5% versus 90.5%. | §4.2; Table 4 |

These results support behavioral evaluation as a complement to solve rate. They establish differences in measured operations, not superior reasoning, patch quality, or practical efficiency. Retrieval identifies complete deployed stacks rather than isolated model weights; repository retrieval does not establish task-independent signatures. The language experiment’s different representation also prevents treating both retrieval results as validation of one universal profile.

## Limitations and validity risks
- **Authors’ measurement limitations:** LLM consensus is not human ground truth and may share systematic biases. The audit does not measure omitted-action recall or validate sequence metrics. Path-dependent write counts remain diagnostic proxies (Appendix A.3).
- **Authors’ scope limitations:** Rules capture coarse operations rather than intent; internal reasoning and intermediate model text are excluded. One benchmark regime leaves contamination, evaluation recognition, and real-world transfer unresolved (§5).
- **Authors’ comparison limitations:** Matching aggregate solve rates does not match per-task outcomes. Unequal task composition can contribute to repository retrieval (§§4.1, 4.3, 5).
- **Analyst inference:** The wide gap between pooled and worst-split multilingual retrieval warrants caution about uniform language transfer (Table 8).
- **Analyst inference:** “Unproductive tail” is a codebook-defined quantity; useful inspection or reading can occur after its final productive anchor. Its name should not be read as independent evidence of wasted work (Appendix A.1).

## Open research questions
1. **Do profiles distinguish stacks under identical task composition?** Repository splits leave this confound unresolved (§4.3). Next experiment: evaluate every stack on identical task panels and repeat repository-disjoint retrieval.
2. **How much do annotation errors alter the conclusions?** The audit lacks human labels and sequence validation (Appendix A.3). Next experiment: human-adjudicate complete trajectories and recompute workflow separation and retrieval.
3. **Which workflows improve cost, latency, or reliability?** The authors leave these relationships to future work (§5). Next experiment: compare matched-success runs using behavioral profiles alongside measured cost, latency, and additional regression checks.
4. **Do signatures transfer beyond this benchmark?** Deployment transfer remains untested (§5). Next experiment: freeze the parser and retrieval protocol, then evaluate comparable stacks on independently collected development tasks.

**Confidence: high** in the summary of reported findings; **medium** in their broader validity.
