# Gamer: A Generalist Vision-Language-Action Foundation Model for Long-Horizon Real-Time Game Agent

> [← Daily summary](../2026-11-16.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.18397) · [arXiv](https://arxiv.org/abs/2611.18397)


## One-sentence takeaway
Gamer combines gameplay pretraining, sparse reasoning and memory supervision, online reinforcement learning, and low-latency serving to improve real-time game control and held-out task success within Honkai: Star Rail, while transfer to distant games remains limited.

## Problem and motivation
The authors target sustained game interaction through screenshots and native keyboard–mouse controls. Modern games combine navigation, dialogue, combat, puzzles, and resource decisions over long trajectories, challenging agents’ perception, memory, planning, and timing.

The identified gap is a unified policy that combines transferable control, long-horizon instruction following, and real-time execution without policy access to game-specific APIs or internal state. Inference delays also affect learning because actions arrive after the observed state has changed (§1).

## Approach and contributions
- **Shared screen-to-action policy:** Continued pretraining (CPT) learns serialized keyboard–mouse actions with game-specific control descriptions. Random key remapping discourages key-identity shortcuts; repeat-aware loss decay reduces domination by sustained actions. Observations arrive at 5 Hz, with six action blocks per observation supporting nominal 30 Hz control (§§2.1–2.2).
- **Sparse reasoning and persistent memory:** Supervised fine-tuning (SFT) combines operation-, subgoal-, and task-level instructions. One autoregressive policy generates actions directly or precedes them with decision reasoning or memory summaries. Summaries preserve selected information across context eviction (§3).
- **Temporal-Aware GRPO:** TA-GRPO compares memory-linked segments from separate rollouts of the same task using environment-verifiable outcomes. A temporal weighting prior emphasizes decisions closer to segment outcomes without requiring a learned critic or intermediate-state restoration (§4).
- **Data and serving infrastructure:** An annotation pipeline constructs instruction, reasoning, and memory supervision from recorded gameplay. Streaming-vLLM combines stateful KV reuse, positional refresh, specialized execution, verified structural-token speculation, and early action dispatch (§§5–6).

The scaling analysis is explicitly summarized from **GameScaling**; it should not be treated as wholly independent evidence newly introduced here (§§2.3, 8.2).

## Evidence and main results

All values below are author-reported.

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| SFT and RL improve side-quest milestone success | *Opportunity Makes the Thief*: base 0.0%, CPT 34.4%, SFT 72.2%, RL 80.0%. *Bestial Ferocity*: 13.9%, 47.9%, 69.1%, 83.6%. Accuracy pools successful milestone executions across repeated evaluations; these are not uninterrupted quest-completion rates. | §8.3; Table 6 caption |
| Post-training improves breadth across minigames | On 40 held-out HSR instances across seven types, unweighted type-level macro-average rises from 3.2% base to 15.0% CPT, 39.2% SFT, and 49.7% RL. Each task is evaluated three times, using valid attempts. | §8.4; Table 7 caption; Appendix D.4 |
| CPT supports executable cross-game control | Across four public benchmarks using their native metrics, reported average RT scores are 29.5 for Qwen3-VL-8B CPT and 31.5 for Qwen3.5-35B-A3B CPT. Authors report both exceed the strongest listed general-purpose baseline, but its score is absent from the supplied table rendering. | §8.2.4; Table 5 caption |
| Additional CPT does not ensure distant-game gains | Distant unseen-game validation loss plateaus or rises after early adaptation. The scaling fit has overall R² = 0.855 but within-mixture R² = 0.079, indicating weak sustained scaling within mixtures. | §§8.2.2–8.2.3 |
| Cumulative serving optimizations reduce request latency | Qwen3.5-35B-A3B on H200: approximately 1.31 s to 65 ms, reported as 20.1× faster. Configurations change cumulatively, with some profiling-boundary changes. | §8.6.1; Table 9 caption |
| Streaming-video accuracy accompanies lower latency | Qwen3-VL-8B: StreamingBench Real-Time 83.29 and OVO-Bench Overall 62.3; H200 query latency falls from DSCache’s 0.53 s to 0.08 s under the stated matched comparison. | §8.6; Table 8 caption |
| Extended autonomy is reported separately | Across approximately 50 hours covering five story arcs, 19 quest chains, and 160 mission entries, authors report autonomy for over 95% of evaluation time. Intervention details and mission-completion rates are not supplied. | Appendix D.4 |

The evidence supports improved verified task execution within a familiar game and substantial latency reductions on evaluated hardware. It does not establish uninterrupted completion of the side quests, universal cross-game generalization, physical-world transfer, or skilled-human parity. The latter is claimed in introductory text without a supporting human-comparison protocol in the supplied material. Throughput-derived control rates also do not measure realized client cadence (§8.6.1; Appendix C.4).

## Limitations and validity risks
- **Author-stated scope:** Evaluation covers selected environments and task structures; gains depend on relevant training-data coverage. Serving costs and deeper strategic reasoning remain limitations (§10).
- **Evaluation interpretation:** HSR tasks are held out within a training-familiar game. Appendix D.3 allows scripted transitions and excludes missing evaluations from failures; exact valid-attempt counts are unavailable here.
- **Analyst inference—component attribution:** Stage comparisons do not isolate sparse reasoning, memory, temporal weighting, or individual data-processing choices. No isolating ablations are visible in the supplied text.
- **Analyst inference—annotation leakage risk:** Memory annotation receives complete clips and is prompted to describe only earlier events. Timestamp-based conditioning alone does not demonstrate that annotations exclude future information (§6.3).
- **Serving correctness boundary:** Retained KV states are explicitly not equivalent to full context re-encoding. Appendix C.1 also says distribution-preserving stochastic correction is not assumed in every deployment, while Appendix F.3 reports temperature 0.9; applicability to reported rollouts is unclear.
- **Resource and reproducibility boundary:** Online RL uses 64 H200 GPUs for 32 game environments and requires an instrumented backend (§7.3). Scaling uncertainty excludes independent training-seed variation (Appendix B.3).
- **Incomplete source:** The supplied text is truncated, and many referenced tables contain captions without cells. Missing evidence cannot be assumed absent from the full paper.

## Open research questions
1. **Does memory improve uninterrupted completion?** Milestone success does not answer this. Compare full quests without scripted recovery under matched budgets, with and without summary memory.
2. **Which post-training components drive gains?** SFT and RL combine several changes. Ablate sparse reasoning, memory, and temporal weighting separately under matched training and serving conditions.
3. **Can broader data overcome distant-game saturation?** Existing scaling gains weaken on distant games. Hold total gameplay hours fixed while varying diversity, then evaluate genuinely unseen games.
4. **Are stochastic serving outputs distribution-consistent?** The verification caveat leaves this unresolved. Compare token distributions and task outcomes with proposal-aware correction enabled versus the reported serving path.

## Confidence and missing information
**Confidence: medium.** The supplied text supports the main method and reported stage-level gains, but coverage is incomplete.

Material missing information includes full comparison-table cells, exact valid evaluation counts, intervention details for extended autonomy, independent-seed variability, component ablations, the stochastic-verification configuration used for rollouts, and verified access to released assets.
