# Don&#x27;t Just Trust Your Memory: Evidence-Linked Memory Reduces Memory-Induced Degradation in LLM Agents

> [← Daily summary](../2026-11-11.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.14320) · [arXiv](https://arxiv.org/abs/2611.14320)


## One-sentence takeaway
WikiTrace links procedural lessons to their source executions, improving average benchmark performance and reducing failures on previously solvable tasks compared with providing the same lessons alone (§§4.2–4.3).

## Problem and motivation
External memory can introduce failures when agents follow incorrect lessons or misapply valid ones. Binary task outcomes do not establish which actions caused success or failure, yet condensed lessons typically omit the executions needed to check their validity. The authors address this gap through evidence access during task execution and separately measure memory’s **Gain** on previously failed tasks and **Regression** on previously solved tasks (§§1, 3.1–3.2).

## Approach and contributions
- **Evidence-linked memory:** A compiler independently converts each past execution into a diagnostic compilation and up to three actionable insights. Each insight links to its compilation and unchanged raw trajectory; memory remains fixed during evaluation (§3.3).
- **Evidence access during execution:** Agents initially receive all insights and pointers to similar runs. Prompts direct them to inspect source files when details are missing, insights conflict, a lesson comes from failure, or an action fails (§3.4).
- **Reliability evaluation:** The study separates Gain from Regression, includes repeated no-memory runs to measure ordinary outcome variability, and compares WikiTrace against identical insights without source evidence (§§4.1–4.3; Appendix C).

The central contribution is reassessing stored guidance against its source execution, rather than hierarchy or terminal-based access alone (§§2.1–2.3).

These results support the combined intervention of linked evidence and instructions for consulting it under the evaluated protocol. They do not isolate evidence availability from prompt changes. Descent analyses are observational: the agent chooses when to consult evidence, so stronger performance among descending runs does not establish descent’s independent causal effect (§5.1).

## Limitations and validity risks
- **Author-stated:** Source links do not verify lessons; compilations and insights can still misdiagnose executions. Injecting every insight scales prompt length with memory size, leaving retrieval at larger scales unresolved (Limitations).
- **Author-stated:** LLM judgments describe agents’ stated reasoning rather than proven causes. Effect labeling has only moderate agreement, and some descents receive no majority label (Limitations; Appendix E.1).
- **Analyst inference:** The Insights Only comparison combines evidence access with different instructions and source annotations; separate contributions remain unresolved (§4.1; Figures 27–28, 32–34).
- **Analyst inference:** Baseline conclusions apply to adapted offline versions. Freezing ReasoningBank and removing ExpeL retries and exemplar retrieval limits conclusions about their original operating modes (Appendix A.3).
- **Scope:** ScienceWorld uses selected task types, PlanCraft excludes unsolvable examples, and retail splits retain customer overlap. Generalization beyond these constructions remains untested (Appendix A.1).

## Open research questions
1. **Does evidence access help independently of the prompt?** The main comparison changes both. Run a factorial ablation crossing source availability with descent instructions.
2. **Can benefits survive much larger memories?** Full insight injection is an acknowledged constraint. Increase corpus size and compare retrieval strategies at fixed context and execution budgets.
3. **How robust is reassessment when evidence is misleading?** Source access does not guarantee correct interpretation. Introduce controlled lesson errors and measure correction accuracy alongside task Regression.
4. **Does the method help with continually changing memory?** Evaluation freezes memory. Test sequential tasks with memory updates and track Gain, Regression, and stale-evidence use over time.
