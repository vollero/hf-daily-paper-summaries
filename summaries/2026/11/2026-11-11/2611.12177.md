# Embodied First Exam

> [← Daily summary](../2026-11-11.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2611.12177) · [arXiv](https://arxiv.org/abs/2611.12177)


## One-sentence takeaway

Embodied First Exam benchmarks coding agents across diverse simulated robots and reports that its strongest agent falls from 77% success with privileged simulator access to 30% under sensor-based constraints on the same 391 hard tasks (§3.2).

## Problem and motivation

The authors ask whether general-purpose coding agents can reliably control diverse robots under physical-world constraints. They argue that existing robotics benchmarks emphasize fixed visuomotor policies, while software benchmarks omit partial observations, irreversible actions, and a world that continues moving during reasoning (§§1, 4).

## Approach and contributions

- **Agent-native evaluation infrastructure:** Containerized tasks let agents choose direct actions, write control programs, or train policies; an isolated verifier checks outcomes (§2.1).
- **Paired evaluation settings:** Standard provides sensor observations and generally disallows resets; Realtime also advances the simulation during reasoning; Privileged provides full simulator access and unlimited resets. Initial scenes, success rules, and task time limits are shared (§2.1).
- **Expanded benchmark:** 1,156 tasks across 35 suites and 47 robots, including 411 tasks in nine newly built suites covering precision manipulation, dynamic coordination, spatial goals, safety, and hidden-dynamics adaptation (§2.3; Tables 1–2).
- **Diagnostic analysis:** Eight agents are evaluated on a hard core set, with task graphs and agent-generated failure-stage labels for 427 tasks (§3).

The contribution is primarily evaluation infrastructure and evidence, rather than a new robot controller.

## Evidence and main results

All findings below are author-reported.

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Strongest agent remains limited in Standard | GPT-6 Astra in Codex solves 33.6% of 456 core Standard tests, rounded to 34% elsewhere. | §3.1, Fig. 7; §3.4 |
| Large paired access gap | On 391 tasks with both settings, Astra solves 303 Privileged tests (77%) and 116 Standard tests (30%). | §3.2, Fig. 10 |
| Resets help more than exact state | Controlled Astra runs on those 391 tasks: unmodified interface 28%; exact state 45%; unlimited resets with saved-state restoration 53%; both 68%; Privileged 77%. | §3.2, Fig. 11(a); Appendix E.1 |
| Precision failures benefit little from state alone | Among 91 baseline failures at precise stages, the state-query run solves 21%, resets solve 36%, and a run hiding the success signal solves 19%. The latter is only a rough repeat-attempt comparator. | §3.2, Fig. 11(c); Appendix E.1 |
| Realtime increases difficulty | On 54 paired tasks, Astra solves 23 Standard versus 17 Realtime tests; 63% of Realtime tests remain unsolved by every agent versus 50% of Standard tests. | §3.1 |
| Agents share failure bottlenecks | Mean Standard failure-stage concentration is 61%, versus 37% for a stage-position baseline and 48% for a stage-type baseline, on eligible multistage tests with located failures. | §3.3, Fig. 13; Appendix E.2 |
| Harness materially affects results | On 456 Standard tests, Astra solves 34% in Codex versus 22% in Claude Code under matched task limits and reasoning effort. | §3.4, Fig. 15(c); Appendix E.3 |
| Soccer policy training is promising but confounded | GPU/library version: three Standard wins in 12 attempts and one Realtime win in eight, all using trained policies; CPU version: no wins in 12 Standard or eight Realtime attempts. | §3.5, Fig. 17(b) |

The evidence establishes substantial performance differences under the benchmark’s access, timing, and harness configurations. It does not establish physical-robot reliability or isolate perception from control errors. The 30% paired leaderboard result and 28% controlled baseline come from different runs and should remain distinct. Privileged performance is an approximate aggregate reference, not a guaranteed upper bound for each task (§2.1; Appendix E.1).

## Limitations and validity risks

- **Author-stated uncertainty:** One attempt per agent–test pair limits conclusions about repeatability, rankings, and complementary capabilities; repeated evaluations are future work (§5).
- **Selection bias:** The core excludes manually judged easy tasks and tasks solved by GPT-6 Luna, potentially biasing selection against the related Astra model family (§2.3).
- **Label validity:** Agents generate stage and control-approach labels. The authors flag possible model-family bias and acknowledge that labels cannot distinguish perception from control errors (§3.4; Appendix E.1).
- **Restricted causal evidence:** State/reset interventions use one agent; the success-signal comparator changes another interface feature. Soccer versions change hardware, training tools, training environments, and instructions together (Appendix E.1; §3.5).
- **Simulation scope:** Benchmark results are simulated, Realtime evaluation covers dynamic tasks only, and suites retain differing physics and grasp aids. A physical buzz-wire demonstration is mentioned, but its details are outside the supplied excerpt (§§2.1, 5; Appendix C.3).
- **Analyst inference:** Frozen initial scenes and a selected hard core do not establish generalization to unseen scene distributions (§2.3; Appendix A).
- **Incomplete coverage:** The source is truncated, omitting substantial appendix material, including detailed labeling validation and further limitations.

## Open research questions

1. **Does the reset advantage generalize across agents?** The intervention uses only Astra (Appendix E.1). Repeat the state/reset factorial comparison across several agents with repeated attempts.
2. **What causes the remaining precision gap?** State plus resets still trails Privileged access, which also permits finer simulation stepping and planning primitives (Appendix E.1). Add those capabilities separately under matched budgets.
3. **Do observed agent differences persist across runs?** Single attempts confound capability differences with run variation (§3.4). Repeat paired tests and estimate uncertainty in rankings and solved-test overlap.
4. **Do simulation bottlenecks predict hardware failures?** Systematic physical evaluation remains future work (§5). Run matched simulated and physical tasks through the same interface and compare success and failure stages.
