# Control-Data Flow Separation: Stable Prompt Optimization in Multi-Agent LLMs

> [← Daily summary](../2026-09-02.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.00621) · [arXiv](https://arxiv.org/abs/2609.00621)


## One-sentence takeaway

The authors separate immutable, schema-validated execution controls from optimizable natural-language messages, achieving 100% eventual protocol validity and the best reported task score across four evaluated settings, though the guarantee covers protocol safety rather than output correctness.

## Problem and motivation

Multi-agent prompts often combine task instructions with code-facing protocols such as routing fields, output formats, and termination signals. Prompt optimizers can therefore improve substantive instructions while accidentally deleting or changing the interface expected by the controller, causing parse failures, invalid routes, or complete pipeline collapse rather than merely lower-quality answers (Sections 1 and 2.3).

The identified gap is that existing prompt-optimization frameworks do not generally preserve external parsing and routing contracts. The paper illustrates the practical consequence on MARG review generation, where naive TextGrad eventually produces no usable output because optimization removes or renames inline JSON instructions (Section 5.2 and Appendix G).

## Approach and contributions

- **Control–data flow separation:** Each agent emits a typed control object for routing and termination plus a free-form data message for task content. The controller reads only validated control, while prompt optimization targets the data-facing behavior (Sections 3.1–3.3).
- **Enforced execution interface:** Control schemas use Python dataclasses or Pydantic models, with closed choices represented by `Literal`. Frozen schema scaffolding, runtime validation, bounded retries, and controlled fallbacks prevent malformed control from reaching routing (Sections 3.2 and 3.4).
- **Formal protocol-stability result:** Lemma 1 proves the absence of unhandled parse, validation, and routing violations under three assumptions: typed routing, optimizer-inaccessible schema scaffolding, and bounded recovery or controlled failure. It does not prove semantic correctness (Appendix A).
- **Implementation and evaluation:** The authors release the `cdsep` Python package and evaluate it on BBH reasoning, MARG review generation, and two insurance-underwriting settings, including a three-family robustness study (Sections 4–5 and Appendix C).

The evidence supports the authors’ claim that separating and validating control prevents the observed class of prompt-induced protocol failures under the evaluated implementations and assumptions. It also shows competitive task performance, but does not isolate control–data separation as the sole cause of every quality gain: Table 2 indicates that per-example feedback is a major contributor, and “Ours” is therefore more than schema separation alone.

The results do not establish semantic correctness, real-world insurance or review quality, fairness, or universal robustness. The formal guarantee also allows failures to be surfaced outside the agent loop, so “no unhandled protocol violation in the trace” is narrower than guaranteeing successful completion for every input (Appendix A).

## Limitations and validity risks

- **Author-stated:** Protocol validity does not imply factual or semantic correctness; valid executions can still produce poor answers (Limitations; Appendix A).
- **Author-stated:** MARG uses an LLM judge and inherits its biases. Absolute results are not directly comparable with the original MARG publication because this paper substitutes `gpt-5.4-mini` for GPT-4 (Section 4.3, footnote 1; Limitations).
- **Author-stated:** Roles and schemas must be declared in advance; dynamic agent creation and runtime schema evolution are not evaluated (Limitations).
- **Author-stated:** Review generation and insurance rating are sensitive domains. The experiments do not establish real-world quality, reliability, or fairness, and the framework is not presented as an automated final decision-maker (Ethical Considerations).
- **Reproducibility constraint:** The partner-supplied underwriting cases and manual are not redistributed, so those results require separately authorized access (Appendix F.1).
- **Analyst inference:** The cross-family robustness evidence is preliminary because it uses only 12 papers, one seed, and reduced optimization steps (Section 5.3).
- **Analyst inference:** Comparisons mix different notions of stability. DSPy sometimes repairs outputs by snapping them to a valid bucket, while MARG DSPy removes dynamic routing and is checked through per-stage non-emptiness instead; these are not identical to `cdsep`’s routing validity (Section 4.2 and Tables 8–10).
- **Analyst inference:** The supplied split descriptions appear inconsistent: Table 5 lists five review test examples, whereas the scaled MARG results describe 14 test papers. The text does not fully reconcile which configuration Table 5 summarizes (Table 5; Appendix D.2–D.3).

## Open research questions

1. **Can the safety property support evolving agent graphs and schemas?** The current method assumes fixed roles and schemas. A next experiment could allow agents to propose new typed schemas that must pass compatibility checks before activation.

2. **Does separation remain effective in long-running, tool-rich systems?** Evaluation uses at most 12 review steps and 10 underwriting steps (Table 5). A next experiment could test longer workflows with external tools, nested calls, and adversarially malformed control outputs.

3. **How much task improvement comes from separation versus feedback design?** The ablation shows large gains from per-example feedback, but does not present a full factorial study across all four tasks. A next experiment could cross schema freezing, retry policy, and feedback granularity under equal call and token budgets.

4. **Does protocol stability improve human-rated usefulness and fairness in sensitive domains?** Current review evaluation relies on an LLM judge, and insurance evaluation uses synthetic cases. A next experiment could use blinded expert ratings and subgroup error analyses while keeping the execution protocol fixed.
