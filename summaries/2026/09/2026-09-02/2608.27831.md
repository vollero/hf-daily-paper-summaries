# RealSWE: A Compositional Evaluation of Coding Agents under Realistic User Requests

> [← Daily summary](../2026-09-02.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2608.27831) · [arXiv](https://arxiv.org/abs/2608.27831)


## One-sentence takeaway

RealSWE shows that replacing detailed SWE-bench descriptions with empirically matched, information-sparse user requests lowers seven coding models’ resolution rates by 6.4 percentage points on average, mainly because omitted desired behavior and motivation matter more than linguistic style.

## Problem and motivation

Coding agents are usually evaluated using long, structured GitHub issues, while real users often provide short, casual, underspecified requests. The authors argue that this communication mismatch can inflate benchmark scores and distort model rankings.

Existing realistic evaluations either use inaccessible production data or transform benchmark prompts without independently controlling information content and writing style. This makes it difficult to identify which aspects of communication cause performance changes (§1–§2).

## Approach and contributions

- **Empirical request characterization:** The authors annotate 718 filtered, user-authored first prompts from SWE-chat and 1,229 SWE-bench Verified/Pro statements using task-specific information fields and four linguistic dimensions (§3.1–§3.2).
- **Compositional benchmark:** RealSWE contains 381 task families—192 bug fixes and 189 feature requests—whose variants retain the same repository task and gold patch while varying information composition and style (§3.3–§3.5).
- **Two evaluation assets:** RealSWE-bench samples variants to match dominant SWE-chat information patterns; RealSWE-framework supports configurable compositions and controlled ablations (§3.5).
- **Controlled findings:** Experiments with seven models quantify the benchmark–reality gap, while four-model ablations isolate the effects of writing style and individual information fields (§4).

The matched-task design supports the authors’ claim that request composition itself affects measured agent performance rather than merely reflecting differences in task identity. It also provides comparatively strong evidence for the value of Desired Behavior in the tested bug-fix setting.

The evidence does not establish equivalent effects for frontier models, interactive agents, arbitrary coding workflows, or every possible field combination. Null results for reproduction steps and environment information are average effects along the tested configurations; they do not show that those fields are never useful for individual tasks.

## Limitations and validity risks

- **Author-stated—model coverage:** The study omits the strongest contemporary coding systems identified by the authors, so its conclusions may not generalize to frontier performance (§5).
- **Author-stated—single-turn setting:** Agents cannot ask clarifying questions, preventing evaluation of whether interaction recovers missing information (§5).
- **Selection constraint:** Only 381 of 1,229 source tasks survive the requirement that all relevant fields be available and the quality gate. The authors report no bias toward easier, smaller, or more concentrated tasks, but the benchmark still represents a restricted subset (Appendix A.4, Table 6).
- **Synthetic variants:** Realism targets come from genuine SWE-chat prompts, but the evaluated variants are produced by GPT-5.4 decomposition and rephrasing rather than being actual requests for those exact tasks (§3.2–§3.4).
- **Analyst inference—external validity:** The 718 prompts are filtered first turns from particular recorded coding tools and only “create new code” or “debug” intents; this may not represent all users, organizations, or software-engineering work (Appendix C).
- **Analyst inference—ablation coverage:** The principal field analysis uses cumulative removal and only four models. Additional-context checks are restricted to two DeepSeek models because of cost, leaving interactions among fields incompletely characterized (§4.3; Appendix E.1.2).
- **Analyst inference—scaffold dependence:** All models use mini-SWE-agent v2 with a Bash-only interface and a 100-step cap. Whether richer tools or different exploration policies change sensitivity to missing information is untested (§4.1).
- **Reproducibility uncertainty:** The supplied text says that prompts and exact model settings are reported, but it does not provide an asset URL, license, full numerical Tables 2–4, or the exact snapshots/settings from Table 16.

## Open research questions

1. **Can clarification recover the loss from sparse requests?** The evaluation is single-turn. A next experiment could allow agents to ask a limited number of questions and compare generic questioning with targeted requests for Desired Behavior or Motivation.

2. **Do frontier models infer omitted fields more reliably?** The evaluated set excludes the strongest systems named by the authors. Running the same matched task variants on those models would test whether the 6.4 pp gap shrinks with capability.

3. **How do field effects interact with task characteristics?** Reported effects are primarily averages. A factorial experiment stratified by repository, language, patch size, and bug category could identify when reproduction steps or environment details become valuable.

4. **Does agent design mediate prompt sensitivity?** Only one scaffold is tested. Holding models and tasks fixed while varying search tools, memory, repository indexing, and step budgets could determine whether stronger exploration compensates for underspecification.
