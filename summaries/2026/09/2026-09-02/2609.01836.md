# Agent Memory Is a Surface for Endogenous Authorization Laundering

> [← Daily summary](../2026-09-02.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.01836) · [arXiv](https://arxiv.org/abs/2609.01836)


## One-sentence takeaway

Persistent agent memory can manufacture apparent permissions that were never valid or are no longer valid, and calibrated executors follow this false authority almost invariably unless the memory itself is repaired.

## Problem and motivation

Long-running LLM agents compress evolving permissions, restrictions, and revocations into persistent memory. If that memory broadens a permission or forgets a revocation, a later request can appear authorized even though the underlying history denies it—a failure the authors call **endogenous authorization laundering**.

Unlike prompt injection or memory poisoning, this threat model contains no attacker: errors arise during ordinary memory maintenance. The identified evaluation gap is that prior work emphasizes recall, adversarial corruption, or overall task performance, while comparatively under-measuring whether memory preserves authorization state and whether memory errors subsequently cause unauthorized actions (Sections 1 and 3.1).

## Approach and contributions

- **Failure decomposition:** The authors distinguish false-authority **formation**—typed memory authorizes an action denied by the canonical state—from **propagation**, where an executor performs that action (Section 3.1, Equations 1–2).

- **EAL-BENCH:** An open-source benchmark built around evolving synthetic organizational histories, hidden deterministic authorization ledgers, and matched authorized–unauthorized requests in procurement, cybersecurity, and finance (Sections 3.2–3.3).

- **Controlled memory evaluation:** Five writer models produce free-text or typed memory through one-shot or incremental updates; two calibrated executor models act using only the resulting frozen memory. Exact-state repair and cross-executor replay isolate memory’s causal role (Sections 3.2–3.3).

- **Mitigation study:** The paper evaluates a deterministic cited-source authority gate and a bounded event-sourced architecture, measuring both unauthorized submission and authorized use (Section 4.4).

- **Secondary analyses:** It tests writer-side candidate scaling, operational pressure, capacity limits, and explicit evaluation framing (Sections 4.3–4.5; Appendices B.1, B.4–B.5, and D.2).

## Evidence and main results

Results pool three seeds, five writers, and two executors. | Section 4.1; Figure 2; Table 6 |
| Typed incremental memory frequently created false authority. | Formation \(P(F)\) was 28.3% in procurement, 10.4% in cybersecurity, and 50.2% in finance, closely matching unauthorized-submission rates of 28.9%, 10.4%, and 51.0%. | Section 4.2; Table 2 |

| Failures largely transferred across executors. | Replaying each frozen memory behind both calibrated executors yielded domain-level unauthorized-submission rates within 1.1 percentage points and per-replay agreement of 97.9%–99.5%. | Section 4.3; Appendix B.2, Table 13 |
| Both tested defenses reduced violations but sharply increased undergranting. | On the shared typed-incremental population, unauthorized submission fell from 25.3% to 7.3% with source gating and 9.0% with event sourcing; authorized use fell from 93.3% to 53.8% and 64.7%. Formation fell from about 25% to 5.5% and 8.7%. | Section 4.4; Figure 3; Tables 21, 24–25 |
| More writer candidates improved behavior, but selection lagged generation. | In procurement, increasing the pool from \(k=1\) to \(k=8\) reduced unauthorized submission from 13.2% to 8.6% and raised authorized use from 94.2% to 95.8%. At \(k=8\), 55.0% of pools contained an exact memory, but self-review selected one in 26.7% and independent review in 30.0%. | Section 4.5; Figure 4; Appendix B.1 |
| The explicit memory-capacity bound was not established as the main cause. | In a procurement typed-incremental ablation, raising the visible budget from 572 to 8,192 unenforced tokens changed unauthorized submission from 54/180 to 46/180; the paired difference was −4.4 points with a 95% interval of [−9.4, 0.0]. | Appendix B.4; Tables 17–19 |

The intervention evidence supports a causal claim within the benchmark: replacing only erroneous memory with oracle-exact state removed all observed unauthorized executions in the eligible trials. It also shows that typed structure makes errors inspectable but does not itself preserve authorization.

The evidence does **not** estimate real-world prevalence, establish a complete safety–utility frontier, show that every free-text failure originated in memory, or demonstrate that the mitigations generalize beyond the tested architectures, models, and synthetic domains.

## Limitations and validity risks

- **Author-stated:** Histories are synthetic, ordered, and clearer than real workplace communication; authorization uses closed-world deterministic ledgers and simulated tools (Section 4.6; Table 26).

- **Author-stated:** The benchmark omits retrieval and ranking, concurrent writers, memory access control, external tool side effects, human approval queues, partial completion, and recovery processes (Appendix C.3).

- **Author-stated:** Deterministic formation measurement applies only to typed memory; free-text memory would require validated semantic annotation (Section 4.6).

- **Author-stated:** The pressure and per-writer comparisons use one fixed seed, and the pressure-related authorized-use effect concentrates in one executor (Section 4.6; Appendix B.5).

- **Author-stated:** Three seeds provide descriptive replication rather than precise distributional estimates, and reported intervals are pointwise without multiplicity adjustment (Section 3.3).

- **Author-stated:** Source gating assumes known authorization-capable principals; event sourcing changes the whole architecture, and its component effects were not separately isolated (Section 4.6; Appendix C.2).

- **Analyst inference:** Because cases were LLM-assisted and manually refined to be challenging, observed rates should not be interpreted as rates under naturally sampled organizational histories; the authors explicitly disclaim real-world prevalence estimation.

- **Analyst inference:** Domain comparisons have limited construct validity because the domains differ in histories, authorization schemas, and model behavior—not merely industry context. The authors make the same caution in Section 4.6.

## Open research questions

1. **Do these failures persist in real organizational communication?** The benchmark uses synthetic, unusually explicit histories. A next experiment could replay de-identified, expert-annotated workplace authorization sequences with adjudicated ground truth.

2. **How can free-text memory formation be audited reliably?** Formation is deterministic only for typed memory here. A plausible next step is a preregistered human-annotation study comparing semantic formation labels with downstream exact-state repair.

3. **Can a mitigation reduce laundering without severe undergranting?** Both tested defenses trade substantial authorized use for safety. Future work could test lifecycle-aware validation that checks revocation, scope, and validity semantics in addition to source identity.

4. **How do retrieval and concurrency affect authorization integrity?** Executors receive complete bounded memory, with no concurrent writers or retrieval layer. A next experiment could introduce immutable source retrieval, competing updates, cache staleness, and memory ACLs while retaining the deterministic ledger.

## Confidence and missing information

**Confidence: high** for the benchmark design, reported outcomes, and stated limitations because the supplied text includes the complete main paper and detailed appendices.
