# ExecRetrieval: Measuring the Functional-Correctness Gap in Code-Embedding Retrieval

> [← Daily summary](../2026-09-03.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.01865) · [arXiv](https://arxiv.org/abs/2609.01865)


## One-sentence takeaway

On a controlled Python retrieval benchmark containing execution-failing near-clones, dense embeddings usually recover correct code within ten results but frequently rank a single-edit buggy variant first, with the best system achieving exec@10 of 1.000 but exec@1 of only 0.331.

## Problem and motivation

Code embeddings are commonly the first-stage retriever for coding agents and retrieval-augmented generation, so their ranking determines which candidates downstream execution, reranking, or agent processing can inspect. Existing benchmarks do not systematically place execution-verified buggy near-clones beside each query’s canonical implementation, leaving functional discrimination confounded with topical relevance or canonical identity.

The authors address this measurement gap by testing whether retrievers rank passing implementations above nearly identical, single-edit implementations that fail the same task’s tests. Reported magnitudes are conditional on such near-clones being present; the paper does not estimate their prevalence in deployed corpora (Introduction; Limitations).

## Approach and contributions

1. **Controlled benchmark:** EXECRETRIEVAL contains 939 natural-language-to-Python tasks across ten algorithmic domains, 939 canonical implementations, and 3,755 paired buggy distractors in a 4,694-snippet shared corpus. Each task has 7–10 tests; every canonical passes all its tests and every distractor fails at least one (Sections 3.1–3.3; Table 1).

2. **Mutation and validation pipeline:** The distractors are produced through targeted edits spanning six main mutation types. A five-gate process checks schema, AST properties, canonical execution, distractor execution, and corpus integrity using isolated Python subprocesses (Sections 3.2–3.3; Table 2).

3. **Functionally grounded evaluation:** The authors define execution-based retrieval metrics—exec@k and execution_precision@k—and also report canonical-ID nDCG at \(k\in\{1,3,5,10\}\) (Section 4.1).

4. **Broad retriever comparison:** They evaluate 23 dense configurations from hosted and open-weight model families plus BM25, using provider-specific query/document conditioning and similarity conventions (Section 4.3; Table 6).

5. **Paired statistical analysis and release:** Results use query-level bootstrap intervals and exact McNemar tests. The released bundle reportedly includes data, execution outcomes, frozen embeddings, evaluation and generation code, manifests, and pairwise results (Sections 4.2–4.4; Appendix D).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Strong top-\(k\) recall coexists with weak rank-1 accuracy. | Gemini Embedding 2 obtains exec@1 = 0.331, 95% bootstrap CI [0.299, 0.362], but exec@5 = 0.997 and exec@10 = 1.000 over 939 queries. | Section 5.1; Figures 2–3; Table 7 |
| The top two systems are indistinguishable at rank 1. | Gemini 2 versus Gemini 001: exec@1 difference +0.002, 95% CI [−0.038, +0.042], exact McNemar \(p=0.958\). | Sections 5.1 and 5.6; Table 5 |
| Rank-1 failures overwhelmingly select the query’s paired mutant. | Among misses, paired distractors account for 624/628 (99.4%) for Gemini 2, 618/630 (98.1%) for Gemini 001, 667/729 (91.5%) for Mistral, and 718/738 (97.3%) for Qwen3-8B. | Section 5.2; Table 3 |
| A single near-clone causes a large rank-1 drop. | Holding the rest of the corpus fixed, Gemini 2 falls from expected exec@1 = 0.993 with zero paired distractors to 0.678 with one; its full-pool score is 0.331. | Section 5.3; Table 4 |
| A buggy variant often scores above the canonical. | Across 938 eligible queries, the canonical loses to at least one paired mechanical distractor in 66.8% of queries for Gemini 2 and 78.4% for Qwen3-8B; both have mean and median canonical-minus-best-distractor gaps of −0.002. | Section 5.4; Figure 4 |
| Deception spans all six main mutation types. | Across 86,135 query–distractor–model triples from 23 dense configurations, overall deception is 44.3%; type-specific rates range from 39.3% for removed edge-case checks to 48.0% for wrong comparisons. | Section 5.5; Figure 5 |
| BM25 is substantially weaker than dense retrieval in this setting. | BM25 obtains exec@1 = 0.058 and exec@10 = 0.422; the lowest-ranked dense model obtains exec@10 = 0.671. | Section 5.1; Table 7 |
| Larger Qwen3 configurations do not show a significant rank-1 advantage here. | Qwen3-8B versus 4B-BF16 has exec@1 difference +0.010 and \(p=0.622\); 4B-BF16 versus 4B-FP16 has +0.009 and \(p=0.456\). | Section 5.6; Table 5 |
| Stacking more verified mutations did not materially improve detectability for the tested subset. | On 371 matched queries and four local embedders, deception is 49.0% with one mutation and 47.6% with four; the four-versus-one change is −1.4 points, 95% CI [−3.7, +0.9]. | Appendix G.2; Table 9 |

The evidence establishes a functional-ranking weakness under a deliberately controlled, closed-world condition: one or more execution-failing near-clones are planted in the candidate pool. It also shows that much of the correct-code candidate recall is recovered by \(k=5\) or \(k=10\).

It does not establish how frequently these candidate configurations occur in real repositories, whether retrieved code is correct beyond the generated tests, or whether full coding agents and rerankers would fail after downstream verification. It also does not support direct comparison with open-domain code-search scores.

## Limitations and validity risks

- **Author-stated:** All tasks, implementations, and tests are Python; cross-language generalization is unknown (Limitations).
- **Author-stated:** Distractors are mainly controlled, LLM-produced mechanical mutations rather than naturally occurring human bugs. Generated tests define correctness and may cover behavior beyond the natural-language query (Limitations).
- **Author-stated:** The corpus is closed-world and contains no open-domain code. Results are conditional on planted near-clones and are not comparable with open-domain retrieval measurements (Limitations).
- **Author-stated:** Tasks are self-contained functions rather than repository-scale programs with cross-file context (Limitations).
- **Author-stated:** Only first-stage embedding retrieval is evaluated; cross-encoder and LLM reranking remain untested (Section 6; Limitations).
- **Author-stated:** Hosted APIs may drift. Frozen matrices preserve the reported scoring computation but cannot guarantee reproduction of future live embedding calls (Limitations).
- **Author-stated:** The subprocess runner has a timeout and process isolation but does not restrict filesystem or network access, so it is unsuitable for arbitrary untrusted code (Limitations).
- **Analyst inference:** Because task selection, implementations, distractors, and tests are substantially machine-generated, shared generation artifacts may influence observed difficulty despite the registry separation and execution checks.
- **Analyst inference:** Passing 7–10 generated tests is a bounded oracle rather than proof of semantic correctness; the supplied text reports integrity checks but no independent human semantic audit of all tasks.
- **Analyst inference:** The edit-size robustness result covers all dense configurations, but the stacked-mutation experiment covers only four local embedders and a non-random 371-query matched subset, limiting generalization (Appendix G).

## Open research questions

1. **Can rerankers close the rank-1 gap?** The paper evaluates only embedding-first retrieval. A next experiment could apply cross-encoder and LLM rerankers to the frozen top-10 candidates and measure paired changes in exec@1 and execution precision.

2. **Does near-clone deception generalize across programming languages?** The benchmark is Python-only. Rebuilding matched JavaScript, Rust, or Go versions with language-specific execution oracles would permit controlled cross-language comparisons.

3. **Do naturally occurring bugs produce the same ranking behavior?** Mechanical mutations provide attribution but cover a restricted bug distribution. A follow-up could collect real pre-fix/post-fix pairs, execute them against strengthened tests, and compare their deception rates with matched synthetic mutants.

4. **How common are harmful near-clones in deployed retrieval pools?** The benchmark conditions on their presence but does not measure prevalence. An execution-backed study over repository histories or agent caches could estimate near-clone frequency and combine it with conditional failure rates.
