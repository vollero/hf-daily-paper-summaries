# CERA-MoA: Co-Evolving Routing Mechanisms with Continually Learning LLM Agents

> [← Daily summary](../2026-09-17.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.18779) · [arXiv](https://arxiv.org/abs/2609.18779)


## One-sentence takeaway

CERA-MoA jointly updates an LLM-agent router and the routed agents, using hidden-state familiarity scores to specialize agents and select a variable-size subset that improves average benchmark performance while reducing generation cost relative to fixed multi-agent routing.

## Problem and motivation

Existing Mixture-of-Agents systems usually optimize either routing among fixed agents or agent policies inside a fixed workflow. The authors argue that this separation creates two problems: routers cannot track capabilities that change during post-training, and manually partitioned or uniformly allocated training data does not encourage complementary specialization (Sections 1–2).

CERA-MoA addresses this gap by placing routing and reinforcement learning in a feedback loop: current competence determines which agents receive each training query, and observed agent rewards update the router’s competence estimates.

## Approach and contributions

1. **Co-evolutionary training:** A sample-level router allocates queries to selected agents, which independently train with a combined DAPO–GSPO reinforcement-learning objective. Their relative rewards then supervise the router (Sections 3.1, 3.4; Algorithm 1).

2. **Predictive familiarity estimator:** For each agent, a trainable head and a frozen, orthogonally initialized target head project fixed features from the router backbone’s middle layers. Their normalized distance is converted into a familiarity score; positive relative advantage pulls the projections together, while negative advantage pushes them apart up to a margin (Sections 3.2, 3.4).

3. **Adaptive routing:** Agents are ranked using familiarity plus exploration bonuses during training. The router activates the smallest ranked subset whose cumulative raw familiarity reaches a threshold; inference removes the exploration terms (Section 3.3).

4. **Resource-aware deployment:** The method supports either four LoRA agents sharing one backbone or a heterogeneous pool of three base models. Deterministic answers use familiarity-weighted voting, while open-ended tasks return the most familiar agent’s response (Sections 3.1, 3.4; Appendix A.2).

These results support the authors’ claim that co-evolution, exploration, middle-layer features, and adaptive subset sizing are useful within the tested configurations. Figures 3 and 5–7 further show differentiated routing and training patterns, which are consistent with emergent specialization.

The evidence does not establish statistical significance, robustness across random seeds, scaling to larger agent populations, or superiority outside the listed models and benchmarks. The specialization evidence is observational and does not by itself prove that specialization causes the performance gains.

## Limitations and validity risks

**Author-stated limitations**

- Routing uses the initial prompt, making the current system suited to single-turn interactions or fixed trajectories rather than changing multi-turn workflows (Appendix F).
- Open-ended aggregation returns only the most familiar agent’s response, leaving potentially useful outputs from other activated agents unused (Appendix F).

**Analyst inferences**

- Results appear to use one reported random seed, **42**, and no confidence intervals or repeated-run variance are supplied; the stability of small differences between methods is therefore unclear (Table 5; Tables 1–3).
- Evaluation is limited to three small base-model families, populations of three or four agents, and tasks with programmable reward functions. Generalization to larger models, more agents, subjective generation, or learned judges is untested (Section 4.1; Appendix C).
- Baseline parity is only partly assessable from the supplied text. Identical generation settings and reward functions are claimed, but complete baseline tuning budgets and computational costs are not reported (Section 4.1).
- The average-token comparison measures generated tokens, while full end-to-end cost also depends on router computation, parallel execution, and hardware utilization. Table 6 profiles routing separately but does not provide complete system latency for every routing alternative.
- No public implementation or checkpoint release is established in the supplied text, although algorithms, dependencies, hardware, datasets, prompts, and hyperparameters are documented.

## Open research questions

1. **Can familiarity be updated reliably during multi-turn work?** The current estimator reads the initial prompt. A next experiment could reroute after every interaction using the updated context and compare quality, latency, and routing stability against single-shot routing.

2. **Does specialization cause the gains?** Routing plots show differentiated agent behavior, but causal attribution remains incomplete. One experiment could swap specialized adapters between routed domains or enforce uniform training allocation while holding total updates constant.

3. **How does the method scale with agent-pool size and model capacity?** Only three- and four-agent pools are tested. A controlled sweep over pool size, model scale, and routing threshold could measure accuracy, starvation, memory, and wall-clock cost.

4. **Can open-ended aggregation exploit multiple selected agents?** Current open-ended inference selects one response. Comparing this rule with verifier-based reranking, learned synthesis, or a meta-aggregator would test whether multi-agent generation adds value beyond routing alone.

## Confidence and missing information

**Confidence: high** for the paper’s stated method, experimental settings, and reported table values; **medium** for causal interpretations of specialization.

Material missing information includes repeated-seed results, uncertainty or significance tests, complete per-baseline training and compute budgets, end-to-end latency comparisons, behavior with larger agent pools and models, and evidence of publicly released code, checkpoints, or processed datasets.
