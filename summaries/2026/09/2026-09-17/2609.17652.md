# Fathom: Per-Query Read Depth for Sparse Decoding over Offloaded KV Caches

> [← Daily summary](../2026-09-17.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.17652) · [arXiv](https://arxiv.org/abs/2609.17652)


## One-sentence takeaway

Fathom reduces host-to-GPU traffic for sparse long-context decoding by storing keys as bit planes and allocating each query’s read budget across channels, yielding faster GPU decode time when the scan index is host-resident while preserving or improving selection fidelity at fewer bits.

## Problem and motivation

In sparse decoding, selecting the top-\(k\) KV rows still requires scanning an approximate representation of every key. When long contexts and many sessions push KV caches and scan indices into host memory, this linear scan can dominate PCIe traffic even though only a small set of winning rows is fetched.

Existing per-token scans use a fixed precision for every selected channel. The author argues this wastes bandwidth because channels differ in their importance to each query, and additional bits on one channel may be less valuable than initial bits on another (Introduction, pp. 1–2).

## Approach and contributions

- **Bit-plane key store:** Keys are uniformly quantized to four bits and stored channel-major by bit plane. Reading the first \(t\) planes produces that channel’s exact \(t\)-bit mid-rise quantizer without maintaining separate lower-precision copies (§3.2).

- **Per-query depth allocation:** For each group of query heads sharing a KV head, Fathom estimates channel importance as query energy weighted by calibrated key variance. Reverse water-filling assigns each channel between zero and four planes under a bit budget (§3.3, Eq. 3–4).

- **Basis selection rule:** It uses raw channels for the tested QK-normalized Qwen3 models and a calibration-derived KLT basis for the tested models without QK normalization (§3.5; Table 11).

- **Optional layer-specific budgets:** A calibrated greedy plan can vary budgets by layer, although the paper recommends a flat budget by default because layer plans do not transfer reliably across models or context lengths (§3.4; Table 10).

- **Systems implementation and evaluation:** A gather kernel moves the selected contiguous plane runs from pinned host memory to GPU memory (§3.6). The study covers timing, attention-output error, synthetic long-range tasks, and next-step agreement on recorded coding-agent sessions (§4–§5).

The evidence supports the author’s central systems claim for an A100 configuration where both KV rows and scan indices reside in host memory. It also shows consistent reductions in attention-output error per scanned bit across the seven headline settings.

It does not establish end-to-end coding-task success, performance on other accelerator or interconnect configurations, or a speed advantage for GPU-resident indices. The million-token timing uses synthetic KV contents, while real-prefill timing stops at 128k (§4, §8).

## Limitations and validity risks

**Author-stated limitations**

- End-to-end agent task completion and test execution were not evaluated; agent quality was measured only by agreement with exact top-\(k\) next-step decoding (§5.6, §8).
- Only 40 of 100 planned agent sessions were run at \(k=512\), with 20 at \(k=2048\) (§5.6, §8).
- Timing beyond 128k used synthetic KV contents, and primary timing used batch 1 with only one batch-2 check (§4, §8).
- Fidelity used one held-out Wikitext window per setting, limiting evidence about variance across text samples (§4, §8).
- The method is not faster when the scan index is in HBM; its benefit depends on slower-tier traffic dominating (§7–§8).
- The separate bit-plane index costs 68 bytes per token per KV head, exceeding Double Sparsity’s 17-byte and landmark indexing’s 32-byte storage. Reusing it as the actual four-bit K cache was not implemented or measured (§7).
- Layer-specific budgets may fail when transferred across models or context lengths; flat budgets are recommended (§3.4, Table 10).
- The landmark baseline was evaluated outside the original systems’ intended index placement and budget settings, while CPU retrieval methods were omitted (§8).
- The prototype harness has method-dependent Python overhead, including an unexplained wall-clock gap; the paper therefore emphasizes GPU time (§6 A6).
- SparQ’s group-shared top-\(k\) and mean-value reallocation were not evaluated (§8).

**Analyst inferences**

- The basis rule is supported by the tested Qwen and Llama variants, but the text does not establish that QK normalization alone predicts the best basis for other model families.
- RULER parity provides weak discrimination among per-token scans because the reported sampling error exceeds their score differences (§5.5, §7).
- The claim that many concurrent sessions create the target regime is based primarily on memory-size arguments; concurrent-session throughput was not directly measured (§8).
- Hardware generality remains uncertain: the arithmetic analysis discusses other GPU classes, but measured end-to-end results come from one A100 pod, with Llama activations captured separately on an L4 (§4, §7).

## Open research questions

1. **Does lower scan error improve completed agent tasks?**  
   This remains open because the paper measures next-step agreement rather than repository-level success. A next experiment could run the same SWE-rebench issues end to end under Fathom, exact top-\(k\), SparQ, and dense attention, reporting task success, tokens, and latency.

2. **Can the bit-plane store serve efficiently as both index and operational K cache?**  
   The paper charges it as a separate 68-byte index and notes that reconstructing individual winner rows from a channel-major layout may be costly. A fused implementation could measure reconstruction overhead, memory savings, and full decode latency when no bf16 key copy is retained.

3. **How does Fathom scale with real concurrent sessions?**  
   The motivating many-session regime is not directly benchmarked. A useful experiment would vary batch size and resident sessions under fixed GPU and host-memory limits, measuring throughput, tail latency, and interconnect utilization.

4. **Can query-dependent depth work with non-uniform or vector KV quantizers?**  
   Exact bit-prefix semantics currently rely on uniform scalar codes (§3.2). Experiments could test learned marginal-gain models for FP8 or lookup-table quantizers, and stage allocation for residual vector quantization.

## Confidence and missing information

**Confidence: high.** The supplied text includes the full method, evaluation protocol, numerical tables, ablations, and stated limitations.

Material missing information includes:

- end-to-end agent task success;
- measured multi-session serving throughput;
- real-prefill timing beyond 128k;
- results on accelerators other than the main A100 setup;
- evaluation on additional model families and domains;
- measured integration with a serving stack that uses the bit-plane store as its actual quantized K cache;
- variability across multiple held-out fidelity windows;
- the planned but unrun remainder of the coding-agent evaluation.
