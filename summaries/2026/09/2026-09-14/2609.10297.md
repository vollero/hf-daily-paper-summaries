# TRACE: Trajectory-robust Admission with Evidence Ordering for Efficient GUI Agents

> [← Daily summary](../2026-09-14.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.10297) · [arXiv](https://arxiv.org/abs/2609.10297)


## One-sentence takeaway
TRACE combines layout-guided visual token selection with reusable screenshot state to improve GUI-agent accuracy at matched pruning budgets, while its largest measured latency saving comes from cache reuse (§4; Tables 1, 23).

## Problem and motivation
GUI agents repeatedly process screenshots from earlier interaction steps, increasing latency and memory use. Once a screenshot enters reusable state, discarded visual tokens cannot serve later instructions without re-encoding. The authors identify two requirements that ordinary relevance-based pruning can miss: preserving evidence for unknown future targets and maintaining spatial coverage under tight budgets (§§1, 3.1).

## Approach and contributions
- **Lifecycle formulation:** Admission happens before the first language-model prefill; historical tokens must be a subset of the admitted native tokens. This makes future pruning a contraction of an existing order (§3.1).
- **Layout-guided evidence ordering:** LIP converts OmniParser detections into soft interaction weights. NEO combines these weights with instruction relevance and feature novelty to construct a nested token order (§§3.2–3.3).
- **Coverage repair:** NCR reserves native tokens for spatial coverage, using stride sampling for current frames and regional medoids for history. Both subsets are committed at admission (Algorithms 1–2).
- **Reusable serving:** MKC truncates the cache at the retiring frame, reuses selected visual embeddings, and recomputes downstream states against the contracted context. It avoids historical image re-encoding but still performs replay prefill (§3.5; Appendix A.2).

The distinctive contribution is the integration of selection, coverage, and serving under this lifecycle. The appendix acknowledges that some existing selectors already satisfy the nesting constraints; nesting alone is not unique to TRACE (Table 8).

## Evidence and main results
Here, `r` is single-frame retention; `c/h` are current/history retention. Results below are author-reported; accuracy and Step SR are percentages.

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Stronger aggregate performance under pruning | GUI-Owl-1.5-8B retains **78.7% / 61.1%** of dense performance on the six-benchmark normalized average, versus VisionTrim’s **72.4% / 49.2%**. Mild: `r=10%, c/h=50%/10%`; tight: `r=5%, c/h=25%/5%`. | Table 1 |
| Tight-budget grounding improves, with substantial dense-model loss remaining | GUI-Owl-1.5-8B, SS-v2, `r=5%`: TRACE **55.19%**, PruneSID **34.20%**, dense **93.79%** accuracy. | Table 1 |
| Gains persist with a shared serving path | GUI-Owl-1.5-8B, Mind2Web, `c/h=25%/5%`: TRACE **34.20%** versus MKC-ported VisPruner **30.66%** Step SR. | Table 24 |
| Coverage repair adds task-level value | GUI-Owl-1.5-8B: adding NCR to LIP+NEO raises SS-v2 accuracy **56.45%→73.90%** at `r=10%`, and Mind2Web Step SR **27.79%→34.20%** at `c/h=25%/5%`. | Table 2 |
| Cache reuse supplies most of the TTFT reduction | Separate OmniGUI timing round, GUI-Owl-1.5-8B: dense **1116.8 ms**, MKC alone **487.4 ms**, full TRACE **452.7 ms** at `c/h=50%/10%`. Full TRACE reduces visual KV by **58.1%**; MKC alone leaves it unchanged. | Table 23 |
| End-to-end savings are smaller than TTFT savings | OmniGUI, GUI-Owl-1.5-8B, mild budget: dense→TRACE TTFT **1102.6→453.9 ms**, end-to-end latency **2958.2→2295.8 ms**, visual KV **697→292 MB**, Step SR **52.45%→48.91%**. | Table 22 |
| Transfer is useful but uneven | UI-TARS-1.5-7B: tight Mind2Web Step SR **17.92%** versus DivPrune **13.00%** at `c/h=25%/5%`; MMBench-GUI L2 accuracy at `r=10%` is **14.41%** versus DivPrune **15.83%**. | Tables 25, 27 |

These results support an accuracy–efficiency trade-off and show selector gains beyond cache reuse alone. They do not establish dense-equivalent accuracy, universal superiority across backbones, or improved complete-task success: the multi-step metric scores individual actions. Tables 22 and 23 use separate timing rounds and should not be mixed.

## Limitations and validity risks
- **Authors—short horizons:** Evaluated trajectories do not systematically test evidence retrieval after long temporal gaps; the authors leave this to future work (§C.1).
- **Authors—coverage is insufficient:** A retained token can overlap a target without preserving enough detail for localization. Thin, low-contrast widgets remain difficult (§C.1; Figure 25). Coverage recall also measures detector proposals, not all true interface elements (Appendix B.3).
- **Authors—context equivalence:** Replay preserves original visual features and aligns downstream states with contracted context; it does not reproduce dense computation at pruned budgets (Appendix A.2).
- **Analyst—comparison and tuning scope:** Only TRACE uses an external detector in the main tables. Shared-prior comparisons partly address this on SS-v2, while configuration choices vary by benchmark and budget; the supplied text does not clearly identify an independent tuning split (Appendices A.4, B.3).
- **Analyst—reporting inconsistencies:** The OmniGUI history-repair comparison is **43.08% versus 41.68%** Step SR in Table 7 but **24.04% versus 23.20%** in Appendix A.2 without a clear setting change. Figure 16’s small-model rankings also disagree with Table 1 on Mind2Web and AndroidControl. These discrepancies limit confidence in secondary summaries.
- **Coverage limitation:** The supplied source is truncated, with material omitted from the middle; this analysis does not cover the complete paper.

## Open research questions
- **Does committed evidence remain useful over long delays?** Short trajectories leave this unresolved (§C.1). Test tasks that require returning to evidence many screens later, measuring full-task success and later-target retention.
- **Can finer visual detail recover remaining failures?** Target overlap often survives while localization fails (§C.1). Compare higher-resolution encoding or targeted crops against additional retained tokens at matched total latency.
- **How well does one configuration transfer to unseen interfaces?** The paper uses benchmark-specific settings and documents dose sensitivity (Appendix A.4). Freeze settings on separate development data and evaluate unseen applications with systematic detector errors.

## Confidence and missing information
**Confidence: medium.** The supplied text supports the core method and principal results, but truncation and internal discrepancies limit precision.

Material information unavailable or unclear includes the omitted appendix content, exact timing hardware and workload configuration, independent configuration-selection splits, numerical uncertainty for the main comparisons, long-horizon complete-task outcomes, and an available code release.
