# SceneMosaic: Efficient and Diverse Simulation-Ready Scene Generation via Hybrid Agentic Layout Evolution

> [← Daily summary](../2026-09-09.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.05594) · [arXiv](https://arxiv.org/abs/2609.05594)


## One-sentence takeaway
SceneMosaic combines image-based reconstruction with local agentic layout refinement and combinatorial variant assembly, reporting competitive semantic quality and a 24× speedup on SceneEval-100, although the supplied text omits the numerical result tables.

## Problem and motivation
Generating dense, diverse indoor environments could support embodied AI training and interactive entertainment. The authors identify two gaps: iterative agentic scene generators are expensive, while faster image-to-3D models produce inaccurate or physically invalid placements; both also struggle to generate coherent rearrangements from one input (§1).

## Approach and contributions
- **Hybrid initialization and refinement:** Agents register and verify object masks using SAM3; SAM3D reconstructs meshes and initial poses. Relation reasoning organizes objects into support/containment hierarchies before physical stabilization and refinement (§§3.2–3.3).
- **Local agentic evolution:** Each anchor and its immediate children form a local unit. Critic–Actor agents refine alternative layouts through orthographic translations and rotations, using simulation feedback, symbolic pose expressions, memory, and cross-unit constraints (§§3.3, 7–8).
- **Combinatorial diversity:** Anchor-relative transforms combine local variants into complete scenes. Global collision filtering precedes greedy selection using position, distance, and orientation differences (§§3.4, 9).

The proposed contribution is this integrated generation and selection framework; SAM3 and SAM3D are reused components.

## Limitations and validity risks
- **Author-stated:** Single-image initialization restricts generation to room scale; multi-room houses and buildings are unsupported (§11).
- **Analyst inference—comparison scope:** Text methods receive prompts, while image methods receive GPT-Image-2 outputs. This tests complete generation pipelines, with potentially different conditioning information (§§4.1, 6).
- **Analyst inference—runtime comparability:** Most runs use one L40S, but SAGE uses five H200 GPUs for local VLM deployment. API resources and concurrency costs are not quantified (§§4.1, 6).
- **Analyst inference—physical guarantees:** Collision counting excludes thin objects, and stabilization uses anchor-dependent artificial gravity. These checks do not establish unrestricted physical realism despite stronger “eliminates” wording in the conclusion (§§5–6).
- **Analyst inference—evaluation breadth:** Diversity comparisons cover internal variants rather than external methods; human evaluation samples only three scenes per method. Separate effects of physics stabilization versus simulation tools, and memory versus other agent mechanisms, are not isolated (§§4.4–4.5, 10).

## Open research questions
1. **Can independent local evolution preserve complex global functionality?** Constraints intentionally cover only strong, unambiguous relations (§8). Test scenes with densely coupled cross-unit requirements and measure global relation violations after assembly.
2. **How does composition scale as scene complexity grows?** The Cartesian candidate pool is exponential, but scaling measurements are unavailable (§3.4). Vary unit and variant counts while measuring memory, assembly time, rejection rate, and retained diversity.
3. **Do generated variants improve embodied learning?** This motivates the work but is not evaluated (§1). Train otherwise identical agents on base-only versus diversified scenes and compare held-out task performance.

## Confidence and missing information
**Confidence: medium.** The method is described in substantial detail, but empirical strength is difficult to assess.

Material omissions include all numerical bodies of Tables 1–5, the underlying agent VLM identity, simulator identity and key thresholds, exact timing boundaries and API costs, uncertainty estimates for benchmark results, and downstream embodied-task evaluation. Code availability is asserted by the authors but was not independently verified.
