# PReCache: Efficient KV Cache Sharing for Multi-LoRA Agents via Low-Rank Precomputation and Neutral Reconstruction

> [← Daily summary](../2026-09-29.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.34054) · [arXiv](https://arxiv.org/abs/2609.34054)


## One-sentence takeaway
PReCache precomputes role-specific low-rank caches to avoid repeated context processing, while optional adapter-free reconstruction improves accuracy preservation at an additional computation cost (§§3–4).

## Problem and motivation
Agents sharing a backbone but using different LoRA adapters repeatedly process the same growing trajectory and retain separate KV caches. Direct cache reuse saves computation but introduces adapter mismatch, potentially weakening role-specific behavior (§§1–2).

The authors identify a gap in BaseShared: its base/low-rank cache decomposition saves memory, but each agent still runs the backbone over shared context to construct its own low-rank cache. Other approaches require retraining, architectural restrictions, or selective recomputation that trades accuracy against savings (§2.2).

## Approach and contributions
- **PreLRShared:** When a context segment is first processed, apply every agent’s LoRA down-projection to the active agent’s hidden states. Subsequent agents reuse the shared base cache and their precomputed low-rank caches, avoiding repeated backbone processing. These caches remain approximations because their hidden states came from another agent (§3.1).
- **ReBaseShared:** Run an adapter-free path to construct a neutral base cache and other agents’ low-rank caches, reducing dependence on the previous agent’s adapted representation (§3.2).
- **Reconstruction schedules:** Lazy prefill (LP) reconstructs after each turn; double batching (DB) schedules adapted and neutral paths together. The authors describe logically equivalent cache states, with LP suited to single-stream inference and DB to concurrent serving (§3.2).
- **Conditional error analysis:** The paper derives when neutral reconstruction has lower base-cache error and measures supporting geometry. This establishes a conditional cache-error result, rather than a universal accuracy guarantee (Appendix A).

“Training-free” describes the sharing framework; the evaluated role adapters themselves were trained (§4.1).

## Evidence and main results

The following are author-reported results; the supplied text contains table captions but omits table cells.

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| ReBaseShared best preserves accuracy overall among evaluated sharing methods | Average **1.1 percentage-point drop** versus NonShared across two backbones × HotpotQA/ScienceQA; comparable to BaseShared | §4.2, Table 2 |
| PreLRShared substantially improves single-stream efficiency | Up to **3.1× TTFT speedup** and **2.3× per-request throughput** versus NonShared; controlled three-agent traces, both backbones, A6000 | §4.3, Fig. 3; Appendix C.1 |
| Reconstruction retains efficiency but reduces throughput gains | ReBaseShared LP: up to **3.0× TTFT speedup**, **1.6× throughput** versus NonShared in the same single-stream setup; reconstruction included in completion time, excluded from invocation TTFT | §4.3, Fig. 3; Appendices B.1, C.1 |
| Concurrent serving improves per-request throughput | Under unsaturated load, PreLRShared **1.6×**, ReBaseShared DB **1.3×** versus NonShared; fixed **17.3k-token** trace, vLLM, A100 | §4.3, Fig. 4; Appendix C.2 |
| Memory remains close to full sharing | At **66.4k tokens**, both designs within **2%** of FullShared peak GPU memory and **17–23% lower** than selective recomputation; LLaMA-3.1-8B | §4.3, Fig. 6; Appendix C.4 |
| Neutral reconstruction reduces cache error on average | Mean token-wise previous-cache/neutral-cache error ratio exceeds one at every measured layer for both backbones on HotpotQA agent transitions | Appendix A.2, Fig. 7 |
| Accuracy variation is reported as small | Standard deviations below **0.60 percentage points** across **20 complete runs** for all evaluated methods | Appendix B.2, Table 4 |

The evidence supports an accuracy–efficiency trade-off in the evaluated workflows. It does not establish exact cache equivalence to NonShared, universal preservation of role behavior, or real-world task completion speedups equal to the controlled-trace maxima. Per-request throughput is trajectory tokens divided by accumulated latency; concurrent results should not be read as aggregate server throughput.

## Limitations and validity risks
- **Author-stated scope:** Main accuracy evaluation uses HotpotQA and ScienceQA because role-specific training trajectories are available; neutral-cache analysis focuses on the base component (Appendix A.2).
- **Analyst inference—generalization:** Two backbones and one principal role structure provide limited evidence for other agent workflows, adapter distributions, or decoding-heavy tasks (§4.1; Appendix C.1).
- **Analyst inference—comparison scope:** Selective recomputation baselines use a fixed 30% ratio, so comparisons do not establish dominance over every accuracy–efficiency operating point (§4.1).
- **Analyst inference—measurement interpretation:** LP reconstruction occurs between invocations and is excluded from TTFT, although included in completion latency. TTFT gains therefore capture only part of the user-visible delay (Appendices B.1, C.1).
- **Analyst inference—serving validity:** Concurrent tests replay fixed schedules with random token IDs, isolating computation but leaving realistic workload diversity unresolved (Appendix C.2).
- **Analyst inference—theory:** Neutral reconstruction helps only under the derived geometric condition; favorable averages do not guarantee improvement for every token or transition (Appendix A).

## Open research questions
- **When does neutral reconstruction fail?** The theory is conditional and measurements are averaged. Next experiment: measure per-token violations and accuracy across adapters with differing role similarity and training distributions.
- **How does serving performance transfer to realistic workloads?** Concurrent tests use controlled random-token traces. Next experiment: replay natural requests with variable generation lengths, tool delays, and arrival patterns, measuring completion latency and aggregate throughput.
- **What happens with broader adapter placement?** QKVO is evaluated for efficiency, but this paper’s supplied text does not report corresponding accuracy results. Next experiment: jointly measure accuracy, cache error, latency, and memory across QV and QKVO settings.
