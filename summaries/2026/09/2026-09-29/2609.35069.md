# RenderRank: Learning to Rerank Text with Compressed Visual Tokens

> [← Daily summary](../2026-09-29.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.35069) · [arXiv](https://arxiv.org/abs/2609.35069)


## One-sentence takeaway
RenderRank learns to rerank rendered text documents with fewer language-backbone input tokens, achieving competitive ranking quality and faster GPU scoring when document visual embeddings are precomputed (Tables 2, 4, 6).

## Problem and motivation
Rerankers score every retrieved query–document pair, so long document inputs multiply computation across candidates; truncation can remove relevance evidence. The authors identify a gap between visual text compression for generation and learning query-dependent relevance from compressed document images (§1–2).

## Approach and contributions
- **Visual document reranking:** Render documents as ordered images and score their visual tokens alongside a textual query. The default uses Roboto Regular, 12pt, single line spacing, and images up to 896 × 896 pixels (§3.1).
- **Two-stage relevance training:** First match a text teacher’s relevance scores using MSE; then discriminate positives from negatives within each query’s candidate set using InfoNCE. The vision encoder stays frozen; decoder LoRA adapters are trained and merged between stages (§3.2, §4, Appendix C).
- **Efficiency characterization:** Evaluate ranking quality, token counts, estimated computation, throughput, fixed token budgets, and rendering density. The contribution is adapting existing visual representations to reranking, rather than introducing a new visual encoder (Appendix A; §5–6).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Competitive BEIR quality with shorter inputs | Across 11 datasets, reranking BM25 top-100: average NDCG@10 **55.96**, versus **55.82** for bge-v2-gemma and **57.99** for Qwen3-4B; **290.07** input tokens per pair, reported **16.5–35.5%** fewer than evaluated text baselines. | Table 2; §5.1 |
| Faster cached BEIR scoring than several baselines | Average **76.83 PPS**, versus **35.51** for bge-v2-gemma; not fastest overall: mxbai-v1 reaches **129.42 PPS**. Best measured batch size per model/dataset on one A6000; GPU forward time only. | §5.2.2; Table 11 |
| Long-document throughput advantage | Across four datasets with eight candidates per query: average NDCG@10 **88.27**, versus **88.26** for zerank-2; **4.51 PPS**, versus fastest baseline Qwen3-0.6B at **2.66 PPS**, reported **1.70×**. | §4; Table 4 |
| Strong results under equal token limits | MLDR NDCG@10 at 2K/4K/8K: RenderRank **97.9/99.5/99.7**, versus Qwen3-4B **96.9/98.0/99.6**; RenderRank leads every compared model at each limit. | Table 5 |
| Training and caching both matter | BEIR image-input NDCG@10 rises **50.20 → 54.86 → 55.96** across initialization, Stage 1, and Stage 2. Throughput falls from **76.83** to **37.31 PPS** when visual encoding is included. | Table 6 |
| Matched text input retains higher quality | After both training stages, the same backbone scores **57.21** average BEIR NDCG@10 with text inputs versus **55.96** with images. | Table 15 |
| Rendering controls the trade-off | Across BEIR, 10pt versus 14pt yields NDCG@10 **55.04/56.43**, average tokens **236.47/370.69**, and throughput **94.46/63.10 PPS**. | Tables 12–14 |

These results support compressed visual inputs as a useful quality–efficiency trade-off in the tested settings. They do not establish universal ranking superiority or end-to-end serving speedups. The matched text-input result also shows a quality cost that comparisons against separately trained baselines can obscure.

## Limitations and validity risks
- **Author-reported conditions:** Main efficiency results assume offline visual encoding; throughput excludes preprocessing and cache I/O. Results come from one training run per configuration (Table 3; §5.2.2; Appendix C).
- **Analyst inference—uncertain small gains:** No confidence intervals or significance tests are supplied, so the small long-document average advantage over zerank-2 is not established as robust.
- **Analyst inference—incomplete causal isolation:** Ablations omit Stage 2 without Stage 1, and no throughput comparison accompanies the final model’s matched text-input evaluation (Tables 6, 15).
- **Analyst inference—limited transfer evidence:** English training and the reported document benchmarks do not establish multilingual performance or downstream RAG answer quality. Training includes several benchmark source families, including MLDR training data; test contamination is not established (§4; Table 9).
- **Representation boundary:** Whitespace normalization removes paragraph boundaries and manual line breaks; sensitivity to this loss is not evaluated (Appendix C).

## Open research questions
- **When does caching pay off?** Offline encoding and cache I/O costs are missing. Measure total latency, storage, and amortized cost across document reuse and update rates.
- **How much efficiency comes from modality alone?** Matched text inputs rank better, but their throughput is unreported. Benchmark the final backbone with text and image inputs under identical serving conditions.
- **Is distillation necessary before discrimination?** Stage 2 alone is absent. Train that ablation with matched data and compute budgets.
- **Does the rendering recipe transfer?** Multilingual and layout-sensitive evaluations are absent. Test additional scripts and compare preserved paragraphs with whitespace-normalized rendering.

## Confidence and missing information
**Confidence: high** in the reported method and descriptive results; **medium** in broader efficiency and generalization conclusions.

Missing material information includes uncertainty estimates, end-to-end latency and cache costs, matched text-input throughput, Stage-2-only results, multilingual evaluation, and an explicit RenderRank code or checkpoint release.
