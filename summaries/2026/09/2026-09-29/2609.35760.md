# TokenCast: Forecasting Token Consumption During LLM Agent Execution

> [← Daily summary](../2026-09-29.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.35760) · [arXiv](https://arxiv.org/abs/2609.35760)


## One-sentence takeaway
TokenCast combines learned segment-cost forecasts with execution evidence to improve online token-consumption prediction, with the authors reporting a 14.5% average MAE reduction across 96 settings but weaker results before execution begins (§4.2.1).

## Problem and motivation
Agent token costs depend on uncertain future actions and repeated processing of accumulated context. Predicting response length alone misses this coupling between future call count and input size. The authors identify a gap in forecasting remaining provider-accounted input and output tokens during open-ended, sequential agent execution without additional LLM estimation calls (§§1–3.1).

## Approach and contributions
- **Composable cost representation:** Each segment records call count \(n\), net input-length change \(g\), and residual consumption \(b=C-nL\). Adjacent segments compose through a cross-term \(n_Bg_A\), accounting for earlier context being reread by later calls. The identity is exact for observed segments under the stated boundary condition; predicted segment values remain uncertain (§3.2; Appendix B.3).
- **Staged forecasting:** LightGBM models predict direct remaining cost and prefix–suffix representations, including the predicted boundary state. Cross-fitting supplies realistic predicted boundaries during suffix training; cost weighting and an out-of-fold correction model combine the forecasts (§3.3).
- **Online updates and uncertainty:** Separate predictors cover Task Start, Call Start, In-call Update, and Task Update. Execution features refresh forecasts without extra LLM calls; held-out calibration widens quantile prediction intervals (§§3.1–3.3; Appendix B.4).

## Evidence and main results
| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Gains concentrate after observations accumulate | Across four benchmarks, six models, and four prediction points, mean MAE reduction versus each setting’s strongest comparator is 14.5%; point-specific averages are −2.2%, 1.9%, 30.4%, and 27.8%, respectively. TokenCast loses in 24 of 96 settings, all at Task Start or Call Start. | §4.2.1; Tables 7–10 |
| Concrete online improvement | SWE-bench Verified/GPT-5.4: In-call Update MAE falls from EGTP’s 74.6 to 38.9 tokens; Task Update falls from TRAIL’s 115,000 to 80,000 tokens. | Table 1; §4.2.1 |
| Calibration remains imperfect | Repeated anchor executions: nominal 90% Task Start intervals cover 82.0% for TokenCast versus 52.7% for native Self-Prediction intervals; online TokenCast coverage ranges from 89.8% to 92.8%. | Table 3 |
| New domains require adaptation | LiveClawBench leave-one-domain-out MAE ratios versus Self-Prediction are 1.31/1.47 at Call Start/Task Update without adaptation, improving to 0.82/0.85 with 20 target-domain tasks. | Appendix D.4.1 |
| Components improve the tested pipeline | SWE-bench Verified/GPT-5.4: removing both cross-fitting and cost weighting raises history-median-normalized average MAE from 0.69 to 0.78. | Table 19 |
| Forecasting overhead is small in the measured setting | SWE-bench Verified/GPT-5.4: initial plus every-call task forecasts average 19.7 predictions and 32.8 ± 30.5 ms per run, including feature extraction and inference. | Table 15 |
| Offline stopping saves tokens | On 288 GPT-5.4 SWE-bench Verified runs, TokenCast averages 21.3% savings across seven budgets while matching fixed-budget trace completion at each budget. | §4.3; Appendix D.7; Table 20 |

These results support useful forecasting within the sampled execution settings, particularly after generation or calls provide evidence. They do not establish universal superiority at task initiation, nominal interval coverage everywhere, or improved task correctness. Replay completion means reaching a recorded terminal state, including unsuccessful termination, rather than resolving the task (§4.3).

## Limitations and validity risks
- **Author-stated:** Forecast-driven runtime execution management remains future work; budget control is evaluated through offline replay (§5).
- **Observed transfer limitation:** Zero-shot new-domain prediction underperforms Self-Prediction; target-domain examples materially improve it (Appendix D.4.1).
- **Analyst inference—scope:** Main traces disable compaction, pruning, browsing, and subagents. Performance with these features or concurrent execution is not established (Appendix C.1).
- **Analyst inference—comparison:** API-model internal-state baselines use a truncated proxy encoder, while Self-Prediction intervals receive no held-out calibration. Comparisons therefore reflect these adaptations and calibration differences (Appendix C.3).
- **Author-acknowledged ablation ambiguity:** Removing composition also changes call-level predictions; segment ablations do not isolate the composition cross-term (Appendix D.6).
- **Analyst inference—statistical uncertainty:** Main MAEs average three split seeds, but the supplied main-result tables provide no uncertainty estimates or significance tests (Appendix C.2; Tables 7–10).

## Open research questions
- **Does forecast-driven control preserve task success?** Replay measures terminal-state completion. Next experiment: deploy the controller prospectively and measure correctness, tokens, and budget violations.
- **How robust is TokenCast to context management?** Main traces disable compaction and pruning. Next experiment: compare matched runs with these mechanisms enabled, measuring forecast error around context changes.
- **Can zero-shot transfer improve?** Held-out domains require adaptation to outperform Self-Prediction. Next experiment: vary source-domain diversity and target-task count using the same task-disjoint protocol.

## Confidence and missing information
**Confidence: high** in the method description and reported results; **medium** in broader deployment implications.

Material gaps include complete training hyperparameters, the precise operational prefix-segment boundary rule, main-result uncertainty estimates, confirmation of released traces or trained models, and prospective budget-control results measuring task success.
