# EmbodiedMemory-Bench: Benchmarking Embodied Memory for Long-Horizon Embodied Tasks

> [← Daily summary](../2026-09-29.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.28236) · [arXiv](https://arxiv.org/abs/2609.28236)


## One-sentence takeaway
EMem-Bench tests four forms of embodied memory in 2,554 simulated episodes, and its structured EMem system improves GPT-5.4-mini’s equally weighted task-family success rate from 35.3% to 58.9%, although physical-robot performance remains untested (Table 2; Appendix E).

## Problem and motivation
Embodied agents must remember visual details, revise changing object states, retain constraints revealed by failed actions, and transfer lessons from prior corrections. The authors argue that existing benchmarks do not jointly test these capabilities through subsequent environment interaction (Sections 1–3; Table 1).

Their motivating audit attributes 91% of 100 failed Gemini-3-Flash and Qwen3-VL-32B trajectories on EmbodiedBench’s EB-ALF and EB-Hab to these four memory-related categories. This describes the inspected failures, rather than estimating their prevalence across all tasks or models (Figure 2).

## Approach and contributions
- **Memory-focused benchmark:** EMem-Bench supplies an offline observation–action–feedback history, then requires interactive completion of a later task. Its four families are Passive Observation, Dynamic Tracking, Interaction Failure, and Experience Generalization. Construction combines simulator-grounded cues, PDDL-planned distractors, automated checks, and manual screening (Sections 3.1–3.4).
- **Structured external memory:** EMem combines a scene-scoped spatial graph that replaces conflicting state, temporal event records and correction-derived rules, and selected visual scene snapshots. A policy writes records without seeing the future task, retrieves relevant evidence, and acts through a validated execution loop (Section 4; Appendix B).
- **Trained memory policy and evaluation:** EMem-8B fine-tunes Qwen3-VL-8B with LoRA on teacher-generated memory-writing, retrieval, and action turns. The paper compares model and memory-system baselines, ablates the three stores, and tests dependence on historical evidence (Sections 5; Appendices B.5 and D).

The interventions support the claim that historical evidence matters for the tested models and episodes. The ablations support complementary roles for the three stores. These results do not establish that structured memory alone explains every gain: EMem also changes historical visual access and action orchestration. The image-expansion experiment tests one model and selection procedure, so the authors’ broader claim that raw context enlargement cannot solve the benchmark exceeds that experiment’s demonstrated scope.

## Limitations and validity risks
- **Author-stated:** Simulation omits deployment conditions such as sensor noise, actuation error, open-world changes, and ambiguous human feedback. Physical-robot memory performance is therefore unestablished (Appendix E).
- **Analyst inference—comparison confounds:** Full-context baselines receive textual history and current RGB, while EMem writes from historical RGB and can retrieve images. Baselines emit one primitive action per call; EMem emits ordered action sequences. Matched backbones therefore do not isolate memory representation from input access and controller differences (Appendices B.2–B.3 and C.1).
- **Analyst inference—restricted persistence:** Memory resets each episode, and execution has an eight-action budget. The benchmark tests long-history dependence rather than persistent memory across ongoing deployment (Appendices B and C.1).
- **Metric boundary:** Canonical ERR is a binary indicator of any qualifying recurrence per episode. Invalid or simulator-failed actions do not independently trigger it; low ERR can coexist with low SR. It is not a comprehensive memory-error measure (Appendix C.2).
- **Coverage and uncertainty:** Interaction Failure has only five receptacle types, and Robotics-ER 1.5 uses a 10% subset. Main leaderboard and ablation results lack reported confidence intervals or repeated-run variability (Table 11; Table 2).
- **Text inconsistencies:** Table 12’s rounded Qwen cue-removal entries imply 11.2 points, whereas the prose reports 11.1. Table 5 implies a 0.3-point HallusionBench decrease, whereas the prose reports 0.4. Exact underlying values are unavailable.

## Open research questions
- **How much improvement comes from memory structure itself?** Input access and execution interfaces differ. Compare EMem with baselines sharing identical historical frames, action orchestration, prompts, and compute budgets.
- **Can EMem maintain reliable memory across episodes?** All stores currently reset. Test persistent multi-task deployments with recurring objects, conflicting corrections, and changing household rules.
- **Does the approach survive physical uncertainty?** Simulation leaves this unresolved. Run paired simulator and real-robot tasks with controlled perception noise, failed grasps, and ambiguous feedback.
- **Can selective visual context outperform maximum-frame expansion?** Only the latter is tested. Compare uniform sampling, task-conditioned frame retrieval, and EMem under matched token and latency budgets.

## Confidence and missing information
**Confidence: high** in the reported benchmark design and within-setting results; lower in their attribution exclusively to memory structure and their deployment generality.

Material missing information includes the training teacher’s identity, detailed semantic-retrieval implementation, full baseline adaptation settings, matched end-to-end EMem ingestion/retrieval costs, main-result uncertainty estimates, verified artifact availability, and physical-robot results.
