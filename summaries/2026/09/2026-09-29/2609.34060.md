# KVCMAS: Efficient KV cache Correction for Shared Context in Multi-Agent Systems

> [← Daily summary](../2026-09-29.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.34060) · [arXiv](https://arxiv.org/abs/2609.34060)


## One-sentence takeaway
KVCMAS combines low-rank online cache corrections with workflow-relative cache reuse, reporting comparable benchmark accuracy to prior sharing methods and a 2.0× median TTFT speedup over no sharing at 32K shared tokens and 8 QPS (§§3–4.3).

## Problem and motivation
Agents sharing model weights still generate different KV caches for identical context because their role-specific prefixes differ. Repeated prefilling wastes computation and memory, while direct cache reuse can degrade accuracy (§§1–2).

The authors identify three gaps: selective recomputation retains model execution costs; preconstructed corrections poorly accommodate changing context; and online correction with full-dimensional anchors consumes substantial memory. Existing context-free correction references also require extra prefill and can introduce first-agent errors into downstream interactions (§2.2).

## Approach and contributions
- **Compact online correction:** Store anchor base caches and transition deltas as truncated-SVD factors; estimate corrections through similarity-weighted interpolation. Active attention caches remain full-dimensional (§§3.1, 3.3).
- **Workflow-relative chaining:** Densely prefill the first agent, then correct each shared segment relative to the preceding agent’s materialized cache. This removes separate reference prefill and preserves an exact first-agent cache (§3.2).
- **Integration for changing context:** Apply an entropy-based reliability gate independently at each transition, fall back to dense prefill when matching is unreliable, and update anchors using densely computed target caches. The gate follows KVComm; the claimed contribution is its combination with compact states and chaining (§3.3; Appendix A.3).

## Limitations and validity risks
- **Author-described boundaries:** Larger reliability thresholds increase reuse while lowering accuracy. One Video-MME transition consistently requires dense prefill. When anchors cannot cover a complete segment, the uncovered suffix retains the aligned source cache without correction (Appendices A.3, B.3).
- **Analyst inference—scope:** Results cover three model families and five benchmarks; heterogeneous model weights and production traffic are not established. Agent/round scaling keeps a large initial context dominant (Appendices C.4–C.5).
- **Analyst inference—measurement:** Factorization occurs after the first token, so its cost is excluded from that hop’s TTFT but included in end-to-end latency and throughput. TTFT alone therefore cannot establish total execution savings (Appendix B.1).
- **Analyst inference—comparison:** GraphFlow’s graph scheduling components are excluded, and default anchor capacities differ between KVCMAS and KVComm. The matched-capacity memory ablation addresses the latter, but uses an estimated KVComm requirement (Appendices B.1, C.3).

## Open research questions
- **How reliable is entropy gating under distribution shift?** Thresholds are selected per workload, leaving cross-workload calibration unresolved. Freeze thresholds and test unseen task distributions, measuring accepted-correction error, accuracy, and fallback frequency.
- **How much does chaining help beyond exact first-agent prefill?** The reported ablation changes both together. Compare exact versus approximate first-agent caches crossed with chained versus context-free references.
- **What happens when anchor coverage lags growing context?** Uncovered suffixes receive direct reuse, but their accuracy effect is not separately reported. Compare this policy with dense suffix prefill under rapidly increasing segment lengths.

## Confidence and missing information
**Confidence: medium.** The method and evaluation settings are described clearly, but all numerical table bodies and plotted values are absent from the supplied text. Material gaps include absolute benchmark scores, evaluated sample counts, complete latency/memory results, statistical significance, detailed trace arrival and warm-up conditions, and confirmation of released code or artifacts.
