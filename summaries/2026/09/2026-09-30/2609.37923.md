# EpiCon: Collective Agent Learning through Co-Evolving Multimodal Memory

> [← Daily summary](../2026-09-30.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.37923) · [arXiv](https://arxiv.org/abs/2609.37923)


## One-sentence takeaway
EpiCon combines trained memory controllers with a shared multimodal experience tree, improving single-attempt benchmark scores across agent configurations while leaving host model parameters fixed (Table 1; §5.3).

## Problem and motivation
Agent executions produce useful procedures, failures, and visual evidence, but transferring that experience across agent systems remains difficult. The authors identify a gap between refining text and image evidence within a question and consolidating those lessons for reuse across questions, harnesses, and backbones (§1). Their motivation is collective learning through external memory rather than host-model retraining.

## Approach and contributions
- **Shared experience bank:** A memory harness maintains lessons independently of the host system. Different systems retrieve from and contribute to this bank; evaluation uses frozen banks and one solving attempt (§4.1).
- **Joint text–visual refinement:** A Memory Controller revises guidance and supporting image regions across attempts, with an adaptive gate controlling whether stored visual evidence enters the solver input (§4.2).
- **Hierarchical consolidation and retrieval:** A Tree Self-Organizer places, merges, splits, and consolidates lessons into qualified rules, then selects relevant experience from text-encoder-recalled candidates (§4.3).
- **Compact trained memory models:** Two independently fine-tuned Qwen3.5-2B models implement these roles. Controller supervision is replay-screened; organizer supervision passes structural checks (§3; Appendices A–B).

The proposed contribution is the integration of these mechanisms and demonstrated experience transfer; the supplied evidence does not independently establish priority over all previous memory systems.

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Compact EpiCon improves historical-memory reuse | Authors report **+1.7–4.9 score points** over No Memory in eleven-benchmark macro-average across four harness/backbone configurations; every method uses one attempt. | Table 1; §5.2 |
| Compact memory trades some performance for speed | Versus backbone-sized EpiCon, trained 2B models reduce memory-operation time **67–74%** and total time **25–35%**, with macro-average scores **0.9–3.6 points lower** across the four configurations. | Table 1; §5.2 |
| Frozen experience transfers across systems | A Codex/Qwen3.8-27B bank yields macro-average gains of **3.2 points** for Codex/Gemma4-31B and **4.2 points** for DeepSeek-Harness/Qwen3.8-27B versus No Memory, with one attempt. | Table 2; §5.3 |
| Another harness’s contributions improve aggregate scores | After a second disjoint construction set, original versus evolved banks score **53.5→55.7** for Codex and **53.4→56.6** for DeepSeek-Harness, on the same 4,388 evaluation questions. Authors report gains of **2.1 and 3.2 points**, respectively. | Table 3; §5.3 |
| Co-evolution helps under adaptive injection | Evolving versus frozen visual memory improves seven of eight benchmark scores and ties one across two Qwen3.8-27B hosts; all memory settings allow up to five attempts without a historical bank. | Table 5; §5.4 |
| Tree organization outperforms flat storage | With matched source questions, host, attempt budget, and context budget, tree memory improves all four reported scores; ParseBench rises **52.2→67.3**. | Table 6; §5.4 |
| Gains extend to the additional API solver | Codex/GPT-5.6-Luna improves on all four tested benchmarks with fixed 2B components and a frozen bank; MATH-Vision rises **51.2→57.2**, using one attempt in both conditions. | Table 7; §5.5 |

These results support experience reuse across the tested systems without additional solving attempts. They do not establish universal improvement: individual benchmarks sometimes decline. Controller-versus-No-Memory comparisons in Table 4 also include extra attempts, so they cannot isolate memory from retry benefits.

The abstract’s **2.6-point** cross-harness claim differs from the detailed directional results. The displayed Codex averages also imply a 2.2-point difference, whereas §5.3 reports 2.1; unrounded values are unavailable.

## Limitations and validity risks
- **Authors’ explicit qualifications:** Tree-operation supervision is structurally validated without individual downstream replay; controller replay validates source-task transitions rather than future-task guarantees (Appendix A).
- **Negative transfer:** Cross-harness evolution lowers Codex ParseBench from 63.4 to 58.9 and DeepSeek-Harness MATH-Vision from 56.6 to 53.4 (Table 3).
- **Analyst inference—expansion confound:** Table 3 measures additional data plus bank evolution. Without an equally expanded same-harness control, it does not isolate the benefit of contributor diversity.
- **Analyst inference—bundled mechanisms:** Flat-versus-tree evaluation changes both organization and consolidation; their separate effects remain unresolved (§5.4).
- **Analyst inference—comparison and uncertainty:** Trained 2B EpiCon is compared with external systems using zero-shot backbone memory models. No repeated-run uncertainty or significance estimates are supplied.
- **Scope:** Banks are built from the same benchmark families as evaluation, using disjoint project-defined splits; this is not evidence of unrestricted transfer to unrelated applications (Appendix C).

## Open research questions
- **Does contributor diversity help beyond adding experience?** Table 3 combines both. Compare equal-sized expansions produced by the original harness, another harness, and mixed contributors.
- **How can harmful transferred lessons be filtered?** Some evolved-bank scores decline. Test contributor-quality weighting or conflict filtering on the affected benchmarks.
- **Which tree mechanism drives gains?** Table 6 bundles hierarchy and consolidation. Compare flat, hierarchy-only, consolidation-only, and full-tree banks under matched retrieval budgets.
- **How much does memory help at equal solving cost?** Controller comparisons permit more attempts than No Memory. Add retry-only and equal-time controls.

## Confidence and missing information
**Confidence: medium.** Protocols and result tables support the central reuse claim, but causal attribution and statistical reliability remain limited.

Material missing information includes repeated-run variability, explicit benchmark metric definitions, absolute runtime and hardware allocation, bank sizes and growth behavior, detailed retrieval and rule-eligibility settings, and verified contents of the announced resource release.
