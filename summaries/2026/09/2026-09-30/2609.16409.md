# Reasoning with Image Generation

> [← Daily summary](../2026-09-30.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.16409) · [arXiv](https://arxiv.org/abs/2609.16409)


## One-sentence takeaway
REIMAGIN uses generated images as intermediate reasoning aids, improving most evaluated visual tasks over text-only and specialist-tool baselines, while remaining limited by generation fidelity, strategy choice, and added inference cost.

## Problem and motivation
Textual reasoning can struggle with problems requiring visual transformations, such as reconstructing occluded patterns or combining room views. The authors argue that specialist tools offer only predefined operations, while handcrafted tool-use examples require effort for each task. They investigate whether one instruction-following image generator can supply flexible visual intermediates and whether useful strategies can be discovered automatically (§1).

## Approach and contributions
- **Generative visual reasoning:** A training-free ReAct-style agent interleaves textual reasoning, Python actions, and `generate_image` calls. Generated images enter its context for subsequent reasoning; deterministic utilities such as cropping and subtraction remain available (§§3–3.1).
- **Evaluation and a new task:** The same generator supports six visual tasks, including a newly introduced dashed-line path-tracing task. Transformations include depth maps, pattern completion, trajectory overlays, and unified room views (§4; Appendix B).
- **Automatic strategy discovery:** A proposal model optimizes agent prompts using labeled training trajectories and development scores, while keeping the reasoning model and generator fixed. This removes human-authored task-specific strategies, but retains substantial shared optimization guidance (§3.2; Appendix L).
- **Image-level test-time scaling:** For multi-view spatial reasoning, the tool samples candidate images and an MLLM selects one before downstream reasoning (§3.1; Figure 3).

## Evidence and main results

Values below are reported means ± standard errors across three seeds unless otherwise stated (§4). Accuracy is higher-is-better; counting sMAPE is lower-is-better.

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Large path-tracing improvement | GPT-5 with Nano-Banana-Pro: **73.5 ± 0.4% accuracy**, versus **48.5 ± 1.2%** No Tools and **41.7 ± 1.7%** Sketchpad, on 100 synthetic instances. | Table 1; Appendix B |
| Better occlusion counting | GPT-5: **7.4 ± 0.1 sMAPE**, versus **12.5 ± 0.6** No Tools and **11.7 ± 0.4** Sketchpad, on 100 sampled CAPTURe instances. | Table 1; Appendix B |
| Improvements are not universal | Gemini depth accuracy: REIMAGIN **94.6 ± 1.5%**, No Tools **91.7 ± 0.3%**, Sketchpad **99.2 ± 0.0%**. Qwen likewise trails Sketchpad on depth. | Table 1 |
| Generated transformations add value within the same scaffold | Gemini path-tracing accuracy falls from **89.0 ± 1.6%** to **77.5 ± 2.5%** when generation returns the unchanged input; all six task scores worsen. | Appendix I, Table 7 |
| Image selection helps handcrafted spatial reasoning | With 10 candidates, MMSI accuracy rises from **51.0% to 59.0%** for Gemini and **42.0% to 54.3%** for Qwen. Baselines receive majority voting over 20 answers as a comparable compute budget. | §4; Figure 3 |
| Automatic strategies recover useful gains | Gemini/Nano-Banana-Pro tracing accuracy: automatic **87.3 ± 0.9%**, no strategy **72.8 ± 0.3%**, handcrafted **89.0 ± 1.6%**. Automatic strategies improve all five reported Gemini tasks over no strategy. | Table 3 |
| Open generators have task-dependent strengths | With Gemini, FLUX.2 puzzle accuracy is **53.8 ± 2.2%**, versus Nano-Banana-Pro’s **42.3 ± 2.2%**; its depth accuracy is **89.1 ± 0.4%**, below No Tools’ **91.7 ± 0.3%**. | Table 2 |
| Faithfulness correlates with answer correctness | Manual audit of 120 generated images: **75%** faithful; answer correctness **87%** with faithful images versus **43%** with unfaithful images. MMSI audit uses selected outputs. | Appendix J |
| Gains incur additional cost | Across task instances with Gemini/Nano-Banana-Pro, REIMAGIN averages **$0.16 per instance and 76 s median latency**, versus Sketchpad’s **$0.04 and 52 s**. | Appendix G, Table 5 |

The evidence supports generated visual intermediates as useful within these benchmark settings, including a controlled no-op ablation. It does not establish superiority on every task, generator, or strategy. The faithfulness audit is explicitly correlational; it does not independently prove that faithful generation causes the entire accuracy difference.

## Limitations and validity risks
- **Author-stated:** Generators can distort layouts or draw incorrect trajectories; MLLMs can still misread correct visualizations. Discovered strategies sometimes add unreliable operations or fail to recover effective multistep policies (§5; Appendices K, M).
- **Author-stated:** Strategy transfer is uneven. Gemini-discovered prompts improve some Qwen tasks but worsen counting relative to its no-strategy setting (§5.2; Table 4).
- **Analyst inference—limited evaluation:** MIRA contains only 26 test instances; other task evaluations use small subsets or a synthetic tracing set. These results provide limited evidence about broader deployment performance (Appendix B).
- **Analyst inference—comparison boundaries:** Baselines differ in prompts and scaffolds. The no-op ablation addresses this, but on MMSI it also removes the opportunity for image selection, so that comparison includes the associated scaling benefit (Appendix I).
- **Analyst inference—automatic discovery scope:** Discovery uses labeled examples and detailed human-written meta-guidance, including worked-example and tool-use requirements. Its automation claim concerns task-specific strategy discovery, not an unguided search (Appendix L).
- **Reporting inconsistencies:** Appendix H’s prose uses a spatial No Tools value that differs from Table 6. Appendix N also contains a subtraction call inconsistent with its documented signature. These leave implementation and reporting details needing clarification.
- **Audit uncertainty:** Annotator count, agreement, and per-task faithfulness rates are not supplied (Appendix J).

## Open research questions
- **Can verification reduce incorrect visual intermediates efficiently?** Generation failures remain prominent. Compare single generation, candidate selection, and source-image consistency verification at matched total cost (Appendices J–K).
- **Can strategy search reliably discover multistep policies?** The reported search does not recover the handcrafted spatial workflow. Test larger search budgets and explicit multistep proposals on held-out MMSI instances (§5.2).
- **When do strategies transfer between model pairings?** Transfer gains vary by task. Run a controlled transfer matrix that changes the reasoning model and generator separately (Tables 3–4).
- **Do gains generalize beyond the evaluated subsets?** Small samples and synthetic tracing leave this unresolved. Evaluate larger held-out sets and tracing variants with different densities, layouts, and line styles (Appendix B).

## Confidence and missing information
**Confidence: medium.** The supplied text includes methods, numerical comparisons, ablations, costs, and failure analysis, but small evaluations and reporting inconsistencies limit broader conclusions.

Material missing information includes exact sampled instance identifiers and split separation for strategy discovery, full executable implementation and release details, audit agreement statistics, significance tests, and a detailed total-compute matching procedure for spatial baselines.
