# VideoLoop: Looped Working Memory Against Semantic Thrashing in Long-Form Video Agents

> [← Daily summary](../2026-09-30.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.38119) · [arXiv](https://arxiv.org/abs/2609.38119)


## One-sentence takeaway
VideoLoop combines filesystem retrieval with an inner memory-rewriting loop, improving Gemini 3 Flash’s VideoMME-long accuracy from 81.9% to 85.8% over an append-only agent with 0.5% more total tokens per question (Tables 2–3).

## Problem and motivation
Long-video agents must gather sparse evidence across many observations. The authors identify **semantic thrashing**: accumulating observations in append-only context can obscure previously collected evidence while increasing context cost.

Their structural argument shows that appending can add missing target evidence but cannot remove existing irrelevant content. This motivates separating persistent observation storage from a compact, editable working memory (§§1, 3.1). The argument establishes a limitation of append-only updates; it does not prove that every growing context necessarily suffers an accuracy collapse.

## Approach and contributions
- **Structural diagnostic:** A symmetric-difference measure separates missing critical evidence from accumulated noise. The rewrite analysis explicitly makes improvement conditional on removing noise and recovering evidence outweighing evidence loss and new noise (§§3.1, 3.4).
- **Dual-loop agent:** An outer multimodal policy explores video through analysis, transcription, code execution, and answer tools. After each step, an inner LLM retrieves filesystem artifacts and edits working memory (§§3.2–3.3).
- **Hierarchical memory:** Six working-memory sections track metadata, narrative understanding, timestamped evidence, temporal coverage, activity, and investigation targets. A compressed action manifest connects this memory to persistent artifacts. The evaluated configuration uses a 32K-token memory budget and eight recent message groups (§§3.4, 4.1).
- **Empirical evaluation:** Benchmark comparisons, memory ablations, context-only answerability probes, and token accounting test the proposed design without backbone retraining (§4).

| Largest memory benefit occurs on hardest questions | On the fixed hardest quartile of VideoMME-long, Gemini 3 Flash task accuracy rises from **70.7%** with append-only memory to **80.0%** with VideoLoop. | Table 2 |

| Total token overhead is small in the reported comparison | Gemini 3 Flash on VideoMME-long: append-only uses **614.9K** mean tokens/question at **81.9%** accuracy; VideoLoop uses **618.2K** at **85.8%**, reported as **+0.5%** tokens. | Table 3, §4.4 |

These results support improved benchmark accuracy and more answer-supporting context in the tested settings. The memory ablation provides stronger evidence about the design than comparisons with native single-pass models, which also change exploration behavior.

The blind-judge measure is an **answerability proxy**, not a direct measurement of recovered evidence. Token totals establish token consumption, not latency or monetary cost. Prior-agent results in Table 1 are not shown to be reproduced under matched backbones and budgets.

## Limitations and validity risks
- **Authors’ explicit qualification:** Rewriting has no unconditional quality guarantee; it can delete target evidence or introduce noise (§3.4, Eq. 8).
- **Analyst inference—statistical uncertainty:** Table 2 reports one run per configuration. No confidence intervals or repeated-run variability are supplied for the main results.
- **Analyst inference—proxy validity:** Judge accuracy can reflect context presentation and the judge’s answering ability as well as evidence retention. No direct evidence-recall annotation or alternative-judge validation is reported (§4.4).
- **Analyst inference—limited generalization:** Evaluation covers three video-question benchmarks. Transfer to other long-horizon agent tasks is proposed in the conclusion but not tested (§§4.1, 5).
- **Analyst inference—resource assumptions:** Storage is treated as unbounded. Storage growth, filesystem-index growth, retrieval overhead, and wall-clock latency are not quantified. The fixed outer-context claim also needs bounds on individual recent observations, beyond limiting their count (§§3.3–3.4).
- **Analyst inference—component attribution:** The ablation separates rewriting and filesystem access but does not isolate memory budget, rewrite frequency, manifest compression, or template structure (Table 2).

## Open research questions
- **How reliable are the gains across runs?** The memory ablation uses one run per configuration. Repeat matched-budget experiments with multiple seeds and paired uncertainty estimates.
- **Does rewriting preserve the actual critical evidence?** The paper measures context answerability rather than evidence recall. Annotate critical evidence and measure retention, retrieval, and accidental deletion alongside judge accuracy.
- **Which memory choices drive the gains?** Budget, rewrite frequency, and manifest compression are not separately ablated. Sweep these choices while measuring accuracy, tokens, and latency.
- **Does the design scale beyond the evaluated scope?** Tests cover finite offline video-question trajectories with unbounded storage assumed. Evaluate longer videos and trajectories under explicit storage and retrieval budgets.

## Confidence and missing information
**Confidence: medium.** The supplied text clearly describes the architecture and reports consistent gains, but statistical reliability and mechanistic attribution remain limited.

Material missing information includes repeated-run uncertainty, exact prompts and decoding settings, direct evidence-retention measurements, alternative-judge checks, detailed prior-baseline matching, latency and storage costs, and verified repository contents.
