# TabFM-Auto: Self-Evolving Pipelines for Tabular Foundation Models

> [← Daily summary](../2026-09-30.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.37989) · [arXiv](https://arxiv.org/abs/2609.37989)


## One-sentence takeaway
TabFM-Auto uses a coding agent to optimize data pipelines around a frozen tabular foundation model, reporting strong benchmark gains and transferable pipelines, although its main TabArena evaluation includes rows previously exposed during pipeline selection.

## Problem and motivation
The authors argue that tabular foundation models ignore useful semantics in column names, task descriptions, and auxiliary files, while end-to-end machine learning agents face noisy searches over features, architectures, and training hyperparameters. TabFM-Auto aims to combine language-model interpretation of metadata with frozen tabular inference, restricting search to the surrounding pipeline (§1–3).

## Approach and contributions
- **Pipeline search around a frozen predictor:** An agent edits cleaning, feature engineering, context sampling, post-processing, and supported constructor settings. Candidates are selected using internal three-fold cross-validation; TabFM receives no gradient updates (§3).
- **Metadata and auxiliary-file integration:** Generated code expresses domain formulas, statistical features, and summaries of external files as tabular inputs, extending beyond feature addition alone (§3.2; Appendix D.1).
- **Transfer and comparative evaluation:** The authors test discovered pipelines on other frozen tabular models without further search, and compare against both AutoML systems and end-to-end coding agents (§4; Table 7).

These contributions concern pipeline optimization and evaluation; the underlying TabFM and generic TabFM+ operations are existing components (§3.2).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Highest aggregate TabArena rating | Across all 51 datasets and official folds, Codex + Opus 5 reaches **2013.0 Elo**, versus **1785.3** for TabFM and **1856.0** for TabFM+; all five configurations occupy the top five positions. Each is rated separately against the 66-method pool. | §4.1; Table 4 |
| Error reductions accompany ranking gains | Across all official folds, Claude Code + Opus 5 and Antigravity + Gemini reduce overall geometric-mean test error versus published TabFM by **4.19%** and **5.05%**; regression RMSE reductions are **3.11%** and **3.15%**. | Table 9 |
| Fully held-out results are less uniform | On fold 0 only, Codex + Opus 5 achieves **1950.7 overall Elo**, versus **1790.2** for TabFM and **1853.2** for TabFM+. Other configurations do not consistently exceed both baselines. | Table 5 |
| Restricted search beats an unconstrained agent | With identical Antigravity harness, Gemini model, sandbox, and six-hour budget, TabFM-Auto scores **1979.6 Elo**, versus **1468.8** for an agent allowed to train arbitrary models without TabFM. | Table 2; §4.1 |
| Pipelines transfer to other predictors | Claude Code + Opus 5 pipelines improve overall Elo by **143.3** for TabICLv2, **130.8** for TabPFN-3, and **88.7** for EXAONE-Tabular, without further search; only context size transfers from constructor settings. | Table 7; Appendix B.3 |
| Leading aggregate MLE-Bench performance | Across eight tabular competitions, the two configurations score **1827** and **1734 Elo**, ranking first and second against 12 external agents with complete submissions. TabFM-Auto uses a 24-hour per-competition budget. | §4.2; Figure 7; Appendix D.1 |

The results support useful pipeline improvements and transfer within the tested settings. They do not establish uniformly superior performance: individual datasets and competitions show losses. Crucially, only TabArena fold 0 is fully held out from pipeline selection; later folds reuse rows from fold 0’s search-training data (Appendix B.1). Aggregate rankings therefore provide weaker generalization evidence than a fully nested evaluation.

## Limitations and validity risks
- **Author-stated:** Gains are smaller on anonymized schemas, and each new dataset requires repeated validation evaluations (§5).
- **Author-acknowledged protocol risk:** Cross-fold row overlap can inflate all-fold scores through pipeline selection, even though fitted statistics and predictions are recomputed per fold (Appendix B.1).
- **Analyst inference:** Pipeline taxonomy comparisons do not isolate the causal benefit of metadata or individual stages; they compare different dataset groups rather than controlled stage-removal experiments (Table 6).
- **Analyst inference:** The unconstrained-agent ablation changes both predictor availability and search scope, so it cannot isolate reduced retraining noise as the cause of improvement (Table 2).
- **Reporting inconsistency:** Appendix B.1 claims all five configurations outrank EXAONE-Tabular overall on fold 0, but Table 5 places Antigravity + Gemini below it in classification, while all five do exceed it overall. More materially, the earlier claim of a single configuration holding first place across overall, classification, and regression is not supported by Table 5: regression is led by Codex + Gemini.
- **Comparison uncertainty:** MLE-Bench uses external leaderboard submissions rather than a uniformly controlled harness/model comparison (§4.2).

## Open research questions
- **How much survives fully nested evaluation?** Cross-fold overlap remains unresolved. Run independent pipeline searches within each outer training split and score only its disjoint test split.
- **How much gain comes specifically from metadata?** Taxonomy results are observational. Repeat searches with original, anonymized, and shuffled column descriptions under matched budgets.
- **Which pipeline stages drive improvement?** Existing results combine multiple edits. Remove cleaning, features, sampling, calibration, and constructor tuning individually from selected pipelines.
- **Can pipelines reduce future search cost?** A reusable operation library is proposed but untested (§5). Compare library-based warm starts with identity starts on unseen datasets at fixed evaluation budgets.

## Confidence and missing information
**Confidence: medium.** Detailed results and verification procedures support the reported benchmark findings, but cross-fold exposure limits the main generalization claim.

Material missing information includes a stated public code/pipeline release, repeated independent search-seed results, controlled metadata and stage ablations, fully nested all-fold evaluation, and uniformly matched resource conditions for external MLE-Bench agents.
