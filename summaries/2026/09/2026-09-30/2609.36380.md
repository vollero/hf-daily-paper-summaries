# LEGO-Anything: Coding Agents for 3D Scene Reconstruction

> [← Daily summary](../2026-09-30.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.36380) · [arXiv](https://arxiv.org/abs/2609.36380)


## One-sentence takeaway
Coding agents can reconstruct single images as executable Blender scenes, but high artifact validity masks weak fidelity, and a training-free control plugin improves Office-subset scores without closing the gap to specialized vision models (§§4–6).

## Problem and motivation
The authors target single-image reconstruction into scene programs whose objects, geometry, camera, and appearance can be inspected, edited, and queried. They identify a gap between fixed reconstruction outputs and iterative, executable scene construction, alongside a lack of benchmarks covering scene-level image fidelity across indoor and outdoor environments (§§1–2).

## Approach and contributions
- **Image-to-Code framework:** A general-purpose coding agent repeatedly writes and executes Blender code, renders the scene, inspects it against the reference, and revises its program (§3).
- **LEGO-Bench:** A simulator-grounded benchmark with 208 images from 104 scenes, separating artifact validity, visible-surface reconstruction, and rendered appearance. Matched scene families control complexity by adding objects while preserving shared scene properties (§4; Table 2; Appendix D.2).
- **Failure diagnosis and LEGO-Plugin:** Trajectory and judging analyses motivate reference-grounded initialization, bounded refinement, and edit transactions with rollback. The plugin uses VGGT, optionally SAM 3 and Depth Anything V2, without accessing private benchmark ground truth (§5; Appendix G).
- **LEGO-World:** Frozen reconstructed scenes yield deterministic detection, segmentation, and relative-depth readouts on separate natural-image evaluation tracks (§6; Appendix H).

The contribution is the combined formulation, evaluation, diagnosis, and control layer; executable Blender reconstruction itself has precedents acknowledged in §2.

These results support artifact deliverability, model-dependent fidelity, and Office-subset plugin benefits. They do not establish complete or physically correct 3D recovery, equal-budget superiority over other systems, or simultaneous detection, segmentation, and depth evaluation of the same natural-image scene.

## Limitations and validity risks
- **Author-described representation limits:** Initialization deliberately avoids absolute object size and metric depth because these are unreliable from a single monocular image (Appendix G.3). Natural-image scenes remain substantially below specialist performance (§6).
- **Author-described comparison limits:** Baselines differ in inference budgets, information access, native outputs, and conversion procedures. VIGA’s external asset generation is disabled; several baselines cover only indoor tasks (Appendix F.2).
- **Author-described metric limits:** Reconstruction measures only reference-visible surfaces and excludes predicted geometry outside scored masks. Appearance measures thresholded pixel agreement rather than perceptual similarity or independent geometry quality (Appendices E.2–E.3).
- **Analyst inference—plugin generalization and attribution:** Plugin evaluation is restricted to Office scenes, and no module-removal ablation is reported. Outdoor benefits and each module’s causal contribution remain unresolved (§5.3; Appendix G).
- **Analyst inference—judging conclusion is narrower than the headline:** Aggregate self-judging is weak, but Astra’s self-judge reaches 61.7% reconstruction agreement. The evidence supports unreliable judging overall, rather than universal chance-level performance (Table 8).
- **Analyst inference—validation strength:** Human-metric validation uses compatibility agreement that treats ties as compatible; sensitivity testing covers only six tasks and two models. These support limited robustness checks rather than broad metric validation (Appendix E.3–E.5).
- **Analyst inference—functional claims remain preliminary:** Articulation testing reevaluates one frozen Office submission, which scores zero; it cannot establish model-wide articulation ability (Appendix B.4).

## Open research questions
- **Which plugin module produces the gains?** The combined plugin improves scores, but component contributions are untested. Run initialization/refinement/version-control ablations with matched budgets and repeated runs.
- **Does the plugin generalize outdoors?** Evaluation covers Office scenes only. Test the unchanged plugin across outdoor and Bird’s-Eye cases, reporting R, A, failures, and provider errors separately.
- **Can one scene support multiple tasks on the same image?** LEGO-World uses separate dataset tracks. Evaluate frozen scenes on images with joint detection, segmentation, and depth annotations to measure cross-task consistency.
- **Does visible-view fidelity predict broader 3D usefulness?** Headline geometry scoring excludes hidden surfaces, and articulation evidence is a single pilot. Add held-out views and broader motion tests alongside existing scores.

## Confidence and missing information
**Confidence: medium.** The supplied text provides substantial protocols and results, but limits causal attribution and reproduction.
