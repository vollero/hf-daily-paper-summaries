# GraphSkillEvo: Evolutionary Optimization of Graph-Structured Agent Skills

> [← Daily summary](../2026-09-21.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.21749) · [arXiv](https://arxiv.org/abs/2609.21749)


## One-sentence takeaway

GraphSkillEvo evolves explicit workflow-based agent skills, improving average test success over SkillOpt by 4.01 percentage points on GPT-5.4-nano and 1.76 points on GPT-5.4 without a harness, with lower aggregate optimization-token consumption (Tables 1–2).

## Problem and motivation

Agent skills encode reusable procedural guidance without changing model parameters. The authors argue that unstructured skill documents obscure execution order, repeat instructions, and create redundant alternatives for optimization—especially problematic for less capable models (§§1–2).

The identified gap is optimization **within an individual skill’s workflow structure**: the related graph-based work described by the authors primarily addresses retrieval or composition across skill libraries (Appendix A.2).

## Approach and contributions

- **Graph-structured skill representation:** Shared global guidance accompanies reusable instruction nodes and conditional workflows. Each workflow specifies an ordered node sequence whose consecutive steps define directed edges (§3.1).
- **Evolutionary skill optimization:** A population undergoes separate mutations and crossovers of global guidance or graph structure. Mutation uses failed execution trajectories; crossover combines parent components. Validation fitness determines parent sampling and survivor selection (§3.2).
- **Structural validation and empirical analysis:** A script rejects malformed skills, including undefined node references and unused nodes. Experiments examine execution structure, optimization operators, and cross-model transfer (Appendix B.3; §5).

The reported configuration uses four candidates over five generations, sampling 15 training instances per generation and retaining at most five failures per skill. Model parameters and execution setup remain fixed during skill optimization (§§2.1, 4).

## Evidence and main results

All success rates below are percentages; differences are percentage points. Main results average three optimization runs (§4.1).

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Higher average success than SkillOpt | Across five benchmarks without a harness: GPT-5.4-nano **60.90 vs 56.89**; GPT-5.4 **75.86 vs 74.10**. Across four benchmarks with GPT-5.4 and Codex: **78.28 vs 76.95**. | Table 1 |
| Largest highlighted gain is spreadsheet execution | GPT-5.4-nano, no harness: SpreadsheetBench **60.71 vs 50.11**. The exception is LiveMath: **28.76 vs 29.56**. Best reported result in **13 of 14** evaluated settings. | Table 1; §4.1 |
| Lower aggregate optimization-token use | Across five benchmarks: GPT-5.4 **61.94M vs 81.08M**; nano **75.94M vs 103.54M**. Savings are not universal: nano ALFWorld uses **47.75M vs 28.18M**. | Table 2 |
| Explicit workflows help execution | Removing workflow organization from optimized nano skills lowers success by **4.52, 2.50, 4.19, 1.35, and 0.75** points on SearchQA, SpreadsheetBench, DocVQA, LiveMath, and ALFWorld respectively. | Table 3; §5.1 |
| Structure and both operator families contribute | Nano, averaged over SearchQA, SpreadsheetBench, and DocVQA: full method **71.52**; without graph structure **64.08**; without mutation **54.50**; without crossover **66.59**. | Table 4; §5.2 |
| Transfer succeeds in the tested direction | SpreadsheetBench on GPT-5.4: nano-optimized GraphSkillEvo skill **71.78**, directly optimized skill **69.40**, transferred SkillOpt skill **53.21**, no skill **39.16**. | Table 5 |
| Statistical support varies by task | Separate five-run nano/no-harness experiment: one-sided Welch tests give **p=0.0162** for SpreadsheetBench and **0.0382** for ALFWorld, versus **0.0687** for SearchQA and **0.0888** for DocVQA. | Appendix C.1; Table 7 |

The evidence supports benefits under the reported benchmark protocols and shows that removing workflows or evolutionary components worsens performance. It does not establish universal superiority, transfer across model families, or statistically significant gains in every setting. The authors’ explanation that graph structure reduces the search space is plausible, but search-space size and representational redundancy are not directly measured.

## Limitations and validity risks

- **Scope acknowledged by the authors:** ALFWorld is omitted from Codex evaluation because its persistent environment is unsupported by the adapter (§4). Richer graph composition, cross-domain merging, and parametric optimization remain future work (§6).
- **Analyst inference—limited generalization:** Evaluation uses two related models; transfer covers only nano-to-GPT-5.4 on three benchmarks. Ablations likewise cover only nano and, for optimization components, three benchmarks (§5).
- **Analyst inference—selection sensitivity:** Validation sets are small, including 18 instances each for LiveMath and ALFWorld, and are repeatedly reused for selection. Alternative split seeds are not evaluated (Table 6; Appendix B.2).
- **Analyst inference—mechanism isolation:** Execution ablation removes workflow information and document organization together. It cannot fully separate graph-specific benefits from clearer formatting or added ordering instructions (Appendices E.3–E.4).
- **Analyst inference—comparison limits:** SkillOpt and GraphSkillEvo use different optimization schedules; final results are not uniformly budget-matched. Token totals do not establish wall-clock or monetary savings (§4; Appendix D.1).
- **Analyst inference—benchmark fidelity:** The spreadsheet example favors static outputs when evaluation requires displayed values. Success therefore does not establish preservation of live spreadsheet behavior (Appendix E.3).

## Open research questions

- **Does structure help beyond formatting and instruction length?** Existing ablations remove several features together. Compare graph skills with length-matched, carefully ordered textual workflows containing identical procedural information.
- **How robust are gains to selection budgets and data splits?** Population size, generation count, and split seed are fixed. Sweep these settings under equal token budgets and report held-out performance across multiple partitions.
- **How broadly do skills transfer?** Only one transfer direction within the evaluated model pair is tested. Evaluate bidirectional transfer across additional model families and task domains.
- **Can explicit graph execution improve reliability further?** The method supplies natural-language workflows; structural validation checks documents, not execution adherence. Compare prompted execution with a controller that enforces node transitions and records deviations.

## Confidence and missing information

**Confidence: medium.** The supplied text provides detailed methods, prompts, splits, ablations, and repeated-run results, but broader claims exceed the evaluated scope.

Material missing information includes full run-level results for the main comparisons, uncertainty estimates outside the separate nano robustness experiment, budget-matched final comparisons, graph-size and skill-length analyses, execution-adherence measurements, and comprehensive latency/cost accounting. Code availability is an author claim and was not independently verified.
