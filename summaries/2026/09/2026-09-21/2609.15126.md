# MoME: Mixture-of-Memory Embeddings for Context-Aware Sparse Lookup

> [← Daily summary](../2026-09-21.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.15126) · [arXiv](https://arxiv.org/abs/2609.15126)


## One-sentence takeaway
MoME adds context-dependent slot selection to token-indexed memory, improving several controlled language-model evaluations while showing metric-dependent gains over strong baselines and only correlational evidence of semantic routing.

## Problem and motivation
Token-indexed memory expands language-model capacity through inexpensive parametric lookups, but deterministic addressing gives the same token or n-gram the same memory regardless of broader context. The authors argue this conflates different word senses and duplicates capacity across semantically similar tokens; they seek contextual retrieval without abandoning lightweight lookup (§§1, 3.1).

## Approach and contributions
- **Context-aware memory addressing:** Each memory row contains multiple slots. A per-head router selects and weights slots using contextual representations; heads share the stored table. A separate gate adds the retrieved vector to attention values (§§3.2–3.5). Appendix Table 11 specifies value-based router inputs for Llama/MobileLLM, versus hidden-state inputs for nanochat and Qwen3.
- **Optional token grouping:** Offline nearest-neighbor matching of pretrained token embeddings groups related tokens into shared rows, reallocating saved capacity to additional slots. Main cross-family experiments use identity indexing (§3.4; §4.2).
- **Empirical validation and composition:** The paper tests matched-budget comparisons, context-free routing controls, memory scaling, and combinations with Bigram and sparse FFN experts. Routing probes investigate whether slot choices track word sense (§4; Tables 12–19).

## Evidence and main results

BPB is bits per byte, where lower is better; CORE averages task accuracies after adjustment for random baselines, where higher is better (§4.1).

These results support context-aware memory as a useful capacity mechanism in the tested settings. They do not establish universal superiority, a general scaling law, or a causal link between sense-sensitive routing and prediction quality. External pretrained-model comparisons are reference points rather than controlled comparisons (§A.8.1).

## Limitations and validity risks
- **Author-stated scale and replication limits:** The largest training experiment uses an approximately 0.8B dense backbone and a single seed (§5). Larger-model latency measurements do not establish training-quality gains at those scales.
- **Author-stated probe limitations:** WiC filtering produces a noun-heavy subset; pooled effects may reflect lexical composition. The probe combines train/test examples, selects strongest sites on the same data, and uses pointwise intervals without multiple-comparison correction. Routing differences do not measure effects on predictions (§A.12).
- **Analyst inference—comparison scope:** Token-matched comparisons have unequal memory budgets; adapted baselines differ from their original architectures. Improvements therefore apply to the reported implementations and budgets (§4.3; Table 16).
- **Analyst inference—efficiency accounting:** Optional grouping requires a separately pretrained embedding reference; inclusion of that preparation cost in matched compute budgets is unclear (§4.2). Table 21 does not specify enough latency conditions to generalize to deployment.
- **Analyst inference—reporting ambiguity:** Table 14’s extracted rows contain fewer values than model headers, preventing reliable reconstruction of its complete per-task comparison.

## Open research questions
- **Does semantic routing cause better predictions?** Current probes are descriptive (§5). Swap or freeze routes on matched sense-disambiguation examples and measure changes in likelihood and task accuracy.
- **Do gains persist at larger trained scales?** Quality experiments stop at sub-billion dense backbones (§5). Repeat matched-FLOP memory and dense-scaling comparisons with larger backbones and multiple seeds.
- **How should memory and expert capacity be allocated?** The combined sparse-MoE model adds stored parameters and trains more slowly (Table 13). Sweep memory/expert allocations under jointly matched storage and compute budgets.
- **Can concentrated slot usage be made more efficient?** Routing concentrates on a subset of slots, but utilization statistics do not establish table coverage (§A.9.5). Test slot pruning or reallocation while measuring quality, throughput, and domain-shift behavior.

## Confidence and missing information
**Confidence: medium.** The supplied text provides extensive methods, controls, and results, but broader claims remain constrained by scale and replication.
