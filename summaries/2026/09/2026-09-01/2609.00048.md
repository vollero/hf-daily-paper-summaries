# GUI-CC: Benchmarking Contextual Consistency of GUI World Models as Agent Environments

> [← Daily summary](../2026-09-01.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.00048) · [arXiv](https://arxiv.org/abs/2609.00048)


## One-sentence takeaway

GUI-CC shows that current mobile GUI world models can generate plausible-looking next screens yet frequently lose task state or action executability when their predictions are reused in multi-step rollouts.

## Problem and motivation

GUI world models are commonly evaluated as one-step next-screen predictors, although their intended role is often to simulate environments for multi-step GUI agents. The authors argue that local visual or semantic quality does not test whether app identity, navigation history, created or selected entities, persistent settings, and action affordances remain coherent after generated states are repeatedly fed back into the model (Introduction; Figure 1).

GUI-CC addresses this evaluation gap by measuring “contextual consistency”: whether an autoregressive rollout admits a plausible latent-state sequence in which every generated screen represents the evolving state and subsequent actions remain executable (Section 3.1).

## Approach and contributions

- **Two-track benchmark:** The offline track follows reference semantic actions from real GUIOdyssey trajectories while feeding predictions—not reference screens—back into the model. The online track lets a fixed probing agent choose actions from generated screens (Sections 3.2–3.5).
- **Curated evaluation tasks:** GUI-CC contains 500 offline tasks covering 4,905 transitions and 130 apps, plus 200 emulator-verified online tasks across 30 apps, six categories, and 18 templates (Figure 2).
- **Trajectory-level evaluation:** It separates transition fidelity and plausibility from contextual consistency and task progress, including reference-action and ordered-milestone progress (Section 3.7).
- **Broad model comparison:** The experiments test 12 code/HTML or image-generation models in 18 configurations per track, including history-conditioned variants where supported (Section 4.1; Table 4).
- **Diagnostic finding:** The authors identify a persistent gap between visually usable screens and executable environments, with limited task progress despite high usability or consistency scores (Sections 4.2–4.3).

The evidence supports the authors’ central claim that single-screen plausibility and usability are insufficient proxies for sustained environment utility. The controlled offline track helps isolate world-model errors from agent choices, while the online track tests closed-loop interaction.

It does not establish that the best-scoring model is universally the best GUI simulator: the scope is mobile-only, the online comparison uses one probing agent, several metrics rely on the same frozen model family used as an evaluated world model, and some valid alternative transitions may be penalized against a single reference (Sections 4.1, 4.3; Limitations).

## Limitations and validity risks

**Author-stated limitations**

- GUI-CC covers mobile GUIs only; web, desktop, multi-device, filesystem, and richer session state remain outside its scope (Limitations, page 9).
- The online track uses a single fixed probing agent, so it does not measure sensitivity to planning strength, recovery behavior, or prompting style (Limitations, page 9).
- VLM judging can miss fine-grained task-state errors, while reference-based fidelity metrics may penalize alternative but valid transitions (Section 4.3).
- Current interfaces emphasize screenshots, images, and HTML; structured state, memory modules, simulator APIs, and hybrid outputs are deferred to future versions (Limitations, page 9).

**Analyst inferences supported by the text**

- **Potential evaluator dependence:** GPT-5.5 is both an evaluated HTML world model and the frozen online agent and VLM judge. The supplied text reports fixed prompts but no judge-model ablation or human-agreement statistics (Section 4.1).
- **Limited history ablation:** History conditioning is capped at three prior observation-action pairs, so the experiments do not reveal whether longer context, explicit state memory, or retrieval would improve long-horizon consistency (Section 4.1).
- **Error-analysis breadth:** The 200-rollout failure analysis covers only GPT-5.5 and GPT Image 2, limiting direct generalization of its 42%/33%/25% taxonomy to all evaluated models (Section 4.3).
- **Selection effects:** Offline trajectories are filtered, VLM-verified, and prioritized for strongly state-dependent steps; this deliberately creates a diagnostic benchmark but may not reflect the natural frequency of task types or failures in deployment (Sections 3.4 and E).

## Open research questions

1. **Would explicit persistent state outperform short visual history?**  
   The tested history contains at most three previous pairs and yields limited progress gains. A next experiment could compare identical models using short history, full-history retrieval, and a structured persistent-state store.

2. **How robust are rankings to the probing agent and judge?**  
   The online track and VLM metrics use fixed GPT-5.5 components. Repeating evaluation with agents and judges of different families and strengths, alongside blinded human ratings, would test ranking stability.

3. **Can executable state checks close the metric–progress gap?**  
   High contextual-consistency scores can still miss wrong items, stale queries, or lost saved states. An extension could instrument emulator state and compare executable assertions with VLM judgments for the same milestones.

4. **Do the findings transfer beyond mobile interfaces?**  
   The benchmark does not cover browser sessions, desktop filesystems, or cross-device context. Parallel web and desktop suites using the same autoregressive protocol could measure whether failure patterns and metric relationships persist.
