# An Empirical Study of Harness Design for Coding Agents

> [← Daily summary](../2026-09-18.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.20804) · [arXiv](https://arxiv.org/abs/2609.20804)


## One-sentence takeaway
Across the tested coding agents, context management mainly prevents overflow, while planning and tool-interface benefits depend on the model and workload, supporting conditional rather than universal harness choices (§§3–4).

## Problem and motivation
Whole-harness comparisons conflate planning, tool interfaces, context policies, and model capabilities. The authors identify a gap in controlled studies that vary these components across both context budgets and model sizes on long coding tasks, making it difficult to determine which components actually help (§1).

## Approach and contributions
- **Controlled harness evaluation:** A fixed ReAct execution loop supports component ablations across four models, two benchmarks, and 176 settings. Context policies span 32k–128k windows; planning and action-space ablations use only T4/128k (§§2–3.1).
- **Composable context policies:** T0 provides no compaction; T1 elides observations; T2 adds recoverable storage; T3 summarizes; T4 stages elision before summarization while retaining recall. Summarization uses the evaluated model (§2.3).
- **Behavioral explanation:** Trajectory annotations examine termination, verification, and edit granularity. The contribution is empirical characterization of these implementations, rather than a new model or benchmark (§4; Appendix C).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Context management helps most under tight windows | Averaged over models and managed tiers, the success-rate advantage over T0 falls from **35.7 to 2.7 percentage points** on SWE-Bench and **9.5 to 2.8 points** on Terminal-Bench as the window increases from 32k to 128k. Managed tiers report zero overflow failures throughout. | §3.2; Tables 3–4; Fig. 3 |
| T4 has the strongest aggregate managed-policy cost profile | Among T1–T4, T4 has the lowest mean cost in **7 of 8 model–benchmark panels**, averaging over window budgets, with broadly similar success rates; it also has the lowest cost averaged across model–benchmark pairs at each budget. | §3.2; Figs. 4–5 |
| Recall shows no consistent accuracy benefit | Across **32 matched T2–T1 comparisons**, T2 wins 15, loses 14, and ties 3; its equal-weight mean success difference is **−0.36 percentage points**. **36 of 64** recall-enabled context settings never invoke recall. | §3.2; Table 13 |
| Planning helps the weakest model reach useful work | On SWE-Bench, Nemotron-3 30B planning off → on raises success **13.6% → 25.2%**, increases mean cost **$0.02 → $0.09**, and reduces runs ending without an edit **68.6% → 27.8%**; full tools, T4/128k. | Tables 3, 6 |
| Planning saves cost for stronger models with small success decreases | On SWE-Bench, planning off → on changes Nemotron-3 550B from **67.8%, $3.31** to **65.8%, $2.33**, and Mistral from **69.0%, $4.65** to **68.6%, $3.14**; full tools, T4/128k. | Table 3; §4 |
| Bash-only can improve both success and cost | Nemotron-3 550B, full tools → bash-only: SWE-Bench **65.8% → 69.4%**, **$2.33 → $1.11**; Terminal-Bench **44.94% → 50.56%**, **$2.43 → $1.70**; planning on, T4/128k. | Tables 3–4 |
| Interface preference depends on workload | Mistral, full tools → bash-only: SWE-Bench success falls **68.6% → 45.4%**, while Terminal-Bench rises **37.08% → 43.82%** and cost rises **$2.22 → $2.75**; planning on, T4/128k. | Tables 3–4 |

Success comparisons use task-paired exact McNemar tests with Benjamini–Hochberg correction (§3.1). The Nemotron-3 550B bash-only gain is significant on SWE-Bench but not marked significant on Terminal-Bench. These results establish conditional performance differences; descriptive trajectory patterns support the authors’ proposed mechanisms without independently proving them. “Comparable accuracy” does not establish statistical equivalence, and T4 does not dominate every individual setting.

## Limitations and validity risks
- **Authors’ limitations:** One planning implementation and fixed compaction settings; no full factorial evaluation; one run per task-setting; limited Terminal-Bench power; narrow model and task coverage. Model size imperfectly represents capability (Limitations, p. 16).
- **Authors’ limitation:** The action-space change bundles tool availability, prompts, file-state tracking, and diagnostics, preventing attribution solely to tool count or action granularity (§2.2).
- **Analyst inference:** T4’s advantage cannot be attributed exclusively to mechanism composition: it also starts elision earlier than T1–T3, and no elision-plus-summarization condition without recall is tested (§2.3).
- **Analyst inference:** Behavioral conclusions depend on annotation definitions. Figure 40 inconsistently describes Fix as requiring a resolving edit and as any source edit; this creates ambiguity for “without-edit” statistics. Human validation supports annotation reliability but does not eliminate that ambiguity (Appendix C.2; Fig. 40).
- **Analyst inference:** Reported dollars are token-price estimates for locally served models, not demonstrated total deployment costs or latency (§3.1).

## Open research questions
- **Do planning and interface effects persist under tight context budgets?** They are tested only at T4/128k. Next experiment: cross planning and interfaces with multiple policies and window budgets.
- **What drives T4’s efficiency?** Staging, thresholds, and mechanism composition vary together. Next experiment: match thresholds and compare elision-plus-summarization with and without recall.
- **Is shell proficiency more predictive than model size?** The authors acknowledge training and interface familiarity as confounds. Next experiment: independently measure shell proficiency across additional model families before repeating interface ablations.
- **Would recall help when observations cannot be regenerated?** Existing prompts permit rereading files or rerunning commands. Next experiment: evaluate tasks requiring earlier, non-reproducible observations under matched context pressure.

## Confidence and missing information
**Confidence: high** in the reported descriptive comparisons; lower in causal mechanism explanations and transfer beyond the tested settings.

Material information unavailable includes a confirmed code/trajectory release, repeated-run variability, full component interactions, threshold sensitivity, and measured latency or total serving cost.
