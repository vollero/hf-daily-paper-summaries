# SoL-Pi: Recursively Scaling Auto-Research Loops for Efficient Agent Harness

> [← Daily summary](../2026-09-18.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.20519) · [arXiv](https://arxiv.org/abs/2609.20519)


## One-sentence takeaway
SoL-Pi’s automated search produces four harness mechanisms that reduce recorded token traffic by 44.7–49.0% and API cost by about one third versus Pi on public EdgeBench tasks, while retaining 93.7–94.3% of Pi’s average score across two backends (§3.1, Tables 1–2).

## Problem and motivation
Long-running agents repeatedly transmit growing histories and tool outputs, making total task cost a harness-design problem as well as a model-serving problem. Harness changes interact with verification, delegation, and recovery, so local savings can cause later failures or additional work. The authors target the difficulty of discovering reusable efficiency improvements through automated search without overfitting development tasks (§1).

## Approach and contributions
- **Automated harness search:** A research agent analyzes trajectories, proposes and implements changes, and uses independent review and development evaluation to refine them. Candidates must satisfy fixed capability tolerances and improve a declared efficiency metric; nondominated candidates survive. Search covers 152 proposed directions and 535 executable environments, including 495 repository issue–PR tasks and 40 verifier-driven synthetic tasks (§§2.1–2.3).
- **Four integrated Pi extensions:** Action Fusion combines edits and follow-up commands; Online Context Compact triggers native compaction using projected savings and cache-rewrite costs; ObservationPack archives large outputs and replaces repeated transmissions with retrievable handles; Evidence-Preserving Reducer uses a cheaper model to extract build/test evidence, with deterministic checks and fallback (§§2.4–2.5).
- **Transfer evaluation:** The frozen complete stack is evaluated on another backend, additional benchmarks, and a coordinated agent swarm (§3).

The claimed contribution is the discovery process and resulting integrated harness. The text does not establish that each underlying compression or action-batching idea is individually novel (§4).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Complete stack cuts cost with lower score on the search backend | On 51 public EdgeBench tasks with GPT-5.6 Sol, Pi → SoL-Pi: token traffic 2.1538 → 1.0990 B; API cost $1,339 → $894; average score 44.833 → 42.003. | §3.1, Table 1 |
| Savings transfer to another backend | On the same EdgeBench set with Opus 5, without further search or adaptation: Pi → complete stack traffic 2.3697 → 1.3101 B; cost $1,741 → $1,158; score 44.756 → 42.224. | §3.1, Table 2 |
| Selected single mechanisms offer higher scores | EdgeBench: ObservationPack on Sol scores 47.208 at $1,271 versus Pi’s 44.833 at $1,339; Action Fusion on Opus scores 50.482 at $1,605 versus 44.756 at $1,741. These are backend-specific selections from the component results. | Tables 2, 4 |
| Terminal efficiency comes with fewer completions | Across 63 CPU-only Terminal-Bench 4 tasks, SoL-Pi solves 15 versus Pi’s 18; total cost is $211.12 versus $286.45, and cost per solved task $14.07 versus $15.91. | §3.2, Table 3 |
| Formal-proof cost falls at Pi’s completion count | On six IMO 2026 problems using Sol xhigh, Lean 4 verification, and a 150-minute cap per problem, both SoL-Pi and Pi pass three; costs are $62.69 and $75.95. Codex passes five at $114.47. | §3.2, Table 3 |
| Swarm result improves over the Pi swarm | One two-hour run per configuration: 20 SoL-Pi workers reach 1,127 simulated cycles at $60.11 versus 20 Pi workers’ 1,366 at $82.12; a single Codex agent reaches 1,333 at $39.20. All final candidates pass correctness checks. | §3.3, Fig. 5 |

These results support a cost–capability trade-off and preliminary transfer, rather than universal capability preservation. “Token traffic” includes cache traffic; the paper defines token efficiency as API cost per aggregate task score. Costs use August 17, 2026 prices (Table 1). The complete stack minimizes total cost among Table 4 configurations, but Opus ObservationPack alone has better cost per score than the complete stack (Table 4).

## Limitations and validity risks
- **Author-stated:** Discovery uses one backend; transfer mechanisms activate less frequently on the other. Controlled search breadth/depth comparisons remain unperformed because search is expensive. Neither a scaling law nor compounding recursive improvement is demonstrated (§§2.2, 5.1).
- **Analyst inference — evaluation selection:** Eleven EdgeBench tasks accept frozen candidates and 40 are reserved for final generalization, but headline tables aggregate all 51 without separate results. The “Performance” configurations are selected from backend-specific component scores, weakening their interpretation as independently selected transfer results (§§2.5, 3.1).
- **Analyst inference — uncertainty:** No repeated-run uncertainty or confidence intervals are reported; the swarm explicitly uses one run per configuration. Lower complete-stack scores and fewer terminal completions prevent interpreting “comparable performance” as demonstrated equivalence (§3).
- **Author-qualified interaction evidence:** Add-one evaluations exist, but triggered-task subsets differ between configurations, so their comparisons do not isolate mechanism interactions (§3.4, Fig. 7).
- **Implementation boundary:** The compaction gate estimates cache-rewrite overhead without separately pricing its summarization call (§2.5). Deterministic receipt checks verify specified properties, but the text provides no guarantee that every diagnostically necessary detail survives reduction (§2.4).

## Open research questions
- **Does greater search breadth or depth improve return per research dollar?** No controlled scaling comparison is reported. Next experiment: allocate equal search budgets across different numbers of hypotheses, environments, and refinement rounds, then evaluate frozen outputs (§5.1).
- **Which combinations best preserve capability?** Add-one tests and differing triggered-task subsets leave interactions unresolved. Next experiment: run a factorial mechanism ablation on identical tasks with repeated trials and a prespecified capability threshold (§3.4).
- **Can efficiency compound across research generations?** Using SoL-Pi to discover its successor remains a proposal. Next experiment: compare successive SoL-Pi-based search cycles with Pi-based cycles under equal budgets, including discovery costs (§5.1).

## Confidence and missing information
**Confidence: medium.** The supplied text supports the mechanisms and reported point estimates, but stronger causal and generalization claims remain uncertain.

Material missing information includes numerical capability tolerances, separate EdgeBench acceptance/final-subset results, repeated-run variability, total discovery cost, complete search prompts/configurations and environment manifests, and an accessible code-release destination.
