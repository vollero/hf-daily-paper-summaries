# Just-in-Time Memory: Learning to Curate Task-Adaptive Memory for LLM Agents

> [← Daily summary](../2026-09-24.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.27334) · [arXiv](https://arxiv.org/abs/2609.27334)


## One-sentence takeaway
JITMEM curates stored trajectories for the current task, improving reported agent success through read-time adaptation and reward-trained curation, although training benefits are tested only on ALFWorld and WebShop.

## Problem and motivation
Most agent memory methods summarize experience before knowing which future task will need it. The authors argue this discards potentially useful details and forces one fixed summary to serve different needs. Learning what to store also involves delayed credit assignment: a memory’s usefulness becomes apparent only when a later task retrieves it (§1).

JITMEM instead preserves accepted trajectories and postpones summarization until the next task is known, making payload quality assessable through that task’s outcome.

## Approach and contributions
- **Task-conditioned read-time curation:** BM25 retrieves raw trajectories using task descriptions; a separate curator synthesizes an ephemeral briefing for a frozen executor. Deployment stores trajectories judged successful by the executor model (§3).
- **Immediate curator training:** GRPO trains the curator using same-task executor rewards and a fixed bank of successful training trajectories. Only the curator changes; no related-task grouping is required (§3).
- **Modular memory architecture:** The trained curator can serve different executors. Evaluation combines an initially empty, growing deployment bank with tests of executor transfer and memory design choices (§§3–4).

The contribution is this combination of learned, separate curation and streaming episodic storage; the paper itself acknowledges other read-time approaches (§2). “Lossless” storage applies to retained trajectories, not rejected experiences.

## Evidence and main results

SR denotes success rate; reported ± values are standard deviations. Tables 1, 3, and 9 use three task-order runs; Table 2 uses four.

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Learned curation beats the strongest listed baseline with Qwen3-8B execution | ALFWorld SR: **77.4 ± 2.9** versus SkillOS **61.2 ± 4.6**, a **16.2-point** gain. WebShop SR: **32.8 ± 1.7** versus **16.5 ± 0.7**, a **16.3-point** gain. | Table 1 |
| Strong prompted read-time curation also helps | With Gemini-2.5-Pro as both curator and executor, WebShop SR is **61.0 ± 0.7** for JITMEM-gemini versus **41.0 ± 1.2** for SkillOS-gemini. | Table 1 |
| τ2-bench gains use an untrained curator | With GPT-5.4 curator and executor, JITMEM micro-average SR is **75.6 ± 2.3** versus ReasoningBank **71.7 ± 3.9**, a **3.9-point** gain; Telecom SR is **72.6 ± 4.5** versus **61.6 ± 8.4**. | Table 2 |
| Curator training transfers across executors | ALFWorld with GPT-5.4 execution: Qwen3-8B-executor-trained curator reaches **86.7 ± 0.7** SR, versus **88.1 ± 0.9** when trained with GPT-5.4 execution. | Table 3 |
| Retrieval and task conditioning contribute to trained performance | With Qwen3-8B execution, removing retrieval lowers ALFWorld/WebShop SR from **77.4/32.8** to **62.6/17.6**; removing task conditioning yields **66.0/22.4**. | Table 9 |
| Executor resource use falls | ALFWorld with GPT-5.4: JITMEM averages **9.8K input tokens and 11.6 steps**, versus ReasoningBank **19.7K/16.2** and SkillOS-base **22.4K/16.9**. Counts exclude curator costs. | Table 4; §4.1 |

These results support task-conditioned retrieval and curator training in the tested settings. They do not establish universal superiority: untrained Qwen3-8B JITMEM trails SkillOS-base on WebShop, and the authors report no clear improvement beyond variance on τ2-bench Airline and Retail (§4.1; Tables 1–2). Retrieval ablations demonstrate dependence on retrieved context, but do not prove that training acquires no standalone task knowledge.

## Limitations and validity risks
- **Author-stated:** BM25 may bottleneck larger, more diverse banks; curation adds an LLM call; payload formats are hand-designed per benchmark; curation occurs only once per task (§5).
- **Training scope:** τ2-bench evaluates only prompted variants because it lacks a standard training split. Executor transfer therefore does not establish transfer to a new application domain (§4.1).
- **Analyst inference—comparison uncertainty:** Appendix A documents inference-setting changes and imperfect baseline reproduction. Table 1 uses no-memory values matching previously reported results rather than all reproduced values; provenance of every other baseline entry is not fully clear. The claimed conservative calibration concerns SR: reproduced non-thinking WebShop score exceeds the reported score (Table 6).
- **Analyst inference—unmeasured system costs and filtering errors:** Executor token savings do not establish total latency or cost savings. Deployment judge accuracy and its downstream effects are not quantified (§3; Table 4).
- **Analyst inference—validation independence:** Training curves use a subsampled test stream for validation; whether this influenced model or hyperparameter selection is unspecified (Appendix B).
- **Evidence ambiguity:** The WebShop prompt permits partially successful experiences, while the method describes successful-only storage; the exact acceptance criterion is unclear (§3; Appendix A).

## Open research questions
- **Does the method remain efficient as memory grows?** Large-bank retrieval and total costs are untested. Vary bank size and diversity while comparing retrievers, success, storage, and end-to-end latency.
- **How much does judge error affect memory quality?** Filtering helps, but judge accuracy is unreported. Compare model judgments with oracle labels and controlled false-positive/false-negative rates.
- **Does learned curation transfer across domains?** The transfer study changes executors, while τ2-bench remains training-free. Train on one environment and evaluate the frozen curator on a held-out domain.
- **Would adaptive timing or payload formats improve results?** Both are fixed in this study. Compare once-per-task briefings with observation-triggered updates under matched token budgets.

## Confidence and missing information
**Confidence: medium.** The supplied text supports the architecture and reported results, but broader causal and efficiency claims require caution.

Material missing information includes code/weight availability, exact training-bank sizes, deployment judge accuracy, total inference cost and latency, complete baseline provenance, and whether test-stream validation affected model selection.
