# EmbodiedSWE: Coding Agents for Long Horizon Dexterous Robotics

> [← Daily summary](../2026-09-24.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.27308) · [arXiv](https://arxiv.org/abs/2609.27308)


## One-sentence takeaway
Coding agents can produce effective simulated robot programs and diversify them into useful policy-training demonstrations, but evidence for broad real-world generalization remains limited to a small, closely matched hardware experiment.

## Problem and motivation
Long-horizon, contact-rich robot tasks are difficult to demonstrate through teleoperation and expensive to learn through physical interaction. The authors identify two gaps: coding-agent benchmarks rarely combine long execution horizons with demanding manipulation, and successful agent-written programs are typically specialized to individual instances rather than immediately useful as scalable policy supervision (§1).

## Approach and contributions
- **EMBODIEDSWE-BENCH:** A human-led benchmark of 28 tasks across five embodiments, covering assembly, packing, puzzles, deformables/liquids, cutting, and locomotion with manipulation. Agents inspect simulator state and iteratively develop executable `solve(env)` programs; grading occurs separately (§2; Appendix B).
- **Coding-agent evaluation:** Comparisons of six models, solution transfer across tasks and arms, and supporting tools including checkpoint trees, CMA-ES parameter search, strategy sweeps, and visual inspection (§3).
- **EMBODIEDSWE-GEN:** A pipeline expanding verified programs through scene, strategy, phase, dynamics, and visual variation. Demonstrations must pass task grading and open-loop action replay before VLA training (§4.1; Appendix D).
- **Exploratory agent training:** Synthetic task construction and PPO post-training of a coding agent show training-set improvements, without held-out evaluation (Appendix G).

The central contribution is the combination of difficult program-synthesis tasks with verified demonstration diversification, rather than a new VLA architecture.

## Evidence and main results
| Finding | Evidence / setting | Location in paper |

| Strongest coding agent solves most benchmark tasks | GPT-6 Astra solves 82%, versus Fable 5.1 at 61% and GPT-5.6 Terra at 11%; Astra’s hack-adjusted mean rubric score is 0.94 ± 0.03. One run per model/task, 28 tasks, nominal four-hour budget, one RTX 4090. | §3.1; Tables 6, 8 |

| Additional tools improve partial credit, not completion consistently | Opus 5 mean score rises 0.66→0.70, but success falls 50%→43%; Sol score rises 0.44→0.51 with success unchanged at 18%. Tool runs use two GPUs instead of one. | §3.3; Table 7 |
| More generated demonstrations improve VLA performance overall | Authors report six-task mean success rising 18%→69% and rubric score 0.32→0.76 with 10→400 demonstrations per task. SmolVLA evaluation uses three training seeds and 32 episodes per policy; some task criteria are relaxed. | §4.2; Fig. 9; Appendix E; Table 22 |
| Diversification improves held-out rubric scores | With 1,000 training trajectories per task/setting and 256 held-out configurations, overall score is 0.233 ± 0.016 for agent-aided generation versus 0.066 ± 0.008 for script-only generation. These are scores, not success rates. | Table 1; Appendix E |
| Simulated finetuning transfers to one real task | After finetuning on 500 simulated demonstrations, cumulative lamp-disassembly milestone success is 100%, 80%, 30%, and 20% across ten trials; pretrained π0.5-DROID achieves 0% at every milestone across ten trials. | §4.3; Table 2 |
| Agent post-training improves training performance | On 400 generated environments, Seed-2.1-Lite task reward rises approximately 0.09→0.18 and success 2.7%→7.5%; no held-out evaluation was conducted. | Appendix G.2; Fig. 20 |

These results support simulation program synthesis and the usefulness of generated supervision on selected tasks. They do not establish generalist robot capability, reliable real-world deployment, or held-out benefits from coding-agent post-training. The PPO comparison favors coding programs on five selected tasks, but cannot establish superiority over reinforcement learning broadly (§3.1; Appendix C.2).

## Limitations and validity risks
- **Author-stated:** Solutions require substantial iteration and remain instance-specific. More complex dexterous hands, an end-to-end synthetic-task-to-VLA pipeline, visual grounding improvements, and held-out agent-training evaluation remain unresolved (Abstract; Appendix I).
- **Analyst inference—comparison controls:** Cross-embodiment transfer compares hinted Kinova/xArm7 runs against unhinted **Franka** runs, leaving embodiment difficulty confounded with hint benefit. Tool experiments also change GPU resources (§§3.2–3.3).
- **Analyst inference—evaluation strength:** Base results use one run per task/model; reported SEM across tasks does not measure repeated-run variability. Reward-hack detection relies on an Opus 5 audit, with no audit-accuracy validation reported (Appendix C.1).
- **Analyst inference—policy scope:** Some VLA successes mean inserting one pen or clearing one object, rather than completing the original benchmark task. Table 21 includes eight tasks although the main scaling analysis describes six; Appendix E’s single-arm observation format also leaves the humanoid clearing-task setup unclear (Tables 3, 21–22; Appendix E).
- **Analyst inference—real-world validity:** Hardware evaluation uses one reconstructed scene and a matching printed lamp. The deployed checkpoint was selected using real-robot performance, so simulation-only finetuning did involve real-world model selection (Appendix F).
- **Missing isolation:** The paper explicitly does not isolate diversification levels. Appearance variants can share identical physical trajectories, and per-task diversity allocations vary (Appendix D.3).

## Open research questions
1. **Which diversification levels drive generalization?** Their contributions are not isolated. Run equal-size, compute-matched leave-one-level-out ablations on the same held-out configurations.
2. **Does solution transfer help independently of embodiment difficulty?** Target-arm no-hint controls are absent. Compare hinted and unhinted runs on each target arm using paired seeds and budgets.
3. **How robust is sim-to-real transfer beyond the matched lamp setup?** Only one hardware task is evaluated, with real-performance checkpoint selection. Fix selection in advance and test new lamps, layouts, and additional tasks.
4. **Does coding-agent post-training generalize?** Only training improvements are reported. Evaluate frozen pre/post-training checkpoints on held-out generated tasks and EMBODIEDSWE-BENCH under identical budgets.

## Confidence and missing information
**Confidence: medium.** The supplied text contains extensive methods and results, but several comparisons have limited controls or reporting ambiguities.

Material gaps include per-level diversification effects, exact physical-trajectory versus rendering counts, audit reliability, target-arm no-hint results, held-out post-training results, real-robot checkpoint-selection trial counts, and reconciliation of the VLA task/setup inconsistencies. Actual repository and dataset availability cannot be confirmed from the supplied text alone.
