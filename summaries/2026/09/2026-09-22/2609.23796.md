# Mira-Scene: Pixel-Aligned Layouts for Generative 3D Scene

> [← Daily summary](../2026-09-22.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.23796) · [arXiv](https://arxiv.org/abs/2609.23796)


## One-sentence takeaway
Mira-Scene jointly generates object geometry and pixel-aligned canonical coordinates, then aligns those coordinates with estimated scene geometry, improving layout accuracy over SAM3D on two benchmarks evaluated with supplied instance masks and scene alignment (Table 1; §§E.2–E.3).

## Problem and motivation
Single-image scene reconstruction must recover detailed objects and place them coherently. The authors argue that holistic generation limits per-object detail, while compositional methods often regress sparse, unbounded pose parameters that are difficult to learn with limited scene supervision. They propose learning dense, bounded correspondences from abundant object assets instead (§1).

## Approach and contributions
- **Correspondence-based layout:** A Canonical Coordinate Map (CCM) assigns each visible object pixel a canonical surface coordinate. Pairing it with a scene-space Point Cloud Map (PCM) enables scale, rotation, and translation recovery using RANSAC and Umeyama alignment (§§2.2, 2.4).
- **Geometry–layout co-generation:** Separate rectified-flow transformer streams jointly generate voxel geometry and CCMs, exchanging information through shared attention and positional embeddings (§2.3). The novelty claimed is this integration with generation; the authors acknowledge earlier canonical-coordinate pose estimation (§B.2).
- **Object-level supervision:** Training uses 60K Objaverse assets rendered into 1M views, 20K background-completed views, and fine-tuning on 20K 3D-FRONT scene views (§2.5). The system initializes geometry from TRELLIS and uses SAM3D’s mesh refinement module, so these counts do not describe all inherited training exposure (§§D.2–D.3).

These results support improved layout under the reported protocol, including a matched-data comparison. They do not establish absolute metric placement: layout evaluation normalizes scenes and applies a shared scene-level ICP alignment, while 3D-IoU measures axis-aligned object boxes (§E.2). CCM–mesh consistency measures agreement between generated outputs, not ground-truth fidelity (§3.3).

## Limitations and validity risks
- **Author-stated:** Independent reconstruction can cause object intersections; noisy masks create floaters or missing parts; monocular geometry can collapse cartoon inputs into sheet-like structures; single-object generation remains weaker in some settings (Appendix F).
- **Analyst inference — deployment gap:** Ground-truth-mask quantitative comparisons do not establish end-to-end performance with automatic segmentation (§D.4).
- **Analyst inference — attribution:** Matched training data strengthens the representation claim, but token budgets, conditioning, targets, and downstream solvers differ across representations; the ablation does not isolate boundedness alone (§D.5).
- **Analyst inference — generalization and efficiency:** Real-image evidence is qualitative, BlendSwap’s size is unspecified, and inherited pretrained components complicate interpreting the authors’ data-efficiency claim (§§E.1, D.2–D.3). No uncertainty intervals or runtime measurements are supplied.

## Open research questions
- **How much does PCM quality determine layout accuracy?** Appendix F identifies depth failures without a controlled estimator comparison. Hold generated geometry and CCMs fixed; compare estimated, ground-truth, and deliberately corrupted PCMs.
- **How robust is the full pipeline to segmentation errors?** Quantitative results use supplied masks. Compare ground-truth masks, automatic masks, and controlled boundary or instance-omission errors.
- **Can joint scene constraints reduce intersections without harming alignment?** Independent generation causes collisions. Compare per-object assembly with joint refinement, measuring collision rates alongside layout metrics.
- **How much benefit comes from additional object supervision?** Table 5 shows a gain but not a scaling curve. Vary object-data volume while fixing pretrained initialization, scene data, and evaluation.
