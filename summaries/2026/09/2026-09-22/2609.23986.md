# Jev-Mem: System-One-Controlled Agentic Memory for Efficient AI Agents

> [← Daily summary](../2026-09-22.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.23986) · [arXiv](https://arxiv.org/abs/2609.23986)


## One-sentence takeaway

Jev-Mem separates lightweight memory control from generative reasoning, reporting better LoCoMo answer scores and lower construction and query times than evaluated baselines, although missing ablations and experimental details limit causal interpretation (§§4.2–4.3).

## Problem and motivation

Persistent agents accumulate more interaction history than they can reliably use within a prompt. Organizing and retrieving that history also becomes expensive when frequent decisions require autoregressive generation. The authors identify a gap between efficient but inflexible heuristics and flexible but costly LLM control: many memory operations need only bounded labels or scores, rather than generated text (§§1–2).

## Approach and contributions

- **Unified memory-control architecture:** A typed System-One controller manages both construction and retrieval; a shared memory plane stores evidence; System Two handles answer synthesis and optional textual consolidation. The claimed novelty is this lifecycle-wide separation, rather than the underlying Jev service itself (§§1, 3.1).
- **Evidence-preserving construction:** Canonical observations carry overlapping memory-type scores and semantic, temporal, causal, and entity links. Deterministic retrieval narrows relation candidates, while structured identifiers and timestamps avoid some learned judgments. Consolidation retains raw observations (§3.2; Appendix B.2–B.3).
- **Adaptive retrieval:** Hybrid lexical/vector anchors seed graph search. The controller routes queries, allocates traversal budgets, scores candidates, assesses evidence, and stops under sufficiency, utility, or resource limits (§3.3; Appendix B.4–B.5).

They do not isolate which architectural component produces the gains or establish generalization beyond LoCoMo. ## Limitations and validity risks

- **Author-stated qualifications:** Controller outputs are not assumed calibrated probabilities. Resource limits can stop retrieval with incomplete evidence, and the time budget is checked between operations rather than enforced through strict preemption (Appendix B.1, B.5).
- **Analyst inference—limited evaluation scope:** §4.1 announces two benchmarks, but only LoCoMo is named and reported. Likewise, §4.2 claims performance across six categories but supplies scores for only five named categories.
- **Analyst inference—unresolved attribution:** No reported ablations separate lightweight control, graph structure, hybrid anchors, candidate scoring, or adaptive stopping. Explanations assigning gains to these mechanisms remain author interpretations.
- **Analyst inference—comparison uncertainty:** Hardware, service configuration, judge identity/prompt, evaluation sample counts, repeated runs, and uncertainty estimates are absent. Missing table bodies also prevent identifying several best-baseline comparators.
- **Analyst inference—scaling remains untested:** Preserving every valid observation avoids irreversible evidence loss, but bounded per-operation search does not establish bounded storage or sustained performance as histories grow (§3.2; Appendix B.2).

## Open research questions

1. **Which components drive the quality–latency improvement?** No component ablations are reported. Compare fixed versus adaptive retrieval and heuristic, Jev, and autoregressive controllers while holding the memory representation and answer model constant.
2. **How robust is stopping with uncalibrated scores?** The paper specifies thresholds but provides no calibration or sensitivity evaluation. Sweep stopping thresholds and measure answer quality, evidence completeness, and latency.
3. **Does performance persist as memory grows and changes?** Only the reported LoCoMo setting supports the empirical claims. Evaluate progressively longer interaction streams with contradictions and obsolete facts, tracking storage, retrieval recall, and runtime.

## Confidence and missing information

**Confidence: medium.** The architecture and narrative results are explicit, and Appendix B provides useful implementation settings. Confidence in reproducibility and broad superiority is lower.

Material missing information includes complete result tables, the claimed second benchmark and sixth category, controller model/version details, embedding configuration, hardware and service conditions, judge protocol, sample counts, run variability, and component ablations. Public code availability is an author claim, not independently verified here.
