# Editable Visual Design

> [← Daily summary](../2026-09-04.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.04034) · [arXiv](https://arxiv.org/abs/2609.04034)


## One-sentence takeaway
Editable Visual Design combines generated visual references and standalone assets with agent-written HTML/CSS to produce editable designs, supported by qualitative single-page examples rather than measured performance gains (§§2–3, 5).

## Problem and motivation
The authors identify a gap between image generation, which produces visually rich but flattened outputs, and code generation, which supports precise text and editable structure but struggles with aesthetics and complex assets. They aim to combine visual quality with independently editable text, images, and backgrounds for downstream design work (§1).

## Approach and contributions
- **Image-guided code generation:** A VLM first requests an imagined finished design, interprets its composition and colors, then generates separate assets and writes HTML/CSS. The reported implementation uses Codex with GPT-5.6 Sol and GPT Image 2; the imagined image’s pixels never enter the deliverable (§§2–2.3).
- **Structured delivery and repair:** Fixed-size canvases contain separately tagged DOM layers. Browser checks identify structural problems, while screenshot-based VLM review guides local code repairs. Users can edit text, move and scale assets, and export layers (§§2.3–2.5).
- **Agent Design Replay:** Recorded planning, asset prompts, code changes, and review steps expose the production trajectory (§2.5).

The contribution is a workflow integrating existing model capabilities and structured delivery, rather than a newly trained model (§§4.1, 5).

The supplied descriptions support feasibility on showcased designs. They do not establish average aesthetic improvement, editing efficiency, failure rates, or superiority across representative briefs. Layer counts establish structural complexity, not practical usability; the authors explicitly acknowledge this distinction (§5).

## Limitations and validity risks
- **Author-stated:** Quality remains bounded by both underlying models; ordinary visual references and poorly separated assets constrain results (§5).
- **Author-stated:** All reported cases are single-page designs. Maintaining consistency across decks or websites remains unresolved (§5).
- **Author-stated:** Aesthetics are assessed through cases and VLM judgment, and editability lacks a demonstrated designer-centered measure (§5).
- **Implementation boundary:** Green-background matting requires the subject itself to contain no green; layouts use fixed dimensions (§2.3).
- **Analyst inference:** Without component ablations, the contribution of imagined references cannot be separated from asset generation or visual repair. The qualitative comparison also lacks reported sampling and budget controls (§3).
- **Analyst inference:** Replay demonstrates recorded process visibility, but reproducible reruns and faithful access to the full decision process are not independently validated (§§2.5, 3.3).

## Open research questions
- **Does the imagined reference independently improve aesthetics?** No ablation isolates it. Compare matched workflows with and without that step, holding asset generation and repair budgets constant, using blinded designer ratings (§§2.1–2.4, 3).
- **Does DOM layering improve practical editing?** The paper reports structural properties rather than designer task performance. Measure completion time and errors on standardized text, layout, and asset edits (§5).
- **Can the workflow maintain consistency across pages?** Evaluation is restricted to single-page outputs. Test related multi-page briefs and assess typography, palette, and layout consistency (§5).
- **How reliably does visual review detect defects?** Replay examples show repair and acceptance, without aggregate accuracy. Evaluate reviewer detection and repair on designs with independently annotated defects (§2.4, Fig. 5).

## Confidence and missing information
**Confidence: medium.** The workflow is clearly described, but efficacy rests on author-reported qualitative cases.

Material omissions include quantitative evaluations, human editing studies, component ablations, case-selection protocol, repeated-run variability, latency/cost measurements, full implementation and prompting details, and confirmed public code or artifact availability. The supplied text includes figure captions and image links, but not inspectable figure pixels.
