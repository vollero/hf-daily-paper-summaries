# TimeEvo: Failure-Driven Self-Evolution of a Time Series Agent

> [← Daily summary](../2026-09-28.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.27277) · [arXiv](https://arxiv.org/abs/2609.27277)


## One-sentence takeaway
TimeEvo synthesizes tools from a frozen time-series agent’s failures and screens their repairs against regressions, reporting positive accuracy gains across all 30 main task–backbone settings, although supporting runs show that admission does not guarantee improvement.

## Problem and motivation
A fixed analytical tool library can help some questions while hurting others. Generic answer revision can likewise repair errors and break correct answers, with average accuracy concealing that turnover. The authors demonstrate both effects and argue that tool development should follow observed capability gaps, while evaluation should explicitly count repairs and regressions (§1, Fig. 1).

The target is closed-option time-series question answering, where labeled examples allow automatic correctness checks—not unrestricted autonomous analysis (§3.1).

## Approach and contributions
- **Failure-driven tool construction:** Cluster training errors by missing capability, write measurement contracts with applicability boundaries, and coordinate overlapping proposals. Updates can create, refine, rescope, or retire artifacts (§3.3).
- **Constrained synthesis:** Generate deterministic Python tools returning numerical evidence rather than answer verdicts. Tools can optionally use Chronos-2 or training-only decision-tree calibration; candidates undergo execution checks and an attributable-repair prefilter (§3.4).
- **Library-level admission and conservative review:** Compare current and candidate libraries on identical validation questions, counting answers helped and harmed. Admission uses a positive lower-bound criterion or a supplementary single-round rule; rejection permits one pruning attempt. At inference, scoped tools review an existing answer, with fallback when execution or replacement fails (§§3.2, 3.5).
- **Empirical diagnosis and transfer:** Evaluate curated tools, generic revision, evolved libraries, and cross-model reuse. The distinctive contribution is their integration with explicit regression accounting; the supplied comparisons do not establish superiority over other self-evolving agent systems (§§2.2, 4).

## Evidence and main results
| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Main comparison consistently improves the base | Across ten tasks and three backbones, all 30 TimeEvo deltas are positive. Reported ten-task mean gains: **+8.79 pp** for luna, **+7.21 pp** for terra, **+8.73 pp** for mini. | Table 1, §4.2 |
| Curated tools can hurt their intended task | TimeART’s 21-tool library reduces Time-MQA Anomaly test accuracy by **6.25 / 8.75 / 5.79 pp** under luna / terra / mini. TimeEvo gains **14.69 / 12.50 / 16.25 pp**, respectively. | Table 1, Fig. 3a |
| Aggregate revision scores conceal turnover | On luna across ten tasks, Self-Refine changes **147** answers: **49** fixes, **56** regressions, and **42** wrong-to-wrong changes; reported mean delta is **−0.93 pp**. | §1, Fig. 1b, Table 1 |
| Libraries transfer across models | Installing luna-evolved libraries gives reported ten-task mean gains of **+10.50 / +10.65 / +8.27 pp** for opus-5 / sonnet-5 / sol. Sol’s Classification result falls **2.50 pp**. | Table 1, §4.3 |
| Conservative review trades repairs for fewer regressions | With identical libraries, Anomaly/mini review fixes **33** and harms **19** answers; unconditional overwrite fixes **58** and harms **59**. | Table 5 |
| Admission is imperfect | Authors report one accepted T1 library with **−1.27 pp** test delta and one rejected Merrill candidate with a diagnostic **+5.00 pp** delta. | §4.4, Fig. 5b |

These results support useful task-specific tool synthesis and cross-model reuse on the supplied suite. They do not establish elimination of answer-level harm, superiority on every individual task over every baseline, or generalization to new datasets. Table 1’s uniformly positive results and the negative accepted run in Fig. 5 require distinguishing the reported run collections.

## Limitations and validity risks
- **Acknowledged residual risk:** In-scope questions can still regress. The supplementary admission rule does not require a positive lower bound, and the authors report both false acceptance and false rejection (§§3.2, 3.5, 4.4).
- **Analyst inference—limited generalization:** Evaluation uses adapted closed-option tasks with labeled training and validation data. Cross-model transfer reuses the same tasks; cross-dataset, open-ended, and deployment-shift robustness remain untested (§4.3, Appendix A).
- **Analyst inference—limited causal isolation:** Ablations cover only Anomaly and TSAQA-DT under two backbones. Their base accuracies vary between configurations, complicating attribution; repeated-run uncertainty is not reported (Table 4).
- **Reporting inconsistencies:** The text says removing scopes costs 1.00–9.25 points, while Table 4’s gain-gap entries differ. It describes alternative roots as uniformly inferior, but Anomaly/terra with a Chronos root gains **15.00 pp**, versus **12.50 pp** for the empty-root full method, despite lower final accuracy (§4.4, Table 4).
- **Analyst inference—validation reuse:** Pruning, scope reconciliation, and subsequent checks reuse validation evidence. The paper limits retesting but provides no correction or demonstrated statistical coverage for this adaptive selection (Appendix C).
- **Resource comparison remains incomplete:** Synthesis-attempt counts are supplied, but end-to-end token, latency, and monetary costs are absent. The budget interpretation of baseline comparisons therefore remains uncertain (§4.2, Tables 6–7).

## Open research questions
1. **Does admission remain reliable under distribution shift?** Validation-positive libraries sometimes fail on test. Next experiment: freeze libraries and measure repairs, harms, and gate calibration on new source datasets.
2. **How much benefit comes from calibration versus generated measurements?** Removing calibration rejects both tested Anomaly libraries, leaving their contributions entangled. Next experiment: hold measurements fixed and compare calibrated and uncalibrated evidence across repeated runs.
3. **Does extended evolution remain useful without validation overfitting?** The main protocol uses one round, with only one illustrated three-round trajectory. Next experiment: evaluate repeated evolution across tasks using fresh admission sets and a final untouched test set.

## Confidence and missing information
**Confidence: medium.** The method and main results are well specified, but inconsistent supporting summaries weaken confidence in broad claims.

Material missing information includes repeated-run variance, exact aggregation behind Table 1, reconciliation of main and diagnostic run collections, complete prefilter harm/error thresholds, end-to-end costs, and an explicit account of how calibrated decision boundaries satisfy the evidence-only output contract. Code availability is claimed but was not independently verified.
