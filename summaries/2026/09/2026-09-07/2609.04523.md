# MaxKernel: Agentic Kernel Generation for TPUs

> [← Daily summary](../2026-09-07.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.04523) · [arXiv](https://arxiv.org/abs/2609.04523)


## One-sentence takeaway
MaxKernel’s parallel agent search reports 50/50 correct TPU kernels and a 1.58× geometric mean speedup over XLA on JaxBench, with regressions floored at 1× in the aggregate metric (§3.2, Table 1).

## Problem and motivation
High-performance TPU kernels require specialized memory management, tiling, compiler debugging, and empirical profiling. The authors identify a gap between generating plausible code and producing correct, fast implementations: static LLM completions lack execution feedback, while optimization can require sustained debugging before a promising design becomes viable (§1).

## Approach and contributions
- **Modular kernel engineering framework:** Specialized agents plan, implement Pallas code, fix compilation errors, synthesize and execute tests, autotune configurations, and analyze XProf traces. Retrieval supplies static hardware and framework documentation, explicitly excluding hand-tuned kernel code (§§2.1–2.2).
- **Three orchestration modes:** Human-in-the-loop execution pauses after each sub-agent; Auto iterates through generation, validation, tuning, and profiling; graph search coordinates parallel or beam exploration using Auto workers (§§2.3–2.5).
- **Validation and search infrastructure:** Auto freezes tests before optimization and restores the fastest valid candidate. Graph search persists candidate states and isolates expansions into separate sessions (§§2.4–2.5).
- **Empirical contribution:** The paper evaluates the integrated system on existing JaxBench tasks and selected model kernels. Its contribution is the framework and evaluation; it does not introduce JaxBench or establish that its individual search and retrieval techniques are new (§3).

These results support improved tested correctness and device execution speed for the evaluated settings. They do not establish universal correctness, generation-cost efficiency, or broad superiority to experts. **Table 2 contradicts its accompanying prose:** analyst counting finds five workloads where at least one agent strictly beats the human reference, one rounded tie, and two losses—not seven wins. The table also assigns the 6.74× Paged Attention result to Parallel, whereas the prose attributes it to Beam.

## Limitations and validity risks
- **Author-acknowledged scope:** All experiments use Gemini 3.1 Pro; other LLM ablations remain future work (§3.2). The authors attribute Beam’s plateau partly to insufficient debugging time before pruning (§3.3).
- **Analyst inference—metric interpretation:** Flooring regressions at 1× suppresses their aggregate penalty. Reported geometric means therefore do not describe uncensored performance (§3.1).
- **Analyst inference—correctness coverage:** Frozen generated tests prevent subsequent test alteration but do not prove correctness beyond tested inputs. Tolerances reach 0.1; test counts and input coverage are unavailable (§§2.4, 3.1; Appendix A).
- **Analyst inference—causal attribution:** Search methods use different iteration allocations, and Auto reports medians while Parallel selects best outcomes. No matched-cost comparison or isolated ablation of retrieval, profiling, or agent decomposition is reported (§§3.1–3.3).
- **Reporting ambiguity:** Correctness is defined over compiled kernels, but Table 1 reports counts out of all tasks. Its relationship to the stated conditional metric is unclear (§3.1, Table 1).
- **Reproducibility limits:** The supplied text lacks exact model-workload shapes, generation costs, timing uncertainty, and quantitative HITL evaluation.

## Open research questions
- **Would Beam improve with longer debugging budgets?** Its proposed failure mechanism is not isolated (§3.3). Compare search strategies at matched LLM and TPU budgets while varying inner-loop length.
- **Which components drive the gains?** The integrated evaluation does not separate retrieval, profiling, and agent specialization. Ablate each under fixed search budgets.
- **How well do generated kernels generalize?** Tests use specified tolerances on one TPU generation. Evaluate held-out shapes and edge cases, tighter tolerances, and another TPU generation.

## Confidence and missing information
**Confidence: medium.** The supplied text supports the architecture and tabulated results, but internal comparison errors weaken broader claims. Material gaps include full per-task timings, uncensored speedups, test coverage, timing repetitions and uncertainty, search costs, workload shapes, and component ablations. The stated code release was not independently inspected.
