# WebFovea: When the Model Is Right but the Click Is Wrong -- Reliable Round Trips for Vision-Based Web Agents on Live Websites

> [← Daily summary](../2026-10-08.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.03036) · [arXiv](https://arxiv.org/abs/2610.03036)


## One-sentence takeaway

WebFovea’s browser-harness improvements accompanied a rise from 31.0 to 57.0 on the WebRetriever Challenge hidden set with the model fixed, although bundled changes and single live-site runs prevent isolating each component’s contribution (§5.2, §6.2).

## Problem and motivation

Vision-based web agents can choose the right action yet fail because the harness misparses it, clicks the wrong coordinates, silently fails to enter text, misreports page changes, or omits necessary visual evidence. The authors identify this model–browser interface as an underexamined source of apparent reasoning failures (Introduction, §4).

The target is verifiable retrieval through live websites’ own interfaces: a correct answer must also have a valid trajectory reaching its evidence. This matters when models answer from memory, invent trajectories, or encounter reference answers that no longer match live data (Introduction, §3, §5.5).

## Approach and contributions

- **Diagnostic framework:** Treat each interaction as four stages—parsing, execution, feedback, and observation—with rule and resource guardrails around the loop (Figure 1, §4.1).
- **Implemented harness:** Preserve the reference implementation’s observe–think–act loop while adding output sanitization, screenshot-to-viewport coordinate alignment, element-aware input actions, iframe execution fallback, frame-aware change feedback, and visual-evidence tools. The model receives screenshots rather than a DOM tree; limited DOM access supports execution, feedback, and text verification (§4.1–§4.5).
- **Empirical engineering evidence:** Report challenge performance, targeted paired comparisons, calibration experiments, offline parser replay, failure cases, and unsuccessful interventions. This is a harness contribution rather than a newly trained model or benchmark (§5).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Official performance improved with the model fixed | Four submissions on 100 hidden tasks rose from 31.0 to 57.0; final placement was 2nd, with no manual-review deduction. Changes were bundled. | Abstract; §3; §5.2; Table 4 caption |
| Coordinate correction removed demonstrated targeting error | Three real-page targets previously missed by 122–189 pixels were hit within 1–5 pixels after alignment. | §4.3; Figure 3 |
| Alignment-containing version substantially improved local success | Paired comparison on 24 development tasks: 8/24 → 20/24 solved, 12 fixed and none broken; step-limit incidence 67% → 4%. Other changes were included, and the baseline retained a shortcut. | §4.3; §5.3 |
| Token stripping selectively altered recorded contaminated outputs | Offline replay changed all 551 contaminated steps and none of 7,154 clean steps, across 7,705 recorded steps. This measures parser selectivity, not online task recovery. | §4.2 |
| Feedback alone failed to resolve repetition | On 10 idle-looping tasks, adding no-change notes left success at 0/10 and total steps at 400. | §5.4 |
| More steps helped after upstream fixes | On eight targeted tasks, raising the limit from 40 to 80 increased solved tasks from 0–1 to 4; two successes required more than 40 steps. | §5.3–§5.4 |
| Text verification showed no demonstrated recovery | `read_text` was used on five of six targeted tasks, fixing none and breaking none. | §5.4 |
| Evaluation was costly under the mandated endpoint | A 100-task run cost approximately $170–230; prompt caching was unavailable. | §5.6 |

The evidence supports concrete interface defects and useful engineering remedies. It does not establish a clean causal effect for every component, statistically reliable component gains, or superiority over leaderboard agents evaluated on different task sets. The authors explicitly characterize the small component studies as directional (§2, §5.3, §6.2).

## Limitations and validity risks

**Author-stated limitations:** All results use `claude-opus-4-6`; some fixes address that model/API’s behavior. There is no reference-implementation submission on the hidden set. Component studies use targeted samples of 1–24 tasks, and each official score represents one live-site run. Public development results are not comparable to leaderboard scores (§6.2).

Live-site validity is also imperfect: the authors identify 13 public tasks with changed data or mismatched metric definitions and 16 sites unreachable from their network. The best-outcome failure analysis combines multiple runs and is an upper bound rather than a single-version score (§5.5).

**Analyst inference:** Bundled interventions leave interactions between calibration, observation tools, budgets, and feedback unresolved. Moreover, selective parser replay demonstrates preservation of recorded clean outputs but cannot establish how sanitized outputs alter subsequent online trajectories (§4.2, §5.2–§5.3).

## Open research questions

- **Do the fixes transfer across models and endpoints?** Only one model was tested (§6.2). Next experiment: repeat calibration and paired harness comparisons across several models/endpoints.
- **Which components independently improve completion?** Official submissions bundled changes, and targeted comparisons sometimes changed multiple components (§5.2–§5.3). Next experiment: repeated component ablations and interaction tests on a fixed task panel with timestamped evidence.
- **Can richer feedback prevent loops on visually dynamic pages?** DOM feedback alone did not change repetition, and canvas/image change detection remains proposed (§5.4, §6.3). Next experiment: compare DOM fingerprints, visual change detection, and their combination under identical budgets.
- **Can independent verification reduce answer-selection errors?** A fresh-context verifier is proposed but unevaluated (§6.3). Next experiment: compare completion with and without verification, measuring corrections, false rejections, and added cost.
