# DAEDALUS: Bootstrapping Agent Memory from Self-Generated Tasks

> [← Daily summary](../2026-10-07.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.08048) · [arXiv](https://arxiv.org/abs/2610.08048)


## One-sentence takeaway
Daedalus builds procedural memory from self-generated practice and failure-to-success validation, improving agent success on three benchmark subsets without curated task instructions, oracle verification during memory construction, or weight updates (Sections 3–4).

## Problem and motivation
Agents entering unfamiliar environments repeatedly discover tool behavior and operational conventions, causing avoidable failures and longer executions. The authors identify a supervision gap: existing memory methods commonly require curated tasks and verifiers, while learning from deployment tasks leaves initial users exposed to failures (Section 1).

## Approach and contributions

- **Autonomous, calibrated practice:** An Explorer creates and completes tasks with explicit success conditions, then adjusts their difficulty using Solver outcomes. A Surveyor and accumulated task-design guidelines improve coverage and generation efficiency (Section 3).
- **Failure-to-success memory validation:** An Extractor derives or revises guidance from failed Solver trajectories. A heuristic is accepted only after an initial failure followed by three consecutive LLM-judged successes; retries reset the environment. The Extractor receives no detailed success-condition feedback (Sections 3, 4.1).
- **Consolidated procedural memory:** Accepted heuristics are merged into a frozen bank and injected at task start without updating model weights. The experiments compare this with retrieval and alternative injection policies (Sections 3, 5.2).
- **Additional empirical contributions:** The paper tests transfer across model families and whether generated tasks preserve model rankings from an official benchmark. The authors report releasing code, prompts, tasks, memory banks, and trajectories (Sections 4.2, 5.3; reproducibility statement).

The evidence supports useful memory and local transfer in the tested settings. Counterfactual replay strengthens evidence that accepted heuristics help their source tasks. It does not establish universal environment coverage, negligible total cost, or general validity of generated evaluation sets. The authors’ “within error margins” comparisons are not equivalence tests.

## Limitations and validity risks

**Author-stated limitations:** Memory is built once and frozen; preliminary iterative updates did not consistently help. Exploration requires resettable environments where the Explorer can act alone, excluding dual-control settings. LLM verification remains imperfect, and consolidation can alter heuristic scope as banks grow (Appendix B).

**Analyst inferences grounded in the setup:**

- Evaluation covers selected subsets, with most ablations and the ranking-proxy study confined to AppWorld; broader generalization remains untested (Sections 4.1, 5).
- One bank per method means inference-run errors do not capture variability between independent memory-generation runs (Section 4.1).
- Matched session counts do not equal matched compute: Daedalus uses substantially more Solver rollouts than baselines (Appendix E).
- Baseline adaptations limit conclusions about their original full systems; for example, ReasoningBank omits test-time scaling and ACE uses an offline, ADD-only configuration (Appendix E).
- The main AppWorld bank replaces seven filtered tasks with successful scaling sessions, while task analyses use the original 81 accepted tasks. This complicates alignment between headline memory results and task-level analyses (Appendix E).

## Open research questions

- **How can memory scale without corrupting advice?** Larger banks lose performance through scope changes. Next experiment: compare scope-preserving consolidation and retrieval across increasing budgets and multiple environments (Appendix B).
- **How much improvement comes from method design versus extra compute?** Construction budgets differ substantially. Next experiment: compare Daedalus, PREPING, and curated-task methods under equal token or dollar budgets (Appendix E).
- **Can verification improve outside benchmark settings?** Judge agreement is imperfect, and generated-task correctness lacks independent oracle confirmation. Next experiment: audit generated tasks and compare single judges, judge ensembles, and executable checks (Section 5.1; Appendix B).
- **Do generated tasks rank models beyond AppWorld?** The proxy result is confined to one benchmark and solver-calibrated task set. Next experiment: repeat ranking comparisons across environments and calibration models (Section 5.3).

## Confidence and missing information

**Confidence: medium.** The supplied text contains substantial methodological and numerical evidence, but several validity questions remain.

Materially unavailable: complete prompt contents, underlying trajectories and per-task results, independent generation-seed variability, detailed numerical data from several figures, and verified repository contents. The release is an author claim; its artifacts were not inspected.
