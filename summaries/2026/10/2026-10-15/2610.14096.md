# SWEeper-Bench: Can Agents Discover Bugs in Interactive Software?

> [← Daily summary](../2026-10-15.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.14096) · [arXiv](https://arxiv.org/abs/2610.14096)


## One-sentence takeaway
SWEeper-Bench evaluates autonomous discovery and repair of interaction-dependent web bugs, with the best tested agent passing 59.0% of tasks and detailed bug descriptions raising five agents to 96.0–96.5% (§§3.1, 4.2).

## Problem and motivation
Interactive software can fail only after particular sequences of user actions, leaving users responsible for discovering and reporting problems. The authors identify a gap in benchmarks that provide an existing bug report: these evaluate diagnosis and repair while largely bypassing discovery (§1).

## Approach and contributions
- **Discovery benchmark:** 200 tasks from 200 open-source web applications, each derived from a real merged bug fix. Agents receive a product-area request, buggy source, a running application, shell tools, and a browser, without the original issue or reference repair (§§2.1–2.2).
- **Behavior-based verification:** A source-blind verifier tests the patched application through its browser interface. Success requires both restoring the target behavior and preserving a nearby behavior (§2.3).
- **Empirical diagnosis:** Evaluations, trajectory analysis, and prompt, harness, and time-budget experiments investigate where discovery fails and how much assistance improves performance (§§3–4).

## Evidence and main results
| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Discovery remains difficult | Among 15 agents on 200 tasks with browser instructions and an 8-hour limit, Grok 4.6 with Cursor leads at 59.0%; nine agents pass fewer than half. Success requires both behavior tests. | §3.1; Table 2 caption |
| Failures mostly concern the target bug | Preservation-test pass rates across agents are 97.5–100%, while nearly all failures arise on the target test. | §3.1 |
| Identifying buggy behavior is the largest stage drop | Averaged over 14 agents, cumulative trajectory shares are 75.4% for reaching the feature, 50.0% for identifying buggy behavior, 43.8% for diagnosing the cause, 41.0% for target-test success, and 40.8% for joint success. | §3.2 |
| Bug descriptions substantially improve success | Five agents achieve 96.0–96.5% with detailed prompts versus 35.0–51.5% with open-ended prompts; GPT-5.6 Sol has 199 detailed-prompt tasks. | §4.2; Table 4 caption |
| Browser prompting changes behavior and outcomes | Removing the instruction reduces browser use from all 200 tasks to 2 for GPT-5.6 Luna and 6 for GLM 5.3; pass rates fall from 42.0% to 39.5% and 43.5% to 31.5%, respectively. | §4.1 |
| Verifier calibration is strong on known endpoints | Three verifier configurations, each run three times over 200 tasks on buggy/reference versions, stay within one percentage point of ideal behavior-test rates; standard deviation is at most 0.8 points. | §2.3; Table 1 caption |
| Additional time shows limited evidence of benefit | Three agents receive 20-, 40-, 60-, and 80-minute budgets on the same 40 tasks; rates improve to 40 minutes but not thereafter. Authors report differences are not statistically significant. | §4.4; Figure 10 |

The evidence supports the authors’ conclusion that discovery is a major bottleneck in this setting. **Analyst inference:** detailed prompts also narrow the search space and clarify expected behavior, so the comparison does not isolate failure recognition alone. Verifier calibration on buggy and reference versions does not establish accuracy for every alternative agent patch.

## Limitations and validity risks
- **Author-stated:** Only web applications are covered; one known bug is scored per task. Other valid repairs receive no credit, and unnecessary changes are penalized only when a preservation test catches a regression (§6).
- **Author-stated:** Tests cover functional correctness, excluding visual design, usability, and responsiveness (§6).
- **Author-stated:** The time-budget experiment is small and its differences are not statistically significant (§4.4).
- **Analyst inference:** High preservation scores establish success on the selected nearby behavior, not comprehensive regression safety (§2.3).
- **Analyst inference:** Discovery-stage judgments depend on GPT-5.6 Luna using reference-derived descriptions; independent validation of these labels is not reported in the supplied text (§3.2).
- **Analyst inference:** Main comparisons combine models with different harnesses. The harness experiment isolates this factor for only GPT-5.6 Luna, limiting model-only attribution (§§3.1, 4.3).

## Open research questions
1. **Can structured exploration improve discovery?** Agents often reach the relevant feature without triggering the failure (§3.2). Compare systematic scenario planning against the default workflow under matched time and cost budgets.
2. **Can agents recognize failures despite misleading existing tests?** The Focalboard example shows tests reinforcing an incorrect expectation (§3.2). Evaluate explicit behavioral-expectation checks on tasks with conflicting tests.
3. **How accurately does the verifier judge unconventional repairs?** Calibration uses buggy and reference versions (§2.3). Compare verifier verdicts with independent human judgments on diverse agent patches.
4. **Can evaluation measure useful discoveries and unnecessary changes together?** Current scoring rewards one target bug and incompletely penalizes extraneous changes (§6). Audit all reported issues and edits to measure discovery precision alongside target recall.

## Confidence and missing information
**Confidence: medium.** The narrative clearly supports the central findings, but the supplied retrieval omits the bodies of Tables 1–5 and the numerical contents of most figures. Material gaps include the complete agent leaderboard and costs, per-harness results, all task/test specifications, independent trajectory-label validation, and explicit benchmark release/access details.
