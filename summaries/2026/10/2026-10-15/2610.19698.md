# RuleTrek: Benchmarking Agentic Rule Reasoning in Complex Scenarios

> [← Daily summary](../2026-10-15.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.19698) · [arXiv](https://arxiv.org/abs/2610.19698)


## One-sentence takeaway
RuleTrek evaluates rule identification and application across distributed files, with the best tested agent reaching a 55.29% end-to-end score on its human-verified benchmark (§§3–4).

## Problem and motivation
Specialized tasks require agents to find applicable rules, recover dependencies and exceptions, and apply them to evidence scattered across files. The authors argue that existing rule benchmarks simplify scenario evidence, while realistic workspace benchmarks rarely isolate domain-rule reasoning (§§1–2). RuleTrek combines these demands in interactive workspaces.

## Approach and contributions
- **Benchmark and diagnostic settings:** RuleTrek contains 240 instances across six domains. Rule Identification (RI) requires recovering applicable rules and dependencies; Rule Deduction (RD) supplies the verified rule graph; End-to-End Rule Reasoning (E2E) requires finding and applying rules (§§3.5, 4.1).
- **Construction pipeline:** GPT-6-Astra extracts rule graphs, generates rule-specific sub-scenarios, and composes them according to dependencies. Human reviewers verify rules, cross-file consistency, solvability, and answer uniqueness throughout construction (§§3.1–3.4; Appendix A).
- **Empirical diagnosis:** Evaluation of 11 models examines performance, graph complexity, failure types, interaction behavior, and scoring reliability. The authors report public code and dataset availability; this analysis does not verify the release (Abstract; §4).

## Evidence and main results
Scores use a 0–100 scale and average three temperature-1 runs over 240 instances. RD/E2E multiply binary answer correctness by a reasoning score; missing or failed submissions receive zero (§4.1). They are therefore **composite scores, not plain accuracy**.

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Rule identification remains difficult | Across 11 models, GPT-6.1-Sol leads RI at 62.47%, followed by Grok-4.7 at 61.86%. | §4.2; Table 2 referenced |
| Providing rules leaves substantial difficulty | GPT-6.1-Sol leads RD at 60.43%; E2E scores across models range from 26.97% to 55.29%, with GPT-6.1-Sol highest. | §§4.2, 4.6 |
| Larger rule graphs associate with lower scores | Mean E2E across 11 models falls from 76.5 to 23.6 between task bins with ≤3 and ≥14 nodes; from 62.3 to 26.4 between depth bins ≤1 and ≥5 edges. | §4.4; Figure 3 |
| Explicit graphs improve reported performance | RD exceeds E2E by 3.79–8.15 points across seven models on the same scenarios and questions. | §4.5; Figure 4 |
| Rule selection dominates one model’s failures | Rule-selection errors constitute 54.9% of GPT-6.1-Sol’s failed trajectories, classified by earliest decisive error. | §4.5 |
| Automatic scoring broadly agrees with humans | Human–judge Spearman correlations are 0.822–0.857 across tasks, versus 0.933–0.951 human–human agreement. Alternative judges yield submission correlations of 0.903–0.934 and ranking correlations of 0.955–0.991 against the primary judge. | §4.7; Table 5 referenced |

The evidence supports difficulty in both finding and applying rules under this benchmark’s execution conditions. **Analyst inference:** the complexity trends are observational; they do not isolate graph complexity from domain or scenario differences. Likewise, supplying a graph changes both rule availability and representation, so the RD–E2E gap does not cleanly measure rule identification alone.

## Limitations and validity risks
- **Author-stated:** Evaluation covers English and predefined repositories; multilingual and dynamically changing environments remain outside scope (§6).
- **Analyst inference:** LLM-generated, expert-revised scenarios offer controlled testing, but transfer to independently collected operational cases is untested in the supplied text (§3; Appendix A).
- **Analyst inference:** No controlled ablation isolates file distribution, graph structure, or the construction pipeline’s individual stages. The reported difficulty cannot be attributed uniquely to any one factor (§§3–4).
- **Scoring ambiguity:** §4.1 describes answer correctness as assessed by the judge, whereas Appendix D.5 says deterministic code checks it separately. The exact implementation is unclear.
- **Incomplete retrieved detail:** Many tables, plots, and prompt figures appear only as captions. Full domain results, verification statistics, rubric anchors, and complexity-bin counts cannot be inspected here.

## Open research questions
- **What causes the complexity penalty?** Graph size and depth correlate with difficulty without controlled matching (§4.4). Next experiment: vary dependencies while holding domain, evidence volume, and file count fixed.
- **Which rule representation best supports deduction?** RD improves performance but remains limited (§4.5). Next experiment: compare matched original rule excerpts, flat rule lists, and dependency graphs containing identical rule content.
- **Can explicit state tracking reduce application failures?** The game case illustrates stale-state propagation, but supplies no systematic intervention (Appendix C.1). Next experiment: add a structured state ledger and compare state-update errors and E2E scores.
- **Do results transfer beyond static English scenarios?** Both boundaries are acknowledged (§6). Next experiment: evaluate matched multilingual instances and controlled rule updates.

## Confidence and missing information
**Confidence: medium.** The supplied prose clearly establishes the benchmark design and headline findings, but omits substantive table and figure contents.

Material missing information includes full per-model/domain results, run variability or confidence intervals, exact prompts and scoring anchors, deterministic answer-checking details, quantitative construction-quality results, and the denominator and annotation procedure for the reported failure breakdown.
