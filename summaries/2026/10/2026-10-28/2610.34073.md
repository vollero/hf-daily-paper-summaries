# Memory Tax: Dissecting the Net Value of Agent Memory

> [← Daily summary](../2026-10-28.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.34073) · [arXiv](https://arxiv.org/abs/2610.34073)


## One-sentence takeaway

Across the tested settings, constructed agent memory often loses more answers than it gains over raw-history retrieval, with evidence loss, retrieval difficulty, and backbone sensitivity helping explain this “memory tax” (§§3–5).

## Problem and motivation

Memory systems reorganize interaction histories to support future queries, but their added value can be confused with the value of retrieving relevant evidence. The authors identify insufficiently specified or absent raw-history RAG controls in prior evaluations and ask when memory construction justifies its accuracy and computational costs (§1; Appendix B.2).

## Approach and contributions

- **Reference-relative evaluation:** Compare representative flat, hierarchical, graph-based, and trained-policy memories against raw-history RAG across conversational benchmarks and three QA backbones. The RAG reference uses BM25 plus dense retrieval and reranking; “naive” therefore means minimal history transformation, rather than lexical retrieval alone (§3.1; Appendix A.2).
- **Benefit–tax decomposition:** Count queries memory answers correctly that single-round RAG misses as benefit, and queries RAG answers correctly that memory misses as tax. Their balance gives the accuracy difference relative to that reference (§4.1).
- **Diagnostic analysis:** Use oracle evidence, human preservation annotations, retrieval replay, similarity shifts, and cross-backbone evaluation to investigate faithfulness, accessibility, and robustness (§§4.2–4.4).
- **Extensions and design implications:** Examine experiential and world-model memory, then propose source-history recovery and reuse of past query–evidence pairs as simple modifications. These are evaluation and design contributions rather than a new memory architecture (§§5–6).

These results support a setting-dependent comparison, not a universal rejection of memory. The decomposition measures disagreement in correctness relative to a particular RAG pipeline; it does not by itself prove the cause of each error. Oracle and annotation analyses provide additional diagnostic evidence, but many supporting numerical tables and figure contents are unavailable here.

## Limitations and validity risks

**Author-stated:** Baseline coverage is representative rather than exhaustive; additional system-specific tuning may help. Evaluation is primarily static, offline, and English-language. Compute constraints restrict model coverage and require benchmark subsets. Broader memory forms and long-lived, interleaved deployments remain underexplored (Limitations).

**Analyst inferences grounded in the protocol:**

- Retrieval scope normalizes exposure by each system’s store size, so it does **not** equalize absolute inference tokens. Reported values also fall below the intended RAG floor for some systems, limiting strict budget-equivalence claims (Appendix B.3; Tables 18–20).
- Gold-based diagnostics exclude queries without gold evidence, and some memory mappings require LLM selection plus adjudication. Missing mapping-quality table values prevent assessing that uncertainty quantitatively (Appendix C.2).
- Judge reliability, uncertainty intervals, and repeated-run variability are not numerically available in the supplied text. Small accuracy differences therefore cannot be assessed for statistical reliability.
- Multimodal retrieval controls operate on generated captions, limiting conclusions about direct visual-memory retrieval (Appendix C.5).
- Several figure cross-references conflict with their captions, complicating evidence tracing (§§4.3–4.4).

## Open research questions

- **Does memory become more valuable during ongoing deployment?** Static evaluation leaves interleaved updates and queries underexplored. Next experiment: compare memory and RAG on chronological streams with changing preferences and explicit corrections.
- **Can memory retain gains under equal absolute budgets?** Retrieval scope does not equalize inference tokens. Next experiment: sweep matched total-token and latency budgets while reporting benefit and tax separately.
- **Do the proposed recovery methods deliver durable net gains?** Section 6 lacks accessible quantitative support. Next experiment: ablate source recovery and query–evidence reuse separately, measuring accuracy, tax, storage growth, and latency.
- **Which tasks require useful abstraction beyond retrieval?** Domain-dependent results leave this boundary unresolved. Next experiment: stratify queries by recall, aggregation, preference inference, and workflow transfer under the same retrieval controls.

## Confidence and missing information

**Confidence: medium.** The evaluation framework and several numerical comparisons are explicit. Material missing information includes most main and diagnostic table cells, readable plot values, judge-agreement results, uncertainty estimates, quantitative support for §6, and release availability. These gaps limit assessment of effect sizes, statistical reliability, and reproducibility.
