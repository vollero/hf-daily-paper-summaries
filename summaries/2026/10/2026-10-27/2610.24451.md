# Assessing the CAD Capabilities of General-Purpose AI Models: A Case Study of GPT-6 Astra

> [← Daily summary](../2026-10-27.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.24451) · [arXiv](https://arxiv.org/abs/2610.24451)


## One-sentence takeaway
In selected CAD tests, tool-enabled GPT-6 Astra generated useful initial geometry, but solid validity, functional connections, assembly fit, and reliable parameter editing remained inconsistent (Tables II–IV; §VII/Appendix Chapter 7).

## Problem and motivation
CAD models must preserve engineering intent through assembly, analysis, manufacturing, and later edits; visual resemblance alone is insufficient. The authors identify a gap in evaluations spanning understanding, generation, editing, and autonomous checking using cases representative of engineering practice (§I–II).

## Approach and contributions
This is an empirical assessment, rather than a new CAD generation method.

- **Assessment design:** Six test families cover part classification, machining-feature recognition, generation from drawings/text/images, and B-rep-to-parametric reconstruction, with task-specific complexity levels (Table I).
- **Engineering verification:** Independent checks separate geometric agreement, solid validity, functional requirements, assembly compatibility, and subsequent editability (§II.C).
- **Failure analysis:** Cross-task analysis identifies recurring problems with freeform surfaces, connectivity, mating dimensions, parameter dependencies, and iterative correction (§IV).

The evaluated system uses GPT-6 Astra at MAX reasoning effort, tools and code execution through a Linux-connected ChatGPT/Codex environment, independent memory-disabled conversations, and autonomous iteration within one turn. Web search is normally enabled; parametric reconstruction explicitly requires the SOLIDWORKS API (Appendix §1.3, Table 1-2).

## Evidence and main results
| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Strong constrained classification | Correct candidate class for **12/12** selected STEP models using a supplied class list and web-enabled setup; one coupling response also cited its embedded model name. | §III.A; Appendix Tables 2-5 and PC-10 analysis, PDF p. 30 |
| Feature recognition remains uneven | **3/6** cases correct across instance grouping, feature type, and relationships; other cases include false features, merged holes, and an external surface labeled as a hole. | Table II; Appendix Table 3-4 |
| Valid parts do not guarantee assembly fit | All components valid in **6/8** drawing cases; among **3** multi-part cases, one assembled, one interfered, and one could not be fully assembled. | §III.C; Table II |
| Listed requirements understate functional risk | **12/12** main text-generation cases met listed requirements, while **11/12** passed validity checks; unlisted connection and motion-transmission defects remained. | §III.D; Table II |
| Image overlap can coexist with local defects | For **6** main cases using six orthographic views plus one isometric view, mean silhouette IoU ranged **0.8790–0.9915**; every output solid was individually valid, but scale, surfaces, and connections differed. | §III.E; Table IV |
| Edit success is conditional on initial validity | All **11** cases produced native parametric models; **6/11** qualified for editing. Of **60** prescribed single-parameter edits, **52** passed; **4/11** models passed initial validity and all ten edits. | §III.F; Appendix Table 7-4 |
| Close initial geometry can conceal missing dependencies | B2P-03 had bidirectional RMS surface distance **0.05565 mm**, but passed only **4/10** edits; increasing housing depth closed a hole opening. | Appendix Table 7-4; Figure 7-9, PDF p. 175 |
| Completion time constrains interaction | Complex text cases averaged **97 min 30 s**; the longest recorded run was image reconstruction I2C-06 at **3 h 41 min**. Times include setup, tool use, and refinement. | §II.C; Table III; Appendix Chapter 8, PDF p. 192 |

These results establish demonstrated capabilities and failures in the selected settings. They do not establish comparative superiority, unrestricted classification accuracy, or a unified CAD success rate. The authors explicitly distinguish shape similarity, individual-solid validity, functional adequacy, and editing behavior; improvements in one do not ensure the others.

## Limitations and validity risks
- **Author-stated scope:** Results concern selected cases and one system configuration. Complexity levels differ by task and cannot serve as a shared difficulty scale (Appendix Chapter 8, PDF p. 194).
- **Author-stated confounds:** Public source models and embedded STEP metadata may provide prior information; their effects and repeated-run variability were not isolated (§2.5; closing limitations).
- **Author-stated evaluation limits:** Editing primarily covers single-parameter changes; combined changes, feature addition/deletion, and full assembly functionality were not evaluated (§7.5).
- **Author-stated comparison limits:** Small supplementary web-search comparisons do not establish a general search effect (§3.3.2.4, §6.5, §7.3.2).
- **Analyst inference:** The conditional edit-pass result should not be generalized to complex models, since invalid reconstructions were excluded before editing.
- **Analyst inference:** The supplied evaluation lacks a matched alternative-model or human baseline, so relative capability and productivity remain unresolved.
- **Coverage limitation:** The source is truncated, omitting substantial middle portions of the appendix. Some detailed procedures, results, and execution records cannot be assessed.

## Open research questions
- **Can explicit dependency constraints improve editing reliability?** Missing dependencies cause hole closure and disappearing features. Compare ordinary reconstruction with dependency-constrained reconstruction under identical single- and multi-parameter edits (§7.5).
- **Can refinement improve several engineering criteria simultaneously?** Error sometimes increases during iteration, and lower geometric error can coexist with invalid solids. Test refinement that checks geometry, connectivity, validity, and dependencies after every revision (§IV; Appendix Chapter 8).
- **How robust are results to metadata and run variation?** These effects were not isolated. Repeat the same cases with STEP names stripped, fixed tool access, and multiple independent runs (§2.5; closing limitations).
- **What performance–time tradeoff is achievable?** Long completion times limit interactive use, but controlled iteration-budget comparisons are not reported. Evaluate fixed time budgets against separately measured engineering outcomes (Table III; §IV).

## Confidence and missing information
**Confidence: medium.** The supplied tables and case analyses support the central distinction between plausible geometry and engineering reliability, but truncation prevents complete coverage.

Material missing information includes portions of the detailed appendix, repeated-run uncertainty, matched model/human baselines, complete verification tolerances and implementation details, controlled metadata effects, and confirmed public availability of prompts, source files, generated models, and execution logs.
