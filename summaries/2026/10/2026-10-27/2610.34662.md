# StreamVibe: Proactive Video Agents for Evolving User Intent

> [← Daily summary](../2026-10-27.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.34662) · [arXiv](https://arxiv.org/abs/2610.34662)


## One-sentence takeaway

StreamVibe combines proactive streaming-video policy training with persistent intent tracking, reporting improved intervention selectivity and dynamic-intent performance, although inconsistent result tables weaken confidence in the overall gains.

## Problem and motivation

Proactive video assistants must infer useful help from high-level goals, track what has already happened, and adapt when users revise or add requests. The authors argue that existing approaches emphasize explicit triggers and isolated responses, leaving repeated, outdated, or missed assistance during sustained interaction (§1).

## Approach and contributions

- **StreamVibe-Bench:** A benchmark spanning explicit, implicit, and dynamic intents in physical and digital tasks, with independent pointwise probes and continuous trajectory evaluation. It contains 4,100 evaluation samples; some explicit-category evidence and duration statistics are estimates (§§3.2–3.5; Table 15).
- **StreamVibe-VL:** Adaptive streaming supervised fine-tuning balances silence/response decisions while learning response content. Localized trajectory RL uses GRPO on short causal rollouts around assistance points, combining timing/content alignment with sequence coherence rewards (§4.2).
- **StreamVibe-Harness:** Explicit intent lifecycles, task progress, response records, and hierarchical visual memory supply context to the policy. An auxiliary Qwen3-VL-4B model summarizes observations; lexical retrieval selects historical evidence. The interaction policy retains responsibility for responding (§4.1; Appendix C).

The authors claim novelty in studying user intents in proactive streaming interaction; the supplied text does not independently establish priority (§1).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| RL improves dynamic-intent trajectory scores over SFT | Without Harness, ±2 s tolerance: timing F1 **9.83 → 13.28**, Content-F1 **3.53 → 5.25**, FPR **26.13 → 17.11**. | Table 7, p. 18 |
| Harness improves dynamic-intent performance, with lower coverage | RL, trajectory evaluation, ±2 s: timing F1 **13.28 → 19.96**, Content-F1 **5.25 → 8.91**, FPR **17.11 → 5.68**, but recall **52.58 → 30.65**. | Table 13, p. 20 |
| External transfer is competitive rather than uniformly best | EgoProactive Macro: RL **59.50**, SFT **53.04**, Qwen3.5-9B **46.20**, Gemini-3.8-Flash **64.96**, using official protocols. | Table 11, p. 19 |
| General video performance improves over the stated base comparison | OVO-Bench overall: RL **59.29** versus Qwen3.5-9B **57.71**; SFT reaches **59.44**. Mage-VL scores **63.94**. | Table 12, p. 20 |
| Annotation review has reported agreement evidence | On **6,005** pre-filter candidates, human Fleiss’ κ is **0.84**; mean Gemini–human Cohen’s κ is **0.76**. | Table 17, p. 26 |

These are reported results, not independently verified measurements. Content-F1 combines temporal matching and normalized LLM content scores while penalizing missed and extra responses; ANS averages quality only over matched responses (Appendix B.5).

The evidence supports selective intervention and gains on dynamic intents, but does not establish universal superiority or improved user outcomes. Tables 2, 3, 7, and 13 disagree on category placement and some values, including whether certain main-table results correspond to Harness configurations. Consequently, the abstract’s aggregate improvement claims cannot be confidently reconciled from the supplied text.

## Limitations and validity risks

- **Author-stated:** Current settings capture only part of the feedback between evolving needs, assistance, and environmental changes; longer, co-evolving interaction remains future work (§6).
- **Analyst inference—comparison reliability:** Conflicting tables make exact rankings and configuration attribution uncertain. Figure 8 also compares different model cohorts between pointwise and trajectory settings, so its aggregate gap does not isolate history accumulation alone.
- **Analyst inference—causal attribution:** The supplied experiments compare the complete Harness, without isolating intent lifecycle, memory, retrieval, skills, or auxiliary-model contributions (Appendix A.3).
- **Analyst inference—ecological validity:** Reused videos and constructed user turns do not demonstrate how real users change behavior after receiving assistance (§3.3; Appendix B.2).
- **Analyst inference—measurement and deployment:** Content evaluation relies on one shared LLM judge. No measured latency, compute overhead, or user study is supplied, despite the Harness requiring a separate inference process (§5.1; Appendix C).

## Open research questions

1. **Which Harness components cause the gains?** Full-system comparisons leave attribution unresolved. A component ablation with matched inference budgets could separate state tracking, memory, and skill effects.
2. **Can recall be preserved while suppressing unnecessary responses?** Table 13 shows a substantial dynamic-intent recall reduction. A controlled policy-calibration experiment could trace the coverage–interruption trade-off.
3. **Does assistance remain useful when it changes user behavior?** The benchmark uses prerecorded trajectories. A live study with branching tasks and user revisions could measure task success, redundant advice, and adaptation.
4. **How robust is state tracking beyond bounded memory?** Appendix C uses compression and FIFO eviction. Longer sessions with delayed references could test forgotten constraints and stale-state errors.

## Confidence and missing information

**Confidence: medium.** The method and evaluation design are described clearly, but numerical inconsistencies limit confidence in comparative conclusions.

The source was truncated, so this analysis does not imply complete coverage. Material unavailable or unresolved information includes reconciled result tables, full policy-training hyperparameters and compute, complete reward specifications, uncertainty estimates, component ablations, measured runtime costs, and confirmed code/model/data release availability.
