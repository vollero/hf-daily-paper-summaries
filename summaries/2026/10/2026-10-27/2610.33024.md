# Evolving to Match Capabilities: Improving Harness Self-Evolution via Skill Adaptation

> [← Daily summary](../2026-10-27.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.33024) · [arXiv](https://arxiv.org/abs/2610.33024)


## One-sentence takeaway
On 103 selected task–skill pairs, a fixed failure-informed rewriting protocol improves skill adaptation and yields higher final scores for all seven tested executors after five rounds of self-evolution, though single-rollout evaluation limits certainty about effect sizes (§4; Appendix D).

## Problem and motivation
Useful skill instructions do not guarantee successful execution: weaker agents can ignore or mishandle guidance that helps stronger models. The authors identify a gap in harness evolution methods that emphasize capturing experience without sufficiently adapting its presentation to the executor’s capabilities (§1).

This mismatch matters because improving the skill’s content alone may leave tool errors, misplaced outputs, missed requirements, and unchecked answers unresolved. The paper studies skill rewriting while keeping model parameters fixed.

## Approach and contributions
- **Capability-sensitive diagnosis:** Compare execution with and without human-crafted skills across three benchmarks, then select pairs where stronger models benefit substantially more than weak models (§2).
- **Failure-informed meta-skill:** Translate four observed failure categories—tool execution, context management, instruction following, and verification—into a fixed rewriting protocol. Guidance includes distinguishing tools from reference material, stating delivery paths, giving actionable completion conditions, and requiring independent checks (§3).
- **Two adaptation settings:** Test capable external rewriters without execution evidence, then let executors revise their own skills using previous trajectories and verifier feedback over five rounds. Both settings reject invalid revisions and fall back to the preceding skill (§4; Appendix B).

The contribution is a diagnostic protocol for skill adaptation and its evaluation, rather than a new model-training procedure.

## Evidence and main results

Scores use native benchmark judges normalized to [0,1]; “points” below denote percentage-point changes on that scale.

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Strong–weak skill mismatch on the selected subset | On 103 pairs selected from 607 tasks, original skills improve GPT-5.6-luna by 31.1 points but reduce Gemma-4-E4B by 8.8 points relative to execution without skills. | Abstract; §2.3; Fig. 3 |
| Failed execution often violates existing guidance | Authors report that 86% of failed weak-model runs with skills violate a requirement already present in the injected skill. | §3.1 |
| External adaptation improves weak executors | Kimi-K3 rewriting with the meta-skill improves the three weak executors by 5.1–14.1 points over original skills on the 103 pairs; each revision is executed once. Gemma-4-E4B rises from 0.029 to 0.170 mean score. | Abstract; §4.1; Table 1 discussion |
| Diagnostic guidance adds value beyond a capable rewriter | With the same Kimi-K3 rewriter, meta-skill guidance adds 5.1–6.0 points over a generic one-sentence rewriting instruction across the three weak executors. | §1; §4.1; Fig. 5 |
| Self-evolution benefits across tested executors | At round five, all seven executors score 0.020–0.051 higher with the meta-skill than without it on the same 103 pairs. Every round is run once; trajectories are not uniformly monotonic. | §4.2; Appendix D |
| Failure-category analysis suggests different repair mechanisms | In one-shot Kimi-K3 adaptation, meta-skill gains over generic rewriting average 0.056 for tool execution, 0.055 for instruction following, and 0.103 for context management. Failure labels overlap. | §4.3; Table 2 discussion |

These results support the authors’ claim that explicit rewriting guidance can improve execution on the selected testbed. They do not establish population-wide skill benefits: the subset was deliberately selected for stronger-model advantage, while the full task suite shows small gains without a clear capability-tier pattern (§2.3). Category analyses and case studies suggest mechanisms but do not isolate the causal contribution of each meta-skill component.

## Limitations and validity risks
- **Author-stated scope:** Retrieval and progressive disclosure are excluded; multiple skills are evaluated as bundles; self-evolution stops after five rounds and never updates model parameters (§6).
- **Author-stated uncertainty:** Each model–task–condition cell has one rollout. The authors emphasize consistent improvement direction rather than precise gap sizes (§4.2; Appendix B).
- **Analyst inference—selection and reuse:** The same selected pairs support failure diagnosis, meta-skill design, and evaluation. Generalization to unseen tasks or independently diagnosed failures is not demonstrated (§§2.3–4).
- **Analyst inference—feedback dependence:** Self-evolution uses verifier output from the task being optimized. The leakage gate explicitly permits information already exposed through feedback, so gains do not establish transfer to new tasks or unseen tests (Appendix B).
- **Persistent execution failures:** Correctly rewritten instructions can still be ignored; observed failures include editing without rerunning and stopping before saving an artifact (§4.3).
- **Evidence availability:** The supplied extraction contains table captions without their numerical bodies and does not include the full meta-skill text promised in Appendix C. Component ablations are not reported in the supplied text.

## Open research questions
1. **Does the protocol generalize beyond the diagnosed subset?** Evaluation reuses the selected task pairs. A next experiment could freeze the meta-skill and test an independently selected task suite without capability-gap filtering.
2. **Which rewriting components drive improvement?** The four guidance categories are evaluated together. A controlled ablation could remove each component while holding rewriter, execution budget, and task set fixed.
3. **Are gains reliable across repeated attempts?** Single rollouts leave outcome variability unresolved. Repeated paired runs could estimate uncertainty and the frequency of regressions.
4. **Do revised skills transfer across tasks?** Appendix E explicitly describes task-specific adaptation. Testing each revised skill on related unseen tasks could distinguish reusable improvement from task-specific optimization.

## Confidence and missing information
**Confidence: medium.** The supplied prose clearly describes the method, comparisons, and headline results, but precise effects have limited replication.

Material missing information includes complete numerical tables and plotted values, the full meta-skill and baseline prompt text, repeated-run uncertainty estimates, failure-label annotation agreement, held-out transfer results, and currently available code and experiment configurations.
