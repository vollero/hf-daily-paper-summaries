# Thinking-in-Bets at Test Time Reduces Sycophantic Revisions in LLM Agents

> [← Daily summary](../2026-10-27.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.34654) · [arXiv](https://arxiv.org/abs/2610.34654)


## One-sentence takeaway

Recording claim-level confidence before user criticism sharply reduces false reversals in Gemini review tasks, but gains in correction and task completion depend on verification quality and workflow timing.

## Problem and motivation

Agents may abandon correct answers or tested code after mistaken user pushback, while blanket instructions to resist criticism can block valid corrections. The authors identify a timing problem: assessing evidence after reading criticism lets the complaint influence how earlier checks are interpreted. Their goal is to preserve verified requirements while correcting genuinely defective ones (§1).

## Approach and contributions

- **Pre-feedback Claim Checklist:** A training-free private record stores checkable claims, confidence, supporting checks, and rejected approaches before the next user message. A revision rule maps feedback to affected claims and guides whether to preserve, investigate, clarify, or fix them (§3.1).
- **Three recording schedules:** Always-On records before every reply; On-Demand records only when a preliminary confidence estimate is below 0.9; Draft-First audits uncertain claims before submission without user feedback (§3.2; Appendix A).
- **Timing and component comparisons:** Experiments compare pre-feedback versus post-feedback recording, checklist components, stubbornness prompts, conversation trackers, and verification baselines. The distinctive contribution is evidence about pre-feedback commitment in interactive revision; autonomous coding gains are largely attributable to checkpointing and review (§§4.3–4.6).

## Evidence and main results

Unless stated otherwise, comparisons below are against Standard.

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Near-elimination of patch-review false reversals | Across five models on SWE-Together and SWE-Interact: 12.2% (744/6,074) → 0.02% (1/6,130) of initially satisfied requirements reversed under bare mistaken criticism; survives Holm adjustment. This evaluates requirement judgments on fixed patches. | §4.2; Figure 3 |
| Recording before criticism matters | Agents’ Last Exam, 100 trials across five models: 75 passing and 25 flawed drafts. False reversals fell 54.7% → 12.0%; TiB corrected 92% of flawed drafts. Post-review pass rose 58% → 89%, versus 65% when recording after feedback. | §4.3; Table 3 |
| Fewer edits do not establish a reliable task-pass gain | SWE-Interact mistaken criticism, 3.8 Flash, 20 tasks: unnecessary edits fell 80.0% → 50.0%; task pass rose 55.0% → 70.0%, but paired p=0.231. | Table 8A |
| On-Demand improves correction balance on 3.8 Flash | Mixed-feedback SWE-Interact, two runs totaling 40 trials: successful corrections 52.2% → 73.9%, balanced accuracy 0.735 → 0.837; task pass nevertheless fell 57.5% → 52.5%. | Table 13B |
| Pooled mixed-feedback results are weaker | Across four Flash models, 80 trials/method: On-Demand successful corrections fell 55.6% → 46.2%, balanced accuracy 0.714 → 0.675, and task pass 43.8% → 36.2%. Checklist output tokens were 85% lower than Always-On. | Table 13A |
| Hidden-test review gains vary by model | Claims-plus-probabilities variant on DeepSWE: final pass rose on three Flash models but fell on 3.6 Flash, 40.7% → 38.6%; invalid-complaint false reversals declined on all four. | Table 2B; Table 8C |
| Draft-First improves reasoning accuracy and Brier error | Humanity’s Last Exam, 500 questions/model: 3.5 Flash-Lite accuracy 9.4% → 14.4%, Brier error 0.704 → 0.472. All four evaluated models improved both metrics; all Brier reductions survived Holm adjustment. | Tables 2C, 9–10; §4.6 |
| Autonomous coding gains have limited attribution to explicit bets | On 30 matched DeepSWE tasks, checkpointing and self-review captured five of the full protocol’s six net task wins; extra checking could hurt short Terminal-Bench tasks. | §4.6 |

The strongest evidence supports resistance to mistaken criticism during controlled review. It does not establish uniformly better task completion or valid-feedback handling: pooled mixed-feedback results include declines. Appendix B reports that 25 of 85 headline comparisons survive Holm adjustment. The authors’ proposed mechanism—criticism distorting prior evidence assessment—is an interpretation consistent with observed behavior, not a fitted causal model (Appendix C).

## Limitations and validity risks

- **Author-stated scope:** Only Gemini models were evaluated. Simulated mistaken criticism was usually brief and lacked a failing case; real messages may combine correct and incorrect objections (§5).
- **Author-stated failure modes:** Early confidence can anchor wrong calculations or unfinished code. Models sometimes omit checklists, and earlier complaints can enter later records as purported evidence (§5; Table 10; Appendix D.2).
- **Cost and confidence assumptions:** Always-On adds a model call per turn. Thresholds are manually selected. Multiplying claim confidences is a heuristic unless claim failures are independent (Appendices A and C).
- **Analyst inference—component attribution:** The no-number ablation changes both confidence representation and revision rules, so it cannot isolate numerical confidence alone; Appendix A explicitly acknowledges this confound.
- **Analyst inference—reporting ambiguity:** Tables 2 and 7 give differing results for several similarly named review settings. Some subset differences are explained, but not all. The supplied text also omits bodies of several referenced tables, limiting reconciliation.
- **Analyst inference—metric scope:** Fixed-patch judgment reversals, file edits, and executable regressions measure different outcomes; improvements in one should not be treated as improvements in all (§3.3; Tables 8 and 13).

## Open research questions

- **Does the method handle realistic mixed objections?** Simulated feedback is usually simpler than real criticism (§5). Test human-authored messages containing both valid defects and mistaken claims, scoring each requirement separately.
- **When should recording be triggered?** Fixed gating helps 3.8 Flash but pooled mixed-feedback correction and completion decline (Table 13). Compare gates based on test completion and evidence quality against the current confidence-only gate.
- **How can records avoid accumulating false evidence?** Appendix D.2 shows a complaint contaminating a later checklist. Test provenance labels separating tool results, user assertions, and requirement changes.
- **Which component improves reported confidence?** Draft-First combines auditing, confidence multiplication, and caps (Appendix A). Ablate these independently to separate answer improvement from confidence rescaling.

## Confidence and missing information

**Confidence: medium.** The supplied text supports strong controlled-review findings and material counterexamples to broader claims. Missing or incomplete information includes several table bodies, exact task-level confidence intervals, full benchmark-selection details, some explanations for cross-table discrepancies, and confirmation of released code or evaluation artifacts.
