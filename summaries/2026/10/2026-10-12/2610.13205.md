# Rethinking Relative Policy Differences Transfer of On-Policy Distillation

> [← Daily summary](../2026-10-12.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.13205) · [arXiv](https://arxiv.org/abs/2610.13205)


## One-sentence takeaway
On Qwen-family math and code tasks, transferring expert–reference log-probability differences works better for task-trained improvements than scale gaps, but success depends strongly on the reference and target.

## Problem and motivation
Conventional on-policy distillation (OPD) trains a student on its own rollouts to match a teacher’s distribution, which the authors argue usually requires a substantially stronger teacher. Relative policy transfer instead transfers an expert’s improvement over a reference, potentially reusing post-training outcomes from weaker models. The unresolved gap is which source differences are useful and which targets can realize them (§1–2).

## Approach and contributions
- **Unified objective:** A²-OPD treats the proxy expert/reference log-ratio as an implicit token-level reward and separately regularizes the target toward its initial policy. Conventional OPD is a special case (§3, Eq. 7; Table 1).
- **Theoretical interpretation:** Under state-wise KL-regularized optimality, the log-ratio preserves reward differences between actions. The induced target distribution reweights its own reference by the proxy ratio; training uses a centered on-policy surrogate (§3.2–3.3; Appendix A).
- **Empirical characterization:** Controlled source, reference, and target sweeps compare RL, SFT, and scale differences, identifying task relevance, reference filtering, and target compatibility as factors in transfer (§4).

Relative policy transfer itself predates this work; the claimed contributions are its unification and systematic analysis (§2.2–3.3).

## Evidence and main results

Math results below average Mean@16 over eight benchmarks; code results average Mean@8 over HumanEval+, MBPP+, and LiveCodeBench. Gains are differences from the target base on the reported score scale (§4.1; Appendix B).

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Task-trained differences outperform scale-only differences | With Qwen3-8B fixed, six RL/SFT configurations yield G_T of +9.78 to +32.23; four scale-only configurations yield −1.03 to +8.23 on math. | Table 2 |
| Useful supervision can come from a weaker expert | Qwen3-1.7B-RL scores 25.15; transferring its difference over Qwen3-1.7B raises Qwen3-8B from 18.43 to 28.21 on math. | Table 2 |
| Relative transfer can exceed conventional OPD | For Qwen3-4B-RL → Qwen3-8B, using Qwen3-4B as proxy reference yields 45.27, versus 42.30 when the proxy reference equals the target base, recovering OPD. | Table 3 |
| Reference selection changes the transferred residual | With Qwen3-4B-RL expert and Qwen3-8B target fixed, math G_T is +9.62 with an early-RL reference, +26.84 with the base reference, and +29.09 with Qwen2.5-3B. | Table 3 |
| Changing the reference can rescue transfer | For Qwen3-4B-RL → Qwen2.5-7B, changing the proxy reference from Qwen3-4B to Qwen2.5-3B changes math G_T from −1.74 to +6.74. | Table 4 |
| Selected patterns extend to code | Qwen3-4B-RL/Qwen3-4B → Qwen3-8B gives math/code G_T of +26.8/+2.3; the same source pair → Qwen2.5-7B gives −1.7/−6.4. | Table 5 |

These comparisons support reference-sensitive transfer in the tested configurations. They do not establish universal any-to-any success or a reliable advance predictor of compatibility. Overlap and train/validation trajectories support the authors’ interpretation that successful updates approach the expert and generalize, but remain diagnostic evidence (§4.4, Figures 5–6).

## Limitations and validity risks
- **Author-qualified scope:** Arbitrary source–target combinations are permitted in principle, but not all transfer successfully (§3.3). The implicit-reward interpretation is approximate for practical RL/SFT experts that do not satisfy the theoretical optimization assumption (§4.2).
- **Analyst inference—limited generality:** Experiments cover Qwen-family models, math, and selected code configurations, with fixed transfer strength and top-16 scoring. Broader model families, domains, full-vocabulary scoring, and strength sweeps are not evaluated in the supplied text (§4.1–4.5).
- **Theoretical qualification:** Appendix A.3 treats sampled states as fixed. Its gradient is exact for the conditional surrogate; a full trajectory objective requires return-to-go weighting.
- **Comparison ambiguity:** §4.4 describes changing the reference while holding the “difference” fixed, but changing the reference changes the log-ratio. The experiment holds the expert fixed and supports a reference intervention, without isolating model generation from other reference properties.
- **Reporting inconsistencies:** The Qwen3-14B/Qwen3-4B proxy scores and gains conflict across Tables 2–3 and the appendices. An earlier Appendix D metrics block also shifts configuration IDs relative to Table 7. Appendix B’s definition of K_Induced differs from the description in §4.1.
- **Cross-domain overstatement:** §4.5 claims consistent signs, but Table 5’s Qwen3-4B/Qwen3-1.7B scale pair improves math and worsens code.
- **Missing uncertainty:** No repeated-run variability or confidence intervals are supplied.

## Open research questions
- **Can compatibility be predicted before training?** Raw policy distance fails to order outcomes (§4.4). Next experiment: test reference-selection predictors on held-out source–target combinations.
- **Can tuning rescue scale-only transfer?** Only one transfer strength and top-16 scoring are tested (§4.1). Next experiment: sweep strength and token support for matched task-trained and scale-only pairs.
- **Which reference properties cause recovery?** Reference changes alter several properties simultaneously (§4.4). Next experiment: compare references matched for capability and overlap across multiple model families.
- **Do the findings extend beyond math and code?** Code coverage is selective (§4.5). Next experiment: repeat controlled sweeps on additional language tasks and independently trained model families.

## Confidence and missing information
**Confidence: medium.** The main trends are supported by multiple tables, but reporting inconsistencies and narrow evaluation weaken broader conclusions.

Material missing information includes run-to-run uncertainty, compute costs, precise top-16 support/normalization procedures, tokenizer-alignment retention rates, code benchmark version details, and a stated release of implementation or trained checkpoints.
