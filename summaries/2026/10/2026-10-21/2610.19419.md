# WinARDet: Compressed Window Auto-Regression for Long-Horizon Vision-Language Grounding

> [← Daily summary](../2026-10-21.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.19419) · [arXiv](https://arxiv.org/abs/2610.19419)


## One-sentence takeaway
WinAR compresses completed coordinate-generation windows while preserving local context, improving RexOmni’s image-averaged RSDense F1@IoU=0.5 from 32.16 to 39.36 against an exposure-matched full-history baseline while reducing duplicate predictions (Table 1).

## Problem and motivation
Autoregressive vision-language detectors must discover new objects while remembering previously generated locations. In dense scenes, repeated boxes can consume the decoding budget without improving coverage.

The authors associate this failure with growing attention to historical coordinate tokens and declining attention to initial system tokens. They identify unmanaged raw answer history as a gap in existing detectors, including systems with parallel box decoding (§1, Fig. 2). This attention-based explanation is an author interpretation of observed behavior, rather than an independently established causal mechanism.

## Approach and contributions
- **Failure analysis:** Documents a box-repetition loop and its association with historical-answer attention takeover during long decoding (§1, Fig. 2).
- **Compressed Window Auto-Regression:** Retains exact autoregressive history within the current window and conditions subsequent windows on compressed representations of completed windows. The original image-and-text prefix remains available (§3.2).
- **Window History Compressor:** Preserves exact tokens at both window boundaries and summarizes the middle using pooled queries, positional embeddings, cross-attention, and feed-forward layers. Training supervises the current window; inference compresses each completed window before continuing (§3.2, Fig. 4).
- **Integration and evaluation:** Applies token-aligned windows to RexOmni and block-aligned windows to LocateAnything, with experiments covering boxes, quadrilaterals, training memory, and effective decoding throughput (§§3–4).

The evidence supports reduced repetition and improved dense-scene coverage across the tested implementations. Exposure matching strengthens the comparison against simply training longer. It does not establish universal accuracy or raw-speed improvements. Main-table and supplementary RSDense scores use different aggregation and matching protocols, so their absolute values are not directly comparable (§A.3).

## Limitations and validity risks
- **Author-stated trade-offs:** Compression and cache prefilling add inference overhead; shorter windows can reduce grounding accuracy (§§4.2–4.3).
- **Analyst inference—causality:** Attention changes coincide with repetition, but no direct intervention isolating attention takeover is reported (Fig. 2).
- **Analyst inference—evaluation scope:** Prompts contain the ground-truth categories present in each image. This leaves performance with unknown, absent, or incorrectly specified categories unestablished (§A.3).
- **Analyst inference—ablation isolation:** Table 4 changes window length, boundary size, and latent count together; its boundary-removal comparison also changes latent capacity.
- **Reporting ambiguities:** §4.1 describes validation-set evaluation, whereas §A.1 specifies SODA-A test evaluation. The abstract’s approximate RSDense range differs from Table 7’s 201–2,305 objects/image.
- **Uncertainty reporting:** No repeated-run variability or confidence intervals are supplied. Training-memory comparisons also use different GPU types for FHAR and WinAR (§A.2).

## Open research questions
- **Does historical-answer attention cause repetition?** The reported association leaves causality open. Directly manipulate historical-answer or system-token attention while holding training and context length fixed.
- **Can adaptive windows improve the trade-off?** Fixed configurations jointly alter several parameters. Test density- or repetition-triggered compression against fixed windows under matched training exposure and compute.
- **How robust is grounding without oracle category prompts?** Current evaluation supplies present categories. Evaluate unrestricted prompts and prompts containing absent or omitted categories.
- **How far can compressed memory scale?** Memory accumulates per completed window rather than remaining globally fixed (§3.2). Measure coverage, repetition, latency, and memory over progressively longer decoding horizons.
