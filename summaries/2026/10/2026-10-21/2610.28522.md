# DecisionPivot: A Diagnostic Benchmark for Decision Models in LLM Systems

> [← Daily summary](../2026-10-21.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.28522) · [arXiv](https://arxiv.org/abs/2610.28522)


## One-sentence takeaway
DecisionPivot shows that similar aggregate scores can conceal substantial differences in controlled decision correctness and confidence reliability, using generated contrast groups alongside public reference tasks.

## Problem and motivation
Decision models route requests, enforce policies, verify outputs, and validate agent actions. The authors argue that item accuracy alone misses whether models correctly handle decisive changes across related cases and whether confidence supports reliable deferral. Public benchmarks also retain shortcuts and uncertain training exposure, motivating controlled cases with independently computed answers (§1).

## Approach and contributions

- **Controlled benchmark:** 7,800 generated items across 13 families, complemented by 32,233 items from 35 public test sets. Core contrast groups usually change a pivotal detail; `policy_case` instead groups cases under a shared policy. Independently implemented solvers verify every core answer (§§3.2–3.4).
- **Combined diagnostic framework:** Item accuracy, all-members-correct “pair accuracy,” binary probability ordering, calibration, and retrospective selective coverage distinguish complementary failure modes. Pair accuracy also applies to groups larger than two (§3.6).
- **Empirical characterization:** Evaluation of 40 decision models and 14 general models examines confidence, difficulty, reasoning settings, input presentation, and fresh samples. The contribution is the integrated benchmark and analysis, rather than invention of each constituent metric (§§4–5; §2).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
| --- | --- | --- |
| Similar reference scores conceal different contrast performance | Perplexity Decider versus JEV-27B: reference scores **57.0 versus 54.4**, but core pair accuracy **70.1% versus 44.2%**, macro-averaged across 13 families. | §4.1; Table 4 |
| Probability ordering does not ensure correct decisions | On **2,400 binary pairs** across eight families, Perplexity Decider achieves **92.3% pair direction** but **74.1% pair accuracy**. | §5; Table D6 |
| Similar item accuracy conceals confidence differences | Kev 27B versus JEV-27B: core item accuracy **70.6% versus 70.3%**; among pooled predictions with confidence ≥0.90, accuracy is **93.8% versus 88.9%**, covering **34.1% versus 47.4%** of items. | §4.2; Table D1 |
| Higher reasoning setting improves sampled contrast performance | On a **1,296-item** subset preserving complete groups and balanced levels, GLM-5.3 pair accuracy rises from **81.5% [78.4, 84.6]** to **93.5% [91.7, 95.3]**; intervals are 95% bootstrap intervals. Sampling and output budgets also differ. | §4.3; Table D5 |
| Fresh-sample rankings are stable within existing designs | Across **34 decision models** on **4,200 fresh items** from seven generators, rank correlation is **Spearman ρ=0.994**; score-change intervals include zero for **32 models**. | §3.4; Table E3 |
| Aggregate input robustness can hide prediction changes | Version-1.0 presentation variants produce pair-accuracy changes from **−2.2 to +2.2 percentage points**, while natural wording changes up to **20.7%** of predictions in the reported four-model study. | §5; Figure 7; Tables D8–D9 |

These author-reported results support the value of measuring joint correctness and confidence separately. They do not isolate contrast grouping as the cause of differences between tracks, because task content and scoring also differ. Retrospective coverage does not establish deployable error guarantees, and the reasoning comparison does not isolate reasoning effort from sampling and output budget.

## Limitations and validity risks

- **Authors’ scope limits:** Written cases do not measure end-to-end system behavior, multilingual performance, or inference efficiency. Difficulty jointly changes case size and complexity (§6).
- **Protocol comparability:** Probability interfaces, input limits, and reasoning settings differ. Missing predictions count as incorrect, so some scores combine compatibility failures with decision errors; most evaluations use one run (§6; Appendix B).
- **Residual shortcuts and exposure:** Schema-only checking achieves **91.7% item accuracy on `toolcall_valid`**. Training overlap is incompletely known, and filtering addresses detected overlap in the authors’ models only (§3.4; Appendix E).
- **Design independence:** Fresh samples reuse existing generators, and the benchmark team also develops StartLux-Decision. The authors explicitly call for independent evaluation and additional case designs (§6).
- **Analyst inference:** Solver agreement strengthens answer verification but cannot independently establish that generated cases represent deployment traffic; textual review and computational verification address different validity questions (§3.4; §6).

## Open research questions

- **Do rankings transfer to independently designed cases?** Fresh-sample stability covers existing generators only. Next experiment: commission external generators with matched decision roles and compare rankings (§6).
- **Can confidence thresholds maintain error targets prospectively?** Reported selective coverage uses evaluation labels and family-specific cutoffs. Next experiment: choose thresholds on separate calibration data, then evaluate frozen thresholds on fresh cases (§3.6).
- **How much improvement comes specifically from reasoning effort?** Sampling and output budgets change alongside effort. Next experiment: vary effort while holding these settings fixed (§4.3).
- **Does contrast performance predict operational reliability?** End-to-end systems are outside scope. Next experiment: compare benchmark scores with routing, guardrail, or tool-validation errors in instrumented workflows (§6).
