# Last Secure Code Benchmark: Is the Code You Vibe Secure?

> [← Daily summary](../2026-10-14.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.14766) · [arXiv](https://arxiv.org/abs/2610.14766)


## One-sentence takeaway
On LSCBench’s 450 security-neutral implementation tasks, six coding agents achieve 73.6%–91.3% functional pass rates, but the best passes both functional and targeted security tests on only 25.1% of tasks (Abstract; §4–5).

## Problem and motivation
Functional correctness can conceal exploitable behavior: ordinary inputs work while malicious inputs cross security boundaries. The authors ask whether coding agents supply necessary defenses when users request functionality without mentioning security. They identify a benchmark gap in jointly covering multiple languages, vulnerability categories, and implementation scopes (§1–2).

## Approach and contributions
- **Matched benchmark tasks:** LSCBench turns 150 vulnerability scenarios—115 public CVEs and 35 expert-crafted Java scenarios—into function, file, and repository-scope reconstruction tasks. It covers seven languages and 24 CWE categories (§3.2).
- **Executable construction protocol:** Separate hidden functional and behavioral security suites are validated against vulnerable and fixed implementations. Environment sweeps remove answer artifacts; reference, commented-patch, and empty-solution controls screen tasks for grading failures. Specifications undergo agent and expert review (§3.1; Appendix B).
- **Evaluation and diagnosis:** The authors evaluate six agents, analyze scope, weakness families, languages, turns, and failure trajectories, and rerun four agents with a generic security reminder (§4–5). This is a benchmark and evaluation contribution; no new training method is tested.

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Functionality substantially exceeds joint success | Across six agents on 450 tasks, FuncPass is 73.6%–91.3%; Claude Fable 5 leads Func∧Sec at 25.1%, versus 16.4%–24.7% for the others. All are pass@1. | Abstract; §4–5; Figure 4 |
| Consistency across scopes is weak | The best scenario-level joint pass rate is 12% across 150 scenarios; success requires passing both suites at all three granularities. | Abstract; §5; Figure 4 |
| Models cover complementary tasks | At least one agent jointly succeeds on 198/450 tasks (44.0%), versus 113/450 (25.1%) for the best single agent; 252 tasks are secured by none. | §5; Appendix E |
| Broader scope can improve joint success | On the fixed subset of 52 scenarios that every agent solves functionally at every scope, GPT-5.6-Sol’s Func∧Sec rises from 23.1% at Function to 42.3% at Repo. | Appendix E, discussion of Table 13 |
| A generic reminder helps but leaves substantial failures | Four agents are rerun on all 450 tasks. GPT-5.6-Sol, Qwen3.8-Max, and GLM-5.3 gain 15–21 percentage points in Func∧Sec with little functional change; DeepSeek-V4-Pro is the exception. Exact per-model reminder rates are absent. | §5.5 |
| Local defenses fare better than unstated policies | Memory safety ranks highest across models; information exposure and SSRF are described as almost never secured. Language differences partly reflect different weakness compositions. | §5.3; Figure 8 discussion |

These results establish a substantial gap between functional and targeted security-test success under the evaluated workflow. Passing the security suite does not establish freedom from other vulnerabilities. Complementary coverage is an observed union, not a demonstrated ensemble or review system; Appendix E explicitly makes this distinction.

## Limitations and validity risks
- **Author-stated scope:** Repository tasks often rebuild a selected source scope while retaining infrastructure and callers; they do not uniformly generate complete repositories (Appendices A, B.4).
- **Author-stated confounding:** Language outcomes reflect different vulnerability mixtures. Turn counts also differ between Codex and Claude Code (§5.1–5.3).
- **Analyst inference—generalization:** Selection prioritizes difficult, convertible vulnerabilities and balances languages and weakness categories. The resulting failure rates should not be treated as estimates for arbitrary production coding requests (§3.1; Appendix B.1).
- **Analyst inference—causality:** Observational turn comparisons do not establish that additional deliberation cannot help. Similarly, deployment-policy reasoning and memorized-code replay are author interpretations supported by audits and cases, rather than controlled causal tests (§5.2–5.4).
- **Analyst inference—comparison uncertainty:** Each task has one attempt, and GPT uses a different scaffold. The supplied text provides no repeated-run uncertainty estimates (§4).
- **Evidence ambiguity:** Appendix B.4 describes source-scope caps, but Table 2 reports larger maximum withheld line/file counts without a full reconciliation. Several tables contain captions but no numerical bodies in the retrieval.

## Open research questions
- **Would explicit threat models improve policy-dependent defenses?** Generic reminders leave SSRF and information exposure difficult (§5.5). Compare neutral specifications, generic reminders, and explicit trust-boundary policies on matched tasks.
- **Can complementary agents deliver practical gains?** The observed union assumes knowledge of which attempt succeeds (Appendix E). Test a fixed reviewer or selector without access to hidden verdicts.
- **Does security-focused verification improve results?** Turn counts are observational, and case studies show functional testing missing hostile inputs (§5.2; Appendix F). Randomize agents to ordinary verification versus a required adversarial-testing phase.
- **How much does the scaffold affect rankings?** GPT alone uses Codex (§4). Evaluate compatible models under matched scaffolds and repeated attempts.

## Confidence and missing information
**Confidence: medium.** The supplied prose supports the principal findings and construction details, but many table bodies and plotted values are unavailable.
