# Learning How to Remember: Memory Modality Selection for GUI Agents

> [← Daily summary](../2026-10-14.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.17928) · [arXiv](https://arxiv.org/abs/2610.17928)


## One-sentence takeaway
SwitchMem learns to choose text or screenshot memory at each GUI interaction step, with statistically significant gains over the strongest fixed memory baseline on AITW and LearnGUI but an inconclusive gain on MobileMiniWoB++ (§B.6).

## Problem and motivation
GUI agents reuse demonstrations to guide actions, but existing memory systems generally fix how those demonstrations are represented. The authors identify a gap: text abstracts interface content, screenshots preserve visual detail, and their relative usefulness may change within a task. Fixed memory formats can therefore miss useful information at individual steps (§§1, 3.2).

## Approach and contributions
- **Controlled modality study:** Compare text and image versions of the same retrieved demonstration while holding the actor, current observation, and decoding configuration fixed. The authors report substantial step-level variation in modality preference (§3; §A.1).
- **Directional Chain-of-Embedding (D-CoE):** Subtract text-conditioned from image-conditioned actor hidden states and probe whether this signed difference predicts modality preference. Standardization, PCA, and a logistic probe produce continuous training targets (§§3.3, 4.1).
- **SwitchMem router:** Train a shared MLP to score each state–memory pair and regress the difference between image and text scores toward those targets. At inference, current-state hidden features and memory embeddings select one modality for the frozen actor (§4). This changes memory presentation rather than retrieval.

The evidence supports adaptive memory presentation in the tested settings. It does not quantify most effect sizes because the supplied text contains table captions and figure descriptions without their numerical contents. AITW/LearnGUI measure action matching rather than closed-loop task completion; MobileMiniWoB++ supplies completion evidence, but its comparative gain is statistically inconclusive. The second-actor experiment establishes application of the protocol, not transfer of an unchanged trained router.

## Limitations and validity risks
- **Authors’ limitations:** Evaluation covers controlled mobile Android settings; iOS, newer Android versions, and physical-device variability remain unverified. Hidden-state access prevents direct use with opaque APIs (Limitations).
- **Analyst inference—representation dependence:** Text comes from structured annotations or accessibility data. Findings may change with weaker textual descriptions or different annotation quality (§B.1).
- **Analyst inference—comparison scope:** Memory baselines are adapted as training-free components under a shared actor and retrieval bank, whereas SwitchMem receives supervised router training. Results assess these implementations rather than complete original systems (§A.2).
- **Analyst inference—transfer scope:** MobileMiniWoB++ memory, calibration, and evaluation use different instances of shared task templates; this does not establish transfer to unseen templates (§B.1).
- **Analyst inference—interpretation:** Density, action category, and trajectory position correlate with modality utility, but their causal effects are not isolated (§6.1; §B.7). The claim that D-CoE targets are “necessary” is stronger than the reported comparisons establish, especially with competitive Binary routing on AITW (§B.3).

## Open research questions
- **Does routing improve long-horizon completion outside controlled templates?** AITW/LearnGUI use action-level evaluation and the online gain is inconclusive. Next experiment: larger closed-loop evaluations on held-out applications and task templates.
- **How dependent are gains on text quality and retrieval?** The study fixes one retrieved demonstration and uses structured text. Next experiment: cross retrieval quality with annotation-derived, automatically generated, and degraded text.
- **How robust is D-CoE supervision relative to simpler labels?** Binary routing is close on AITW, and numerical ablation margins are unavailable. Next experiment: repeated training runs comparing D-CoE, Binary, and Utility supervision with paired uncertainty estimates.
- **Can routing work without internal actor access?** The current method explicitly requires hidden states. Next experiment: train an observable-input router and compare accuracy, task success, and inference cost against SwitchMem.

## Confidence and missing information
**Confidence: medium.** The supplied text explains the method and protocols, but omits numerical bodies of Tables 1–5 and most figure values.
