# A Decade in a Day: Synthesizing Agent-Native Interfaces from Human-Oriented Software Evolution

> [← Daily summary](../2026-10-14.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.15765) · [arXiv](https://arxiv.org/abs/2610.15765)


## One-sentence takeaway
ANIS synthesizes runtime-validated desktop commands that improve artifact-verified agent success and reduce online token use, although capability coverage remains incomplete in applications with implicit object dependencies (§5.3).

## Problem and motivation
Desktop GUIs and SDKs require agents to locate controls, discover operations, compose low-level calls, and verify results through interfaces designed for people. The authors identify a gap in evidence about which interface properties help agents, and use historical software releases as realistic interface variations while fixing tasks, agents, and verifiers (§§1, 4).

## Approach and contributions
- **DeskIF-Bench:** Artifact-verified tasks with outcomes screened for feasibility across releases; the cross-version benchmark is expanded with additional applications for ANIS evaluation (§3).
- **Interface analysis:** Historical comparisons motivate discoverability and goal-aligned granularity; a separate failure audit identifies limited artifact observability (§4.3).
- **ANIS:** Runtime capability discovery produces atomic commands validated through saving and reopening artifacts. Commands support hierarchical discovery and available read accessors; recurring successful sequences become parameterized goal-level commands after replay validation (§§5.1–5.2, 16).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Newest releases consistently outperform oldest releases | Across 255 tasks, two backbones, and six applications, all 12 model–application series improve; QGIS pass@3 rises from 41% to 69% for DeepSeek and 33% to 65% for Haiku. | §§4.1–4.2; Fig. 2 |
| ANIS improves DeepSeek success and online efficiency | On 368 tasks across eight applications: native SDK 68.5%, atomic commands 72.3%, goal-augmented commands 74.5% pass@3; tokens/task are 84.4K, 22.6K, and 21.2K, respectively. CLI-Anything achieves 17.4%. | §5.3; Table 2 discussion |
| Gains also occur with Haiku | Same 368 tasks and generated interfaces: native SDK 61.4%, atomic commands 64.9%, goal-augmented commands 67.4%; tokens/task decrease by over 70% relative to SDK use. | §9; Table 4 discussion |
| Observation access materially affects success | DeepSeek atomic interface on all 368 tasks: prohibiting observation commands by instruction reduces pass@3 from 72.3% to 60.3%; trajectory audit finds no prohibited invocations. | §10; Table 5 discussion |
| Goal commands transfer modestly to held-out tasks | Commands synthesized only from 258 training tasks increase successes from 64 to 67 on 110 held-out tasks; tokens/task fall from 22.8K to 21.7K. | §11.2; Table 6 discussion |
| Synthesis incurs substantial offline cost | Interface generation requires 17.1–36.4 elapsed hours per application across eight applications. | §12 |
| Coverage remains application-dependent | Both ANIS variants underperform native SDK use on FreeCAD and Blender; 28.6% of ANIS FreeCAD failures lack a required command. | §5.3.2 |

These results support benefits within the tested programmatic desktop setting and across both evaluated backbones. Historical comparisons associate release changes with performance, but do not independently isolate discoverability from granularity. The observation ablation provides more direct intervention evidence, specifically for an instruction-based restriction. Online token savings exclude the reported offline synthesis effort.

## Limitations and validity risks
- **Author-reported coverage gap:** Validation can reject useful operations whose prerequisites involve linked modeling objects, selections, or editing modes, particularly in FreeCAD and Blender (§5.3.2).
- **Author-reported observation boundary:** ANIS exposes paired readers when accessors exist; it does not establish universal readback for every writable property (§5.1).
- **Author-reported deployment approximation:** Runtime learning is simulated from prior solved-task trajectories. Goal-level sequence publication remains future work (§§2, 5.2).
- **Analyst inference—causal attribution:** Changing releases can change multiple interface properties together. Feasibility screening reduces functionality confounds but does not separate each proposed mechanism (§§3.2, 4).
- **Analyst inference—evaluation scope:** Persistent artifact tasks exclude transient interface states. Cross-version trajectory-cost analysis also conditions on success in every release, limiting conclusions about failed attempts (§§4.1, 15).
- **Analyst inference—generalization and reproducibility:** Held-out applications and tasks provide useful checks, but the supplied text reports no uncertainty intervals or separate discoverability ablation. Many table bodies and release details are absent from the retrieved text.

## Open research questions
- **Can implicit preconditions be recovered automatically?** Coverage failures persist in FreeCAD and Blender. Test dependency-aware validation that constructs required object relationships and modes, measuring command coverage and task success (§5.3.2).
- **How much does discoverability contribute independently?** ANIS changes discovery, validation, and observation together. Compare flat and hierarchical command exposure while holding commands, descriptions, and read access fixed (§§5.1, 16.1).
- **Do goal commands remain useful during live deployment?** The paper simulates accumulating requests and reports modest held-out gains. Run a chronological request stream with frozen evaluation windows and measure reuse, success, and maintenance cost (§§5.2, 11).
- **When does synthesis cost pay off?** Online tokens decrease, but generation takes substantial elapsed time. Measure total generation and serving cost over increasing task volumes and application updates (§§5.3.2, 12).
