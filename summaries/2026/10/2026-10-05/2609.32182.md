# KeyRec: Bounded Visual Memory for Streaming and Long-Video Understanding

> [← Daily summary](../2026-10-05.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.32182) · [arXiv](https://arxiv.org/abs/2609.32182)


## One-sentence takeaway
KeyRec separates recent visual detail from bounded historical event memory and adaptively reads both, with authors reporting the best compressed performance in 13 of 15 settings at approximately 10% of the dense decoder-facing visual-token budget (§3.2).

## Problem and motivation
Visual tokens accumulate as videos grow, increasing storage and decoder computation. The authors argue that existing training-free token selection can fragment events, discard supporting context, and make recent detail compete with historical coverage under one retention policy (§1). KeyRec addresses this gap by organizing retained tokens as reusable memory before questions arrive.

## Approach and contributions
- **Two-part bounded memory:** A recent cache retains the latest detailed observations; an event bank stores selected historical tokens, route embeddings, timestamps, and utility scores. Persistent storage and per-query readout have separate bounds (§§2.1–2.2).
- **Online event organization:** Tokens novel relative to stored event routes form candidates. Semantic similarity and temporal proximity determine merging; utility and temporal coverage guide eviction. Offline long-video retention uses visual utility without temporal weighting (§2.2; Appendix B).
- **Query-adaptive readout:** The frozen VLM routes each question, using text only, into five allocation states. These choose the recent/event split and relevance-based or coverage-based event retrieval without replaying frames (§2.3).
- **Architecture adaptation:** NEO-ov retains each selected token’s native spatial and temporal metadata. The memory algorithm otherwise remains unchanged (§2.4).

These are the authors’ claimed contributions; the supplied evidence does not independently establish novelty relative to all prior work.

## Evidence and main results

All findings below are author-reported; the supplied text contains table captions and narrative summaries, but omits table cells and plotted values.

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Broad compressed advantage | Best compressed performance in 13/15 settings across four benchmarks and three backbones; approximately 10% decoder-facing tokens, versus approximately 20% persistent storage for KeyRec. Main sampling: 32 streaming-prefix frames or 64 long-video frames. | §§3.1–3.2; Table 1 |
| Strong streaming results | Best compressed result in 8/9 settings; accuracy gains of 2.21–18.37 points over the strongest compressed baseline on OVO-Bench Realtime and StreamingBench. Matches or exceeds Vanilla in all nine streaming settings, by up to 10.01 points. | §3.2; Table 1 |
| Compression remains lossy on long videos | Best compressed result in 5/6 settings, with reported accuracy gaps of 0.30–3.37 points below Vanilla under the main 10% readout setting. | §3.2; Table 1 |
| Persistent storage alone does not explain the reported advantage | On StreamingBench with both Gemma backbones, KeyRec reportedly beats baselines at approximately matched persistent storage while decoding half as many tokens; accuracy peaks at a 5% readout. | §3.3; Figure 2 |
| NEO-ov scales more stably than compared methods | On LongVideoBench’s 900–3,600-second group at a 10% readout ratio, KeyRec stays above 44% accuracy at 512 sampled frames; STC-Pruner and CausalMem fall below 25%. | §3.4; Figure 3 |
| Efficiency includes additional overhead | On LongVideoBench/Gemma E4B at 10% readout, E2E latency overhead versus StreamingTOM-CTR falls from approximately 19% at 64 frames to 10% at 512. KeyRec remains feasible at 512 frames, where Vanilla runs out of memory. | §3.6; Table 2 |
| Advantage persists without the streaming frame cap | Full-prefix 1-FPS evaluation uses a fixed 1,792-token decoder budget. KeyRec has higher overall performance than CausalMem on both streaming benchmarks and both Gemma backbones; E4B backward tracing is only described as close. | §3.7; Table 3 |
| Allocation and presentation matter | With memory and readout held fixed, routing is best or tied against fixed allocations; neutral segmented presentation generally beats flat or explicitly typed presentation. | §3.5, Figure 4; Appendix A.1, Table 4 |

The evidence supports a useful compression trade-off in the evaluated settings. It does not establish lossless memory, universal superiority, or exact per-setting effect sizes from the supplied extraction. The authors’ explanation that redundant context dilutes decisive evidence remains an interpretation rather than an isolated causal finding.

## Limitations and validity risks
- **Author-stated:** Fixed novelty, merging, and retention rules may benefit from learning; selected patches do not explicitly represent identities, trajectories, or state transitions, limiting precise temporal reasoning (Appendix E).
- **Author-stated:** Gemma compression occurs after vision encoding and therefore does not reduce ViT encoding latency. Preliminary intermediate-token reduction did not improve wall-clock encoding time (Appendix E).
- **Analyst inference:** Equal decoder budgets do not imply equal storage or latency. KeyRec retains a larger candidate memory and adds routing overhead, although storage-matched comparisons partly address this concern (§§3.1, 3.3, 3.6).
- **Analyst inference:** Visual-only evaluation and the main streaming sampling cap restrict generalization to audiovisual or continuously processed streams. The full-prefix test addresses the cap only for Gemma against CausalMem (§§3.1, 3.7).
- **Evidence gap:** The supplied text reports granularity, threshold, allocation, and serialization studies, but no isolated removal ablations for novelty scoring, temporal eviction, or positional preservation.

## Open research questions
1. **Can explicit object and state representations improve temporal reasoning?** Patch memory lacks these representations (Appendix E). Compare object-centric memory against KeyRec at matched storage and readout budgets on order, duration, and state-change questions.
2. **Which event-bank rules drive the gains?** Their individual contributions are not isolated in the supplied results. Ablate novelty scoring, temporal merging, and coverage-based eviction separately under matched budgets.
3. **How far does fixed-budget streaming robustness extend?** Full-prefix evidence covers Gemma and one bounded-memory comparator (§3.7). Test longer streams and NEO-ov with fixed storage, measuring QA accuracy and event retention as history grows.
4. **Can encoder-side compression improve total latency?** Preliminary pruning disrupted the optimized encoder path (Appendix E). Test encoder-compatible pruning jointly with KeyRec, measuring ingestion-to-first-token latency and accuracy.
