# The Extender: A Log-Structured Transformer

> [← Daily summary](../2026-10-05.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.32759) · [arXiv](https://arxiv.org/abs/2609.32759)


## One-sentence takeaway
The Extender separates residual computation from append-only attention features, reporting 104× lower between-turn attention memory than its MHA reference at the largest tested size, comparable short-context accuracy, and better average long-context accuracy (§5.1–5.2).

## Problem and motivation
Standard Transformers derive each layer’s keys and values from a changing, full-width residual stream, requiring separate per-layer caches that grow with width, depth, and context length. The author also argues that using this same stream for next-token prediction and communication between layers may create competing demands (§1).

The identified gap is **persistent attention memory between turns**: the paper proposes changing the architecture’s attention inputs rather than only compressing or sharing existing KV caches (§1–2).

## Approach and contributions

- **Two communication channels.** Each layer updates a conventional residual stream, \(h\), and appends a small normalized extension to a separate stream, \(x\). Keys and values read windows of \(x\); queries combine normalized residual and extension-window inputs. Final logits use \(h\) (§3, Figure 1).
- **Shared persistent cache.** Because \(x\) is append-only, one fully extended per-token cache contains the inputs needed by every attention layer. Initial token embeddings can be reconstructed from token identifiers rather than retained as full vectors (§3).
- **Ephemeral KV reconstruction.** Layer-specific KV caches are materialized from the shared cache during turns and may be freed afterward. This preserves ordinary softmax attention while trading reconstruction work for lower between-turn memory (§4).
- **Controlled architectural evaluation.** The paper compares closely matched Extender and Llama-style reference models, studies channel and window choices, and explores logit distillation and GQA compatibility (§5; Appendices B–D).

The default extension width is 32 features, except for a 64-feature first-layer extension; the final layer emits no extension (§3.1).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Much smaller persistent attention memory | At 64k context, the largest size class requires approximately 54.5 million features / 109 MB in bf16 versus 5.67 billion features / 11.3 GB for reference MHA: reported 104× reduction. | §5.2 |
| Comparable short-context performance | Author reports similar DCLM CORE performance across three size classes, with parameter counts within 1% and equal training budgets. Exact main comparison scores are absent from the supplied text. | §5.1, Figure 2 |
| Better average long-context performance, with task-specific exceptions | Largest models evaluated on 13 RULER tasks, with 30 samples per task and greedy decoding, across 1k–32k contexts after ProLong training. Author reports Extender advantages on harder multikey tasks, but a clear Transformer advantage on variable tracking. | §5.2, Figure 3, Table 3 |
| Both channels help query formation | Matched approximately 200M models trained on approximately 4B ClimbMix tokens: queries using either channel alone reportedly underperform on long-context tasks. Numerical ablation entries are unavailable. | §5.3, Table 4 |
| Distillation improves the small Extender | For 199M students using 64-feature extensions and random value windows, trained on 4B ClimbMix tokens at 2k sequence length, centered CORE rises from 15.9% from scratch to 19.1% with an Extender teacher or 17.2% with a Transformer teacher. | Appendix C, Table 6 |
| GQA appears compatible | The 813M GQA Extender reportedly tracks the 924M MHA Extender closely and outperforms reference MHA Transformer; no matching GQA Transformer was trained. Exact scores are unavailable. | Appendix D, Table 7 |

These results support a substantially smaller **between-turn attention cache** and promising accuracy under the reported training settings. They do not establish lower peak within-turn memory, faster inference, statistical significance, or superiority over a matched GQA Transformer. Most main accuracy results are available only as narrative descriptions and figure/table captions.

## Limitations and validity risks

- **Author-stated:** Models larger than 924M parameters were not tested, and training budgets were largely limited to approximately 20 tokens per parameter (§5.4).
- **Author-stated:** Within-turn memory requirements remain comparable to a standard Transformer when ephemeral KV caches are retained (§1, §4).
- **Author-stated:** Quantization and cross-layer attention combinations were not evaluated; the GQA study lacks a matching Transformer GQA baseline (§2, Appendix D).
- **Analyst inference:** Robustness across training runs remains uncertain: §5.1 describes one model per architecture and size, while uncertainty estimates are not supplied.
- **Analyst inference:** Practical serving benefits remain unverified because the text provides no measured reconstruction latency, throughput, or amortization break-even point (§4).
- **Evidence ambiguity:** Appendix B describes its window ablations as both 9.6B tokens in the caption and 9B in prose; Appendix C likewise gives differing teacher-token descriptions.

## Open research questions

1. **Does a fixed small extension remain sufficient at larger scales?** The paper stops below one billion parameters (§5.4). Next experiment: compare matched larger models while sweeping extension width and training budget.
2. **When does cache reconstruction pay off in serving?** Reconstruction is proposed without timing measurements (§4). Next experiment: measure latency, throughput, and peak/persistent memory across context lengths, turn lengths, and concurrent sessions.
3. **What causes the variable-tracking deficit?** The author notes but does not investigate the task-specific reversal (§5.2). Next experiment: vary extension width and read-window policy on controlled variable-tracking and multikey tasks.
4. **How does Extender compare under matched GQA?** The relevant baseline is missing (Appendix D). Next experiment: train both architectures with identical query/KV head configurations and matched budgets.

## Confidence and missing information
**Confidence: medium.** The architecture and memory accounting are clearly described, and Table 6 supplies numerical distillation results. However, supplied Tables 1–5 and 7–8 lack their data bodies, and figures lack plotted values. Material missing information includes exact main accuracy scores, uncertainty estimates, measured inference costs, and evidence of released code or checkpoints.
