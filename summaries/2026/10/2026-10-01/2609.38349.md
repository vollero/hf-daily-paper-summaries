# MILO: Automated Harness Discovery via Orchestrated Multi-Agent Evolution

> [← Daily summary](../2026-10-01.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.38349) · [arXiv](https://arxiv.org/abs/2609.38349)


## One-sentence takeaway
MILO jointly evolves agent harnesses and their search strategy, reporting higher benchmark accuracy and lower token use with fixed solver models, although its broad generality claims exceed the supplied evaluation evidence (Secs. 4–5).

## Problem and motivation
Agent harnesses govern tools, memory, control flow, verification, and stopping, making their design consequential for long tasks. The authors identify four gaps in automated harness discovery: restricted mutation surfaces, repeated failed edits, fixed search strategies that stagnate, and accuracy optimization that neglects cost (Sec. 1, pp. 2–3).

Their objective is to improve a fixed model’s accuracy–cost frontier by searching over runnable harness source code rather than retraining model weights (Sec. 3).

## Approach and contributions
- **Failure-aware island search:** Separate seed lineages preserve distinct designs; hierarchical memory records both accepted and rejected mutations, their edits, costs, and execution evidence (Sec. 4.1.1).
- **Evidence-driven harness rewriting:** Coding-agent mutators inspect source, failure traces, and lineage history before choosing local refinement or structural redesign (Sec. 4.1.2).
- **Search-strategy adaptation:** A stall-triggered orchestrator reassigns mutators, grafts ideas between islands, and creates new islands. The methodology additionally proposes changing the task curriculum (Sec. 4.1.3).
- **Accuracy–cost selection and scientific extension:** Candidates are selected using accuracy, tokens, and latency; an extension evolves harnesses whose agents write mathematical optimizers (Secs. 4.2–4.3). The authors’ claim of unusually broad self-adaptation is a novelty claim, not independently established here.

## Limitations and validity risks
- **Author-stated comparison gap:** Self-Harness, DarwinX, and AIDE2 were excluded because their code was unavailable (Sec. 5.3).
- **Analyst inference—validation reuse:** Held-out scores repeatedly trigger interventions and select the final harness. This split therefore influences search and is not an untouched final test set (Algorithm 1).
- **Analyst inference—component attribution:** The additive ablation covers only Opus 4.8 on Terminal-Bench and does not separately isolate rejected-history retention or each orchestration action (Table 2c; App. A.5).
- **Implementation ambiguity:** The main method specifies random initial mutator assignments and curriculum adaptation, whereas App. A.1 starts all islands with Claude Code and the supplied orchestration prompt exposes no curriculum action (Secs. 4.1.2–4.1.3; App. C.2).
- **Cost interpretation:** Equal wall-clock budgets do not establish equal inference spending. Selection is explicitly accuracy-primary and can accept sufficiently large accuracy gains regardless of cost (Apps. A.1, A.3).
- **Scope and evidence limits:** Experiments instantiate DeepAgents/Python harnesses; transfer is tested within command-line tasks. Mathematical scores are reportedly verifier-confirmed, but supplied optimizer listings are excerpts (Apps. A.1–A.2, E).

No dedicated author limitations section appears in the supplied text. The source is truncated, so this analysis does not imply complete coverage.

## Open research questions
- **Does adaptation generalize to an untouched test distribution?** Validation scores guide search; a next experiment could reserve a third split exclusively for final evaluation.
- **Which orchestration actions drive gains?** The ablation evaluates orchestration as a bundle; a next experiment could disable grafting, reassignment, speciation, and curriculum changes separately under matched budgets.
- **How much do rejected candidates help?** Memory structure and negative evidence are not isolated; a next experiment could compare identical lineage trees with rejected-node evidence visible versus hidden.
- **Are gains framework-independent and cost-effective?** The tested implementation uses DeepAgents and equal wall-clock limits; a next experiment could repeat search in another harness framework while matching total inference expenditure.
