# LEAP: Learned Block-wise Evidence Retrieval for Long Audio-Video Perception

> [← Daily summary](../2026-10-01.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.39938) · [arXiv](https://arxiv.org/abs/2609.39938)


## One-sentence takeaway
LEAP improves long audio-video question answering by learning to select evidence windows through bounded block scans, then answering from raw media, gaining 4.5–16.8 percentage points over same-stack Qwen3-Omni official-style baselines while keeping per-pass context independent of recording duration (Table 1; §3.5).

## Problem and motivation
Hour-scale recordings contain brief, scattered evidence. Whole-recording encoding exhausts context, while uniform compression reduces the detail available for answering. The authors identify a gap in existing selection and agentic approaches: coarse selection can miss evidence, and general-purpose models used for search are often not trained to localize it (§1).

The goal is to preserve timeline coverage and local detail without loading the entire recording into one context.

## Approach and contributions
- **Learned block-wise retrieval:** Divide recordings into 600-second blocks and 75-second candidate windows. A localization LoRA scores window option-letter logits; each block’s maximum score determines block ranking. Retain up to three blocks and three windows per block (§§3.1–3.3).
- **Separate evidence reading and answer training:** Re-encode the selected windows as synchronized raw audio-video, with timestamps, in one bounded answer pass. A separate answer LoRA trains on gold evidence mixed with distractors from other recordings (§§3.2.2, 3.4).
- **Transcript scanning channel:** Search timestamped transcripts using the base selector, then answer from the selected raw media. A capped transcript outline also supplies broader speech context (§4.5).
- **Causal historical retrieval:** Apply the same grid to the prefix available at query time, reserving a recent window and retrieving older evidence without streaming-specific training. This setting uses base answer weights (§4.6; Table 5).

The distinctive contribution is the combination of trained within-block localization, direct cross-block logit ranking, and bounded joint evidence reading—not the general coarse-to-fine strategy, which the authors acknowledge predates LEAP (§1; Appendix A.5).

The evidence supports retrieval and answer-adaptation benefits across several benchmarks and two backbones. The authors define significance through paired, video-clustered bootstrap intervals (Appendix B.1). Bounded context does **not** establish constant total compute: every block is scanned. Cross-backbone results demonstrate adaptation of the framework, rather than transfer of unchanged adapters.

## Limitations and validity risks
- **Author-identified:** Retrieval can miss evidence; the conclusion proposes stronger scores and an answer pass that detects misses and requests another scan (§5).
- **Analyst inference—fixed-budget scope:** A bounded window pool may struggle with broadly distributed evidence. VideoOdyssey counting accuracy is **34.6% versus 38.3%** for the same-stack official recipe, although LEAP improves the other listed task types (Table 20).
- **Analyst inference—cost accounting:** Transcript latency excludes transcription, and optional prefix caching grows linearly with duration. Streaming also requires retained raw media for re-reading (Table 2; Appendices A.4 and B.5).
- **Comparison validity:** Some whole-clip failures count as errors, inflating differences attributable to context feasibility; both-forms-fit controls address this only where available. Published and streaming comparisons also differ in input recipes, voting, judges, or conversational context (Appendices B.3–B.5; D).
- **Attribution limit:** The answer-stage “muted” ablation removes both audio and the transcript outline, so it does not isolate raw audio’s contribution (Table 16b).
- **Reproducibility and contamination:** Code is deferred until acceptance. The contamination audit excludes StreamArena; identifier overlap is reported absent, but outcomes of the described frame-hash and audio-fingerprint checks are not supplied (reproducibility statement; Appendix B.6).

## Open research questions
- **Can LEAP detect missing evidence?** Retrieval misses remain, and rescan behavior is proposed rather than tested (§5). Compare confidence-triggered rescanning against fixed retrieval under matched compute budgets.
- **Can retrieval budgets adapt to question type?** Window-count sensitivity differs across backbones and benchmarks, while counting remains weaker (Figure 8; Table 20). Test question-conditioned window allocation at a fixed answer-token cap.
- **When should transcript and media search be combined?** Transcript retrieval depends on speech content and loses visual clue coverage on CG-Bench (Appendix C.2). Test a channel gate or fused ranking, including transcription cost and speech-poor recordings.

## Confidence and missing information
**Confidence: high** in the method description and reported benchmark results; **medium** in broader efficiency and generalization claims.

Material missing information includes current code and adapter availability, complete media-level contamination outcomes, numerical paired intervals for many headline comparisons, measured peak GPU memory across durations, and end-to-end transcript costs including ASR.
