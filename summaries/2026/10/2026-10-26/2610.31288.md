# DISC: Domain-Integrated Similarity Cost for Time-Series Dataset

> [← Daily summary](../2026-10-26.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.31288) · [arXiv](https://arxiv.org/abs/2610.31288)


## One-sentence takeaway
DISC learns task-specific combinations of time-series dataset distances that outperform the best individual metric in forecasting-error correlation across four settings on one shared dataset split (§§V-E–V-F).

## Problem and motivation
Comparing every possible source–target transfer is expensive, motivating dataset similarity as a screening signal. Existing distances capture different relationships—distribution, temporal shape, or alignment—and the authors argue that their usefulness depends on the forecasting model and adaptation protocol (§I). The gap is how to combine these signals using observed downstream behavior rather than choosing one metric manually.

## Approach and contributions
- **Learned metric integration:** DISC combines standardized distances into a softmax-weighted base score and source-wise percentile ranks into a separately weighted prior. A learned sigmoid gate uses the prior to multiply the base score (§§IV-B–IV-C).
- **Task-specific calibration:** Parameters are trained separately for each forecasting setting using observed source–target errors. Training primarily maximizes mean source-wise Pearson correlation, with a smaller global-correlation term and regularizers encouraging sparse, distinct mixtures. Frozen parameters then score evaluation pairs using similarity features alone (§IV-D).
- **Empirical and interpretive contribution:** The study compares individual metrics and learned aggregation across forecasting settings; learned weights expose which metric signals each calibrated score uses. The underlying distances and forecasting models are existing components (§§V-B–V-F).

## Evidence and main results

All correlations below use the reported test split: mean Pearson correlation across 14 source datasets, each compared with the other 13 test targets (§V-D).

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Aggregation exceeds individual-metric references on average | Across Time-MoE and Lag-Llama under OOD and transfer learning, DISC averages **0.598**, versus **0.403** for PCA-ED, the strongest average single metric, and **0.543** for the per-task best-single-metric oracle. | §V-E; Tables II–III referenced, bodies unavailable |
| DISC improves every task column | Authors report **10.29% average relative improvement** over the best single metric per task. OOD-Time-MoE has only a modest gain. | §V-F; Table IV referenced |
| Improvement persists in the weakest absolute setting | For transfer-learning Lag-Llama, DISC exceeds the best single metric, MMD, by **10.15%** in correlation. Exact correlations are unavailable. | §V-F |
| Learned aggregation beats the sampled-search baseline | Approximately **7.9 million configurations per task** yield average test correlation **0.291**, versus DISC’s **0.598**. Manual-search correlations are **−0.066, 0.571, 0.316, 0.344**, respectively for OOD-Time-MoE, OOD-Lag-Llama, TL-Time-MoE, and TL-Lag-Llama. | §V-G; Table VI referenced |
| Best individual metric changes with setting | MAD leads OOD-Time-MoE; DBA-DTW/DBA-ED lead OOD-Lag-Llama; PCA-ED leads TL-Time-MoE; MMD leads TL-Lag-Llama. | §V-E |

These findings support improved **source-conditioned error alignment on the reported split**. They do not establish better source selection, lower forecasting error after DISC-guided selection, or isolation of transfer compatibility from target difficulty; the authors explicitly distinguish these outcomes (§V-D). Table bodies are absent, so numerical reporting relies on the supplied prose.

## Limitations and validity risks
- **Authors’ scope qualification:** Results use one shared split of 46 datasets into 24 training, 8 validation, and 14 test datasets, without repeated-split uncertainty analysis (§§V-A, V-F).
- **Authors’ measurement qualification:** Forecasting error includes target difficulty, and evaluation fixes a source while varying targets. It does not directly benchmark choosing sources for a fixed target (§V-D).
- **Authors’ sampling concern:** Similarity uses 100 windows of length 16 per dataset; short, flat, or low-diversity samples can weaken metric reliability (§§V-A, V-H).
- **Analyst inference:** The supplied comparison with manual search does not isolate the benefits of ranks, gating, or individual regularizers; component-removal ablations are not reported in the available text.
- **Analyst inference:** Figure 3 selects each task’s highest-correlation source, so its plots illustrate favorable cases rather than typical source behavior (§V-F).
- **Reproducibility gap:** Tables I–VII contain captions but no bodies in the supplied text, leaving detailed hyperparameters, task-wise results, weights, and diagnostics unavailable.

## Open research questions
1. **Do gains persist across dataset partitions?** Only one split is reported (§V-F). Repeat calibration and evaluation over multiple dataset splits and report uncertainty.
2. **Does DISC improve actual source selection?** Source-wise correlation does not test this (§V-D). Rank sources for each fixed target, adapt from selected sources, and compare forecasting error with individual-metric selection.
3. **Which components drive improvement?** The reported search comparison retains the aggregation family (§V-G). Compare base-only, rank-only, ungated, and unregularized variants under identical splits.
4. **How sensitive is DISC to sampling and candidate composition?** Short-window concerns are acknowledged, and features are candidate-relative (§§IV-B, V-H). Vary window lengths, sample counts, and candidate pools while tracking correlation and ranking stability.

## Confidence and missing information
**Confidence: medium.** The method and evaluation scope are clear, but material omissions limit verification: numerical table bodies, complete dataset identities and split assignments, precise downstream loss definitions, forecasting/adaptation settings, several optimization settings, uncertainty estimates, component ablations, runtime costs, and code or artifact availability.
