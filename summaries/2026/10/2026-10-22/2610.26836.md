# Same Simulation, Different Evidence: Where Retrieved Tool Output Costs LLM Agents Accuracy

> [← Daily summary](../2026-10-22.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.26836) · [arXiv](https://arxiv.org/abs/2610.26836)


## One-sentence takeaway
On verified PHREEQC questions, retrieving simulator reports can reduce agent accuracy by redirecting answers toward agent-created outputs that are misrounded, and explicitly naming the authoritative report largely repairs this failure (§§3–5).

## Problem and motivation
Agent harnesses often replace long inline tool outputs with files that agents inspect on demand. An accuracy drop alone cannot reveal whether the agent computed incorrectly, missed the relevant evidence, or answered incorrectly despite seeing it. The authors use deterministic simulation to distinguish these stages and test where output delivery causes losses (§1).

## Approach and contributions
- **Verified evaluation subset:** Re-execute an existing question pool and retain 158 items across 19 setups whose keyed answers are uniquely reproduced and numerically stable; this is verification of an existing benchmark, rather than creation of the original questions (§2.1).
- **Execution-grounded diagnosis:** Re-run 11,007 simulator calls from 5,773 logged trajectories and separate numeric performance into **build**, **exposure**, **closure**, and unsupported answers. Shapley attribution describes how these stages contribute to observed accuracy differences (§§2.3, 4).
- **Mechanism and interventions:** Identify “evidence substitution”—answering from agent-created files instead of the canonical report—and test it through frozen-computation replay, authoritative-report instructions, a rounding-only control, and conditional inlining (§§4–5).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Retrieval losses depend on the model | On 158 verified items, pooled TOC-minus-inline accuracy is **−11.3 percentage points** for GPT-5.1 (95% CI [−18.0, −4.9]) and **−7.9 points** for GPT-5.2 ([−14.9, −0.9]). Only GPT-5.1 survives Holm correction across five models: p=0.005 versus p=0.128 for GPT-5.2. | §3, Table 1 discussion |
| Near-zero net effects can conceal failures | Pooled differences are −0.6, −0.5, and +0.2 points for Opus, Sonnet, and GPT-5.4, respectively; intervals include zero. On numeric items against its logged inline run, GPT-5.4 has exposure and closure contributions of −2.6 and −7.2 points, partly offset by improved build. | §§3–4, Tables 1 and 3 discussion |
| Delivery alone can reduce accuracy | Across three paired continuations of 131 frozen GPT-5.2 numeric checkpoints, TOC reduces accuracy by **9.4 points** (95% CI [−14.5, −4.6]); setup-bootstrap CI is [−13.9, −5.2]. Computation and visible history are held fixed. | §4; Appendix D |
| Agent-created evidence is associated with truncation errors | Under TOC, GPT-5.2 and GPT-5.1 skip the report in 60.3% and 53.0% of trajectories. Among trajectories seeing a value that rounds to the key but truncates to a distractor, they choose that distractor in 26/35 and 19/27 cases; Sonnet does so in 1/35. | §4, Table 4 discussion |
| Naming the report repairs closure | TOC+Report raises accuracy over pooled TOC runs by +6.3, +7.9, and +7.8 points for GPT-5.1, GPT-5.2, and GPT-5.4. Numeric closure reaches 99.2%, 98.8%, and 99.0%, respectively. | §5, Table 5 discussion |
| Rounding advice alone provides little gain | For GPT-5.2 and GPT-5.1, TOC+Round changes accuracy by only +0.6 and +1.2 points relative to pooled TOC runs; closure remains about 82%. Hybrid improves accuracy over the single TOC control by +4.6 and +8.0 points, respectively. | §5 |

The paired replay supports a causal delivery effect for GPT-5.2 in this setting. The interventions support the authors’ evidence-selection explanation, but Shapley contributions are descriptive allocations, not independent causal effects. No detectable net difference does not establish equivalence, and the findings do not establish that retrieval generally harms agents.

## Limitations and validity risks
- **Author-stated:** All models are closed API systems; decoding settings differ, explicit reasoning settings are untested, and served-model changes between runs are not modeled (§9).
- **Author-stated:** Logging and repetition are uneven. Long-output TOC items share one corrected-index run; decomposition uses one logged inline run per model. Frozen replay covers only GPT-5.2 checkpoints originating from inline execution (§9).
- **Author-stated:** Full-agent conditions change prompt descriptions as well as delivery. Only one wording of each instruction is tested; TOC+Report combines source authority, a reading directive, and a precision warning (§9; Appendix B).
- **Measurement risk:** Numeric matching can mistake another quantity’s value for relevant evidence. Manual labels agree with automatic labels on 52/58 audited numeric trajectories, but the audit is outcome-selected (Appendix C).
- **Analyst inference:** Generalization beyond this simulator and precision-sensitive multiple-choice format remains uncertain. Verification establishes execution consistency, not independent scientific correctness (§§2.1, 9).

## Open research questions
- **Does the mechanism transfer beyond PHREEQC?** Only one simulator is evaluated. Repeat the delivery and frozen-replay comparisons on another deterministic tool with competing output files.
- **Which instruction component matters?** TOC+Report bundles several directives. Ablate file naming, mandatory reading, authority language, and the precision warning separately.
- **Would matching output precision prevent substitution errors?** Higher-precision agent files are implicated but not directly manipulated. Hold delivery fixed and vary selected-output precision.
- **Do reasoning settings change evidence choice?** Explicit reasoning is untested. Repeat matched comparisons across reasoning settings while measuring report skipping and closure (§9).

## Confidence and missing information
**Confidence: medium.** The supplied text supports the principal findings and their qualifications, but many referenced tables contain captions without their complete cells. Public availability of code, verified inputs, logs, and checkpoints is not established; complete per-condition results, exact served-model snapshots, and broader-domain validation are unavailable.
