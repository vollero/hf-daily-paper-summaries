# OpenRUA: Robot-Use Agents Are Zero-Shot Visuomotor Policies

> [← Daily summary](../2026-10-06.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.02459) · [arXiv](https://arxiv.org/abs/2610.02459)


## One-sentence takeaway
The authors report that an off-the-shelf coding agent using documented native ROS 2 interfaces can achieve strong zero-shot manipulation success in simulation by writing perception and control programs during execution, while physical deployment remains untested (§§3–5).

## Problem and motivation
Robot-use agents commonly depend on custom interfaces, predefined primitives, or learned robot policies. The authors ask whether capable coding agents can instead use the robot’s existing software stack, reducing additional harness engineering and avoiding task-specific robot training (§§1–2).

The identified gap is whether native-interface access and a workspace suffice for observation-to-action control without a prescribed agent workflow (§1).

## Approach and contributions
- **Workspace harness:** OpenRUA supplies terminal access to ROS 2, machine documentation, configuration, and editable starter tools; the agent chooses its own observation, execution, and verification sequence (§3; Appendix B).
- **Perception and control through code:** Sensor readings become image and numerical files; the agent writes measurement programs, motion clients, and feedback controllers using native interfaces (§§3, 4.3–4.4).
- **Empirical characterization:** The paper evaluates zero-shot manipulation, task perturbations, composite-task generalization, computation scaling, and agent-generated program usage (§4).

The contribution is the harness design and its evaluation, rather than ROS 2 or code-based robot control themselves. “Zero-abstraction” means no additional agent-specific API: substantial generic guidance and executable perception/control examples are still supplied (Appendices B.2, H).

## Evidence and main results
All findings below are author-reported.

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Strong CaP-Bench success | Claude Code–Opus 5, high reasoning effort: **99.0%**, versus ASPIRE’s **81.0%**; seven tasks, 100 trials each; official success predicates. | Table 1(a); §§4.1–4.2 |
| Strong perturbation robustness | **87.0%** across eight LIBERO-PRO suite–perturbation cells, versus Claude Code–Opus 4.7 Harness VLA’s **82.4%**; 800 OpenRUA trials. The six-cell OpenRUA average is separately **91.8%**. | Table 1(b); Appendix C.1 |
| Composite-task generalization with modest absolute success | RoboCasa365: **26.3%** seen and **28.1%** unseen composite success; **39.4%** overall. Ten trials per task across 50 tasks. Codex Harness VLA reports **61.0%**, **13.8%**, and **57.1%**, respectively, under a different sampling/exploration protocol. | Table 4; §4.5; Appendix C.1 |
| Frequent self-written perception programs | Across 1,500 CaP-Bench/LIBERO-PRO episodes, including failures: **72.67%** use self-written image processing; **96.80%** run self-written metric programs. | Table 2; §4.3 |
| Frequent self-written control programs | Same 1,500 episodes: **95.87%** contain agent-written motion clients; **50.13%** execute self-written feedback-control programs. | Table 3; §4.4 |
| More computation improves success | On LIBERO-10, 200 trials per configuration: Opus 5 success rises from **50% to 70%** when the turn budget increases from **100 to 200**; GPT-6 Astra achieves **62.5%** at medium versus **69.0%** at high reasoning effort. | Figure 8; §4.6 |
| Failures have multiple sources | Of **413** failed Opus 5 episodes, **238 (58%)** are assigned to instruction/predicate issues or budgets exhausted handling undocumented machine behavior; **75 (18%)** to physical limits; **100 (24%)** to agent errors. | Table 5; §4.7 |

These results establish feasibility in the tested simulations. Program frequencies document behavior, but do not establish that those programs caused the success gains. Cross-system comparisons use previously published results, different models, and differing experience/oracle settings (§4.2; Tables 1, 4).

The unseen-task comparison also depends on the Harness VLA variant: Table 4 reports **15.0%** for its Claude Code variant and **13.8%** for its Codex variant. These should not be conflated.

## Limitations and validity risks
- **Author-stated deployment limits:** Evaluation is simulation-only. Paused deliberation omits environmental evolution during inference; realistic sensing errors and independently enforced safety controls remain untested (§5).
- **Author-stated execution weaknesses:** Agents can issue unsafe motions, misidentify objects, misuse measurements, or exhaust budgets polling jobs. Verifying placement can miss incorrect object identity (§4.7; Figure 24).
- **Comparison limits:** CaP-Bench initial states are not paired with prior systems; RoboCasa365 trial counts and prior exploration differ (Appendix C.1).
- **Analyst inference:** The supplied evidence does not isolate the harness’s contribution from model capability, available sensing, or starter guidance. Appendix H includes grasping patterns, troubleshooting, geometric measurement, IK motion, and feedback-based base control.
- **Coverage limit:** The source is truncated, omitting substantial protocol and analysis material; this digest does not imply complete coverage.

## Open research questions
1. **Does performance survive continuous environmental evolution?** Simulation pauses during deliberation (§5). Next experiment: repeat dynamic tasks with continuous simulation and measured inference delays.
2. **How much do starter tools and guidance contribute?** The workspace includes meaningful operational support (Appendix H), whose individual effects are not established here. Next experiment: hold the model and trials fixed while ablating documentation and tool groups.
3. **How robust are generated measurements to sensing errors?** Realistic noise, missing depth, and calibration errors remain untested (§5). Next experiment: introduce controlled sensor corruption and measure success and geometric error.
4. **Can independent safety controls preserve task performance?** Agent-generated safeguards are not guaranteed correct (§5). Next experiment: enforce collision and motion checks while measuring success, interventions, and unsafe requests.
