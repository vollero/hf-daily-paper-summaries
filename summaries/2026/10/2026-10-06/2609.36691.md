# Video2Skill: From Streaming Experience to Reusable Embodied Skills

> [← Daily summary](../2026-10-06.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2609.36691) · [arXiv](https://arxiv.org/abs/2609.36691)


## One-sentence takeaway
Video2Skill shows that supervised VLMs can better group streaming manipulation events into symbolic skills while still struggling to recognize when an unfamiliar transformation requires a new schema (§§4–5).

## Problem and motivation
An embodied agent needs a repertoire of reusable skills before it can compose them into plans. The authors ask whether passive video observation can build that repertoire incrementally, rather than relying on predefined skills, execution feedback, or robot trajectories (§1).

Their identified gap is between describing individual events and maintaining consistent abstractions across experience: an evolving library can merge distinct transformations or accumulate duplicate schemas, affecting subsequent decisions (§1).

## Approach and contributions
- **Task and benchmark:** Streaming Embodied Skill Discovery processes video chunks with a persistent library and optional unfinished event. Outputs contain temporal boundaries, symbolic transformation schemas, and typed arguments. Video2Skill curates RoboInter and HD-EPIC into a reference partition of 48 canonical transformations, withheld from models (§§2.1–2.2).
- **Evaluation protocol:** Measures temporal coverage, naming-invariant grouping through pair precision/recall and Adjusted Rand Index (ARI), and creation–reuse decisions inferred from first occurrences in the matched sequence (§2.3).
- **Comparative diagnosis:** Evaluates 19 open-source VLMs using unified visual recognition/library updating versus factorized event description followed by text-only library updating (§3).
- **Training intervention and analysis:** Introduces Counterfactual Library-state Rebalancing (CLaRe), editing library states while holding observations fixed and adjusting targets. Compares it with oracle-history SFT and student-history on-policy correction, then examines order sensitivity, training frequency, and unseen transformations (§§4–5).

The resulting skills are semantic descriptions, not executable controllers (§2.1).

## Evidence and main results

Scores below use the paper’s ×100 reporting convention, except schema counts.

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Factorization trades overmerging for fragmentation | On balanced-order HD-EPIC without task-specific training, Qwen3.5-2B unified → factorized: pair precision 9.2 → 48.0, pair recall 53.8 → 2.4; Create recall 9.1 → 92.1, Reuse recall 99.3 → 18.2. | Table 1; §3 |
| Scale does not consistently improve grouping | Unified Qwen3.5-4B → 27B: ARI 8.7 → 19.9 on HD-EPIC, but 19.4 → 4.6 on RoboInter, under the same zero-shot protocol. | Table 1; §3 |
| Oracle-history supervision substantially improves unified grouping | Qwen3.5-4B zero-shot → oracle-history SFT: RoboInter ARI 19.4 → 60.0, coverage 56.9 → 52.4; HD-EPIC ARI 8.7 → 31.0, coverage 61.4 → 49.6. | Table 2 |
| CLaRe provides setting-specific benefits | Unified Qwen3.5-4B on HD-EPIC, oracle-history SFT → CLaRe: Create recall 28.6 → 40.0 and coverage 49.6 → 53.3, but ARI 31.0 → 29.2. | Table 2 |
| Better recurrence handling can weaken creation | Factorized LLaVA-OneVision-2-8B on RoboInter, zero-shot → on-policy correction: pair recall 0.8 → 25.1, Reuse recall 29.1 → 94.6, Create recall 80.0 → 20.0; coverage stays 71.7. | Table 2 |
| Library expansion remains limited across orders | Unified Qwen3.5-4B with oracle-history SFT finishes three orders of 40 HD-EPIC clips with 21–22 schemas versus 46 observed reference classes. | Figure 2; §5 |
| Localizing training-unseen transformations rarely triggers creation | Unified Qwen3.5-4B on HD-EPIC: supervised unseen-class coverage is 57.6–66.1; new names at first matched occurrences occur for 1/10 classes with oracle history, 1/9 with CLaRe, and 0/10 with on-policy correction. | Table 3(b); §5 |

These results support improved grouping with persistent creation–reuse failures in the tested settings. They do not establish downstream planning or control benefits. Grouping is evaluated only on matched events, so changing coverage can change the evaluated subset; creation scores also do not determine whether a schema is introduced later (§§2.3, 5, 7).

## Limitations and validity risks
- **Author-stated scope:** Evaluation covers tabletop robotics and egocentric kitchens; broader activities and downstream planning/control remain untested (§7).
- **Protocol limitations:** Unmatched predictions receive no penalty, and one prediction may match multiple references. Pair metrics favor frequent classes; synonymous schema strings count separately. Creation/reuse measures first-name occurrence rather than semantic correctness or complete library history (§2.3).
- **Analyst inference:** Unified training comparisons partly confound grouping improvement with changes in recovered events. RoboInter references are explicitly nonexhaustive, limiting conclusions about complete event detection (§§2.2–2.3; Table 2).
- **Reporting inconsistencies:** §4.2 gives Qwen3.5-4B baseline precision and HD-EPIC coverage values that disagree with Tables 1–2; the results above use the tables. §5 refers to “Table 5,” while the supplied frequency/novelty table is labeled Table 3.
- **Reproducibility gaps:** The supplied text does not provide full prompts, video sampling/chunk settings, training hyperparameters, teacher identity, repeated-run uncertainty, or component-level CLaRe ablations.

## Open research questions
- **Can novelty supervision improve creation without increasing duplicates?** Training-unseen events are recovered but rarely receive new names (§5). Test explicit novelty supervision on held-out transformations while measuring both creation and fragmentation.
- **How much improvement comes from library management alone?** Unified coverage changes after training (Table 2). Compare strategies on identical oracle event segments to isolate schema assignment.
- **Do discovered schemas improve embodied task performance?** Their downstream utility is untested (§7). Compare planning success using discovered versus reference libraries with a fixed planner and controller.

## Confidence and missing information
**Confidence: medium.** The task and tabulated findings are clear, but reporting inconsistencies and missing implementation details limit precise interpretation and reproducibility.

Material missing information includes statistical uncertainty, complete training/inference configuration, annotation agreement, component ablations, confirmed asset releases, and downstream planning/control evaluation.
