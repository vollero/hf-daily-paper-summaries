# RobotUse: Allocating Computation, Context, and Decisions

> [← Daily summary](../2026-10-06.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.04929) · [arXiv](https://arxiv.org/abs/2610.04929)


## One-sentence takeaway
RobotUse combines visually editable robot actions, subgoal-local agent contexts, and a persistent playbook, achieving 45% success on the selected RoboLab tasks while reducing token use relative to its single-agent ablation (§§4–5).

## Problem and motivation
Robot agents must revise physical choices after observing failures, but high-level tools can hide grasp or approach decisions, while code-based interfaces expose execution complexity and accumulate lengthy histories. The authors identify a need to delegate geometry and control while preserving inspectable action choices and the context needed to correct them (§§1, 3).

## Approach and contributions
- **Visual action interface:** Agents select targets and grasp candidates, inspect pose previews, and edit positions and orientations; the backend performs geometric conversion, motion planning, and control (§§4.1, 4.3; Appendix B).
- **Context handoff:** A main agent delegates language-defined subgoals to subagents using the same model. Detailed interactions stay local; outcome reports, images, and unresolved constraints return to the main agent (§4.2).
- **Experience-based guidance:** A refiner updates a persistent playbook from main-agent trajectories and returned reports, keeping model parameters and backend code fixed (§4.4).

The contribution is this combined harness design and its evaluation; delegation and persistent guidance are explicitly built on prior work (§2).

## Limitations and validity risks
The supplied text contains no dedicated author limitations section, but documents these protocol qualifications:

- **Comparison conditions:** Methods have different stopping rules; direct-action policies have separate repetition protocols, and π₀.₅ uses different initialization. CaP-X’s motion implementation is modified to share RobotUse’s path checks (Appendix A.1).
- **Resource coverage:** Reported API costs exclude local perception/GPU costs; learning evaluations exclude development probes and playbook updates (Appendices A.1–A.2).
- **Analyst inference—generalization:** Simulation refinement uses the evaluated catalog, so its improvement does not demonstrate transfer to held-out tasks. Physical transfer covers only the stated task sequence (§5.4).
- **Analyst inference—attribution and uncertainty:** No separate pose-interface ablation or statistical uncertainty analysis is supplied. The context ablation also allows a longer single-agent limit for CleanUpToysTask (Appendix A.4).

## Open research questions
- **Does playbook refinement transfer to unseen task families?** Catalog reuse leaves this open. Refine on one task subset, freeze the playbook, and evaluate disjoint tasks.
- **Which interface features drive robustness?** Grasp-tool removal does not isolate previews, pose editing, and feedback interpretation. Ablate these features individually under matched budgets.
- **How robust is physical transfer to scene changes?** The physical evidence covers three tasks in the stated setup. Test frozen playbooks with new objects, occlusion, and altered camera configurations.

## Confidence and missing information
**Confidence: medium.** The method and headline results are explicit, but the supplied text lacks most table cells and plotted values, numerical physical-baseline results, uncertainty estimates, full prompts/playbooks, detailed perception and grasp-generation implementation, total adaptation cost, and confirmed code or asset availability.
