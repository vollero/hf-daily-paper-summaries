# Beyond Semantic Similarity: Performance and Costs of Agentic Retrieval for Complex Tasks

> [← Daily summary](../2026-10-06.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.05750) · [arXiv](https://arxiv.org/abs/2610.05750)


## One-sentence takeaway

A ReAct retrieval agent improves nDCG@10 over the same embedding models on ViDoRe v3 and BRIGHT, but its ViDoRe evaluation requires substantially more latency and tokens than standard retrieval (Tables 1 and 3).

## Problem and motivation

Complex retrieval queries may require reasoning, decomposition, and exploration rather than direct semantic matching. The authors argue that dense retrieval misses relevant documents when queries and documents have little surface similarity, while static LLM query rewriting cannot adapt to newly retrieved information (§§1–2). They investigate whether making retrieval itself agentic provides a reusable search component for diverse tasks.

## Approach and contributions

- **Adaptive retrieval pipeline:** NeMo Retriever Agent receives the query and initial dense retrieval results, then uses a ReAct loop with `Retrieve`, `Think`, and `Final_Results` tools to explore and rank documents. Failed runs fall back to reciprocal rank fusion of previous searches (§2; Figure 1).
- **Comparative evaluation:** The study measures retrieval quality across two benchmarks, embedding models, and LLMs, and tests transfer against the specialized INF-X-Retriever pipeline (§3; Tables 1–2).
- **Cost and infrastructure analysis:** It reports latency and token consumption and describes replacing MCP with an in-process, thread-safe singleton retriever (§2, Infrastructure; Table 3).

The contribution is the pipeline and its empirical characterization; ReAct and dense retrieval are existing components. An earlier pipeline version was already released (§1, footnote 1).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Agent improves enterprise retrieval | ViDoRe v3 nDCG@10: Opus 4.5 agent with colembed-vl-8b-v2 scores **69.22**, versus **64.36** for standard retrieval with that embedding model | Table 1 |
| Agent improves reasoning-intensive retrieval | BRIGHT nDCG@10: Opus 4.5 agent with llama-nv-reasoning-3b scores **50.79**, versus **38.28** for its standard retrieval baseline | Table 1 |
| Gains persist with the weaker embedding model | With llama-nemotron-1b, gpt-oss agent versus standard retrieval: **62.42 vs 55.83** on ViDoRe v3 and **33.85 vs 19.56** on BRIGHT, measured by nDCG@10 | Table 1 |
| LLM choice matters | With each benchmark’s stronger embedding model, Opus versus gpt-oss agent nDCG@10 is **69.22 vs 66.38** on ViDoRe v3 and **50.79 vs 41.27** on BRIGHT | Table 1 |
| More exploration accompanies the stronger LLM | On ViDoRe v3, average search calls per query are **9.2** for Opus 4.5 and **2.4** for gpt-oss-120b | §3.2 |
| Transfer comparison favors different systems on different benchmarks | Table 2 reports agent versus INF-X scores of **69.22 vs 51.01** on ViDoRe v3 and **50.90 vs 63.40** on BRIGHT. On ViDoRe, INF-X with the agent’s embedding model scores **62.31**, below dense-only **64.36** | Table 2; §3.3 |
| Agentic retrieval is expensive | ViDoRe v3 per-query averages: Opus **136.3 s**, **759.4k input / 6.2k output tokens**; gpt-oss **78.6 s**, **768.9k / 5.4k tokens**. Standard retrieval takes **0.67 s** | Table 3; §3.3, Costs |

These comparisons support improved ranking quality over the tested same-embedding baselines and substantial inference overhead. They do not isolate whether reasoning, additional searches, or final document selection drives the gains. The transfer results support reuse across these two benchmarks, rather than unrestricted generalizability.

The authors summarize the best agent’s improvement as **8.7 nDCG@10 points averaged across the two benchmarks** (§1). BRIGHT agent scores differ between Tables 1 and 2 (**50.79 versus 50.90**), without explanation. Table 2 does not explicitly label its score metric.

## Limitations and validity risks

- **Author-stated:** LLM inference latency and token consumption limit deployment at scale (§3.3, Costs; §4).
- **Author-stated:** Agents can exceed their context window or encounter content errors; RRF provides fallback results (§2, Reliability).
- **Analyst inference:** The supplied text reports no controlled ablations of the Think tool, initial retrieval results, iterative feedback, or final ranking. Their individual contributions remain uncertain.
- **Analyst inference:** Search-call counts differ between LLMs, so their quality comparison does not isolate reasoning capability at equal exploration budgets (§3.2).
- **Analyst inference:** Generalizability evidence covers two benchmark collections and one specialized comparator. Cost measurements cover only ViDoRe v3 (§3).
- **Reporting gaps:** Exact prompts, retrieval budgets, hardware, failure rates, uncertainty estimates, and quantitative infrastructure comparisons are unavailable in the supplied text. The linked code was not inspected.

## Open research questions

1. **How much quality survives a strict retrieval budget?** The paper reports high costs without a budget sweep. Next experiment: vary search-call and token caps and measure nDCG@10, latency, and failure rates.
2. **Which agent components produce the gains?** Component ablations are absent. Next experiment: compare static rewriting, adaptive retrieval, and adaptive retrieval with Think under matched search budgets.
3. **Does transfer extend beyond these benchmarks?** Generalizability is demonstrated only on ViDoRe v3 and BRIGHT. Next experiment: freeze the pipeline and evaluate additional corpora and query types.
4. **Can parallel searches reduce latency without degrading quality?** Section 4 proposes parallel tool calls but reports no comparison. Next experiment: compare sequential and parallel search with matched retrieval and token budgets.

## Confidence and missing information

**Confidence: medium.** The supplied tables clearly support ranking gains and high costs, but causal attribution and broader transfer remain uncertain.

Material missing information includes benchmark sample counts and aggregation details, exact prompts and stopping rules, execution hardware and timing protocol, repeated-run variability, fallback frequency and quality, BRIGHT costs, monetary costs, and an explanation for the inconsistent BRIGHT agent scores.
