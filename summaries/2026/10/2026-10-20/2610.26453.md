# Remembering Has a Price: Learning Memory Worth under Resource Constraints

> [← Daily summary](../2026-10-20.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.26453) · [arXiv](https://arxiv.org/abs/2610.26453)


## One-sentence takeaway
TokenWorth learns which past experiences to retrieve and retain from online task outcomes, reporting higher success and fewer output tokens than evaluated baselines across six tightly budgeted LifelongAgentBench settings (§5.2).

## Problem and motivation
Lifelong language agents must reuse experience while respecting limits on generation, interaction rounds, memory capacity, and injected context. The authors argue that semantic relevance alone cannot identify memories that improve execution: an unhelpful retrieval can waste scarce context and recovery opportunities. They identify joint resource constraints—and memory selection under those constraints—as a gap in existing evaluations (§§1–3).

## Approach and contributions
- **Joint-budget formulation:** Defines lifelong adaptation with a frozen backbone under explicit generation, interaction, storage, retrieval-count, and context limits; auxiliary language-model generation counts toward the main per-task output budget (§3).
- **Online memory-worth learning:** TokenWorth combines a prior-regularized linear scorer with an RFM residual predictor. Kernel ridge regression updates predictions frequently, while slower Average Gradient Outer Product updates adapt feature geometry. Supervision comes only from outcomes for selected memories (§§4.2–4.3).
- **Unified retrieval and retention:** Query-dependent scores select a memory; scores averaged over recent probe queries guide admission, replacement, and eviction. Only externally verified successful tasks create memories. The controller requires no backbone updates or auxiliary language-model calls (§4.4; Appendix B).
- **Empirical evaluation:** Tests joint-budget effectiveness across two backbones and three main environments, with additional coding and text-based embodied evaluations (§5; Appendix C).

The reported results support improved task success and output-generation efficiency under the specified main-evaluation budgets. They do not establish lower total inference cost: input tokens and controller computation are excluded (Appendix A.4). Additional benchmarks use per-call output limits and separate auxiliary-call allowances, so they do not reproduce the pooled per-task budget used in the main experiments (Appendix C).

## Limitations and validity risks
- **Author-stated credit-assignment limit:** Success or failure supervises only the selected memory; it does not identify that memory’s causal contribution. No alternative-memory re-execution is performed (§4.2; §6).
- **Author-stated budget scope:** Main results concern one fixed stringent budget per environment, without a claim of robustness across budget levels (§5.1).
- **Analyst inference—limited component attribution:** The core ablation covers local DB only. It does not separately isolate learned retrieval from worth-guided retention, and the full system’s gain over the base scorer is modest (§5.2).
- **Analyst inference—uncertain robustness:** Main task ordering is fixed, and the supplied text reports no repeated-run uncertainty or significance estimates. Small transfer margins therefore have unclear reliability (Appendices A.3, C).
- **Analyst inference—comparison reproducibility:** Baselines are adapted to common limits, but their detailed adaptation procedures are not supplied. Table 1 and Table A2 contain captions without their full numerical bodies in the retrieved text (Appendix A.2; §5.2; Appendix C).
- **Evaluation boundary:** ALFWorld success includes training and validation phases with memory updated throughout; it measures online adaptation rather than evaluation with memory frozen after training (Appendix C).

## Open research questions
1. **Does the advantage persist as budgets change?** Only fixed main budgets are tested. A next experiment could sweep output allowance, memory capacity, and injection length while measuring success and total resource use.
2. **How much improvement comes from retrieval versus retention?** The reported ablation does not separate them. Cross learned versus relevance-only retrieval with learned versus fixed retention policies under identical budgets.
3. **Can feedback distinguish useful memories from successful executions?** Selected-only outcomes leave causal credit unresolved. A controlled diagnostic could compare alternative memories and no memory on sampled tasks, accounting for the extra execution cost.
4. **Are small gains robust to task order?** Fixed sequences and missing uncertainty leave this open. Repeat evaluations across shared shuffled streams and report paired success differences and variability.

## Confidence and missing information
**Confidence: medium.** The method and protocols are described in detail, but result verification is limited by missing full tables.

Material unavailable information includes complete baseline success and token counts, absolute output-token averages, main OS/KG task counts, repeated-run uncertainty, detailed baseline adaptations, total-cost measurements, and separate retrieval-versus-retention ablations. Code availability is author-reported and was not independently checked.
