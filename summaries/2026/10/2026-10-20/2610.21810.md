# N-Gram Memories at Two Bits: Quantizing Lookup Tables in Large Language Models

> [← Daily summary](../2026-10-20.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.21810) · [arXiv](https://arxiv.org/abs/2610.21810)


## One-sentence takeaway
Conditional Program compresses trained hashed n-gram lookup tables using independently decoded trellis codes and row scales, reporting 41–63% lower output KL than two-bit rounding while improving serving capacity primarily under memory pressure (§§3–5).

## Problem and motivation
Conditional-memory language models retrieve only a few embedding rows per input, but must retain the entire table. Compression must therefore reduce total storage while preserving independent row access and the information consumed downstream. The authors identify a gap in dense-weight compression methods, whose reconstruction layouts may require fetching or decoding unrelated entries (§§1–2).

## Approach and contributions
- **Selective compressed representation:** CP stores a short code and a local scale per row, with a shared decoder; inference reconstructs only requested rows while leaving addressing and other model parameters fixed (§§3.1, 3.4).
- **Concrete encoding design:** Gaussian trellis coding operates without coordinate rotation. A bf16 scale restores each decoded row’s original norm rather than minimizing coordinate reconstruction error. Storage is \(b+16/d\) bits per parameter before alignment (§§3.2–3.4).
- **Empirical design and deployment analysis:** The paper compares compression fidelity, downstream scores, alternative representations, and serving layouts. Its contribution is the combination and evaluation for selective lookup; trellis quantization itself builds on prior methods (§§4–6).

## Evidence and main results

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Better output fidelity than rounding | Across the three hashed-memory models, two-bit CP reduces six-domain geometric-mean per-token KL to the original model by **41–63% versus two-bit RTN**. | §4.2; Figure 2 |
| Smaller improvement over adapted QTIP | Two-bit CP lowers the same KL metric by **3–9% versus QTIP**, while adding a bf16 scale per row. Effective CP rates are **2.06/2.10/2.06 bpp** for DeepSeek/Qwen/LongCat, versus QTIP’s **2.00 bpp**. | §4.2; Table 18 |
| Knowledge-score gains over RTN vary by model | On the seven-task knowledge group, CP two-bit minus RTN two-bit is **+0.67 percentage points [0.27, 1.06]** for Qwen, **+0.82 [0.23, 1.41]** for LongCat, and **+0.40 [−0.04, 0.84]** for DeepSeek; intervals are paired 95% bootstrap intervals. | Appendix B.2 |
| Norm restoration helps at fixed codes and storage | At two-bit codes, norm-restoration/row-LS KL ratios are **0.991 [0.987, 0.995]**, **0.937 [0.904, 0.970]**, and **0.922 [0.917, 0.928]** for DeepSeek, Qwen, and LongCat over six domains. | Table 18 |
| Row layout improves isolated prefill lookup | For identical requests from **4,096 tokens**, with **48 rows/token** on one H200, CP versus tile windows takes **0.1905 ± 0.0034 versus 0.2210 ± 0.0034 ms** in HBM and **6.544 ± 0.022 versus 10.781 ± 0.091 ms** from pinned host DRAM; statistics summarize five run medians. | §5.1; Appendix G.1 |
| Compression relieves GPU memory pressure | On four H200s, DeepSeek table memory falls from **50.7 GB/GPU FP8 to 12.7 GB/GPU CP**. For eight 4k-token prompts, prefill falls from **64.66 ± 2.49 to 13.27 ± 0.22 s** across three runs; decode latency remains similar. | Table 5(a) |
| Larger tested workloads fit | On eight H200s, largest successful tested decode batch rises from **1,024 FP8 to ≥2,048 CP**, and prefill from **96k to ≥128k tokens**; each setting has one run. | Table 5(b) |

The evidence supports improved compression fidelity and memory-constrained serving capacity in the tested systems. It does not establish task-score equivalence, universal speedups, or exact capacity thresholds. The lookup-layout experiment measures access cost rather than matched output fidelity; when memory is sufficient, the authors report little complete-step speed improvement (§7; Appendix G).

## Limitations and validity risks
- **Author-stated scope:** Main conclusions concern three trained hashed-memory models. Token-indexed Gemma PLE experiments require different handling of sensitive rows, limiting architectural generalization (Limitations; Appendix H).
- **Author-stated comparison limits:** Fitted-codebook and structured-residual output-KL comparisons use Qwen only; some matched-rate trellis results are interpolated without uncertainty. Higher-rate settings have less downstream-task coverage (Limitations).
- **Statistical limits:** Task intervals are unadjusted for multiple comparisons, and intervals containing zero do not establish equivalence (Appendix B.2).
- **Deployment limits:** Measurements use one node and eager inference; some settings have one run. English-web read counts may not represent deployment traffic (Limitations).
- **Reproducibility and accounting:** Independent encodes are not bit-reproducible because of k-means. Qwen RTN metadata is evaluated in fp32 but counted as bf16; reported logical sizes may exclude SSD padding (Appendix A.3).
- **Analyst inference:** Gaussian-looking coordinates alone are insufficient to select a codec: the synthetic rank sweep favors structured coding in some settings, while the local sensitivity predictor fails at the two-bit operating point (Appendices D.2, E.2).

## Open research questions
1. **Can downstream-aware scaling reliably improve on norm restoration?** The local quadratic predictor fails, and held-out gains vary by model and domain. Next experiment: calibrate fixed-code scales on separate domains and evaluate both output KL and task scores (Appendix E.2).
2. **When should structured coding replace the shared trellis?** Synthetic low-rank tables can favor PCA coding, but real-table output comparisons are limited to Qwen. Next experiment: measure actual matched-budget structured codecs across all three models without interpolation (Appendix D.2).
3. **Do serving gains persist in optimized inference engines?** Existing measurements use eager inference and show little speed benefit when memory is sufficient. Next experiment: repeat matched workloads with optimized execution, reporting memory pressure, lookup share, and complete-step latency (Limitations; §7).
4. **Can mixed precision remain beneficial under distribution shift?** Web-derived frequency allocation sometimes worsens code and multilingual fidelity. Next experiment: compare uniform CP with allocation calibrated on mixed-domain traffic under held-out workload shifts (Appendix E.3).

## Confidence and missing information
**Confidence: medium.** The supplied prose and populated tables support the central findings, but many referenced tables contain captions without their numerical bodies.

Material missing information includes complete per-task scores, full rate–distortion values, several ablation tables, detailed model-table dimensions, and evidence of released implementation or compressed checkpoints. These omissions prevent independent assessment of every reported comparison.
