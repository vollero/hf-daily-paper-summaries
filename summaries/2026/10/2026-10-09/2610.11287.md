# REMORY: Learning Residual Memory for Context Compaction

> [← Daily summary](../2026-10-09.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.11287) · [arXiv](https://arxiv.org/abs/2610.11287)


## One-sentence takeaway
REMORY supplements textual summaries with learned soft memory tokens, improving source attribution and agent benchmark scores for two frozen actors, although total execution efficiency and robustness across repeated runs remain incompletely established.

## Problem and motivation
Compacting an agent’s history into a summary can discard details needed for later decisions. The authors argue that these future needs cannot reliably be identified in advance, motivating a bounded memory supplement that preserves useful access to prior context without retaining the full history in the active window (§1).

## Approach and contributions
- **Summary-conditioned residual memory:** A neural network encodes history into continuous vectors conditioned on the generated summary, then appends those vectors after it. Later compactions incorporate previous memory, while ordinary retrieval tools retain access to exact records (§2.1).
- **Training through a frozen actor:** Reconstruction training precedes summary-conditioned continuation training. A reverse-KL objective matches the student’s response distributions to those produced with full history; only the memory network changes, and its encoder never receives the future response (§2.2).
- **Bounded compression and empirical evaluation:** Hierarchical compression limits final memory to 4,096 slots. Actor-specific networks are evaluated on attribution, complete agent tasks, and immediate post-compaction actions (§§2.1, 3).

The distinctive contribution is the learned supplement targeting the prediction gap left by an existing summary; continuous context compression itself is acknowledged as prior work (§4).

These comparisons support the usefulness of adding memory under the reported settings. SummHay provides particularly direct evidence because compacted conditions share the actor, query, decoding, and base summary, with retrieval disabled. It supports improved attribution, rather than equivalent recovery of all full-context information. Tool-count reductions suggest better use of feedback but do not isolate that mechanism because trajectories differ in actions and length. Published frontier scores use different protocols and are not controlled comparisons (Figure 1).

## Limitations and validity risks
- **Author-stated qualifications:** Generation costs omit memory computation and tools; next-action preferences do not measure executed outcomes; the two trading accounts differ in market selection and timing; the cell-repair example does not identify which details memory supplied (§§3.2–3.4).
- **Analyst inference—repeatability:** BrowseComp and Terminal-Bench have only one run per configuration, leaving run-to-run uncertainty unresolved. The five-run workflow evaluations offer stronger evidence on this point (§3.2).
- **Analyst inference—component attribution:** Figure 3 compares reconstruction versus random initialization through training diagnostics, but no downstream ablations isolate summary conditioning, memory size, hierarchical compression, or reconstruction initialization.
- **Analyst inference—transfer and reproducibility:** Evaluation uses two actor-specific networks. The supplied text does not establish transfer across actors or provide released checkpoints, code, detailed training hyperparameters, or complete training-data composition.

## Open research questions
- **Does REMORY improve total execution efficiency?** Reported savings exclude memory computation (§3.2). Measure end-to-end latency, accelerator use, and monetary cost with all components included.
- **Which components drive downstream gains?** Training diagnostics do not isolate their task-level effects (Figure 3). Compare reconstruction initialization, summary conditioning, and memory budgets under matched training and evaluation settings.
- **How stable are gains across stochastic runs?** Browsing and terminal results use single runs (§3.2). Repeat paired evaluations and report uncertainty for scores and tool behavior.
- **How well does memory survive many successive compactions?** Recursive memory construction is described, but retention is not evaluated by compaction depth (§2.1). Test delayed information dependencies over controlled sequences of repeated compactions.

## Confidence and missing information
**Confidence: medium.** The supplied text clearly describes the method and controlled comparisons, but broader validity is limited by single-run evaluations and incomplete implementation details.

Material missing information includes code/checkpoint availability, training hyperparameters and compute, precise training-data composition and overlap controls, total runtime costs, downstream component ablations, and uncertainty estimates for the single-run benchmarks.
