# Frozen Models, Evolving Expertise: Model-Agnostic Learning from Deployment Experience for Multimodal Medical AI

> [← Daily summary](../2026-10-09.md) · [Relationship graph](relationships.md) · [Hugging Face](https://huggingface.co/papers/2610.09146) · [arXiv](https://arxiv.org/abs/2610.09146)


## One-sentence takeaway
The authors report that updating validated external procedures, factual memory, and visual references improves frozen models across six benchmarks, with gains also observed on held-out cases and across base models (§§4.2–4.5).

## Problem and motivation
Frozen deployed models cannot automatically reuse experience or incorporate changing medical evidence. The authors identify three gaps in existing parameter-free approaches: repeated selection on fixed validation sets, insufficiently supported domain knowledge, and loss of visual evidence when experience is stored only as text (§1).

## Approach and contributions
- **External expertise without weight updates:** An LLM optimizer rewrites a bounded natural-language **Skill** from scored trajectories and proposes evidence-supported additions to **Knowledge Memory**. Knowledge checks exclude patient-specific observations and answer keys (§§3.2–3.3).
- **Multimodal Knowledge Base (MMKB):** Stores original images, context, source answers, and available explanations. Retrieval uses image–question embeddings; explicit instructions require interpreting each reference and comparing its evidence with the current case (§3.4; Appendix C.4).
- **Deployment validation:** Candidate Skill and Memory updates must improve a fresh batch while avoiding average decline on a refreshed past-case buffer. Periodic checks can restore earlier versions; MMKB continues growing independently (§3.5).
- **Reusable expertise:** Experiments test frozen held-out evaluation, unchanged cross-model transfer, and non-medical visual tasks (§§4.4–4.5).

The claimed contribution is this combination and its validation strategy; external memory and multimodal retrieval themselves are acknowledged prior approaches (§2).

## Evidence and main results

All gains below are **relative changes**, not percentage-point improvements.

| Finding | Evidence / setting | Location in paper |
|---|---|---|
| Consistent online improvement | Above Base in all 24 benchmark–model pairs; average relative gain **17.6%**, versus **5.6%** for ACE. Aggregates benchmark-specific accuracy, MedChain Average, and QCalEval overall score across six benchmarks and four models. | §4.2; Table 1 caption; metrics in §4.1 |
| Largest reported online gains | Up to **34.2%** relative improvement in AgentClinic diagnosis accuracy and **81.9%** in VisuLogic answer accuracy over Base. The prose does not identify the maximizing base models. | §4.2; Table 1 referenced |
| Validation ablation | With GPT-5.6-Sol, accepting every update reduces each benchmark’s native score by **21.8%–37.8% relative to Full**, and all six scores fall below Base. | §4.3; Table 3 |
| Explicit reference analysis adds value | With GPT-5.6-Sol and identical retrieved references, MMKB improves MedChain Task 3 macro claim recall by **23.9% relative to Base**; Initial MMKB gives **22.6%**. Growing MMKB improves further on all four image-based tasks. | §4.3; Figure 3; Table 7 caption |
| Held-out generalization | After learning on approximately the first **70%** of grouped streams, frozen expertise beats Base in **21/24** pairs. Average relative gain is **20.7%**, versus **8.3%** for SkillOpt and **1.9%** for ACE, using benchmark-specific metrics. | §4.4; Table 4 |
| Cross-model transfer | Expertise from two source-model runs improves **33/36** target results, averaging **20.0%** relative gain over each target’s full-stream Base score, without further learning. | §4.5; Figure 4 |

These author-reported results support useful external adaptation in the evaluated settings. The validation and identical-reference comparisons provide evidence for specific design choices. However, the supplied text contains table captions without numerical table bodies or plotted data, preventing independent checking of most absolute scores and aggregates.

Cross-model transfer is also distinct from held-out generalization: transferred expertise was learned from the complete benchmark later used to evaluate target models, although matching cases and duplicate references are excluded (§4.5).

## Limitations and validity risks
- **Explicit author qualifications:** Splits are custom public-data splits rather than official hidden tests; MedChain scores are not directly comparable with the original paper’s standardized-input results; matching seeds does not ensure deterministic responses (Appendices B.1, B.3).
- **Reference quality:** QCalEval references mix adapted source data, computed fits, and explanatory notes; they are not uniformly expert-authored, and some share a study source (Appendix B.4).
- **Analyst inference—feedback dependence:** “Verified” means the dataset answer has been released, rather than independently clinically adjudicated. Robustness to delayed, erroneous, or unavailable feedback is therefore unestablished (§3.1).
- **Analyst inference—limited robustness coverage:** Component ablations use GPT-5.6-Sol; case-order repetitions cover only AgentClinic and QCalEval with that model. Every learning run uses GPT-5.6-Sol as optimizer (§§4.1–4.5).
- **Analyst inference—deployment cost and safety:** Candidate evaluation and replay require additional executions, while MMKB grows with completed cases. The supplied text gives no measured latency, monetary cost, storage scaling, or prospective clinical outcomes (§§3.4–3.5; Appendix B.1).

## Open research questions
- **Does validation remain reliable under noisy or delayed feedback?** Dataset answers drive updates here. A next experiment could introduce controlled label errors and feedback delays, measuring accepted harmful updates and subsequent task performance.
- **Can weaker optimizers produce equally reusable expertise?** All runs use GPT-5.6-Sol for optimization. Compare optimizers under matched update budgets, including held-out performance and cross-model transfer.
- **Does transfer survive genuinely unseen target cases?** Current transfer uses source expertise learned on the full evaluated benchmark. Learn expertise on a separate grouped source split, then evaluate target models exclusively on untouched groups.
- **Which validation mechanisms matter most?** The ablation removes validation altogether. Separately ablate fresh-batch testing, buffer refresh, win–loss gates, and rollback to measure their contributions (§§3.5, 4.3).

## Confidence and missing information
**Confidence: medium.** The method and protocols are described clearly, but numerical verification is limited by missing table bodies and figures.

Material unavailable information includes most absolute scores, full evaluation-pool counts, numerical uncertainty estimates, complete generation-setting tables, initial reference inventories, measured deployment costs, and a code or artifact release statement.
